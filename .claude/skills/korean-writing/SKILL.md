# 한국어 글쓰기 (Terra In-Cognita)

이 프로젝트의 한국어는 "처음 보는 사람도 한 번에 알아듣게" 쓴다. 사용자는 어려운 말과 긴 설명을 싫어한다.

## 1. 공통
- 결론부터 쓴다. 한 문장에는 한 가지만.
- 쉬운 말을 쓴다. 전문용어가 꼭 필요하면 처음 한 번만 괄호로 풀어 쓴다.
  - 예: 역방향 프록시(외부 주소로 들어온 요청을 NAS 안 서버로 넘겨주는 설정)
- 영어 단어를 섞지 않는다. 코드·명령·파일명·제품 이름만 영어로 쓰고 `백틱`으로 감싼다.
  - 나쁨: "디플로이 파이프라인을 트리거했습니다" → 좋음: "배포를 시작했습니다"
- 숫자는 단위와 함께 쓴다: "약 77ms", "3초", "1,000개".
- 과장과 상투어를 쓰지 않는다: "완벽하게", "획기적인", "~하는 것이 중요합니다", 끝에 같은 말을 다시 정리하는 문장.
- 굵은 글씨와 이모지는 정말 중요한 한두 곳에만 쓴다.

## 2. 사실 표기
- 확인한 것은 "확인함"(문서에서는 **Verified**), 추정은 "추정"(**Assumed**), 모르면 "모름"(**Unknown**).
- 실행하지 않은 코드를 "된다", "동작한다"고 쓰지 않는다. "미실행"이라고 쓴다.
- 진행 상황은 퍼센트가 아니라 개수로 쓴다: "10개 중 4개 완료".

## 3. 사용자에게 하는 보고 (대화)
- 존댓말 "-습니다/-요"체.
- 순서: 결과 한 줄 → 이유(필요할 때만) → 사용자가 할 일(번호 목록) → 확인하지 못한 것.
- 사용자가 할 일은 메뉴 경로를 그대로 적는다: "제어판 → 보안 → 인증서".
- 내 실수는 짧게 인정하고 무엇을 고쳤는지 말한다. 변명하지 않는다.

## 4. 문서 (docs/, 작업 기록, ADR)
- "-다"체로 쓴다. 예: "배포는 실행기가 한다."
- 양식은 템플릿을 따른다: `docs/worklog/TEMPLATE.md`, `docs/adr/README.md`.
- 파일 이름은 영어, 본문은 한국어.

## 5. 게임 화면 문구 (UI)
- 화면 문구를 코드에 직접 쓰지 않는다. 메시지 키로 쓰고 `apps/game/messages/ko.json`과 `en.json`에 함께 넣는다(AGENTS.md 6장 Paraglide 항목).
- 버튼은 짧은 동사: "저장", "다시 연결", "취소". "~하기"를 붙이지 않는다.
- 상태는 짧게: "서버에 연결됨", "연결하는 중…"(줄임표는 `…` 한 글자).
- 오류는 무엇이 문제인지와 무엇을 하면 되는지를 함께: "앱이 오래된 버전입니다. 새로고침해 주세요."
- 영어 문구는 한국어를 직역하지 말고 자연스러운 영어로 쓴다(같은 뜻, 비슷한 길이).
- 휴대폰 화면은 좁다. 짧게 쓰고, 긴 한국어·영어 문구로 화면이 깨지지 않는지 `break-ui` 스킬로 확인한다.

## 6. 자주 틀리는 맞춤법
- 띄어쓰기: "할 수 있다", "안 된다"(부정), "하는 중", "한 뒤".
- "돼요"(되어요), "됐다"(되었다). "되요", "됬다"는 틀린 표기.
- 헷갈리면 국립국어원 표준국어대사전 기준을 따른다.
