### 0.2 개편 요청 (원문)
> 이 프로젝트는 낡은 기술이 많이 활용되고 여러번 수정되어 쓸모없는 파일도 많다, 또한 코드나 파일, 아키텍쳐가 매우 비효율 적이다. 전체적으로 뜯어고치고 효율적이게 만들기 위한 대대적인 개편 계획을 세워야한다.
> /docs 의 기획서는 보존해야한다. 단 로그나 PRD, 아키텍쳐 등은 작업마다 업데이트되어야 하나 역시 방치되어 수정하도록 바꿔야한다.
> 비공개 깃허브로 알고있어 나스접속 비번은 바꾸지 않아도 되나 추후 정식서비스전 마지막 단계에서 고려할일이다.
> .js파일은 대다수 1회성으로 만들어진걸로알고있고 왜 삭제를 안하고 깃허브에 올리는지 이해가 안된다. 불필요하고 사용되었으면 제거해야한다.
> 사실상 기획서도 불안정하여 계속 수정보완될것이나 프로젝트 구현상태는 더욱 MVP같이 대충만들어진것으로 아주 처음부터 기술스택 선정부터 전부 재검토해달라.
> 맷포코의 그릴미라는 스킬을 설치하고 사용해달라

→ `grill-me`·`grilling` 스킬 설치(mattpocock/skills, MIT). 조사 에이전트 4개 실행(서버 파일 사용 여부, 클라이언트 파일 사용 여부, 문서·기획서 분류, 기술스택 최신 현황).

### 0.3 조사로 확인된 주요 사실
- 서버 JS 315개 중 268개(85%)가 실제 실행 경로에 포함 → "대부분 일회성"은 사실과 다름. 실제 군더더기는 이미지(서버 221.6MB + 클라이언트 320MiB), 외부 스킬 팩 1,331개(`.claude/skills`), 에이전트 로그 1,072개(`.agents`), 중계 파일 43개.
- 핵심 테이블 78개의 생성 코드가 사용되지 않는 SQLite 파일에만 있음 → 빈 DB를 코드로 만들 수 없음.
- Redis 미설정 시 서버 초기화가 멈출 수 있음, 존재하지 않는 모듈 require 3곳.
- 살아있는 문서 대부분 방치(TASKFORCE 100% ✅는 스크립트가 문자열을 치환한 결과, PROJECT_PROBLEMS는 봇 기록 110건).
- 종교 시스템 기획(REL-1) 약 340줄 인코딩 손상, 기획서 간 모순 10건 이상.
