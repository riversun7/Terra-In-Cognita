## 배경
- 화면은 임시 모양으로 먼저 만들었다(사용자 결정 "화면은 임시 모양으로 먼저, 디자인은 따로"). 색·글자·간격 값은 `apps/game/src/styles/tokens.css` 한곳에 모여 있다.
- 사용자 요구: "설정 페이지에서 일반적인 파스텔모드, 다크모드, 또 다른 모드 등을 선택할 수 있다."
- 기획 톤: 밝은 파스텔이 기본이다(D-063 "다시 푸르러진 지구"). 귀엽고 밝다(D-064).
- 후보 3개를 모드 4개로 그려 비교했다(조사 원본).
- 사용자 결정(2026-10-28)
  - 후보: "A 새싹 장난감".
  - 세 번째 모드: "선명 + 정거장 둘 다 지금".
  - 처음 테마: "늘 파스텔". 기기가 고대비를 요청하면 선명만 자동으로 고른다. 설정에 "기기 설정에 맞추기" 스위치를 둔다.
  - 저장: "기기 + 계정 둘 다". 언어도 같은 방식으로 둔다.

## 선택지
글꼴을 언제 받나:
1. 앱 껍데기와 함께 미리 캐시한다(설치할 때 +560~720KB).
2. 처음 쓸 때 받고 브라우저 캐시에 둔다.
3. 기기 글꼴만 쓴다.

글꼴 파일을 어디서 가져오나:
1. npm 꾸러미(정확히 고정, 잠금 파일의 무결성 해시).
2. 파일을 git에 넣는다(PLAN 9.8 예외가 필요).
3. 빌드할 때 GitHub에서 내려받는다.

## 결정
### 모양과 테마
- 디자인은 후보 A다. 값의 원본은 조사 문서 부록(`tokens.css`)이다.
- 토큰 이름은 지금 코드의 규칙(`--color-*`, `--font-*`, `--space-*`, `--radius-*` 등)을 따른다. 후보 A의 값을 그 이름으로 옮기고, 없는 토큰(버튼 턱, 움직임 시간 등)은 같은 규칙으로 더한다.
- 테마 4개. `:root[data-theme="…"]`에서 같은 이름의 값만 바꾼다. 화면 스타일은 `var(--…)`만 쓴다.
  - `pastel`(기본): 하늘색 바탕 `#dff2fb`, 잎색 버튼 `#8ed97f` + 짙은 글자.
  - `dark`: 밤의 들판 `#13203a`. 잎색 버튼은 그대로다.
  - `contrast`(선명): 본문 7:1 이상, 테두리 2px, 초점 4px, 그림자 없음. 성공은 파랑, 위험은 주황빨강. 상태는 늘 아이콘·글자와 함께 보인다.
  - `station`(정거장): 짙은 청록 `#061a22`, 청록 빛 테두리. 판은 불투명하고 흐림 효과(`backdrop-filter`)는 쓰지 않는다.
- 촘촘 변형: 관리자·거래창처럼 빽빽한 화면은 `data-density="compact"`를 붙인다(버튼 턱 0, 모서리 10px, 조작부 44px).
- 움직임: 기기의 "동작 줄이기"(`prefers-reduced-motion`)를 따른다.
- 아이콘(파비콘·앱 아이콘)은 바꾸지 않는다.

### 처음 테마와 기기 설정
- 저장된 테마가 없으면 파스텔이다. 단, 기기가 고대비를 요청하면(`prefers-contrast: more`) 선명이다.
- "기기 설정에 맞추기"(기본 꺼짐)를 켜면 기기를 따른다. 고대비 요청이면 선명, 다크면 다크, 아니면 파스텔이다. 기기 설정이 바뀌면 바로 따른다. 정거장은 자동으로 고르지 않는다.
- 첫 화면이 다른 색으로 번쩍이지 않게, CSS보다 먼저 작은 외부 스크립트(`apps/game/public/theme-init.js`)가 `data-theme`을 정한다. 인라인 스크립트는 쓰지 않는다(나중에 넣을 CSP). 이 스크립트도 앱 껍데기로 미리 캐시한다.
- 주소창 색(`<meta name="theme-color">`)은 늘 현재 테마의 바탕색이다: 파스텔 `#dff2fb`, 다크 `#13203a`, 선명 `#ffffff`, 정거장 `#061a22`.
- manifest의 `theme_color`·`background_color`는 `#dff2fb`(기본 파스텔)로 바꾼다. 지금 값 `#0b1020`은 PWA ADR이 정한 임시값이다.

### 글꼴
- 제목은 Jua, 본문은 Pretendard다. 받기 전과 받지 못할 때는 기기 글꼴(Apple SD Gothic Neo, Noto Sans KR 등)로 보인다.
- 직접 배포한다. CDN은 쓰지 않는다.
- 처음 쓸 때 받는다. 미리 캐시하지 않는다. 서비스 워커의 캐시 범위(앱 껍데기만)는 그대로다.
- `/assets/`의 파일은 이름에 내용 해시가 있다. 서버는 이 경로에 `Cache-Control: public, max-age=31536000, immutable`을 준다. 한 번 받은 글꼴은 다시 묻지 않는다. 해시가 없는 파일(`index.html`, `sw.js`, 아이콘, `theme-init.js`)은 지금처럼 매번 확인한다.
- Pretendard
  - 제작자가 배포한 KS X 1001 부분 집합(한글 2,350자)을 그대로 쓴다. 굵기는 Regular(400)·SemiBold(600) 2개다(267·269KB).
  - 다른 굵기 값은 가장 가까운 굵기로 그려진다(500 → 400, 700 → 600). 토큰도 이 두 굵기만 쓴다.
- Jua: Fontsource의 조각 파일(`unicode-range`)을 쓴다. 화면에 보이는 글자가 든 조각만 받는다. 지금 제목은 6조각, 약 147KB다.
- `font-display: swap`. WOFF2만 내보낸다(지원 하한 브라우저가 모두 읽는다). 글꼴 파일은 CSS에 인라인하지 않는다.
- 글꼴 파일을 고치거나 줄이지 않는다. Pretendard는 예약 이름이 있어 고치면 이름을 바꿔야 한다(Assumed: OFL FAQ).
- 의존성(게임 앱 `dependencies`, 기기로 간다. Verified: npm 2026-10-28)
  - `pretendard` 1.3.9: 2023-11-05 공개, OFL-1.1, 예약 이름 "Pretendard". 압축 72MB(풀면 97MB) 중 2개 파일을 쓴다.
  - `@fontsource/jua` 5.3.0: 2026-07-19 공개, OFL-1.1, 예약 이름 없음. 압축 2.6MB.

### 설정 화면과 저장
- 설정 화면: 테마 4개(미리 보기), "기기 설정에 맞추기" 스위치, 언어. 계정 줄의 [설정]으로 연다. 로그인 화면의 언어 고르기는 그대로 둔다.
- 기기에는 `localStorage`에 저장한다. 언어는 지금처럼 Paraglide가 저장한다.
- 계정에는 서버 표 `user_settings`(사용자당 한 줄: 테마, 기기 설정 따르기, 언어, 바꾼 시각)에 저장한다.
  - tRPC `settings.get`·`settings.set`. 로그인한 본인 것만 읽고 쓴다.
  - 테마·언어 목록은 `@terra/shared`에 두고 서버와 기기가 같이 쓴다. 모르는 값(더 새 버전이 저장한 값)은 기본값으로 본다.
- 맞추는 규칙
  - 로그인한 동안 바꾸면 기기와 계정에 함께 저장한다.
  - 로그인하지 않은 동안 바꾼 값(예: 로그인 화면에서 바꾼 언어)은 로그인할 때 계정에 올린다.
  - 그 밖에는 로그인할 때 계정 값이 기기 값을 덮는다. 계정에 값이 없으면 기기 값을 올린다.
  - 언어가 바뀌면 새로고침한다(Paraglide 기본 동작).

### 검사
- `pnpm check`에 대비 검사를 넣는다. 테마마다 본문·흐린 글자·버튼 글자·상태색은 4.5:1 이상, 선명 테마 본문은 7:1 이상, 초점 표시와 입력칸 테두리는 3:1 이상이다.

## 이유
- 후보 A
  - 기획 톤(D-063·D-064)에 가장 가깝다.
  - 파비콘 색(파란 행성, 초록 땅, 금색 고리)과 같다.
  - 모드 4개 모두 대비 기준을 넘는다(Verified: 계산, 조사 원본).
- 처음 쓸 때 받기
  - 미리 캐시하면 기기마다 처음 설치할 때, 쓰지 않는 굵기·글자까지 모두 받는다(560KB 넘게).
  - 처음 쓸 때 받으면 화면에 보이는 굵기·글자만 받는다.
  - 게임은 서버 없이 할 수 없다. 그래서 오프라인 첫 실행의 글꼴은 이득이 작다(Assumed).
- 브라우저 캐시(`immutable`)
  - 서비스 워커 캐시 범위(PWA ADR)를 바꾸지 않아도 된다.
  - 지금은 `/assets/*`도 매번 다시 확인한다(`max-age=0`). 글꼴을 쓸 때마다 확인 요청이 생기므로 해시 이름 파일은 오래 캐시한다.
- Pretendard는 KS X 1001 부분 집합 한 파일
  - 본문은 쓰는 글자가 많다. 조각 방식은 지금 문구만으로도 굵기마다 14조각·약 162KB다. 글자가 늘면 1.16MB까지 는다(Verified: 이 세션 계산).
  - 부분 집합 한 파일은 267KB에서 끝난다.
- 굵기 2개(400·600)
  - 후보 A 시안에서 가장 많이 쓴 굵기다(본문 400, 버튼·이름표 600).
  - 4개를 다 받으면 약 1.07MB다.
- Jua는 조각 방식
  - 제목에만 써서 글자가 적다.
  - 한 파일로 줄이려면 원본 TTF가 필요한데 npm에 없다. git에 바이너리를 넣거나(PLAN 9.8 예외), 빌드할 때 내려받아야 한다.
- npm 꾸러미
  - 잠금 파일이 무결성 해시로 고정한다. Dependabot이 새 판을 알려 준다.
  - git에 바이너리를 넣지 않는다(PLAN 9.8).
  - 큰 꾸러미(72MB)는 CI 설치에서만 받는다. 이미지는 GitHub 실행기가 만들고 NAS는 이미지만 받는다(Verified: CI #36).
- 테마 시작 스크립트: CSS가 먼저 그린 뒤 테마를 정하면 첫 화면이 다른 색으로 번쩍인다.
- 기기 + 계정
  - iOS는 오래 쓰지 않은 사이트의 기기 저장소를 지운다(PWA ADR).
  - 계정에 두면 다른 기기에서도, 저장소가 지워진 뒤에도 같은 설정이 된다.
  - 로그인 전에 바꾼 값을 올리는 규칙은 기기 시계를 쓰지 않는다. 로그인 화면에서 언어를 바꾸고 로그인해도 되돌아가지 않는다.

## 결과
- 좋은 점: 테마는 토큰 값만 바꿔 끼운다. 화면 코드는 그대로다. 테마를 더하기 쉽다.
- 감수할 점
  - 처음 켤 때 글자가 기기 글꼴로 보였다가 바뀐다(한 번).
  - 본문 글꼴은 처음 쓸 때 약 536KB, 제목 글꼴은 보이는 글자만큼(지금 약 147KB) 받는다.
  - KS X 1001 밖의 드문 음절과 Jua에 없는 글자는 기기 글꼴로 섞여 나온다.
  - 검사할 화면 모양이 테마 4개 × 언어 2개다.
  - `pretendard` 꾸러미가 커서 CI 설치가 느려진다. 2023-11 뒤로 새 판이 없다(2026-10-28 확인). 글꼴이라 보안 갱신 부담은 작다(Assumed).
  - 다크·정거장 테마에서도 세계(지도) 조명은 바뀌지 않는다(D-070). 그래서 화면 위 판(HUD)은 밝은 지도 위에서도 읽혀야 한다(불투명 판).
- 나중에 다시 볼 것
  - 지도 라벨(S1, troika-three-text 0.52.5): WOFF2를 못 읽고, 글꼴에 없는 글자를 CDN(jsDelivr)에서 받는다. 지도용 글꼴(WOFF·TTF, 모든 글자)은 따로 정한다(Verified: 패키지 코드, 조사 원본).
  - 게임 콘텐츠 색(계열·12속성·이로치, D-070·D-071)은 UI 의미 색과 따로 관리한다.
  - iOS 홈 화면 앱의 상태 표시줄 색은 켤 때 고정되는 것으로 본다(Assumed). Android 설치 앱이 주소창 색 변경을 바로 반영하는지도 추정이다.
  - 정거장 테마의 빛 효과는 휴대폰 GPU 부담을 잰 뒤에 키운다.
- 확정할 때 할 일: PWA ADR 상태 줄에 "일부 대체됨(manifest 색)"을 표시한다.

## 구현하며 정한 것
2026-10-28 구현(Verified: 시험·빌드·Playwright Chromium, 작업 기록 `2026/10/28-2340-design-system.md`). 같은 날 main에 합치며 확정했다. 글꼴 라이선스 원문은 빌드 결과 `licenses/`에 함께 내보낸다(`THIRD_PARTY_NOTICES.md`).

### 값
- 부록 값은 그대로 옮기고 이름만 지금 규칙으로 바꿨다(`--bg` → `--color-bg`, `--accent` → `--color-primary`, `--shadow-1` → `--shadow-control` 등).
- 글자 크기는 rem으로 적었다(값은 부록과 같다, 16px = 1rem). 브라우저 기본 글자 크기를 키운 사람에게는 글자도 커진다. 입력칸은 `max(16px, 1rem)`이다(iOS 확대 방지).
- 선명 테마의 `--weight-regular: 500`은 옮기지 않았다. 본문 글꼴은 400·600만 받아서 500은 400으로 그려진다(위 "글꼴").
- 부록에 없던 값을 같은 규칙으로 더했다: 상태 알림 상자 바탕(`--color-success-surface`·`--color-warning-surface`·`--color-danger-surface`, 테마마다), 아이콘·상태 점·스위치·미리 보기 크기, 새 버전 배너가 가리는 높이(`--banner-reserve`).
- 다른 토큰을 `var()`로 묶은 토큰은 만들지 않는다. 묶은 값은 `:root`에서 한 번 계산돼 테마·촘촘 변형의 값을 따르지 않는다. 그래서 부록의 `--font-num`은 두지 않고, 숫자는 본문 글꼴 + `tabular-nums`로 쓴다.
- 촘촘 변형은 판 모서리(`--radius-panel`)도 16px로 줄인다.
- 부록의 게임 설정 "동작 줄이기"(`data-motion`)는 넣지 않았다. 이 ADR은 기기 설정만 따른다.
- 윈도 고대비(`forced-colors`)에서는 테마를 바꾸지 않는다. 지워지는 배경색 대신 시스템 색으로 상태 점·고른 표시·스위치를 그린다.

### 테마와 설정
- 기기 저장: `localStorage` 열쇠 `terra.settings`, 값 `{ v: 1, theme, followSystem, locale, pending }`. 판(`v`)이 다르거나 깨졌으면 아무것도 정하지 않은 것으로 읽는다. 저장소를 못 쓰면 이번 실행 동안만 기억한다.
- `theme-init.js`와 실행 코드(`src/settings/theme.ts`)가 같은 열쇠·색 표·규칙을 쓰는지 시험이 확인한다(`themeSources.test.ts`).
- 따르는 중에 테마를 고르면 "기기 설정에 맞추기"가 꺼진다. 스위치를 끄면 지금 보이는 테마가 고른 테마로 남는다(화면이 갑자기 바뀌지 않게). 따르는 동안 고른 표시는 지금 걸린 테마에 있다.
- 언어: Paraglide는 처음 정한 언어도 저장한다. 그래서 "사용자가 고른 언어"는 우리 설정(`locale`)에 따로 적는다.
- 언어 고르기는 로그인하지 않은 화면 아래와 설정 화면에 둔다. 로그인한 뒤 상태 화면 아래에서는 뺐다(작업 기록 `28-2150-auth-ui.md`의 "모든 화면 아래"를 바꿈).
- "올릴 것" 표시: 묶음(화면 = 테마 + 맞추기, 언어)마다 바꾼 사람을 적는다(로그인한 사용자 id, 로그인 전이면 없음). 로그인할 때 묶음마다
  1. 그 사용자가(또는 로그인 전에) 바꾸고 못 올린 값은 올린다.
  2. 그 밖에 계정에 값이 있으면 계정 값이 기기를 덮는다. 다른 계정이 바꾸다 못 올린 표시는 버린다(한 기기를 같이 쓰는 다른 계정 값이 섞이지 않게).
  3. 계정에 값이 없고 기기에 있으면 기기 값을 올린다.
- 올리기에 실패하면 표시가 남아 다음 로그인(앱을 다시 켤 때 포함) 때 올린다. 요청은 10초에서 끊는다.
- 로그인한 동안 언어를 바꾸면 계정에 올리기를 최대 3초 기다린 뒤 새로고침한다.
- 계정 언어로 바꾸는 새로고침은 같은 언어로 1분 안에 다시 하지 않는다(탭마다, `sessionStorage`). 저장이 막힌 기기에서 새로고침이 끝없이 반복되지 않게.
- 계정 맞추기 코드와 tRPC 클라이언트는 로그인한 뒤 따로 내려온다(동적 import). 첫 화면 JS는 7.4kB(gzip 3.9kB) 늘었다.

### 서버
- 표 `user_settings`: `theme`·`locale`은 text이고 모양만 검사한다(영문 소문자 이름, 언어 태그 모양). `follow_system`은 기본 false다. 사용자가 지워지면 함께 지워진다.
- 목록 검사는 입력 검사(Zod, `@terra/shared` 목록)에서만 한다. 그래서 더 새 버전이 쓴 값도 표가 막지 않는다. 읽을 때 모르는 값은 기본값(null)으로 본다.
- `settings.set`은 바꿀 칸만 받는다(부분 저장). 빈 요청과 모르는 칸은 400이다.
- immutable은 `/assets/` 아래(하위 폴더 포함) 파일에만 준다. 없는 파일(404)에는 주지 않는다.

### 글꼴
- Jua CSS(`@fontsource/jua/400.css`)는 `main.tsx`에서 불러온다. 빌드 변환(`vite.config.ts`의 `woff2Only`)이 WOFF 줄을 지우는데, CSS 안 `@import`에는 이 변환이 돌지 않는다.
- Pretendard `@font-face` 2개는 우리 파일(`src/styles/fonts.css`)에 있다.
- 글꼴은 CSS에 넣지 않는다(`assetsInlineLimit`). 빌드에는 WOFF2 89개(Jua 조각 87 + Pretendard 2)가 나오지만 쓰는 것만 받는다. 로그인 화면은 6개를 받는다(Pretendard 2개 535.8KB + Jua 4조각 91.5KB).
- 감수할 점(새로): Jua 조각 87개의 `@font-face` 규칙이 첫 화면 CSS에 들어간다. CSS가 6.4kB에서 58.2kB(gzip 1.7kB → 17.4kB)로 늘었고, 그중 글꼴 규칙이 41.7kB(gzip 12.9kB)다. CSS는 앱 껍데기로 미리 캐시되므로 두 번째부터는 기기에서 읽는다.

### 검사
- 대비 검사(`pnpm check:contrast`, `scripts/check-contrast.mjs`)는 위 "검사"의 쌍에 더해 입력칸 글자·자리 표시 글자, 바탕 그라데이션의 모든 색 위 글자·입력칸 테두리·초점, 꺼진 스위치 손잡이, 잘못 입력한 칸 테두리를 잰다(테마 4개, 136쌍).
- 화면 CSS(토큰 파일 밖)에 색·px 값을 직접 쓰면 실패한다.
- PWA 빌드 검사(`scripts/check-pwa.mjs`)가 더 본다: `theme-init.js`가 `<head>`에서 CSS·모듈보다 먼저인지, 인라인 스크립트가 없는지, `theme-init.js`는 미리 캐시하고 글꼴은 하지 않는지, 글꼴은 `assets/`의 해시 이름 WOFF2만인지, CSS에 `data:` 글꼴이 없는지.
