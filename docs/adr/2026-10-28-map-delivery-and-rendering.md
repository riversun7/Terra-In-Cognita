# 맵 전송·캐시·렌더링

- 상태: 확정 (일부 대체됨: `2026-10-28-unit-display-real-size.md` — 유닛 중간 단계의 크기 과장)
- 날짜: 2026-10-28
- 관련: PLAN 5.6·5.7, DECISION_LOG Round 7·8·9

## 배경
기존 2차맵은 1분 이상 멈췄다. 원인은 그래픽이 아니라 클라이언트의 불필요한 연산이었다(사용자, Round 1). 사용자는 구글어스처럼 끝까지 확대해도 렉이 없기를 원했다(Round 7). 모바일이 1순위다.

## 결정
- 1차맵: 서버가 단계별 타일을 미리 굽고 버전 붙은 불변 주소로 제공한다. 첫 진입 로딩에서 넓은 단계를 한 번에 받는다.
- 2차맵: 처음 요청될 때 워커가 생성해 저장하고 캐시한다. 최대 확대 시 주변을 미리 받는다. 이웃 2차맵과의 이음매 없는 스트리밍은 검증 결과에 따라 적용한다.
- 기기 저장은 서비스워커 Cache Storage + HTTP 캐시. 지워져도 다시 받으면 되는 데이터만.
- 숨김 정보(자원 위치, 크리쳐)는 지형 데이터에 넣지 않는다.
- 렌더링: 면별 쿼드트리 LOD(화면 오차 기준, 부모 먼저, 화면당 타일 상한, 틈 메우기, 카메라 기준 좌표), 지표 레이어는 셰이더 데이터 텍스처 + 인스턴싱. three-globe는 쓰지 않는다.
- 2차맵 메싱은 Web Worker에서. 유닛은 확대 단계별 표현(근접 실제 크기, 중간 최대 약 3배 과장 + 외곽선, 원거리 아이콘·묶음).
- WebGL2 기본. WebGPU와 셰이더 언어(TSL/GLSL)는 S2 1주차에 측정해 정한다.
- 모바일 예산(메모리·드로우콜·인스턴스 상한), KTX2 압축, 픽셀 비율 상한, 변화 없으면 렌더 중지, 컨텍스트 손실 복구.

## 이유
- 공개 표준 3D Tiles도 같은 원리(계층형 LOD + 화면 오차)로 동작한다(Verified: 3D Tiles 스펙). 화면에 그리는 타일 수가 행성 크기와 무관하게 일정해진다.
- three-globe는 위경도·직사각형 이미지 기반이라 격자 계약과 맞지 않는다(Verified: README).
- 반지름 531km에서 32비트 실수는 6.25cm 단위라 확대하면 떨린다(Verified: 계산).
- iOS는 앱 전환 시 WebGL 컨텍스트를 잃고, 메모리를 넘기면 경고 없이 탭을 종료한다(Verified: three.js·Apple 포럼, WebKit 버그 — 독립 검토 확인).

## 결과
- 자체 LOD 렌더러를 만들어야 한다(검증 단계 S2).
