# 행성 생성 파이프라인과 세계 데이터 버전

- 상태: 확정 (일부 대체됨: `2026-10-28-planet-generation-order.md` — 파이프라인 순서)
- 날짜: 2026-10-28
- 관련: PLAN 5.3~5.5, DECISION_LOG Round 5·6

## 배경
사용자는 기존 PixiMap의 지형 타입과 큰 흐름만 참고하고, 문명 시리즈나 오픈소스 맵 생성기 방식으로 지구와 행성을 자연스럽게 표현하길 원했다(Round 5). 고도·온습도는 자원·크리쳐 배치의 근거다. 기존에는 서버와 클라이언트 생성기가 서로 달라 "보이는데 없는 자원" 같은 문제가 있었다.

## 결정
- 파이프라인: 판 구조(구면 보로노이) → 침식·배수(Priority-Flood, 물 흐름 누적) → 수심 등급 → 기후(위도·고도·바람·비그늘·바다 거리) → 바이옴 → 기본 밀도(숲, 광물).
- 지구: NOAA ETOPO 2022 고도를 1차맵 해상도로 미리 변환하고, 2차맵 디테일은 절차 생성.
- 노이즈는 3D 구면 좌표에서 계산한다. 생성 코드는 `packages/planet` 하나를 서버와 편집기가 공유한다.
- 위에서 생성(1차맵 기본값 → 2차맵), 아래에서 변화(2차맵 활동 → 1차맵 표시). 기본 환경 값은 바꾸지 않는다.
- 모든 결과에 `generatorVersion`, `contentVersion`. CI에서 고정 시드 결과 해시 비교. **플레이어가 처음 손댄 2차맵은 저장본으로 고정.** 편집기 공개 = 새 행성 버전.

## 이유
- 참고 메커니즘의 라이선스: WorldEngine MIT, mapgen4 Apache-2.0, mewo2/terrain MIT, Azgaar FMG MIT, FreeCiv GPL-2.0(방식만 참고) (Verified: 각 저장소 LICENSE). richdem은 GPL-3이라 Priority-Flood는 논문을 보고 새로 구현한다.
- ETOPO 2022는 CC0 퍼블릭 도메인이고, 1:12 축척에서 1차맵 해상도에 충분하다(Verified: NOAA).
- 생성기 코드가 바뀌어도 이미 플레이어가 쓰는 땅이 바뀌면 안 된다.
