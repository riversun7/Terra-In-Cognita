# 행성 생성 순서: 물 흐름 양·침식·강·호수는 기후 뒤에

- 상태: 확정
- 날짜: 2026-10-28
- 관련: `2026-10-28-planet-generation-and-versioning.md`(파이프라인 순서를 이 ADR이 대체), docs/PLAN.md 5.3, 기획 D-141(행성 단위 설정값), 기획 세션의 지적(2026-10-28, 원본 커밋 f0d7708 이후 메시지)

## 배경
- 행성 생성 ADR의 순서: 판 구조 → 침식·배수(Priority-Flood, 물 흐름 누적) → 수심 등급 → 기후 → 바이옴 → 기본 밀도.
- 강의 물 양은 비에 달려 있다. 이 순서는 기후보다 먼저 강을 정한다. 그래서 강수·기온 설정을 바꿔도 강이 바뀌지 않는다.
- 기획 D-141: 사용자는 해수면·평균 기온 같은 행성 단위 설정으로 "다른 맵 생성기를 참고하여 체계적으로" 행성을 만들기를 원한다. 설정값 목록(해수면, 평균 기온 보정, 적도–극 기온차, 강수, 산악도 등)은 기획 세션이 사용자에게 확인하는 중이다.
- 기획 세션이 참고 생성기 코드를 보고 이 문제를 알려 왔다. 기술 세션이 코드를 다시 확인했다.

## 선택지
1. 지금 순서를 둔다. 강은 고르게 내린 비로 계산한다.
2. 배수를 둘로 나눈다. 흐름 방향(고도만 씀)은 기후 앞에, 물 흐름 양·침식·강·호수는 기후 뒤에 둔다.
3. 기후와 침식을 여러 번 번갈아 돌린다.

## 결정
2번. 새 순서는 다음과 같다.
1. 판 구조(구면 보로노이) → 기본 고도
2. 해수면(행성 설정값)으로 땅과 바다를 나눈다
3. 웅덩이 채우기·흐름 방향(Priority-Flood, 고도만 씀)
4. 기후(위도, 고도에 따른 기온 감소, 바람·비그늘, 바다까지 거리, 행성 설정값) → 기온·강수
5. 물 흐름 누적(강수로 가중) → 침식 → 강·호수
6. 수심 등급
7. 습도(강수 + 강·호수 주변)
8. 바이옴 → 기본 밀도

- 침식 뒤에 기후를 다시 계산하지 않는다(한 번만 돈다). 1차맵 해상도에서 침식이 바꾸는 고도는 작다고 본다(Assumed). S2에서 고정 시드 결과로 차이를 재고, 크면 다시 본다.
- 지구(ETOPO)는 1단계 대신 실측 고도를 쓴다. 실측 고도에 침식을 적용할지는 S2에서 정한다.

## 이유
- 참고 생성기 코드(Verified: 2026-10-28, 원본 저장소 master)
  - WorldEngine(HEAD 80dd33e) `worldengine/generation.py`: 기온 → 강수 → 침식 → 물 지도 → 관개 → 습도 → 투수성 → 바이옴 → 빙하 순서다. `simulations/erosion.py`의 강 지도는 강수를 더해 간다(`rivermap_update`).
  - mapgen4 `map.ts`: 강수(`assignRainfall`, 바람 순서·비그늘)를 먼저 정하고 강(`assignRivers`)을 계산한다. 흐름 방향(`assignDownslope`)은 고도만, 흐름 양(`assignFlow`)은 강수에서 온 습기로 계산한다.
- 흐름 방향은 고도만 쓰므로 기후 앞에 둬도 된다. 기후는 바다까지 거리를 쓰므로 해수면은 기후 앞에서 정한다.
- 3번은 계산 시간이 늘고, 고정 시드 결과 해시를 맞추기 어렵다. 지금 필요한 것은 설정값이 강·침식에 반영되는 것이다.

## 결과
- 강수·기온 설정을 바꾸면 강·호수와 침식이 따라 바뀐다. D-141의 설정값이 실제로 행성 모양을 바꾼다.
- 생성기 코드는 아직 없다(S2). 지금 바꿀 코드·데이터는 없다. 생성기가 생긴 뒤 순서를 바꾸면 `generatorVersion`을 올린다(옛 ADR의 규칙 그대로).
- 침식 뒤 기후를 다시 계산하지 않는 근사를 감수한다.
- PLAN 5.3을 이 순서로 고친다.
