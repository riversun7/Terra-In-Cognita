# 행성 격자·스케일·ID 계약

- 상태: 확정
- 날짜: 2026-10-28
- 관련: PLAN 5.2, DECISION_LOG Round 4·5·7·9, 독립 검토 2

## 배경
기존 지구 맵이 반복해서 실패한 근본 원인은 "타일 1칸 = 몇 m"를 끝내 정하지 않은 것과 위경도 격자였다. 코드에는 150m·1km·1.5km가 동시에 쓰였다(Verified: `docs/research/2026-10-27-earth-map-failures.md`).

## 선택지
1. 위경도 격자 — 극지 찌그러짐
2. 육각 격자(H3 등) — 오각형 12개, 단계가 정확히 포개지지 않음, 사각 2차맵과 맞추기 어려움
3. **정육면체를 구에 투영한 사각 격자(cube-sphere)**

## 결정
| 항목 | 값 |
|---|---|
| 격자 | cube-sphere, 자체 구현(S2 방식 계층), **탄젠트 투영** |
| 행성 크기 | 면 레벨로 정함. 지구 기본 = 레벨 9(면당 512칸), 약 1:12, 반지름 약 531km |
| 1차맵 | 5단계(면당 32 → 512칸), 최소 칸 평균 약 1.5km |
| 2차맵 지형 | 1차맵 최소 칸 1개 = 128×128칸(평균 약 11.7m) |
| 2차맵 배치 | 256×256 세부 격자(평균 약 5.9m), 차지된 칸만 저장 |
| 유닛 위치 | 연속 좌표 |
| 규칙 단위 | 이동·사거리·건물 크기는 칸 수. 미터는 표시용 |
| 꼭짓점 8곳 | 행성을 회전시켜 바다에 두고, 주변을 바다·통행 불가로 처리 |
| 면 경계 | 좌표 변환표 + 전수 테스트 |
| ID | 행성 ID + 셀 키(면 3비트 + 레벨 5비트 + 힐베르트 순서), 53비트 안 |

## 이유
- 같은 단계에서 칸 면적 차이: 탄젠트 투영 약 1.4배, 기본 이차 투영 약 2.1배(Verified: S2 라이브러리 문서). 그래서 "정확히 10m"는 불가능하고, 규칙은 칸 수로 정한다.
- 2의 거듭제곱(128, 256)이라 단계가 정확히 포개지고 ID 체계가 하나로 이어진다.
- 캐릭터가 잘 보이는지는 칸 크기가 아니라 카메라 거리로 정해진다. 그래서 지형 데이터는 128로 줄이고, 배치는 256으로 세밀하게 한다(사용자 질문, Round 9).
- 64비트 S2 ID는 JS 숫자에 들어가지 않는다(s2js는 BigInt 사용 — 독립 검토 확인) → 53비트 자체 ID.

## 결과
- 면 경계와 꼭짓점 처리가 가장 까다로운 부분이다 → 전용 테스트를 먼저 쓴다.
- 지구의 꼭짓점 8곳이 모두 바다에 오는 회전이 있는지는 아직 모른다(Assumed) → 없으면 그 지점만 개별 진입.
