# 리부트 방식과 저장소 전략

- 상태: 확정
- 날짜: 2026-10-28
- 관련: PLAN 1장·2장, DECISION_LOG Round 1·2·4·9

## 배경
기존 프로젝트(AntiGravt01, 약 21만 줄)는 MVP 수준으로 여러 번 덧대어져 구조가 무너졌다. 핵심 테이블 생성 코드가 쓰이지 않는 SQLite 파일에만 있어 빈 DB를 만들 수 없고, 맵은 로딩 지연과 생성기 불일치를 반복했다(Verified: `docs/research/2026-10-27-legacy-server-inventory.md`, `...-earth-map-failures.md`). 기획서도 다시 쓰는 중이라 자주 바뀐다.

## 선택지
1. 점진 리팩토링(기존 코드를 모듈 단위로 교체)
2. 혼합(골격만 새로, 검증된 계산식은 이식)
3. 완전 재작성 + 새 저장소

## 결정
**완전 재작성**한다. 새 저장소로 `riversun7/Terra-In-Cognita`를 쓰고, 그 안의 2025-09 프로토타입은 이력까지 지운다. 기존 AntiGravt01은 보관만 하고 바꾸지 않는다. 기획서는 별도 세션이 `docs/design/`에 새로 쓴다.

## 이유
- 사용자 판단: 기획이 불안정해 혼합안도 다시 갈아엎을 가능성이 있다(DECISION_LOG Round 1).
- 기술스택을 처음부터 다시 고르기로 했으므로 기존 골격을 살릴 이유가 약하다.
- 새 저장소는 쓸모없는 파일 문제를 "옮겨오지 않는 것"으로 해결한다(기존 `.git` 487MiB).

## 결과
- 다시 플레이 가능한 상태가 되기까지 공백이 생긴다 → 로드맵을 기간 상한이 있는 검증 단계로 나눈다(PLAN 11장).
- 기존 코드는 참고 자료로만 쓴다. 계산식을 가져올 때는 새 규칙(결정적 판정, 칸 단위)에 맞게 다시 쓴다.
