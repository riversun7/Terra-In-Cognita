# S1 2차맵: 쿼터뷰 카메라, 서버 경로 이동, 건물 배치, 측정 계획

- 상태: 제안 (S1 측정 뒤 확정)
- 날짜: 2026-10-28
- 관련: docs/PLAN.md 5.2·5.7·11장(S1), `2026-10-28-planet-grid-contract.md`(격자·ID), `2026-10-28-map-delivery-and-rendering.md`(전송·렌더링), `2026-10-28-unit-display-real-size.md`(유닛 표현), `2026-10-28-simulation-model.md`(이벤트 예약), `2026-10-28-server-authority.md`, `2026-10-28-time-and-session-protocol.md`, `2026-10-28-fog-and-map-visibility.md`, `2026-10-28-stack-baseline.md`(Three.js), 기획 D-064·D-102·D-108·D-120·D-133·D-135·D-139

## 배경
- S1의 목표(PLAN 11장): 임시 지형으로 2차맵 스트리밍, 서버 경로를 따르는 유닛 1,000개, 건물 배치, 유닛 표현 단계.
- 통과 기준: 기준 기기 20분 연속, 프레임 시간 p95 ≤ 33ms, 메모리 예산 이내, 재진입 ≤ 1초, 첫 진입 ≤ 3초(4G).
- 2차맵을 보는 시점은 기획서·계획서 어디에도 정해져 있지 않았다.
- 사용자 결정(2026-10-28): "쿼터뷰 + 회전".

## 선택지 (시점)
1. 쿼터뷰(약 45°) + 회전.
2. 거의 위에서(60~75°) + 회전.
3. 자유 카메라(기울기를 수평 가까이까지).

## 결정
### 카메라와 조작
- 쿼터뷰다. 기울기는 약 35~55°(기본 45°)로 묶어 지평선이 보이지 않게 한다. 회전은 자유다. 확대는 근접(화면 가로 약 40m)부터 2차맵 전체가 보이는 거리까지다.
- 휴대폰: 한 손가락으로 끌면 이동, 두 손가락으로 확대·회전, 누르면 고르기·명령. 데스크톱: 끌기 이동, 휠 확대, 오른쪽 끌기 회전.
- 2차맵 밖은 그리지 않고 경계를 표시한다. 경계를 넘어가면 짧게 전환한다(D-139).

### 2차맵 데이터 (임시 지형)
- 2차맵 하나 = 1차맵 최소 칸 하나(격자 ADR). 지형은 128×128칸(높이는 꼭짓점 129×129), 배치는 256×256칸이다.
- S1은 임시 지형을 쓴다. 칸 키에서 시드를 만들어 노이즈 고도와 임시 지표 종류(물·풀·흙 등)를 만든다. 행성 생성기(S2)가 생기면 바꾼다.
- 서버가 처음 요청 때 만들고 저장·캐시한다(맵 ADR). 이진 형식에 `generatorVersion`을 붙인다.
- 숨김 정보(자원·크리쳐)는 넣지 않는다. 탐사·시야 확인 뒤에만 준다(ADR 26). S1은 확인하는 자리만 두고 모두 통과시킨다.

### 유닛 이동 (서버 판정)
- 위치는 2차맵 로컬 연속 좌표다. 값은 정수 고정소수점이고, 단위는 배치 칸의 1/1024다.
- 시각은 서버 시계의 ms, 속도는 단위/초 정수다. 출발값은 기획 D-120(걷기 약 0.42칸/초 이상, 차 약 4.7칸/초)이다.
- 경로탐색: 배치 칸 격자에서 8방향 A*. 대각선으로 모서리를 뚫고 지나가지 않는다.
  - 크기 등급은 2~3개다(통과 폭 1·2칸, 필요하면 3칸, D-135). 등급마다 통과 가능 지도를 따로 둔다.
  - 도로는 종류별 이동 비용이 있다(D-102). S1의 비용 수치는 임시값이다.
- 저장은 경로(꺾이는 점 목록), 출발 시각, 속도다. 위치는 필요할 때 계산한다. 도착만 이벤트로 예약한다(시뮬레이션 ADR).
- 판정 코드는 새 패키지 `packages/sim`에 둔다. 정수 계산만 쓰고 초월함수는 쓰지 않는다.

### 전송
- 2차맵에 들어가면 그 2차맵을 구독하고, 나오면 해제한다.
- 서버는 처음에 유닛 목록(위치 + 경로)을 준다. 그 뒤에는 경로가 바뀔 때만 보낸다. 기기는 경로를 따라 위치를 계산해 그린다. 위치를 계속 보내지 않는다.
- 이동·배치 명령은 WebSocket 프로토콜(`packages/protocol`)로 보낸다(AGENTS 4장).

### 렌더링
- 새 패키지 `packages/engine`에 Three.js 엔진을 둔다. React와 나눈다(stack ADR).
- 의존성(Verified: npm 2026-10-28, 둘 다 MIT)
  - `three` 0.186.1(2026-09-24 공개): 기기로 가는 코드.
  - `@types/three` 0.186.0(2026-09-11 공개): 개발 의존성.
- 지형 메시는 Web Worker에서 만든다. 유닛·건물은 인스턴싱으로 그린다.
- S1 그림은 임시 도형(캡슐·상자)이다. 원거리는 아이콘·묶음으로 바꾼다(ADR 25). 바꾸는 거리는 S1에서 잰다.
- 렌더러는 하나를 재사용한다. 화면 변화가 없으면 그리기를 멈춘다. 컨텍스트 손실 뒤 복구한다. 픽셀 비율에 상한을 둔다(PLAN 5.7).

### 건물 배치
- 칸 조합 모양이다(S1은 직사각형). 90° 회전, 2차맵 하나 안이다(D-133).
- 겹침·지형·도로 검사는 서버가 한다. 기기는 미리 보기만 한다.

### 측정
- 성능 오버레이와 텔레메트리(M0에서 만듦)로 프레임 시간 p95, 메모리, 진입 시간을 잰다.
- 기준 기기는 사용자 휴대폰과 출시 3년 안의 중가 안드로이드폰이다(PLAN 11장).
- 유닛 1,000개는 서버의 시험용 봇이 움직인다.

## 이유
- 쿼터뷰
  - 사용자 결정이다.
  - 기획 톤(D-064, 라그나로크·메이플 느낌)과 맞는다.
  - 기울기를 묶으면 보이는 범위가 정해진다. 그래서 메모리·그리기 예산을 지키기 쉽다(Assumed).
- 경로가 바뀔 때만 보내기
  - 유닛 1,000개가 움직여도 보낼 것이 적다.
  - 틱마다 위치를 보내면 휴대폰과 NAS 둘 다 부담이 크다(Assumed: S1에서 잰다).
- 정수 고정소수점: 판정 결과가 서버·버전마다 같아야 한다(시뮬레이션 ADR).
- 크기 등급별 통과 지도: 큰 유닛이 좁은 길로 가지 않는다(D-135).

## 구현하며 정한 것 (2026-10-29, `packages/sim`)
전체 표와 시험 내용은 작업 기록 `docs/worklog/2026/10/29-0020-sim-core.md`에 있다. 확정할 때 측정 수치와 함께 다시 본다.
- 크기 등급 1·2·3 = 통과 폭(칸)이다. 유닛은 s×s 정사각형이고, 위치는 그 왼쪽 위 칸(기준 칸)으로 나타낸다. 등급별 통과 지도는 배열 하나(통과 폭 ≥ s)로 둔다.
- 대각선은 도착 칸과 양옆 두 기준 칸 모두에 설 수 있어야 한다(모든 등급).
- 걸음 비용 = 길이(직선 1024, 대각선 1448) × 들어가는 칸 비용(천분율)이다. 대형 유닛은 발자국 중 가장 비싼 칸을 쓴다.
- 추정값 = 옥타일 거리 × 지도에서 가장 싼 칸 비용이다. 그래서 늘 최적 경로다. 동점은 (f, h, 칸 번호) 순서이고 이웃 순서를 고정했다.
- 도로 칸은 지형이 막혀도 지나간다(다리·터널). 철도는 걷기 경로에 넣지 않는다(역에서 타고 내리는 별도 이동).
- 시야선 다듬기는 하지 않고 꺾이는 점만 남긴다.
- 반올림: 구간 길이는 √의 가장 가까운 정수, 도착 = 출발 + ⌈누적 거리 × 1000 ÷ 속도⌉, 지난 거리 = ⌊경과 ms × 속도 ÷ 1000⌋, 구간 안 위치는 출발점 쪽으로 자른다.
- S1은 경로 전체를 같은 속도로 간다. 걷기 출발값은 437단위/초(약 0.427칸/초, D-120 "2차맵 하나를 10분 안에")다.
- 이벤트 순서는 (시각, 예약 번호)다.
- 임시 수치: 도로 비용 길 909 ~ 고속도로 400(1000 ÷ D-108 예시 배율), 지표 비용 풀 1000·흙 1050·바위 1300, 물과 가파른 비탈은 막힘.
- 벤치마크(Verified: 개발 컨테이너, 공유 CPU라 흔들림. 임시 지형 + 건물 145개 + 2칸 폭 도로 격자, 유닛 1,000개)
  - 경로 1,000개 1.6~2.8초, 한 개 p95 5~9ms, 최대 15~37ms. 그래서 경로는 메인 스레드가 아니라 워커에서 푼다.
  - 위치 계산 1,000개 0.05ms 아래, 도착 이벤트 1,000개 0.6ms 아래.
  - 메모리: 배치 격자 0.5MiB(2차맵마다), 길찾기 작업 배열 2.75MiB(워커마다).
  - NAS CPU에서는 S1 측정 때 다시 잰다.

## 구현하며 정한 것 (2026-10-29, `packages/engine`·시험 화면)
2026-10-29 엔진·시험 화면 구현(작업 기록 `2026/10/29-0130-engine-s1.md`). 상태는 제안 그대로다. 휴대폰 측정 뒤 확정한다.

### 꾸러미와 입력 모양
- `packages/engine`(`@terra/engine`)에 엔진을 둔다. 의존성 `three` 0.186.1, `@types/three` 0.186.0(Verified: 설치, 둘 다 MIT). 시험 화면용 가짜 자료는 `@terra/engine/mock`에 따로 둔다([임시], 서버가 생기면 지운다).
- 지형 입력(`TerrainInput`): 높이 `Int16Array` 129×129(0.1m 단위, `baseHeightM` 기준), 지표 `Uint8Array` 128×128(0 물, 1 풀, 2 흙, 3 바위, 모르는 코드는 회색), `cellSizeM`(표시용 칸 크기), `waterLevelM`. 행 우선이다. 칸은 왼쪽 위–오른쪽 아래 대각선으로 나눈다. 서버 이진 형식은 이 모양으로 바꿔 넣는다.
- 세계 좌표는 m(x 동쪽, z 남쪽, y 위)다. 유닛 경로는 배치 칸 좌표(실수)·출발 시각(서버 ms)·속도(칸/초)다. 서버 고정소수점(칸의 1/1024)은 1024로 나눠 넣는다.

### 카메라와 조작
- 세로 시야각 40°. 기울기 35~55°(기본 45°). 가장 가까이 = 화면 짧은 변 40m, 가장 멀리 = 2차맵 대각선 × 1.02가 짧은 변에 드는 거리(돌려도 전체가 보인다), 처음 = 짧은 변 약 70m(실제 크기 단계).
- 끌기·확대·회전은 손가락(커서) 아래 땅을 붙잡고 한다(목표점 높이 평면 기준). 두 손가락은 이동·확대·회전을 한 번에 한다. 오른쪽(가운데) 끌기는 가로 = 회전, 세로 = 기울기다. 터치로 기울이는 동작과 관성은 아직 없다.

### 유닛 표현
- 실제 크기 캡슐(인스턴스) + 모든 유닛에 화면 1.25px 외곽선. 고른 유닛은 발밑 링(화면 반지름 14px 이상) + 3px 강조 외곽선이다.
- 아이콘으로 바꾸는 기준: 키 1.8m 유닛이 8 CSS px보다 작아질 때(1m < 4.4px, 390px 세로 화면에서 가로 약 88m). 9.2px를 넘으면 돌아온다(경계에서 깜박이지 않게). 이유: 이보다 작으면 폭 0.6m 유닛이 3px보다 가늘어 모양을 알아볼 수 없다. 아이콘은 그리기 1번이라 싸다. 휴대폰에서 다시 잰다(Assumed). 묶음(부대) 표시는 아직 없다.
- 실제 크기 단계는 시야 안 유닛만 인스턴스 버퍼에 담는다(헤드리스: 처음 화면은 1,000개 중 8개).

### 렌더링
- 렌더러는 앱 전체에 하나다. 화면을 닫으면 캔버스를 떼고 그리기 버퍼를 1×1로 줄인다. 장면의 지오메트리·재질·워커·입력은 모두 버린다. 컨텍스트를 잃은 채면 새로 만든다.
- 픽셀 비율 상한: 거친 포인터 + 짧은 변 600px 이하(휴대폰) 1.5, 그 밖 2. MSAA를 켠다. 색 관리를 끈다(적은 색이 그대로 보인다).
- 유닛이 가는 중이거나 목표점 높이를 맞추는 중이면 다음 프레임을 그리고, 아니면 멈춘다. 숨겼다 보이면 한 번 그린다. 컨텍스트를 잃는 동안 멈추고 복구되면 다시 그린다.
- 지형 메시는 워커가 만들고 결과 배열을 넘긴다(transfer). 워커를 못 쓰면 화면 스레드에서 만든다.

### 측정(참고용: 헤드리스 Chromium, 소프트웨어 WebGL, 390×844 → 그리기 585×1266, 유닛 1,000개, 60초씩)
- 처음 화면(실제 크기): 프레임 p95 66.6ms(22.2fps), 엔진 몫 p95 0.6ms. 전체(아이콘): p95 66.7ms(20.1fps), 엔진 몫 0.7ms. 소프트웨어 그리기가 대부분이라 휴대폰 기준값이 아니다.
- 첫 열기 약 0.9~1.1초(같은 기기 서버, 조각 받기 포함), 다시 열기 0.1~0.5초, 지형 메시 47~71ms(워커).
- 첫 화면 JS는 그대로다(363.32 → 363.72kB). 2차맵 조각은 따로 받는다(약 574kB, gzip 약 146kB).
- 서비스 워커 미리 캐시는 454 → 1,020KiB로 는다. 2차맵 조각도 앱 껍데기로 받기 때문이다(PWA ADR "빌드한 JS는 모두"). 휴대폰 측정 뒤 뺄지 정한다(`workbox.globIgnores` 한 줄).

## 결과
- 새 패키지 2개(`packages/sim`, `packages/engine`)와 런타임 의존성 `three`가 생긴다.
- S1이 끝나면 측정 수치와 결론을 이 ADR에 더하고 확정한다(PLAN 11장 공통 규칙).
- 통과하지 못하면 대안(PLAN 11장)을 쓴다. 2차맵마다 따로 들어가는 방식이나 밀도·주변 범위 축소다.
