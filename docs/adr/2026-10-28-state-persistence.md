# 상태 저장·복구

- 상태: 확정
- 날짜: 2026-10-28
- 관련: PLAN 4.5, 독립 검토 3

## 배경
월드 상태, 전투, 호가창을 메모리에 들고 있으면 서버 재시작, 메모리 초과, NAS 재부팅 때 세계가 사라지거나 갈라진다. 지속 세계에서 이 문제를 나중에 고치기는 매우 비싸다.

## 결정
- 경로·출발 시각, 예약 이벤트, 전투 시드·입력, 주문, 잔고는 **DB가 원본**이고 메모리는 캐시다.
- 경제 변동은 즉시 커밋한다. 다시 계산할 수 있는 값(현재 위치 등)은 저장하지 않거나 묶어서 늦게 저장한다.
- 주기적 스냅샷 + 명령 로그. 종료 신호(SIGTERM)를 받으면 새 명령을 막고 진행 중 작업을 정리한 뒤 끝낸다.
- 부팅 시 DB에서 상태를 읽어 예약 이벤트를 다시 걸고, 호가창은 미체결 주문으로 복원한다.
- CI 통합 테스트: 부하 중 `kill -9` → 재시작 → 불변 조건(원장 합계, 중복 아이템, 예약 누락) 검사.

## 이유
- 이벤트 예약 모델에서는 "예약된 사실"만 지키면 나머지를 다시 만들 수 있다.
- 강제 종료 테스트가 없으면 이 규칙이 조용히 깨진다.

## 결과
- 모든 상태 변경 경로가 DB 쓰기를 거쳐야 해서 코드가 조금 늘어난다.
- 복구 시간 목표(60초 이내, Assumed)는 검증 단계 S3에서 측정해 확정한다.
