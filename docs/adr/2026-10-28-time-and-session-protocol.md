# 시간 기준과 세션 프로토콜

- 상태: 확정
- 날짜: 2026-10-28
- 관련: PLAN 4.6, 독립 검토 13·20

## 배경
경로 기반 이동 보간은 기기가 서버 시각을 알아야 한다. PWA는 배포 뒤에도 옛 코드를 들고 있을 수 있다. iOS는 앱을 내리면 소켓을 끊는다. tRPC 응답과 WebSocket 상태의 순서가 어긋날 수 있다.

## 결정
- 시간 기준은 서버(UTC ms). 기기는 접속·복귀 때마다 여러 번 왕복해 시계 차이를 맞춘다.
- 접속 핸드셰이크: `protocolVersion`, `simVersion`, `contentVersion`, `clientBuild`. 서버는 현재와 직전 프로토콜을 지원하고, 최소 버전 미만이면 새로고침을 강제한다.
- 게임 상태를 바꾸는 명령은 WebSocket 한 채널로만, `id` + 응답 확인 + 중복 방지 키.
- 모든 스트림에 순번. 끊기면 버퍼로 이어 받고, 안 되면 스냅샷.
- 하트비트 약 25초, 메시지 상한 약 64KB, 계정별 속도 제한, 느린 기기 전송 버퍼 상한.
- 전송 범위는 화면이 아니라 **시야 판정**으로 거른다. 남의 경로는 보이는 구간만 보낸다.

## 이유
- ws의 기본 메시지 상한은 100MiB로 과하다(독립 검토 확인: ws 문서).
- 전체 경로를 보내면 목적지가 노출되고, 화면 범위만 거르면 맵핵이 가능하다.

## 결과
- 프로토콜 변경은 버전 관리 대상이 된다(PROTECTED.md).
