# 유닛 상한: 주거 수용(기획 D-153)과 서버 전체 보호 장치

- 상태: 확정
- 날짜: 2026-10-28
- 관련: `2026-10-28-npc-scale-and-stage.md`(ADR 27의 "넘치는 부분은 기획의 유지비로 맞춘다"를 이 ADR이 대체), docs/PLAN.md 1.4·11장(S3), 기획 D-150(유지비는 누진 아님, D-126 대체)·D-153(유닛 상한은 주거 수용)·D-137(도시 주민도 개별 유닛)

## 배경
- ADR 27: 유닛 10만 개는 유저와 NPC를 합친 수다(사용자 결정). 거기에 "넘치는 부분은 기획의 유지비로 맞춘다"고 적었다.
- 그때 기획의 유지비는 누진이었다(D-126). 사용자가 이를 정정했다(D-150). 유지비는 유닛마다 필요한 생필품의 합이다. 유닛 수에 비례할 뿐 상한을 만들지 않는다.
- 기획 D-153(사용자 선택): 유닛 수의 상한은 주거 수용이다.
  - 유닛을 늘리려면(포획·구매·출생) 빈 주거가 있어야 한다. 휴먼은 주거, 크리쳐는 우리·둥지, 안드로이드는 정비실이다.
  - 주거는 땅을 차지하므로 땅이 자연 상한이 된다.
  - 서버 전체 상한은 기술 쪽 보호 장치로 둔다(기획이 질문할 때 밝힌 전제).

## 선택지 (서버 전체 보호 장치)
1. 주거 수용만 믿는다.
2. 주거 수용 + 서버 전체 상한. 가까워지면 NPC 세력의 증가부터 늦춘다.
3. 세력마다 고정 할당량을 준다.

## 결정
- 세력·유저의 유닛 상한은 그 세력·유저가 가진 주거 수용의 합이다(D-153). 포획·구매·출생 요청 때 서버가 빈 수용을 확인한다.
- 서버 전체 보호 장치를 둔다(2번).
  - 기준은 S3 규모 목표(유저 + NPC 합계 10만 개, ADR 27)다.
  - 총수가 기준에 가까워지면 NPC 세력의 증가(출생·구매)부터 늦춘다.
  - 그래도 기준에 닿으면 새 유닛 생성을 잠시 막고 운영자에게 경보를 보낸다.
  - 문턱 값(예: 90%·100%)과 늦추는 방법은 S3에서 측정해 정한다.
- ADR 27의 나머지(합계 10만 개, S3 시험 구성, N1 단계)는 그대로다.

## 이유
- 주거 수용은 기획이 정한 게임 규칙이다. 땅이 유한해서 자연 상한이 된다(D-153).
- 그래도 땅·주거의 합이 서버가 감당할 수보다 클 수 있다(행성 크기·도시 수에 달림, Assumed). 감당할 수는 S3에서 잰다. 그래서 보호 장치가 따로 필요하다.
- NPC 수는 서버가 정한다. 그래서 NPC 증가부터 늦추면 유저가 직접 하는 일(포획·구매)을 막는 경우가 준다.
- 3번(고정 할당량)은 세력이 크는 것을 막는다. 개인에서 세력으로 성장한다는 기획(D-009)과 맞지 않는다(Assumed).

## 결과
- S3 시험에 주거 수용 판정과 서버 전체 보호 장치를 넣는다(총수가 문턱에 닿는 경우 포함).
- 기획 Step 5에서 주거 종류별 수용 수치가 정해지면, NPC 국가별 유닛 수(D-137)와 함께 S3 시험 데이터에 넣는다.
- NPC 증가를 늦추면 게임에도 보이는 영향이 있다(NPC 세력의 성장 속도). 실제 운영에서 문턱에 자주 닿으면 기획 세션과 다시 본다.
