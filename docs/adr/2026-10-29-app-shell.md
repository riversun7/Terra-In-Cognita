- 예약만 한다(지금 만들지 않는다. 그 화면을 만들 때 표에 줄을 더한다)
  - 첫 접속(6-6): `/start`. 성인 인증(D-7009)은 `/start` 앞에 단계 자리만 둔다. 인증이 필요한지부터 Assumed다(법 요건, D-7009·PLAN 14장). 방식은 Step 7-4, 시점은 PLAN 14장 기획 질문 67이다.

  - 유닛: `/units/:unitId`.
  - 경제(6-5): `/economy/:section`.
    - 거래창: `/economy/market` → `/economy/market/:itemId` → `/economy/market/:itemId/:cityId`. 차례로 쌓고(push), 부모도 이 순서다.
    - 내 주문 `/economy/orders`(휴대폰 자리, 기술 제안). D-6033은 "내 주문"을 데스크톱 옆 패널에만 두었으므로 휴대폰 자리는 기획에 묻는다("결과" 끝 "남은 것").
    - 품질·등급 구분은 PLAN 14장 기획 질문 61의 답에 따라 `?band=`로 한다. 유닛 경매는 `/economy/auction/:kind`만 예약한다(D-242).
    - 거래창은 `data-density="compact"`다. "남은 주문"을 누르면 거래소 유닛 배치 화면(`/units?job=exchange&city=`, Assumed)으로 간다.
  - 세력: `/faction/:section`. 공성 시각 고르기(D-6029)는 `/faction/siege/:siegeId`이고, 처리할 일 `siege_declared`가 이리로 간다(지금 종류 표의 이동 화면은 `faction`이다. 그 화면이 생기면 바꾼다).
  - 전투(6-4): `/battle/:battleId`. 배너에서 쌓는다(push). 틀을 숨기고 가로 권장 안내를 띄운다(D-6002). 부모는 `map?focus=battle:<ID>`다.
    - 끝난 전투는 같은 주소가 결과 화면이다. 다시 보기는 `/battle/:battleId/replay`, 공유 보고서는 `/report/:token`이다.
    - 토큰은 ADR 35의 128비트 공유 토큰이다. 그래서 주소에 전투 ID·편이 드러나지 않고, 주소를 고쳐 상대 편 시야를 볼 수 없다.
    - 매개변수 값 규칙(`id` = 숫자·영문 소문자·`_`)은 uuid·base64url처럼 `-`·대문자가 든 ID를 그대로 받지 않는다. ADR 35 토큰의 "URL 문자 22자"는 base64url로 보인다(Assumed). 계정 표의 uuid 키, 행성 초안 ID(ADR 38)도 같다. 그런 ID를 주소에 넣는 화면을 만들 때 값 규칙 종류(예: `uuid`·`token`)를 더하거나 ID 모양을 맞춘다(토큰이면 소문자 base32 26자 등).
    - 공유 보고서를 로그인 없이 여는지는 ADR 35 질문 35다(기술 제안: 로그인한 사람만). 그래서 D-6038의 "누구나"는 지금 "로그인한 계정 누구나"다. 로그인 없이 열기로 정하면 1절 표의 `access`에 로그인 없는 종류를 더하고, 로그인 화면 규칙(아래 "로그인 화면들")에 이 주소만 예외를 둔다.
    - 실시간 조건은 "전투 화면에 들어간 사람"이다(D-6023, ADR 35 b8bb55d 반영). 화면을 떠나면 빨리감기로 돌아가도 결과는 같다.
    - 부모에 검색어가 붙는 첫 주소다. 그때 표의 부모 칸을 넓힌다(주소 ID + 매개변수로 만든 검색어). 지금 `parentTarget`은 부모 경로의 매개변수만 넘긴다.
  - 개발자 도구(ADR 38의 `/dev/:tool` 예약): 지형 정보(D-214), 출현 분포(D-5018·D-5020), 크리쳐 생성 에디터(D-5024)가 온다. 도구마다 정적 줄(`/dev/<도구>`, 조각은 영어 소문자·`-`, 예: `/dev/planet-editor`)을 더한다. 매개변수 줄 `/dev/:tool`은 두지 않는다. 값 규칙 `id`가 `-`를 받지 않아 이미 있는 두 도구와 주소 모양이 갈리기 때문이다(0단계 검토).
- 지도 주소(기획 6-3 답. 화면은 6-3에서 만든다)
  - 검색어 없는 `/map`은 내 사이보그 위치로 연다(D-6017. "마지막으로 본 곳"은 기각됐다). 탭·메뉴·카드는 늘 맨 `/map`으로 간다.
  - 지도 안에서 옮기면 `?at=`을 바꾸기(replace)로 적는다. 새로고침·공유하면 그 자리로 연다.
    - 자리는 `?at=` 하나다. 어느 2차맵의 어디인지를 함께 담는다(모양은 6-3).
    - `?at=`은 카메라가 멈춘 뒤 한 번만 적는다(디바운스). 브라우저는 짧은 동안 기록 바꾸기가 너무 많으면 막거나 예외를 낸다(Assumed, 확인하지 않음: WebKit은 30초에 약 100번, Chromium은 10초에 약 200번).
    - 다른 검색어(이 기기가 모르는 것 포함)는 그대로 둔다. `buildPath`로 주소를 다시 만들지 않고 `replaceSearch`로 그 검색어만 바꾼다.
  - 처리할 일에서 지도로 갈 때는 `?focus=<종류>:<ID>`다. 서버가 시야를 확인한다(Assumed).
  - 사이보그가 2차맵에 없으면: 전투 중이면 그 전투의 2차맵 자리, 이동 중이면 계산한 위치로 연다. 사이보그가 없는 계정은 6-6 전까지 S1 시험맵, 그 뒤에는 `/start`로 보낸다(Assumed). 모항(D-058)에 있을 수 있는지는 Unknown이다.
  - `map_planet`의 부모는 `home` 그대로다(6-3에서 다시 보기로 한 것을 닫았다). 줄이기 한계·키우기·전환 버튼(D-6018)과 2차맵 경계 넘기(D-139)는 바꾸기(replace)라서 뒤로 = 지도를 떠남이다. 부모를 `map`으로 두면 바로 연 1차맵의 [뒤로]가 2차맵으로 가서 "뒤로 = 지도를 떠남"과 어긋난다.
  - 두 모드는 한 화면·한 캔버스다(렌더러 하나를 다시 쓴다, PLAN 5.7). 줄이기 한계 근처에서 1차맵 조각·맵 레벨 F 타일을 미리 받는다(기술 제안. 기획 "5단계"를 맵 레벨 F로 본 것은 Assumed, PLAN 14장). 1차맵 가장 가까운 확대(약 12km, ADR 36)에서는 주변 2차맵을 미리 받는다(PLAN 5.6). 전환 때 카메라를 이어 준다.
- 경로 규칙
  - 조각은 영어 소문자·숫자·`-`다. 점(.)을 쓰지 않는다. 서버가 점 있는 경로를 파일로 보고 404를 준다.
  - 매개변수 값에도 점을 넣지 않는다(값 규칙: `id` = 숫자·영문 소문자·`_`, `digits` = 10진수. 끝의 "구현하며 정한 것").
  - `/api`·`/ws`·`/health`로 시작하지 않는다. 서버는 글자 앞부분만 본다(`/apiary`도 404). 서비스 워커는 조각 단위로 본다(끝의 "구현하며 정한 것").
  - 시험이 표의 모든 경로 예를 서버 규칙과 서비스 워커 제외 규칙에 대 본다(0단계에서 만들었다).
    - 서버: 화면 경로 판정을 `apps/server/src/spaFallback.ts`의 `isPagePath`로 꺼낸다(`app.ts`는 그 함수를 부른다). 서버 시험이 경로 예를 넣어 본다.
    - 서비스 워커: `scripts/pwa-build.mjs`가 `packages/shared/src/routes.ts`를 상대 경로로 가져와(Node 24 타입 지우기) 경로 예를 `ALLOWED_NAVIGATIONS`에 더한다. CI(`check-pwa.mjs`)가 빌드된 `sw.js` 제외 목록에 대 본다. 그래서 `packages/shared`는 지울 수 있는 TS 문법만 쓴다(tsconfig `erasableSyntaxOnly`는 이미 켜져 있다).
  - 경로에 언어를 넣지 않는다. 화면 제목은 메시지 키다.
  - 모르는 검색어는 무시하되 지우지 않는다.
- 원격 측정 보고의 page는 경로 패턴이다(예: `/units/:unitId`. ID는 보내지 않는다). 지도는 지금처럼 `#second-map`·`#planet-map`을 붙인다(전 측정과 비교). 지도 모드가 바뀌면 `setTelemetryView`도 바꾼다(Verified: `apps/game/src/telemetry/reporter.ts`에 있다).
- 로그인 화면들(로그인 → 새 아이디 확인 → 비밀번호 찾기)은 지금처럼 상태로 바꾼다. 비밀번호가 주소에 남지 않게 하려는 것이다.
  - 로그인하지 않은 채 어떤 주소로 열면 그 자리에 로그인 화면이 뜬다. 로그인하면 그 주소의 화면이 열린다.
  - 주소 없이 켜면(`/`) 홈이다(D-6001). 로그인하지 않은 화면 아래 언어 고르기는 그대로 둔다.
- 라우터: 자체 라우터다([결정 1]. `apps/game/src/shell/router.ts`, 핵심 약 150~250줄 + 시험, 추정). TanStack Router·TanStack Query·Zustand는 이번에 넣지 않는다.
  - 기록 한 칸마다 열쇠와 순번을 `history.state`에 둔다. 새로고침해도 남는다.
  - 앱 안 링크는 `<AppLink>`가 맡는다. 보조 키·가운데 버튼·`target`·다른 출처는 브라우저에 맡긴다.
  - `history.scrollRestoration = "manual"`(시작점 `main.tsx`에서). 칸마다 스크롤을 저장하고, 지연 로딩 화면이 그려진 뒤 되돌린다. 탭끼리는 칸을 바꾸므로 첫 단계 화면은 화면 ID마다 스크롤을 기억한다.
  - 앱 안에서 옮기면 새 화면 제목(h1)에 초점을 두고 `document.title`을 바꾼다. 처음 켤 때는 초점을 옮기지 않는다(지금 `useMountFocus`와 같다).
  - 주소 ID·매개변수·검색어의 타입은 주소 표에서 나온다. 틀린 주소 ID·매개변수는 타입 검사가 잡는다.
  - 나중에 TanStack Router로 옮기면("결과"의 다시 볼 조건) 같은 주소 표로 경로 트리를 만든다. 아래 뒤로·겹침 규칙은 그때도 직접 만든다.
  - 실시간 자료(6-3~6-5에서 만든다): 구독 도우미 하나가 지도 피드·전투 스트림·호가 피드를 주소에 묶는다. 화면에 들어오면 구독하고, 떠나면 끊고, 다시 붙으면 스냅샷 + rev로 잇는다.

### 2. 뒤로

| 상황 | 동작 |
|---|---|
| 홈에서 탭·사이드 메뉴로 다른 첫 단계 화면 | 쌓는다(push). 칸 상태(`history.state`)에 "앞 칸이 홈"을 적는다 |
| 홈이 아닌 첫 단계 화면끼리 | 바꾼다(replace). "앞 칸이 홈" 표시는 이어 적는다 |
| 홈이 아닌 화면에서 홈으로(탭·메뉴·[홈]) | 앞 칸이 앱 안의 홈이면 `history.back()`, 아니면(바로 연 주소) 홈으로 바꾼다. 그래서 뒤로 → 홈 → 앱 닫힘이 늘 같다 |
| 지금 탭을 다시 누름 | 맨 위로 스크롤 |
| 지도(탭·가운데 버튼·카드 어디서든)·상세 화면 | 쌓는다. 지도는 틀을 숨기므로 [뒤로]로 앞 화면에 돌아와야 한다 |
| 지도 안에서 옮기기(`?at=`)·모드 전환(줄이기 한계·키우기·전환 버튼, D-6018)·2차맵 경계 넘기(D-139) | 바꾼다(replace). 뒤로 = 지도를 떠남(6-3) |
| 지도 위 명령 흐름(D-6019·D-6021, 아래 시트) | 기록은 한 칸만 쌓는다. 단계 사이는 시트 안 [뒤로]로 오간다. 시스템 뒤로로 닫아도 초안을 남긴다. 같은 시트를 거래창 "운송 발주"(D-6032)에 쓴다(Assumed, 6-3) |
| 전투 시작 배너의 [들어가기](D-6023) | 쌓는다(`/battle/:battleId`). 바로 연 주소의 [뒤로]는 부모 `map?focus=battle:<ID>`로 간다(6-4) |
| 화면 안 [뒤로] | 앱 안에서 쌓은 기록이 있으면 `history.back()`. 없으면(푸시·바로 연 주소) 부모 화면(1절 표)으로 바꾼다 |
| ☰ 서랍·편집 시트(사람이 눌러 연 겹침) | `<dialog>.showModal()`로 열고 같은 주소로 기록 한 칸을 쌓는다. 뒤로 → 그 칸이 빠지며 닫힌다. 닫기 버튼·Esc·브라우저 닫기 요청으로 닫히면 그 칸을 `history.back()`으로 뺀다 |
| 복귀 요약(저절로 뜬 겹침) | 기록 칸을 쌓지 않는다. [확인]·Esc·브라우저 닫기 요청으로 닫는다. 닫기 요청이 없는 브라우저(사파리, 하한 안드로이드)에서 뒤로는 요약을 닫지 않는다(켠 직후면 앱을 떠난다. 감수: 확인하지 않았으므로 다음에 또 뜬다) |
| 새로고침했는데 지금 칸이 겹침 칸 | 그 칸을 바로 뺀다(`history.back()`). 겹침은 다시 열지 않는다 |
| 서랍에서 다른 화면을 고름 | 겹침 칸을 `history.back()`으로 빼고, `popstate`를 받은 뒤 위 규칙대로 옮긴다(가짜 `history` 시험에 넣는다) |
| 로그아웃·다른 계정 | `/`로 바꾼다(지금 `OpenView.userId` 규칙을 잇는다) |
| 모르는 경로 | "없는 화면" + [홈] |
| 여는 역할이 아닌 화면(1절 표 "누가": `/admin`, `/dev`·`/dev/…`) | "권한 없음" + [홈](`canOpenRoute`). 화면 편의일 뿐이고 서버가 매 요청 확인한다 |

- iOS 홈 화면 앱에는 브라우저 뒤로 버튼이 없다. 그래서 홈이 아닌 모든 화면에 [뒤로]를 둔다.
- 푸시·즐겨찾기로 바로 열었을 때 부모 칸을 미리 끼워 넣지 않는다. 누르기 전에 넣은 칸은 브라우저가 건너뛸 수 있다(Unknown). 화면 안 [뒤로]가 부모로 보낸다.

### 3. 화면 틀
- 폭 3단계. 경계는 미디어 쿼리에 `em` 숫자로 쓴다. CSS 변수는 미디어 쿼리에 못 쓴다. 대비 검사는 선언 줄만 보므로 이 숫자를 막지 않는다(Verified: `scripts/design-tokens.mjs`). JS가 쓸 같은 값은 `shell/layout.ts`에 두고 시험이 CSS와 같은지 본다.

| 단계 | 폭 | 하단 탭 | 사이드 메뉴 |
|---|---|---|---|
| 좁음 | 37.5em(600px) 미만 | 있음(배치 C·A) | ☰로 여는 서랍 |
| 중간 | 37.5em 이상 64em 미만 | 없음 | 접는 레일. 접으면 아이콘 + 짧은 이름, 펴면 이름 + 한 줄 설명. 접힘 상태는 기기에만 저장 |
| 넓음 | 64em(1024px) 이상 | 없음 | 늘 펼침 |

  - 휴대폰 가로(예: 844×390)는 중간이라 레일이 된다. 세로 공간을 아낀다.
- 위 띠(D-6010)는 본문 위에 붙는다(중간·넓음에서는 사이드 메뉴 오른쪽).
  - 왼쪽: [☰](좁음 + 배치 C. 중간에서는 레일 펴기), 사이보그 얼굴(→ `/cyborg`).
  - 오른쪽: 알림 종(배지, → `/inbox`), 우편(→ `/mail`).
  - 사이보그가 없어서 얼굴은 기본 실루엣 아이콘이다. 로그인 아이디는 사이드 메뉴 머리에만 보인다.
- 하단 탭(D-6007·D-6010)
  - 기본 C: 홈 · 유닛 · [지도](가운데 큰 버튼) · 경제 · 세력.
  - A: 홈 · 지도 · 유닛 · 경제 · ☰.
  - 이름은 늘 보인다(아이콘만 두지 않는다). 지금 화면은 `aria-current="page"`.
- 사이드 메뉴: 머리(앱 이름표, 아이디), 메뉴 항목 6개(유저 순서), 시스템 묶음.
  - 시스템 묶음: 설정 · 개발자(dev·admin) · 관리자(admin) · 로그아웃(ADR 38 1절). 개발자·관리자는 하단 탭과 메뉴 편집 목록에 넣지 않는다.
  - [메뉴 편집]은 설정의 "메뉴" 칸으로 간다.
  - 1차맵은 지도 항목 밑의 작은 [임시] 링크다. 6-3에서 지도 안 전환이 생기면 지운다(아래 "지도 안 단추").
- 지도 안 단추(6-3): 지도는 틀을 숨기므로 지도 안에 [뒤로]·[1차맵/2차맵]·[내 사이보그로]를 둔다. 이것이 생기면 사이드 메뉴와 홈 `maps` 카드의 1차맵 [임시] 링크를 지우고 지도 안 전환만 둔다.
- 틀을 숨기는 화면: 지도 2개(화면 전체를 덮는다, 지금과 같다), 행성 편집기(ADR 38), 전투(6-4), 로그인 화면들, 로그인 확인 중·확인 못 함.
- 연결 줄: 서버 연결이 2초 넘게 끊기면 위 띠 아래에 한 줄로 알린다. 틀을 숨긴 화면(지도·행성 편집기·전투)에서는 같은 줄을 화면 맨 위(안전 영역 아래)의 전역 층에 띄운다(해석). 서버 거절 안내(`RejectedNotice`)는 모든 화면에 남긴다.
- 전투 시작 배너(D-6023, 6-4)는 틀을 숨긴 지도·전투 화면에도 뜨는 전역 층이다. 서버 거절 안내·새 버전 배너, 그리고 틀을 숨긴 화면의 연결 줄과 같은 층이다. 배너와 처리할 일 `battle_started`는 같은 사건에서 나오므로 "처리할 일이 바뀜" WebSocket 알림(7절)과 함께 설계한다.
- 연결 상태는 화면 밖 저장소(`net/connectionStatus.ts`, `useConnectionStatus()`)에 둔다. 틀·홈 카드·다시 받기가 같이 읽는다. 프레임 측정(`monitor`)은 주소 → 화면 표(`shell/routeViews.tsx`)가 화면에 넘긴다.
- 새 버전 배너는 하단 탭 위에 뜬다. 탭 높이 + 안전 영역만큼 화면 아래를 비운다.
- 화면 방향(D-6002)
  - manifest는 `orientation: any` 그대로다. iOS는 방향을 잠글 수 없다.
  - 휴대폰 세로로 지도에 들어가면 "가로로 돌리면 더 넓게 볼 수 있어요"를 가운데에 4초 띄운다. 누르면 닫힌다. 앱을 켤 때마다 한 번만 띄운다(`sessionStorage`).
  - 태블릿·데스크톱에는 띄우지 않는다. 틀이 그리므로 지도 화면 파일은 고치지 않는다.
- 데스크톱 옆 패널(D-6003)은 6-3·6-5에서 만든다. 틀은 오른쪽 칸을 더할 수 있게 격자 영역 이름만 정한다.
- 새 디자인 값은 `tokens.css`에만 더한다: `--topbar-h`, `--tabbar-h`, `--tabbar-map-size`, `--rail-w`, `--sidebar-w`, `--content-max-wide`, `--badge-size`, `--card-min`, `--card-row`, `--card-gap`. 다른 토큰을 `var()`로 묶지 않고 값을 바로 쓴다(tokens.css 머리 규칙). 겹침 바탕은 이미 있는 `--color-overlay`를 쓴다.
  - 0단계가 처음 값을 넣었다("화면 틀" 블록과 "홈 카드" 블록, 값은 끝의 "구현하며 정한 것"). 그 뒤에는 W1이 틀 블록, W4가 카드 블록만 고친다.
- 처리할 일 분류 색은 이미 대비 검사를 받는 상태색만 쓴다: 위협 `--color-danger`, 돈·생존 `--color-warning`, 완료 `--color-success`, 멈춤·제안은 글자색. 분류는 늘 아이콘 + 이름과 함께다. 새 색 토큰이 필요하면 `scripts/design-tokens.mjs` 대비 쌍에 함께 더한다.
- 화면 CSS는 새 파일에 쓴다(`shell/shell.css`, `home/home.css`, `inbox/inbox.css`). `styles.css`는 558줄이라 600줄 경고에 가깝다.

### 4. 메뉴 항목 목록
- 목록은 하나다: `apps/game/src/shell/menuItems.ts`(항목 ID, 주소 ID, 이름 키, 한 줄 설명 키, 아이콘). 항목 ID와 기본값은 `packages/shared/src/navigation.ts`에 둔다(서버 입력 검사도 쓴다).

- 유저 설정 `nav`
  - `layout`: `c`(기본) 또는 `a`.
  - `tabs`: 배치마다 칸 4개의 항목과 순서(`{ c: [...], a: [...] }`). C의 가운데 지도는 배치의 일부라 칸에 넣지 않는다. 기본 C = 홈·유닛·경제·세력, A = 홈·지도·유닛·경제.

- 메뉴 항목 배지: 종류 표에 걸 메뉴 항목을 적는다(예: 직무 없는 유닛 → 유닛). 수는 서버가 `inbox.list`의 `badges`로 보낸다(7절). 지금 걸 종류는 없다.

- 서버 입력 검사(Zod)

### 7. 처리할 일(D-6006·D-6009·D-6015)
- 분류와 순위(`packages/shared/src/inbox.ts`, 진입점 `@terra/shared/inbox`): 위협 1 → 돈·생존 2 → 멈춤 3 → 제안·결정 4 → 완료 5.
- 종류 표(같은 파일): 종류 ID, 분류, 묶기 여부, 이동할 화면(주소 ID. 매개변수·검색어 값은 항목의 `target`), 바로 처리 동작 ID(0~2개. 0개는 기술 해석, 끝의 "구현하며 정한 것"), 배지를 걸 메뉴 항목, 푸시 분류(W6).
- 서버 등록부(`apps/server/src/inbox/registry.ts`): 종류마다 제공 함수(그 계정의 상태 → 항목들)를 둔다. 지금은 0개다. 요청 때 만들어 보낸다.
- 항목 ID는 상태에서 늘 같게 만든다: `<종류>:<묶음 키>`(예: `unit_idle:city_12`), 완료는 `<종류>:<사건 ID>`. 처리함의 `?item=`, 바로 처리, 확인이 모두 이 ID를 쓴다. 서버는 바로 처리·확인 때 그 ID로 지금 상태를 다시 만들어 확인한다.
- 정렬·묶기(순수 함수 `apps/server/src/inbox/order.ts`, 시험 대상)
  - 정렬 키: (분류 순위, 마감 시각, 처음 생긴 시각, 항목 ID). 마감이 없으면 그 분류의 끝이다.
  - 묶기: 같은 종류(그리고 같은 묶음 키)는 한 줄이다. 개수와 가장 이른 마감을 갖는다. 예: "명령 없는 유닛 6". 완료 분류는 묶지 않는다(항목 ID가 사건 ID이고 확인도 사건마다다).
  - 마감 없는 항목끼리 "처음 생긴 순"은 Assumed다. Step 5에서 바꿀 수 있다.
- tRPC(조회와 비실시간)
  - `inbox.list({ preview? })` → `{ generatedAt, items, counts, badges }`. 응답 타입은 `@terra/shared/inbox`에 둔다(0단계).
  - 항목 = `{ id, kind, category, count, deadlineAt | null, firstSeenAt, params, target | null, actions, preview? }`. `counts`는 분류별 줄 수, `badges`는 메뉴 항목 ID → 줄 수다.
  - `params`는 문장이 아니라 값(이름·수)이다. 문구는 기기가 메시지 키로 만든다(다국어 ADR).
  - `inbox.ack({ ids })`(완료 분류 확인)는 첫 완료 종류와 함께 만든다(저장 표 `inbox_acks`와 같은 때). 지금은 만들지 않는다.
- 기기

- 바로 처리(D-6015)

### 8. 복귀 요약(D-6014)
- 묻는 때: 로그인한 채 앱을 켤 때, 30분 넘게 숨겼다가 다시 볼 때. 30분은 PWA ADR의 "켤 때" 기준과 같다(Assumed, Step 5에서 바꿀 수 있다).
- tRPC: `summary.get({ preview? })` → `{ show, since | null, until, sections: [{ kind, count, params, target | null }] }`. 응답 타입은 `@terra/shared/inbox`에 둔다(0단계).
- `summary.ack({ until })`는 첫 사건 출처와 함께 만든다(확인 시각 표와 같은 때). 지금은 만들지 않는다.
- `show`는 서버가 정한다. 마지막 확인 시각 이후 사건이 없거나 적으면 `false`다. 기준은 Step 5이고 처음 값은 "사건 0개면 건너뜀"이다.
- 지금은 사건 기록이 없어서 늘 `show: false`다. 확인 시각 표는 첫 사건 출처(S3 오프라인 정산, 생산)를 만들 때 더한다.
- 화면: 어느 주소 위에도 뜨는 겹침이다(`<dialog>`, 좁으면 화면 전체). 기록 칸은 쌓지 않는다(2절).
  - [확인]을 누르면 닫힌다. `/`로 켰으면 홈(대시보드)이 보인다. 주소로 바로 열었거나(푸시·즐겨찾기) 보던 화면으로 돌아왔으면 그 화면에 남는다(해석: 기획은 "확인하면 대시보드"다. 바로 연 화면을 지키려는 것이다. 기획 질문 `docs/questions/2026-10-29-app-shell.md` Q2).
  - 숫자를 누르면 그 상세 화면으로 가고 확인한 것으로 친다.
  - 템플릿과 상관없이 같다.

### 10. 접근성
- 모든 순서 바꾸기는 버튼으로도 된다(↑·↓·맨 위로, 크기 고르기, 탭 ↔ 메뉴). 끌기는 덤이다(WCAG 2.2 2.5.7 끌기 동작, AA).
- 끌어 옮기기는 직접 만든다(새 의존성 없음).
  - 편집 상태에서만 된다. 손잡이는 44px 이상이고 `touch-action: none`이다. 카드의 나머지는 화면 스크롤 그대로다.
  - `setPointerCapture`를 쓰고 움직임은 `requestAnimationFrame`으로 묶는다. `pointercancel`이면 되돌린다.
  - 끌기 상태는 ref에 둔다. 실시간 갱신이 끌기를 끊지 않게 하려는 것이다.
- 알림 영역(polite)이 결과를 읽는다. 예: "7개 중 3번째로 옮김" / "Moved to 3 of 7".
- 초점: 앱 안 이동 때 새 화면 h1. 서랍·시트는 `showModal()`로 초점을 가두고, 닫으면 연 버튼으로 돌려준다.
- 표지: 위 띠 `<header>`, 메뉴 `<nav aria-label>`, 본문 `<main>`. 중간·넓음에는 "본문으로 건너뛰기" 링크를 둔다.
- 배지는 숫자만 두지 않는다(읽기 프로그램용 "알림 3개" / "Alerts: 3"). 분류는 색 + 아이콘 + 이름으로 보인다.
- 누르는 곳은 44px 이상이다(`--tap-size`).
- 움직임: 서랍·레일은 `--duration-*` 토큰을 쓴다. 동작 줄이기면 0이다. 화면 바꾸기 효과(View Transitions)는 쓰지 않는다. 지원 하한 중 iOS 16.4~17.x와 Firefox 115~143에 없어 기능 확인 뒤 갈래가 생긴다(Verified: MDN browser-compat-data 8.1.7 — Chrome 111, Safari·iOS 18, Firefox 144).

- 화면(Playwright, Chromium, 저장소 `e2e/`, [결정 3]): 390×844(DPR 3, 터치), 844×390, 820×1180, 1440×900. 한국어·영어, 파스텔·다크 사진.
  - 돌리는 때: 에이전트가 화면을 고칠 때 돌린다. 결과(통과·실패, 잰 값)는 작업 기록에 남긴다.
  - CI에서는 자동으로 돌리지 않는다. 필요해지면 손으로 실행하는 워크플로부터 만든다. 개발 방식 ADR의 "야간에 E2E"를 이것으로 바꾼다.
  - 브라우저는 개발 환경에 이미 있다(Playwright 1.63.0의 chromium-1243, `/opt/pw-browsers`). 내려받는 단계를 두지 않으므로 `@playwright/test`는 1.63.0으로 고정한다. 1.64.1은 chromium-1248을 받아야 한다(Verified 2026-10-29: npm `playwright-core` 1.64.1의 `browsers.json`).
  - 개발이 끝나 필요 없어지면 `e2e/`를 지운다.
  - 로그인 → `/` 홈.
  - 탭 이동, 뒤로(`page.goBack`), 서랍 열기·뒤로 닫기(남는 기록 칸 없음), 서랍을 연 채 새로고침(칸이 빠진다), 복귀 요약(시안 자료)이 기록 칸을 늘리지 않는다.
  - 주소로 바로 열고 새로고침. 로그인 안 한 채 주소로 열기 → 로그인 → 같은 화면. 계정 바꾸면 홈. 여는 역할이 아닌 화면은 권한 없음: admin 아닌 `/admin`, player의 `/dev`·`/dev/planet-editor`.
  - 지도 화면 틀 숨김, [뒤로], `?planet-debug=cracks`.
  - A·C 바꾸기와 카드 옮기기가 새로고침·다른 기기(두 번째 브라우저 맥락)에 남는다. `?template=`(admin. player에게는 듣지 않는다).
  - 시안 자료와 템플릿 칸은 admin만(player의 [편집]에는 템플릿 칸이 없다). 새 버전 배너가 탭을 가리지 않는다. 가로 넘침 없음, 누르는 곳 44px.
- 손으로
  - 아이폰 홈 화면 앱(뒤로 버튼 없음), 안드로이드 크롬·삼성 인터넷·웨일의 시스템 뒤로와 서랍.
  - 닫기 요청이 없는 길(뒤로 = 기록 칸 빼기): 아이폰 사파리(브라우저)의 밀어서 뒤로. 안드로이드 하한 판(삼성 인터넷 22~27, Firefox 115~148)은 그 판 기기가 있을 때만 본다(닫기 요청은 삼성 인터넷 28·Firefox 안드로이드 149부터, Verified: MDN browser-compat-data 8.1.7).

### 14. 구현 순서와 기간
- 줄기 하나 = worktree 하나 = 가지 하나다. 줄기는 자기 파일만 고치고, 남의 파일은 정해진 "꽂는 줄"만 고친다.
- 0단계 계약(통합 세션, 먼저 main에): 결정 반영 문서("결과" 끝), `packages/shared`의 `routes.ts`·`navigation.ts`·`dashboard.ts`·`inbox.ts`와 시험, 서버 `isPagePath`, `pwa-build` 경로 대조, 권한 `home: ["preview", "template"]`(dev·admin, 기본 거부), `tokens.css` 블록, 메시지 키 자리. ADR 38의 개발자 영역 주소 3줄과 권한 `planetEditor: ["read", "write"]`(dev·admin)도 함께 넣는다. 2026-10-29에 했다("결과" 끝).
- 줄기
  - W1 화면 길·틀: 1~4절, 10~12절의 틀 부분. 핵심 경로다.
  - W2 계정 설정 넓히기: 5절과 6절의 템플릿 저장 규칙.
  - W3 처리할 일·복귀 요약: 7·8절(서버 + 기기 모듈).
  - W4 홈 대시보드: 6절.
  - W5 시험 틀·첫 화면 크기 검사: 11·13절.
  - W6 알림: 나중이다(9절, 새 ADR).
- 합치는 순서: 0단계 → W2 → W5 → W1 → W3 → W4. 0단계가 합쳐지면 W1~W5를 한꺼번에 시작해도 된다.
- 합칠 때마다 main CI 통과를 확인한다. W1·W4 뒤에는 NAS에 배포하고 사용자 휴대폰(웨일)으로 홈·탭·뒤로·서랍을 본다.
- 기간 상한은 2주다(0단계~W5, Assumed). 넘으면 멈추고 보고한다(PLAN 11장). 줄여야 하면 템플릿 6개 중 조합·격자를 먼저 하고, 나머지 넷과 끌어 옮기기를 뒤로 미룬다.

## 이유
- 주소를 쓰는 이유
  - 처리할 일과 나중의 푸시가 특정 화면을 열어야 한다(D-6011·D-6015).
  - 안드로이드 뒤로가 앱 안에서 돌아간다. 새로고침(언어 바꾸기, 새 버전 적용)해도 그 화면에 남는다.
  - 서버와 서비스 워커가 이미 화면 경로에 `index.html`을 준다(Verified: 코드). 깊은 주소가 지금 바로 된다.
- 자체 라우터를 고른 이유([결정 1])
  - 크기(Verified: rolldown 1.2.15 + oxc 줄이기 + gzip 9단계, React 제외, 2026-10-29 조사): 자체 스케치 1.5KB, wouter 3.0KB, React Router 8.5.1 선언 모드 13.4KB·데이터 모드 32.0KB, TanStack Router 26.9KB(지금 첫 화면의 +23%). 자체 스케치는 크기만 쟀다(미실행).
  - 어려운 부분은 어느 쪽이든 직접 만든다: 겹침 뒤로, 지도 틀 숨김, 깊은 주소, 지연 화면 뒤 스크롤, 초점. 읽은 라이브러리 문서에 초점 관리가 없었다(Verified: 조사).
  - 서버가 같은 주소 표를 써야 한다. TanStack 경로 트리는 게임 앱의 React 코드라 서버가 가져올 수 없다.
  - 타입 검사는 주소 표의 타입으로 한다. PLAN 3장이 TanStack을 고른 이유("타입 안전 라우팅")를 잇는다.
  - 자료는 WebSocket·tRPC로 오므로 경로별 미리 받기(loader)의 이득이 작다(Assumed).
  - TanStack Router는 최근 1년에 안정판 228개(주 약 4개)를 냈다(Verified: npm 2026-10-29). 매주 갱신 PR이 생긴다.
  - Navigation API는 하한 브라우저에 없다. Safari·iOS는 26.2부터다(Verified: MDN browser-compat-data 8.1.7). 그래서 History API만 쓴다.
  - 감수: 링크 규칙, 지연 로딩 중 뒤로, 스크롤 시점 같은 가장자리 경우를 우리가 시험으로 지킨다. 개발 도구가 없다. 사람·AI가 이미 아는 라이브러리가 아니라서 규칙을 이 ADR과 시험으로 남긴다(PLAN 1.3).
- 경로에 언어를 넣지 않는 이유
  - 홈 화면 앱은 주소창이 없다. 로그인한 화면은 검색 노출이 필요 없다.
  - Paraglide `url` 방식은 URLPattern을 쓴다. iOS 26 전에는 대체 코드가 필요하다(Verified: 조사, BCD).
  - 나중의 푸시 주소가 언어에 묶이면 안 된다.
- 겹침 뒤로를 두 길로 맞추는 이유
  - `<dialog>`는 크롬 120부터 안드로이드 뒤로(닫기 요청)로 닫힌다(조사: 크롬 120 소개 글 검색 요약, 2023-12 [OLD]).
  - CloseWatcher는 크롬 126·삼성 인터넷 28·Firefox 안드로이드 149부터이고 사파리에는 없다(Verified: BCD 8.1.7).
  - 하한(삼성 인터넷 22, Firefox 115)에서는 기록 한 칸이 있어야 뒤로가 겹침을 닫는다.
  - 두 길을 맞추면 어느 쪽으로 닫혀도 남는 칸이 없다(Assumed: Playwright와 휴대폰으로 확인).
  - 저절로 뜬 겹침(복귀 요약)에는 칸을 쌓지 않는다. 누르기 전에 넣은 칸은 브라우저가 건너뛸 수 있고(Unknown), 새로고침 뒤 남은 칸은 뒤로를 한 번 헛돌게 한다(`history.state`는 새로고침 뒤에도 남는다).
- 3단계 폭
  - D-6004 기술 전달(넓으면 고정, 중간은 접기, 좁으면 하단 탭)과 같다.
  - 600px·1024px는 흔한 경계다(Assumed). iPad 세로(744~834px)는 중간, 가로(1024px 이상)는 넓음이 된다.
  - 폭은 CSS가 정한다. 그래서 첫 그림에서 데스크톱 모양이 번쩍이지 않는다. 옛 관리자 메뉴는 JS로 재서 번쩍일 수 있었다(Assumed).
- 홈이 아닌 탭끼리 바꾸기(replace): 하단 탭 사이를 오간 기록이 쌓이면 뒤로를 여러 번 눌러야 앱을 나간다. 뒤로 → 홈 → 나감이 안드로이드 하단 탭의 흔한 동작이다(Assumed).
- `jsonb` 묶음 열
  - 맞추는 단위가 묶음이다. 칸마다 열을 두면 열이 늘고, 묶음 모양을 바꿀 때마다 마이그레이션이 생긴다.
  - 탭·카드는 목록이라 칸마다 열로 두기 어렵다.
  - 새 표를 만들면 지금 맞추기 장치가 둘로 나뉜다.
- 서버가 처리할 일을 만드는 이유: D-6006 기술 전달과 서버 권위(AGENTS 4장)다. 옛 앱은 기기에서 경고를 만들고 정렬하지 않았다(Verified: `terra-client/src/components/StatusAlertBanner.tsx:64-135`).
- 공용 바로 처리 메시지: 목록은 닫지 않는다(U5). 메시지 뜻("이 항목에 이 동작")은 그대로라 종류가 늘어도 프로토콜 버전을 올리지 않는다. PROTECTED는 뜻이 바뀔 때만 올리라고 한다.
- 끌어 옮기기 직접 구현
  - `@dnd-kit/react` 0.5.1은 접근성이 가장 좋지만 36.7KB이고 1.0 전이라 작은 판에서도 바뀐다(Verified: npm·변경 기록).
  - 옛 `@dnd-kit/core`는 2024-12 뒤 판이 없다(Verified: npm).
  - 직접 구현 스케치는 1.2KB다(Verified: 크기만 잼, 미실행). 목록이 짧다(탭 4칸, 카드 약 10개). 편집 조각에만 들어간다.
  - 버튼은 WCAG 2.5.7 때문에 어차피 필요하다.
- 편집을 바로 저장하는 이유: 뒤로·Esc로 닫아도 잃는 것이 없다. 라우터에 "저장하지 않은 바꿈" 막기가 필요 없어 자체 라우터 범위가 작게 남는다.
- 지도를 내리는 이유: 다시 열기 0.13~0.44초라 1초 기준 안이다(Verified: 헤드리스 측정, ADR S1. 휴대폰은 Unknown). iOS는 메모리를 넘으면 경고 없이 탭을 끈다(PLAN 5.7).
- 홈 자료를 한 요청으로: `httpBatchLink`는 같은 틱 요청을 하나로 묶는다(Verified: `apps/game/src/net/api.ts`).
- 시안 자료를 역할로 막고 범위를 좁히는 이유
  - 플레이어에게 가짜 숫자를 보이지 않는다. 게임 앱 코드는 누구나 내려받으므로(PLAN 4.1) 자료는 서버가 역할을 확인한 뒤에만 준다.
  - 사이보그·자산·세력 카드의 내용은 기획이 아직 정하지 않았다. 그래서 시안에서도 지어내지 않는다(60_UX 통합 메모 "메인에서 정할 것").
  - 템플릿 바꾸기도 dev·admin만이다(사용자 결정. 추천은 "누구나"였다). 그래서 플레이어는 모두 같은 첫 화면(DT-HYBRID)을 본다. 서버는 거절 대신 기본값으로 바꿔 저장한다(6절). 템플릿은 그리는 모양일 뿐이고 자료는 따로 권한을 보므로, 플레이어 계정에 다른 값이 남는 것만 막으면 된다.
- 화면 시험을 저장소에 두고 CI에서 돌리지 않는 이유([결정 3])
  - 개발 동안 화면을 고칠 때마다 다시 도는 반복 작업이라 저장소에 남긴다.
  - 사용자가 할 일이 없게 에이전트가 돌리고 작업 기록에 남긴다. 사용자는 "통과하고 실패한 기록만 남기면" 된다고 했다.
  - CI의 모든 푸시에서 돌리면 브라우저와 DB가 필요해 CI 시간이 수 분 늘어난다(Assumed).
- 옛 프로젝트에서 가져온 생각(코드는 쓰지 않는다)
  - 로그인 → 홈(`terra-client/src/app/login/page.tsx:147`).
  - 경고 줄의 접은 모양(한 줄, "+N", 펼치기, 항목마다 이동) → 처리함 카드. 다만 서버가 만들고, 문구는 메시지 키, (분류, 마감)으로 정렬한다.
  - 문제가 없을 때 한 줄("모든 시스템 정상") → "지금 처리할 일이 없습니다".
  - 카드 = 요약 + 바로 처리 1개 + 상세 링크([COLLECT ALL], [상세]).
  - 빈 카드에 무엇이 언제 보일지를 적는다.
  - 메뉴 항목 아래 한 줄 설명과 숫자 배지.
  - 잠그지 않고 안내한다(세력 탭).
  - 우편은 위 띠에 둔다.
  - 화면마다 로딩·오류 자리(지금 `LazyView`).
  - `terra-lite`: 틀을 한 곳에서 그린다. 더보기를 묶음으로 나눈다.
- 옛 프로젝트에서 피한 것: 화면마다 메뉴, 26줄 메뉴, 메뉴 목록 두 벌, 기기 계산, 요청 16번·타이머 4개, 마우스 전제(hover), 글자·색 직접 쓰기, 플레이어 화면의 개발 정보(DB 배지), 화면 통째 잠금, 지도에서 나갈 길 없음, 세로 고정, 거대 파일(대시보드 797줄 → 카드·템플릿을 파일로 나눈다).

## 결과
- 좋은 점
  - 앞으로 만들 화면은 주소 표 한 줄, 메뉴 목록 한 줄, 화면 파일 하나로 틀에 붙는다.
  - 카드·처리할 일 종류·메뉴 항목이 모두 데이터다. 새 시스템은 더하기만 하면 된다(U5).
  - 뒤로·새로고침·주소로 바로 열기가 된다. 대시보드가 거짓 숫자 없이 지금 상태를 말한다.
  - 새 런타임 의존성이 없다(자체 라우터, 끌어 옮기기 직접 구현). `@playwright/test`는 개발 의존성이다.
- 감수할 점
  - 라우터·끌기 코드를 우리가 가진다. 가장자리 경우는 시험으로 지킨다.
  - 홈의 게임 카드는 시스템이 생길 때까지 "준비 중"이다. 템플릿은 처리할 일·복귀 요약의 시안 자료로만 비교할 수 있다. 비교는 dev·admin만 한다.
  - 화면 시험은 CI가 지키지 않는다. 화면을 고친 에이전트가 돌리고 작업 기록에 남긴다.
  - 화면 모양이 폭 3단계 × 배치 2개 × 테마 4개 × 언어 2개로 늘었다. 눈으로는 파스텔·다크만 본다(디자인 시스템 규칙).
  - 되돌림 배포 동안 기기의 `nav`·`home`은 지워질 수 있다(5절).
  - 저장소 밖 측정 스크립트의 [1차맵]·[2차맵] 누르기는 주소 열기(`/map/planet`, `/map`)로 바꿔야 한다. 통합 세션이 W1을 합칠 때 한다.
- 다시 볼 조건
  - 거래창(6-5) 등에서 검색어 검사·미리 받기가 중요해질 때: 라우터(TanStack Router로 옮길지), TanStack Query·Zustand.
  - 화면 시험을 CI에서 돌릴 필요가 생길 때: 손으로 실행하는 워크플로부터 만든다. 개발이 끝나 필요 없어지면 `e2e/`를 지운다.

## 구현하며 정한 것 (0단계, 2026-10-29)
ADR과 계획서가 정하지 않아 0단계 코드가 정한 것이다. 같은 날 검토 반영으로 고친 모양까지 적었다. 줄기(W1~W5)는 이 모양을 쓴다. 상태가 제안이라 고칠 수 있다.

### 화면 주소(`routes.ts`)
- 줄마다 `path`, `search`(받는 검색어), `parent`, `frame`(`shown` | `hidden`), `access`(`everyone` | `dev_admin` | `admin`), `params`(매개변수 값 규칙)를 둔다.
- 매개변수 값 규칙은 둘이다.
  - `id` = 숫자·영문 소문자·`_` 1~64자(기본). `-`·대문자가 든 ID(uuid, base64url 토큰)는 못 쓴다(1절 "전투").
  - `digits` = 0 또는 0으로 시작하지 않는 10진수이고 안전 정수(2^53 − 1) 이하다. 한 값에 주소가 하나다(`/x/007`은 없는 화면). 셀 키 같은 숫자 ID용이고, 셀 키는 16자리까지 간다(`packages/planet` `MAX_CELL_KEY` = 6 × 2^49 − 10). 처음에는 숫자 1~16자였다(검토 반영).
- `buildPath`는 값이 규칙에 맞지 않으면 예외를 낸다. 점 든 경로를 만들지 않으려는 것이다. 검색어는 표 순서로 넣고, 값이 `undefined`인 검색어는 넣지 않는다. 그래서 검색어 타입이 `string | undefined`를 받는다(지금 주소에서 읽은 값을 그대로 넘긴다).
  - 주소 ID는 글자 그대로 넣는다. 주소 ID가 값으로 정해지는 곳(메뉴 표·처리할 일)은 `RouteTarget`과 `targetPath`를 쓴다. 주소 ID 타입이 여러 주소의 합이면 모든 주소의 검색어 이름이 열리고, 매개변수 주소가 섞이면 모든 주소에 params를 요구해서다. 합을 타입으로 막지 않았다. 막으면 Id를 받아 넘기는 제네릭 감싸기 함수까지 막힌다(Verified: TS 7.0.2로 두 가지 막는 모양을 컴파일해 봄, 저장소 밖 시험 코드).
- `matchPath`
  - 경로는 글자 그대로 비교한다. 대문자·%로 바꾼 글자는 맞지 않는다. 끝의 `/` 하나는 무시한다.
  - 여러 줄이 맞으면 왼쪽 조각부터 정적 조각이 있는 줄이 이긴다(표 순서와 상관없다. 모양이 같은 두 줄은 시험이 막는다). 예: `/economy/market` > `/economy/:section`, 시험 표의 `/map/planet` > `/map/:mapKey`.
  - 검색어는 표에 있는 것만 돌려준다. 같은 이름은 처음 것, `+`는 빈칸이다. 잘못된 %는 그 검색어만 버린다.
- 검색어 읽기·쓰기는 직접 한다. `URLSearchParams`가 `packages/shared` 타입(ES만, DOM·Node 타입 없음)에 없어서다. 쓰기는 `encodeURIComponent`(빈칸 = `%20`)라 브라우저도 같은 값으로 읽는다.
- 경로 예 = 줄마다 하나 + 검색어를 받는 줄은 검색어를 붙인 것 하나(값 `x.1:y_2`). 값에 점·쌍점을 넣어 서버·서비스 워커가 검색어를 보지 않는지 함께 본다. 지금 17개다.
- 가리키는 화면(target)은 `{ route, params?, search? }`다. 기기는 `isRouteTarget`으로 다시 보고, 모르면 처리함으로 보낸다.
  - 자기 칸만 읽고(원형의 칸은 보지 않는다), 값·`params`·`search`는 배열이 아닌 객체여야 한다. `buildPath`·`targetPath`도 자기 칸만 읽는다.
  - 표에 없는 검색어·매개변수 칸(더 새 서버)은 받되 무시한다. `targetPath`가 넣지 않는다. 좁힌 타입에는 그 칸이 없다.
- 부모 화면 `parentTarget(match)`: 화면 안 [뒤로]가 앱 안 기록이 없을 때 바꾸기로 갈 곳이다(2절). 부모 경로의 매개변수 값은 자식 주소의 같은 이름 값을 쓰고, 검색어는 넘기지 않는다.
  - 표 규칙(시험): 부모 경로의 매개변수는 모두 자식 경로에 같은 이름·같은 값 규칙으로 있다(예: `/economy/market/:itemId/:cityId`의 부모는 `/economy/market/:itemId`).
- 검색어 제자리 바꾸기 `replaceSearch(url, changes)`: 바꾼 검색어만 고치고 경로·#조각·다른 검색어(모르는 것 포함)는 글자 그대로 둔다. 값이 문자열이면 그 이름의 첫 자리에 넣고 뒤의 같은 이름은 지운다. `null`·`undefined`면 지운다. 지도 안 `?at=` 같은 바꾸기는 이것으로 한다(`buildPath`로 다시 만들면 모르는 검색어가 빠진다).
- 예약 주소: `/map/:mapKey`는 지웠다(자리는 `?at=` 하나, 1절 "지도 주소"). 개발자 도구는 도구마다 정적 줄 `/dev/<도구>`다(`/dev/:tool` 매개변수 줄을 두지 않는다, 1절).
- 서버 `isPagePath`는 `/health` 앞머리도 화면으로 보지 않는다. 전에는 `/api`·`/ws`만 봤다. 그래서 `/healthz`·`/health/…`는 index.html 대신 404다(`/health` 자체는 상태 응답 그대로).
  - 앞머리 셋은 서비스 워커 제외 목록과 같다. 맞추는 법은 다르다: 서버는 글자 앞부분을 보고(`/healthz`·`/apiary`도 404), 서비스 워커는 조각 단위로 본다(`/healthz`는 index.html). 주소 표는 두 규칙을 모두 피한다(`routes.test.ts`가 앞머리를 막는다).
  - 같은 앞머리가 네 곳에 적혀 있다: `apps/server/src/spaFallback.ts`, `apps/game/vite.config.ts`, `scripts/pwa-build.mjs`(`DENIED_NAVIGATIONS`), `packages/shared/src/routes.test.ts`(`RESERVED_PREFIXES`). 하나를 바꾸면 넷을 함께 고친다.

### 메뉴(`navigation.ts`)
- C 칸에는 지도를 넣지 않는다(가운데 버튼). 저장값에 있으면 빈 칸으로 본다.
- 빈 칸은 그 배치의 기본 탭 중 없는 것 → 항목 목록 순서로 채운다. 겹친 항목은 앞의 것만 남는다.
- 사이드 메뉴는 빠진 아는 항목을 기본 순서로 끝에 붙인다. 상한(32)을 넘으면 모르는 ID를 뒤에서부터 뺀다(겹침은 Set으로 본다. 기기에 저장된 긴 목록도 선형 시간).
- 모르는 배치 값은 C로 읽는다.
- 그릴 때는 `visibleTabs(설정, 배치)`를 쓴다. 모르는 항목 ID 칸은 그 배치의 기본 탭 중 없는 것 → 항목 목록 순서로 채워 보인다(저장값은 그대로). 되돌림 배포 뒤 모르는 ID가 칸을 모두 채워도 하단 탭이 빈 띠가 되지 않는다.
- 저장할 때는 `mergeNavigation(읽은 원래 값, 바꾼 칸)`으로 원래 값에 바꾼 칸만 덮어 쓴다. 더 새 버전의 칸(`nav.extra`)과 모르는 배치의 탭(`tabs.b`)이 남는다(W1·W2).

### 홈(`dashboard.ts`)
- 카드 크기 처음 값: 처리할 일·다가올 일·부관 보고 2×1·2×2, 사이보그·보유 유닛·자산·세력 1×1·2×1, 지도 2×1, 연결·성능 2×1·2×2. 기본 크기는 첫 값이다(처리할 일 2×1). 고를 수 없는 크기는 읽을 때 기본 크기가 된다.
- 표에 자료 출처(`server` | `inbox` | `device`)를 둔다. 서버 카드는 사이보그·보유 유닛·자산·세력 4장이다. ready 자료 모양은 지금 모두 `never`라 보낼 수 없다. 그 시스템이 정한다.
- `parseHome(값, 역할)`: `cards`가 배열이 아니면(저장한 적 없음) 그 역할의 기본 카드, 빈 배열은 그대로 둔다. 카드 안의 모르는 칸도 남긴다. 상한은 24장이다.
  - 아는 카드의 크기가 없거나 문자열이 아니면 기본 크기로 읽는다(카드가 사라지지 않는다). 모르는 카드는 크기가 문자열이어야 남는다.
  - 비지 않은 배열인데 남는 카드가 없으면 저장한 적 없는 것으로 본다(역할의 기본 카드). 모양이 다른 값을 "유저가 모두 뺀 것"과 같게 읽지 않으려는 것이다.
- 저장할 때는 `mergeHome(읽은 원래 값, 바꾼 칸)`으로 원래 값에 바꾼 칸만 덮어 쓴다(W2·W4). 이 기기가 모르는 `template` 값과 더 새 버전의 칸이 남는다.

### 처리할 일(`inbox.ts`)
- 분류 ID: `threat`·`money_survival`·`stalled`·`decision`·`done`.
- 시각(`generatedAt`·`deadlineAt`·`firstSeenAt`·`since`·`until`)은 서버 UTC ms 숫자다(시간·세션 ADR).
- 항목 ID의 키는 숫자·영문 소문자·`_` 1~64자다. 계정에 하나뿐인 종류는 고정 키 `all`을 쓴다(예: `upkeep_short:all`). uuid처럼 `-`가 든 사건 ID는 키가 될 수 없다. 그런 종류를 만들 때 키 규칙을 넓히거나 숫자 ID를 쓴다.
- 완료 분류 종류는 묶지 않는다(`grouped: false`, 시험이 본다). 항목 ID가 사건 ID이고 확인(`inbox.ack`)도 사건마다라서다. 처음에는 `craft_done`이 묶는 종류였다(검토 반영).
- 바로 처리 동작은 0~2개다. 기획(D-6015)은 "항목마다 자주 하는 처리 1~2개"다. 0개는 기술 해석이다: 완료(확인만 한다)와 그 화면에서만 처리하는 종류(공성 방어 시각 고르기 `siege_declared`, 부상 치료 `unit_injured`)는 줄을 눌러 화면으로 간다. 그 시스템을 만들 때 동작을 다시 본다.
- 전송 타입에서 종류·동작·복귀 요약 칸·배지 키는 문자열이다. 더 새 서버가 모르는 값을 보낼 수 있어서다. 분류는 닫힌 목록이라 타입을 좁힌다.
- 종류 표 칸: `category`, `grouped`, `route`(주소 ID만. 매개변수·검색어 값은 항목의 `target`), `actions`, `badge`, `planned`. 푸시 분류 칸은 W6에서 더한다.
- 복귀 요약 칸 종류: `production`·`raid`·`injury`·`world_news`(D-6014 생산·습격과 방어·부상·세계 소식).
