# 셀 키 비트 배치: [면 3][힐베르트 위치 44][레벨 5], 행성 ID는 키 밖

- 상태: 확정
- 날짜: 2026-10-29
- 관련: `2026-10-28-planet-grid-contract.md`(ADR 9. 이 ADR은 그 ID 항목을 자세히 정한다. 대체가 아니다), docs/PLAN.md 5.2, 작업 기록 `docs/worklog/2026/10/29-0005-planet-grid.md`, 코드 `packages/planet/src/cellKey.ts`

## 배경
- ADR 9는 셀 키를 "면 3비트 + 레벨 5비트 + 힐베르트 순서, 53비트 안"으로 정했다. 세 부분을 놓는 순서와 행성 ID를 어디에 담을지는 정하지 않았다.
- 키는 DB·캐시·전송에 그대로 남는다. 한 번 쓰면 바꾸기 어렵다. 그래서 구현(`@terra/planet`)이 정한 배치를 ADR로 남긴다.

## 선택지
1. `[면][레벨][힐베르트]`: 같은 레벨끼리 모인다. 대신 한 칸의 하위 칸들이 레벨마다 다른 구간에 흩어진다.
2. `[면][힐베르트 위치(왼쪽 맞춤)][레벨]`: S2 방식과 비슷하다. 한 칸과 그 모든 하위 칸이 연속한 키 구간 하나에 들어간다.
3. 행성 ID까지 키에 넣는다: 자리가 없다. 레벨 22가 52비트를 다 쓴다.

## 결정
- 2번이다. 키 = 면 × 2^49 + 힐베르트 번호 × 2^(49 − 2·레벨) + 레벨(52비트).
- 최대 레벨은 22다. 면 레벨(행성 크기)은 4~14만 받는다. 면 레벨 14의 배치 레벨(+8)이 22다. 가장 큰 키는 6 × 2^49 − 10이다(2^52 미만).
- 행성 ID는 키에 넣지 않는다. 전체 ID = (행성 ID, 셀 키) 쌍이고, DB는 복합 키로 둔다. 행성 ID 형식은 생성기(S2) 때 정한다.
- 면 배치와 면별 힐베르트 방향은 S2와 같다(S2 라이브러리는 쓰지 않는다).
  - 면 0 = +x, 1 = +y, 2 = +z, 3 = −x, 4 = −y, 5 = −z.
  - 짝수 면은 기본 방향, 홀수 면은 i·j 축을 바꿔 시작한다. 그래서 곡선이 면 0 → 1 → … → 5 → 0으로 끊기지 않는다.
- 패키지 진입점을 둘로 나눈다.
  - `@terra/planet`: 정수 연산만 쓴다. 판정 보조 코드에서 써도 된다.
  - `@terra/planet/projection`: 실수 투영이다(`Math.tan`·`Math.atan`). 표시·생성 전용이다.

## 이유
- 한 칸의 모든 하위 칸이 키 구간 하나에 들어간다. 그래서 레벨이 섞인 표에서도 지역 하나를 `BETWEEN 최소 AND 최대` 한 번으로 고른다(Verified: `hierarchy.test.ts`, 지역 레벨 0~3 × 키 레벨 0~5 전수).
- 같은 레벨 안에서 키 순서는 면 순서 다음 힐베르트 순서다. 가까운 칸이 가까운 키를 받는다(PLAN 5.2).
- 키가 2^52 미만이라 DB `int8`을 JS 숫자로 읽어도 정확하다. BigInt가 필요 없다.
- 구현에서 잰 값(Verified: 패키지 코드와 따로 쓴 계산이 같음, 작업 기록)
  - 같은 레벨 칸 면적 최대/최소: 레벨 5 1.380배, 레벨 9 1.412배(ADR 9의 "약 1.4배"와 맞음).
  - 지구(면 레벨 9) 반지름 530.917km. 1차맵 최소 칸 평균 1,500.7m, 지형 칸 11.72m, 배치 칸 5.86m.
  - 칸 크기(√면적)는 평균의 0.913~1.085배다(PLAN 5.2의 "약 ±10%"와 맞음).

## 결과
- 셀 키 배치, 면 배치, 면별 힐베르트 방향, 면 경계 변환표(`FACE_EDGE_LINKS`)를 바꾸면 저장된 키가 모두 다른 칸을 가리킨다. 그래서 `docs/PROTECTED.md`에 넣는다. 골든 값 시험(`cellKey.test.ts`)이 바뀐 것을 잡는다.
- 정수 모듈에 초월함수·현재 시각·`Math.random`이 들어오지 않게 `scripts/check-boundaries.mjs`가 검사한다(투영 파일 제외).
- 투영의 `Math.tan`·`Math.atan`은 엔진마다 마지막 자리가 다를 수 있다(Unknown). 생성기의 고정 시드 결과 해시(PLAN 5.5)가 투영 값에 기대게 되면 S2에서 처리 방법을 정한다.
- 지구 꼭짓점 8곳을 모두 바다에 두는 회전이 있는지는 아직 모른다(ADR 9, Unknown). 생성기 일이다.
