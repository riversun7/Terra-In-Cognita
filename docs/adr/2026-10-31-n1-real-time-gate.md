# N1 출시 관문 시험은 실제 시간으로 몇 달, 빠른 시뮬레이터는 개발 중 조정용

- 상태: 확정
- 날짜: 2026-10-31
- 관련: ADR `2026-10-31-roadmap-to-launch.md`(확정, 이 ADR이 4절 측정 계획의 "출시 관문" 부분과 R1·N1 행의 배속 목표를 대체), `2026-10-31-rules-simulator.md`(R1, 만드는 중), 기획 D-391·D-408·D-410·D-412(원본 5341168), 질문 119(D-412로 기본안 받음)

## 배경
- 기술 순서 ADR은 N1 출시 시험을 "빠른 가상 시계 시뮬레이터로 시드 5개 × 180일 분량, NAS 밤 시간"으로 적었다(4절).
- 사용자가 기획 세션에서 다르게 골랐다(D-410, 사용자 선택, 추천안 아님): NPC 자동 시뮬레이션 시험(D-391)은 **실제 시간으로 몇 달** 돌린다. 규칙·타이머·설정값을 바꾸지 않고 정직하게 본다. 출시가 그만큼 늦어진다. 시간 배속 기능은 필요 없다.
- 기획이 정리했다(D-412, 해석): 개발 중 규칙 조정은 빠른 가상 시계 시뮬레이터(기술 ADR)로 하고, 출시 관문(P2) 시험은 실제 시간으로 몇 달이다. 둘은 다른 시험이다.

## 결정
- 시험이 둘이다.
  1. **조정 시뮬(개발 중)**: R1 시뮬레이터(빠른 가상 시계, 결정적, 시드)로 규칙·설정값을 맞춘다. 개발 컨테이너에서 돈다. 배속 목표는 "조정이 하루 안에 몇 번 돌 만큼"이다(관문 기준이 아니다). 지표 기록기는 같다.
  2. **출시 관문(P2, N1)**: 실제 시간으로 몇 달, 헤드리스, 유저 0명, 규칙·타이머·설정값은 출시 값 그대로. 세 조건(D-391)과 문턱(질문 119 기본안: 도시 수 몫, 문턱 3개는 설정 칸 49 S38)을 실제 시간 지표로 본다. 시드 5개 동시 실행은 하지 않는다(실제 시간이라 세계 하나, Assumed: 기획이 시드 5개를 적었지만 실제 시간 몇 달에는 세계 하나가 맞다고 읽음. 다르면 기획이 고친다).
- 관문 세계를 돌리는 곳(기술 기본안, 사용자에게 묻지 않음 — D-409 "출시 얘기는 하지말자"): NAS에 따로 띄운 컨테이너 묶음(앱 + DB, 공개 포트 없음, `s3-ramp`처럼 운영 스택과 분리). 본서버가 생기면 그리로 옮긴다(시계·DB를 그대로 옮김). 지표는 관리자 화면(NPC 세계 건강도 D-6047)과 개발자 페이지 관전판으로 본다.
- 관문 동안 다른 일(콘텐츠 넣기, 내부 플레이판 화면, 법률 자문 D-402)은 함께 한다(D-410 영향, 기획 해석).

## 이유
- 사용자 선택(D-410)이다. 빠른 시뮬레이터는 개발 중 조정에 여전히 필요하다(D-412).

## 결과
- 기술 순서 ADR 4절의 배속 목표(약 540배, 180일 분량을 하룻밤)는 관문 기준이 아니다. R1의 속도는 조정용으로만 잰다.
- PLAN 11장 N1 행과 기술 순서 ADR 상태 줄을 고친다(일부 대체).
- 출시는 관문 몇 달만큼 늦어진다(사용자가 알고 고름).
