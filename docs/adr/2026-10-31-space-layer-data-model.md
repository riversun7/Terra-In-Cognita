  - 출시는 지구 + 모항 강하이고 우주층은 나중이다. 행성 ID와 영역 4종 구조만 처음부터 둔다(D-372).

## 선택지
1. 천체·항성계 ID: (a) 콘텐츠 ID(행성 정의와 같은 이름 공간) / (b) DB uuid(행성 보관함 ID) / (c) 항성계 안 번호.
2. 우주 위치: (a) 천체마다 평평한 우주층 지도(2차맵 배치 격자 틀을 다시 씀) / (b) 항성계 하나의 연속 좌표 / (c) 자리(슬롯) 목록만.
3. 게이트: (a) 스타게이트 = 은하 자료의 연결선, 워프게이트 = 세계 표의 우주 건물 모듈 짝 / (b) 둘 다 세계 표의 건물.
4. 천체 총량 장부: (a) 원장 계정에 천체를 넣고 보유량은 위치 있는 계정의 합 / (b) 원장과 따로 천체마다 숫자 표.

## 결정
### 1. 이름 공간과 ID (선택지 1a)
- 은하는 서버 전체에 하나다. 항성계 ID·천체 ID·스타게이트 ID는 콘텐츠 ID다(영어 snake_case, 다시 쓰지 않음, 이름 `{ko, en}`, ADR 24).
- 천체 종류: `terrestrial`(지면, 격자 있음) · `gas_giant`(우주층만, D-383) · `asteroid_belt`(우주층만). 위성은 부모 천체가 있는 천체다(부모 = 항성 또는 천체). 정착하는 달은 `terrestrial` 위성이다(D-383).
- 격자가 있는 천체는 같은 ID의 `planets` 항목(생성 정의)을 가진다. 그래서 세계 표의 `planet_id` 열은 천체 ID로 읽는다. 모양이 같아 마이그레이션이 없다. 격자가 없는 천체(가스 행성·소행성대)의 줄은 영역이 `space`뿐이다(서버 검사).
- 이름 = 별칭 `{ko, en}` + 실명 `{ko, en}`(선택, D-366). 화면은 "붉은 정원(화성)"처럼 함께 보인다.
- 행성 보관함 uuid는 편집기 초안 ID로 남는다. 행성을 공개할 때(D-365 "편집기 공개 사건") 콘텐츠 ID를 정한다(ADR 38 "바뀜: 행성 보관함": 팩에 반영할 때 새 ID). 항성계 편집기 정의 판 1(uuid를 가리킴)은 편집기 초안 형식이고, 게임 자료(판 2)는 콘텐츠 ID를 가리킨다.
- 콘텐츠 분류 이름(`star_systems`·`celestial_bodies`·`stargates` 등)과 필드는 팩 형식 ADR을 새로 쓸 때 정한다(Assumed).

### 2. 영역과 위치 (선택지 2a)
- 위치 = (천체 ID, 영역, 그 영역 안 자리).
  - 육지·하늘·해상: (2차맵 셀 키, 2차맵 로컬 좌표). 지금 그대로다.
  - 우주: 그 천체 우주층 지도의 좌표. 천체마다 평평한 우주층 지도 하나를 둔다. 2차맵과 같은 배치 격자 틀이고 지형 대신 빈 공간·소행성 같은 장애물만 있다(Assumed: 크기·장애물은 항성계 화면 ADR이 정한다). 셀 키 밖의 좌표다(ADR 9·34를 바꾸지 않고 더한다).
  - 이동 중(워프·스타게이트·워프게이트·발사·강하·정기선): (출발 자리, 도착 자리, 출발 시각, 도착 시각)의 예약 이동 사건이다(D-357·D-363·D-371·D-385). 함선·운송 수단에 실린 사이보그·유닛·화물은 따로 위치를 갖지 않고 싣고 간 것의 위치를 따른다.
- 항성계 화면 = 천체를 궤도에 놓은 개관(편집기 자료의 궤도 거리, 공전 없음, D-381 101). 천체를 누르면 그 천체의 우주층 지도, 지면 천체는 1차맵으로 간다.
- 영역 잇기
  - 육지 ↔ 우주: 우주공항(육지 건물)과 같은 천체 우주층의 궤도 정거장 사이 노선만(D-363·D-376). 궤도에서 지상을 치는 판정은 없다.
  - 육지 ↔ 하늘·해상: 지금처럼 공항·항구 도시(D-106).
  - 노선·정기선 운행 조건 = 그 천체 우주층 주인의 허가(정기선 포함, 지구는 늘 허가, D-388 1). 정기선은 시작 도시가 있는 공개 행성의 시작 도시에 내린다(D-388 7).
- 우주 전투맵 = 우주층 지도의 구역 복사(D-354 "그 위치의 우주 타일"). ADR 35의 복사 방식을 다시 쓰고 영역 층을 하나 더한다(Assumed: 우주 전투를 설계할 때 새 ADR).

### 3. 게이트와 이동 그래프 (선택지 3a)
- 스타게이트: 콘텐츠 자료다. 소유·공성·내구도가 없다(D-385·D-388 3). 끝 둘 = (항성계 A의 천체 a 우주층 자리, 항성계 B의 천체 b 우주층 자리). 은하 그래프의 연결선이다. 끝을 천체 우주층에 두는 것은 보안·소유 단위가 천체라서다(D-388 2, Assumed).
- 함선 워프: 같은 항성계 안 두 천체 우주층 사이. 추진기 모듈이 있어야 한다(D-362).
- 워프게이트: 정거장 모듈이다(세계 표의 우주 건물 + 모듈). 두 모듈을 짝으로 잇고, 주인이 통행료·허가를 정한다(D-385). 짝의 조건·거리 상한은 질문 118이다(기술 기본안: 두 끝의 주인이 같은 최상위 세력, 스타게이트 단계 수 상한 = 설정값, 출발값 1).
- 길찾기 = 정적 그래프(항성계 안 천체끼리 + 스타게이트) + 동적 간선(통과가 허락된 워프게이트). 노드가 수백~수천 개라 서버의 다익스트라로 충분하다(Assumed: 항성계 수십 × 천체 수십).
- 시간은 설정값이다: 발사·강하 U1, 워프 U2, 스타게이트 U3, 정기선 U5, 워프게이트 U27. 큰 함급의 항성계 사이 이동은 연료를 쓴다(U25, D-387).

### 4. 소유·보안·세금 (천체 단위)
- 천체 우주층 소유 = 그 천체에 서 있는 영토 주장 건물의 세력(0~1개, D-378). 따로 소유 표를 두지 않고 건물에서 읽는다. 서버 검사 + DB 부분 고유 색인(천체마다 살아 있는 영토 주장 건물 하나). 개수 1은 구조 값(U21)이라 바꾸면 마이그레이션이다.
- 지구 우주층 = 고정 NPC(정거장 인류) 소유, 영토 주장 금지, 다른 우주 건물은 허용(D-375·D-386).
- "고정" 표시 하나: 시작 도시(D-341)·모항(D-355)·지구 우주층(D-375)은 소유 이전·파괴·폐허 처리를 하지 않는다. 같은 표시를 쓴다(Assumed).
- 보안 등급 = 천체 자료의 값 `high`·`low`·`lawless`(D-380·D-388 2). 기본은 규칙(지구 = high, 모항이 있는 항성계의 다른 천체 = low, 다른 항성계 = lawless). 운영자가 천체마다 바꾼다(U6). 바꾸는 길은 다른 설정값처럼 편집기 → 콘텐츠 팩 → 배포다(D-329 해석, PLAN 7장).
  - 판정: 고보안이면 공격 판정 때 경비 NPC 개입 사건, 저보안이면 늦게·일부(U7), 무법이면 없음(D-380). 정원사 우주 함대도 고보안에 오고 경비가 맞선다(D-388 8).
- 우주 세금: 우주 건물 주인 → 그 천체 영토 주장 건물 주인의 계정(없으면 세금 없음, 지구는 소멸 계정). 원장의 세금 항목이다(D-386, D-128과 같은 종류).

### 5. 천체 총량 장부 (선택지 4a, D-359·D-388 5)
- 남은 매장량 = 원장 시스템 계정 `reserve:<천체>:<자산>`의 잔고. 처음 총량은 천체 자료(콘텐츠 팩)이고, 총량 변경은 운영 중 관리자 명령(D-333, 원장의 매장량 조정 사건)이다.
- 보유량(천체) = 그 천체에 놓인 창고 계정 잔고의 합. 그래서 총량 자원의 창고 계정은 위치(창고 → 천체)를 가진다(D-117 "아이템마다 위치"). 운송 중 화물은 도착 사건까지 출발 천체 몫이다(Assumed).
- 천체 사이 운송 = 도착 사건의 원장 거래 하나(출발 천체 쪽 계정 −x, 도착 천체 쪽 계정 +x). 천체 보유량이 저절로 바뀐다. 따로 세는 숫자 표나 출처 꼬리표를 두지 않는다(D-359 "출처 꼬리표 필요 없음").
- 불변식: 원장 I1(자산마다 모든 항목 합 = 0, S3 ADR 2절)이 서버 전체 Σ총량 = Σ(남은 매장량 + 보유량)을 지킨다. 천체 단위 차이(남은 매장량 + 보유량 − 총량)는 허용한다.
- 경보(D-388 5): 원장 불일치 경보 = I1 위반(서버 전체). 천체 단위 차이는 |차이| ÷ 총량이 설정 문턱을 넘을 때만 알린다(49에 칸이 없어 기획에 알림, 기술 출발값 10%, Assumed).
- 채굴 확률 곡선 하나(D-388 5, 기술 기본안): p = p기본 × r^k, r = clamp((총량 − 보유량) ÷ 총량, 0, 1).
  - 평소(차이 0)에는 r = 남은 매장량 ÷ 총량이라 D-116 곡선과 같다. 실려 나간 천체는 r이 커지고, 실려 온 천체는 작아진다(D-359 방향).
  - 한 번에 캐는 양은 남은 매장량을 넘지 않는다. k는 D-116의 설정값(U8 또는 P3 근처, 기획 판단)이다. 계산은 천분율 정수다(판정 코드 규칙).
- 소비된 총량 자원은 소비한 천체의 매장량으로 돌아간다(D-359 예). 그 천체 분포에 그 자원이 없을 때(지구 궤도에서 태운 가스 연료 등)는 질문 115다.

## 이유
- 1a: 세계 표 `planet_id`가 이미 콘텐츠 ID 모양을 검사한다(Verified: `schema.ts` check). 같은 이름 공간이면 열을 바꾸지 않는다. 콘텐츠 ID는 다시 쓰지 않고 배포 흐름(D-329)·검증이 이미 있다. uuid는 팀 편집 초안에 맞고(ADR 38), 항성계 안 번호는 항성계를 고치면 흔들린다.
- 2a: 우주는 천체의 한 층이고(D-375) 우주 전투맵은 "그 위치의 우주 타일"이다(D-354). 천체 사이 이동은 예약 사건이라(D-385) 항성계 전체 연속 좌표가 필요 없다. 2차맵 엔진·경로·전투 복사·시야 전송을 다시 쓸 수 있다(Assumed). 항성계 좌표(AU 단위)를 실수로 들면 32비트 떨림 문제가 다시 생긴다(PLAN 5.7). 슬롯만 두면 전투맵·건물 배치가 없다.
- 3a: 스타게이트는 운영자 지도 자료이고 건물이 아니다(D-385·D-388 3). 워프게이트는 공성 대상 우주 건물이다(D-354·D-385). 정적 그래프 + 동적 간선이 이 차이를 그대로 담는다.
- 4a: 원장 하나가 보존을 지키면 따로 센 숫자와 원장이 어긋날 일이 없다. I1 검사가 이미 있다(S3 `check-world`). 위치 있는 계정은 D-117(아이템마다 위치)과도 맞는다.
- 채굴 곡선: 입력 하나, 설정값 하나(k)로 D-116과 D-359를 함께 담는다. 평소 값이 D-116과 같아 지구만 있는 출시에는 차이가 없다.
- 확정 ADR을 뒤집지 않는다(Verified: 읽음): 격자(9)·셀 키(34)는 "행성 ID + 셀 키"이고 우주 좌표는 그 밖에 더한다. 원장(8)은 복식부기·추가만이고 천체 계정은 그 안이다. 안개(26)는 2차맵 규칙이고 우주층 시야는 질문 117 뒤 그 원칙(서버가 확인한 뒤 보냄)을 따른다. 그래서 새 ADR과 "대체됨" 표시는 이것뿐이고 옛 ADR 상태는 그대로다.

## 결과
- 좋은 점: 지금 세계 표·타일 주소를 바꾸지 않고 천체 여럿을 받을 수 있다. 총량 보존 검사가 하나다. 스타게이트·워프게이트 차이가 자료 모양에 그대로 있다.
- 감수할 점
  - 우주 위치 열·천체 ID 구독은 우주층 업데이트 때 마이그레이션·프로토콜 새 판이 든다(미리 만들지 않는다).
  - 창고 계정에 위치가 들어가 계정 수가 (주체 × 자산 × 위치)로 는다(Assumed: 창고 수만큼).
  - 천체마다 우주층 지도를 두면 지도 수가 천체 수만큼이다. 빈 지도는 저장하지 않는다(2차맵처럼 처음 쓸 때 만든다, Assumed).
- 다시 볼 조건
  - 질문 115~118의 답, Step 8의 출시·첫 업데이트 범위(D-372).
  - 우주층을 설계할 때: 우주층 지도 크기·좌표 단위, 우주 전투 인스턴스(ADR 35 다음), 팩 형식(새 분류), 프로토콜 판.
