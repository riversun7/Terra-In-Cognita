# 사이보그 화면 스탯 판: 옛 프로젝트 모양 그대로(상세 전투 스펙·핵심 사양), 2차 스탯 색

- 상태: 확정 (사용자 반려와 요청 2026-11-01, 구현 가지 `work/cyborg-ui-2`)
- 날짜: 2026-11-01
- 관련: ADR `2026-11-01-ui-visibility.md`(일부 대체: 상세 전투 스펙·핵심 사양의 모양, 스탯 색 표에 2차 스탯 색 더함), 기획 D-448·D-449·D-024, 48 §3.1·§3.2·§3.3, 옛 프로젝트 AntiGravt01 `terra-client/src/components/character/CyborgProfile.tsx`·`StatBar.tsx`·`SecondaryStatsCard.tsx`(읽기만)

## 배경
- `work/cyborg-ui`(main 반영)의 상세 전투 스펙은 줄마다 막대를 1차 스탯 기여 몫으로 여섯 색으로 나눠 칠했다. 핵심 사양은 몸 값·보너스 두 칸 막대였다.
- 사용자(2026-11-01, 정거장 테마의 상세 전투 스펙 사진을 보고, 원문): "왜 이렇게 조잡하게 만들었냐? 스탯 기여도에 따라 색칠하는게 아니지 장난하냐? 차라리 원래 프로젝트를 그냥 따라해라. 2차스탯색깔도 1차스탯하고 겹치면 안되는거고. 기본 1차스탯이 장비나 스킬등에 합쳐지는것이니 마우스 오버나 모바일에서 스탯바 클릭시 세부 기여 출처를 적어주는거고."

## 선택지
1. 지금 모양을 다듬는다(막대 색만 바꾼다).
2. 옛 프로젝트 화면(SecondaryStatsCard·StatBar)을 그대로 따른다. 수치·공식은 우리 규칙(팩 stat_rows, 서버 풀이)을 쓴다.

## 결정
선택지 2.

### 상세 전투 스펙(옛 SecondaryStatsCard)
- 카드: 머리 띠(아이콘 + "상세 전투 스펙" + 작은 부제), 묶음 칸, 아래 줄(Lv | STR:43 VIT:39 …).
- 묶음 칸 = 옛 다섯 칸. 머리에 영문 표지(VITALS 등) + 이름, 칸 위 가장자리에 묶음 색. 팩 행 배치:

  | 옛 묶음 | 우리 행(팩 stat_rows) | 옛 화면에 있던 것 |
  |---|---|---|
  | VITALS 전투자원 | HP, 아머 HP, 쉴드 HP, MP, 스태미나 | HP, 보호막, MP, 보호막 재생, STA |
  | OFFENSE 공격 | 물리 공격력, 속성 공격력, 명중, 크리 확률, 크리 배율 | 물리·마법 공격력, 크리 확률·배율 |
  | DEFENSE 방어 | 방어율, 회피 | 회피율, 반격 |
  | MOBILITY 기동 | 행동 속도, 시야 | 공격속도, 이동속도 |
  | EFFICIENCY 효율 | (지금 행 없음 — 48 §3.3 직무 효율 행이 생기면 여기) | MP·STA 소모 감소 |
  | 기타 | 표에 없는 새 행 | — |

  행이 없는 묶음은 그리지 않는다. 옛 화면의 보호막 재생·반격·이동속도·소모 감소는 우리 규칙에 행이 없어 넣지 않았다(가짜 수 없음).
- 줄: ▶(펼치면 ▼) + 아이콘(줄마다, 직접 그린 선 그림) + 이름 + **한 색 막대** + 오른쪽 값(고정폭 글꼴). 막대·아이콘·값은 그 2차 스탯의 색 하나다. 1차 스탯 기여로 칠하지 않는다.
  - 막대 채움(꾸밈): 확률 모양 = 값 ÷ 상한, 양 모양 = 값 ÷ 그 값을 넘는 1·2·5 × 10ⁿ(옛 화면이 max(값, 200)을 끝으로 둔 것처럼 크기만 가늠).
- 펼친 공식 상자(옛 그대로, 고정폭): "공식 … | 캡 … · 반감 …"(확률 모양만 캡), 입력 줄 `STR(43)×1.5 = 64.5` …, 기본·장비 줄, 가중합 → 내림, 확률 곡선 줄, "= 결과". 값·항은 서버가 팩 stat_rows 식으로 계산해 보낸다(`CyborgBody.breakdown`, 그대로).

### 2차 스탯 색(`--color-sec-*`, 테마 넷)
- 1차 스탯 색(STR 진홍·VIT 주황빨강·INT 파랑·WIS 보라·DEX 호박·AGI 초록)과 겹치지 않는 계열만 쓴다: 전투자원 = 청록, 공격 = 자홍, 방어 = 회색, 기동 = 연두. 묶음 안에서는 밝기·채도로 행마다 다르게. 모르는 행은 `--color-sec-other`.
- 토큰: `--color-sec-{hp, armor-hp, shield-hp, mp, stamina, physical-attack, elemental-attack, hit, crit-chance, crit-multiplier, defense-rate, evade, action-speed, sight, other}`. 바탕·판·둘째 판 위 글자 4.5:1을 대비 검사가 잰다(`scripts/design-tokens.mjs`).
- 정거장은 네온(청록 `#20eedf`·자홍 `#ff63d2`·연두 `#c6ff3d` 등). 정거장의 INT(`#40b9ff`)·AGI(`#3dff9e`)·WIS(`#c770ff`)와도 색상각을 띄웠다.
- 고정폭 글꼴 토큰 `--font-mono`(기기 글꼴만, 받지 않는다).

### 핵심 사양(옛 StatBar)
- 줄 = 약자·이름 | 막대(합친 값) | 합계(스탯 색). 막대는 그 스탯 색 하나의 진하기로 출처를 나눈다(옛 태생·성장·투자·장비처럼): 몸 값(평소 하나) → 장비 → 인공장기·부품(빗금) → 스킬·효과. 만렙이면 몸 값을 처음 값·레벨 성장으로 나누고 K를 보인다(D-449). 투자 칸은 없다(D-024).
- 막대를 누르면(휴대폰·키보드) 줄 아래에 출처 상세가 열리고, 마우스를 올리면 떠서 보인다: 몸 값(또는 처음 값 + 레벨 성장(K)), 장비 칸 아이템마다(이름 · 칸), 스킬·효과, 합계. 하나만 열리고 Escape로 닫힌다.
- 출처는 서버가 보낸다: `CyborgBody.primarySources`(스탯마다 `body`|`initial`|`growth`(K‰)|`item`(칸·아이템·값, 보석 몫 포함)|`effect`). 더하면 base + bonus(서버 시험). 버프(스킬·효과)는 화면 자료에 아직 없어 0이다.
- 두 칸씩 묶음·스탯 색(D-448)은 그대로다.

### 그대로 두는 것
- 머리 판(그림·인공장기·장비 칸·막대), 스킬 칸, 속성, 인벤토리·환생·랭킹, 상태 줄, 정거장 테마, 첫 접속 초기 스탯·유닛 상세의 스탯 묶음(`roster/StatPairs.tsx`).

## 이유
- 사용자가 옛 모양을 그대로 따르라고 했다(위 원문). 옛 화면의 틀에 우리 규칙의 값만 넣으면 가짜 수가 없다.
- 2차 스탯 색이 1차 스탯 색과 겹치면 "이 막대가 STR 몫인가"로 읽힌다. 계열을 나눠 두 색 체계를 섞지 않는다.
- 출처를 서버가 보내는 까닭: 기기는 판정 코드를 가져오지 않는다(AGENTS 4장). 출처 계산은 `loadoutOf`와 같은 더하기다.

## 결과
- 좋은 점: 줄마다 색 하나라 읽기 쉽고, 공식이 옛 화면처럼 바로 풀린다. 1차 스탯은 막대 하나로 합친 값과 출처를 함께 본다.
- 감수할 점: 2차 스탯 색 토큰 15개 × 테마 넷이 늘었다. 묶음 안 행끼리는 같은 계열이라 이름으로 구분한다.
- 다시 볼 조건: 효율(직무 효율 행)·보호막 재생·반격 같은 행이 팩에 생기면 그 묶음에 넣고 색 토큰을 더한다. 버프가 화면 자료에 들어오면 출처 `effect`를 채운다.
