## 배경
- 사용자(2026-11-01, NAS에서 새 계정으로 들어간 뒤, 원문): "신규 로그인시 사이보그가 없다면 캐릭터도 없고 스타팅포인트도 선택되지 않아 메뉴들을 이용할수 없고 오류가난다(2차맵이 아예 안보이는 등) / 신규는 로그인시 사이보그 생성창부터 구현해야한다 / 지금처럼 필요한 질문은 기획서 제작을 통해 질문해서 결정한다".
- 지금 코드(Verified: main `9900b52`)
  - 사이보그 표가 없다. 사이보그 화면(`/cyborg`)은 계정 이름만 실제이고 본체는 dev·admin 시안 자료뿐이다("본체 자료는 첫 접속(외형·초기 스탯)을 마치면 보입니다").
  - 2차맵은 내 유닛이나 탐사한 칸이 없으면 열리지 않는다(`not_visible`, S3 ADR 3절, 사용자 결정 U3). 새 플레이어는 둘 다 없어서 2차맵이 까맣다.
  - 시작 도시는 시험 NPC 세력(`s3_test_npc`, 고정)에게 시험 2차맵마다 하나(가운데 칸)다(`apps/server/src/world/cities.ts`). 세력 가입 표(`faction_members`)는 있으나 넣는 길이 없다.
  - 유닛을 주는 길은 개발 시험 명령 [시험 일꾼 받기](`dev_spawn_units`, `settlement.giveWorkers`)뿐이다.
  - ADR 37은 첫 접속 주소를 `/start`로 예약했고, "사이보그가 없는 계정은 6-6 뒤에 `/start`로 보낸다(Assumed)"고 적었다.
- 기획 흐름(60 7.1): 이름(서버 고유, D-134) → 외형(프리셋 → 무작위 → 부위 → 색, D-6040) → 초기 스탯(성향 → 무작위 합 60 → 다시 굴리기 몇 번, D-6039) → 세력(추천 지역, D-218) → 시작 도시(세력의 안전 도시 2~4곳, 자원·기후·붐빔, D-6041) → 강하(D-058) → 튜토리얼(D-6042·D-6043) → 대시보드. 성인 인증은 게임 안에 없다(D-6044).

## 결정
### 1. 흐름과 주소
- 주소 `start` = `/start`, 틀 숨김(편집기와 같다), 누구나. 부모 `home`.
- 길잡이(틀 `Shell.tsx`): 로그인 뒤 `cyborg.status`를 읽는다. 사이보그가 없으면 아래 예외 밖의 모든 주소를 `/start`로 바꾼다(replace). 사이보그가 있으면 `/start`는 홈으로 바꾼다. 읽는 동안은 화면을 그리지 않고 "확인 중"을 보인다. 읽기에 실패하면 막지 않는다(화면들은 사이보그가 없어도 빈 상태로 돈다, 4절).
  - 예외(사이보그 없이 여는 주소): `settings`(언어·테마·로그아웃). dev·admin 역할은 더 `admin`, `dev`·`dev_*`, `map`·`map_planet`(전체 보기·시험 일꾼은 지도 안의 개발 도구다).
- 단계(한 화면 안 상태, 기록 칸은 쌓지 않는다. 단계 사이는 화면 안 [뒤로]·[다음])
  1. 이름: 글자 규칙을 기기에서 바로 보이고(같은 규칙 함수), [다음] 때 서버에 묻는다(`cyborg.nameCheck`). 최종 확인은 강하 때 서버가 한다.
  2. 외형: 프리셋 4개 → [무작위] → 부위 4곳(머리·얼굴·몸통·팔다리) 넘기기 → 색 2칸(주색·포인트). 2D 그림(SVG). 무작위는 기기 난수(꾸밈이라 판정이 아니다), 서버는 ID만 확인한다.
  3. 초기 스탯: 성향 고르기 → [굴리기](서버) → 여섯 스탯·합 → [다시 굴리기(남은 n번)]. 성향을 바꿔 굴려도 한 번으로 센다(질문 169).
  4. 세력: 가입할 수 있는 NPC 세력(고정 세력 + 시작 도시 ≥ 1). "추천"은 사이보그가 가장 적은 세력(D-218, 금액은 질문 174).
  5. 시작 도시: 그 세력의 시작 도시, 붐빔(그 도시에서 시작한 사이보그 수), 기본 선택 = 가장 덜 붐빔(D-6041). 자원·기후는 "곧 보임"(질문 175).
  6. 강하: 요약(얼굴·이름·스탯·세력·도시) → [강하] → 서버가 만들고 놓는다 → 짧은 연출(움직임 줄이기면 없음) → 홈.
- 로그아웃·설정 단추를 `/start` 머리에 둔다(틀이 없다).

### 2. 자료 모델 (마이그레이션 하나, 모두 새 표라 직전 판 앱이 그대로 돈다: ADR 22)
| 표 | 내용 |
|---|---|
| `cyborgs` | `user_id`(기본 키, 계정당 하나 D-096), `name`(보이는 이름, NFC), `name_key`(유일: 대소문자 무시 열쇠), `temperament`, `initial`(int2[6] STR·DEX·AGI·VIT·INT·WIS), `k_pm`(int2[6], 숨김 D-417), `appearance`(jsonb: 프리셋·부위 4·색 2의 ID), `faction_id`, `start_city_id`, `unit_id`(세계 유닛, 외래 키 없음: 유닛 행을 지우는 정리가 있다), `level`·`exp`·`rebirths`·`faith`(기본 1·0·0·0), `created_at_ms` |
| `cyborg_rolls` | 만드는 중인 굴림: `user_id`(기본 키), `temperament`, `stats`(int2[6]), `rolls_used`, `seed`(마지막 굴림, 감사용), `updated_at_ms`. 만들면 지운다 |
- 세력 가입은 지금 표 `faction_members`(사용자당 한 줄)에 넣는다. 시야 묶음은 아직 사용자 한 명이다(S3 3절, `groupKeyOf`). 그래서 가입해도 NPC 유닛을 보지 않는다.
- 세계 유닛: 종류 코드 `UNIT_KIND_CYBORG = 3`(`unitKinds.ts`, 저장값), 크기 1, 걷기 속도, 소유 주체 = 그 사용자. 시작 도시 칸에서 나선으로 빈 칸을 찾아 놓는다. 직무 없음.
  - 시험 유지비·직무 정산에 넣지 않는다(D-445 178: 본체는 생필품 유지비 D-150 없음). 유닛 화면 목록·보유 유닛 수(주거 상한 D-153)에도 넣지 않는다(본체는 사이보그 화면). 피로 회복은 주거에 따른다(D-430) — 피로·주거 규칙이 서버에 들어올 때 본체에도 건다.
- 쓰기: 만들기 한 번 = 한 번의 동기 처리로 소유 주체·유닛·사이보그 행·가입·굴림 지우기를 월드 쓰기 대기열에 넣고 `durable()`을 기다린 뒤 답한다(소유는 커밋 뒤 답, U2). 굴림도 대기열로 쓰고 커밋 뒤 답한다.
- 부팅: 사이보그·굴림을 메모리로 읽는다(이름 열쇠 → 사용자). 유닛이 없는 사이보그(옛 시험 2차맵 정리 등)는 시작 도시에 다시 놓는다(불변 조건 I9 "사이보그마다 세계 유닛 하나").
- 이름 고유는 메모리 표가 먼저 막고(쓰는 프로세스 하나, ADR 3), DB 유일 색인이 뒤를 받친다.

### 3. 규칙 (서버 권위)
- 이름(`packages/shared/src/cyborgName.ts`, 기기·서버 같은 함수, 질문 170·171): NFC로 바꾼 뒤 한글 완성형(가~힣)·영문·숫자만. 빈칸·기호 없음. 글자가 하나는 있어야 한다(숫자만 안 됨). 길이는 한글 1자 = 2칸, 영문·숫자 = 1칸으로 3~16칸(한글만 2~8자, 영문만 3~16자 = D-134, D-445 170). 열쇠 = 소문자(대소문자 무시). 사칭 목록(운영·관리자·admin·gm·system·moderator 등, 데이터 `CYBORG_NAME_RESERVED`)을 막는다. 욕설은 나중에 같은 자리에 더한다(외부 목록은 라이선스 확인 뒤, D-445 171). 다른 나라 글자는 처음부터 받지 않아 혼동 문자 섞기(D-134, UTS #39)가 생기지 않는다.
- 초기 스탯(`packages/sim/src/society/cyborgStats.ts` `firstStatRoll`·`rerollStats`·`rollStatSpread`, 질문 168): 고른 성향 칸의 평균을 `initialFavorMilli`만큼 올리고 나머지 칸은 합이 그대로가 되게 내린다. 잡음 = 균등 굴림 12개 합(어윈-홀, 표준편차 `initialSpreadMilli`, 초월함수 없음), 칸 범위로 자른 뒤 합 60에 비례로 맞춘다(가장 큰 나머지). 합·칸 범위는 팩 tuning N9(`n9_initial_*`). 시드는 서버가 `crypto`로 뽑아 굴림 행에 남긴다(같은 시드 = 같은 값).
  - 성향(D-445 168): 균형(치우침 없음)·전투(STR·VIT)·기술(INT·DEX)·교역(INT·WIS). 치우침은 설정값이고 출발값은 D-445 168이 받은 값이다: `n9_initial_favor` 4000(고른 두 칸 평균 14, 나머지 넷 8, 균형 10), `n9_initial_spread` 3000(표준편차 약 3). 굴림 상한 = 처음 1 + 다시 굴리기 `n9_initial_rerolls`(출발값 3, D-445 169 — 생성과 환생이 같은 칸, D-444 164). 시작 도시 붐빔 문턱 `d6041_crowd_normal`·`d6041_crowd_busy`(20·50)도 같은 계수표(`cyborg.startCrowd*`)다.
  - K(N6 800~1200‰ 균등, 여섯)는 만들 때 굴린다(환생과 같은 `kFromRolls`).
  - 합치기(2026-11-01, `work/d444` = main 8e1faae): 처음에는 이 줄기가 `packages/sim/src/cyborg/initialStats.ts`(어윈-홀 셋 + 한 칸씩 ±1, 팩 `n9_rerolls`·`n9_bias_*`·`n9_spread`)를 만들었고, 같은 때 세력 줄기가 환생용 `society/cyborgStats.ts`(어윈-홀 12개 + 비례 맞춤, 치우침 출발값 +3)를 만들었다. 굴리기 규칙·다시 굴리기 횟수를 한 곳에 두려고 이 줄기의 파일·팩 항목을 지우고 `cyborgStats.ts`를 쓴다. 치우침 출발값은 D-445 168 값(4000)으로 바꾸고, 이 줄기의 시험 생각(시드 2000개의 합·칸 범위, 평균 14·8·10, 표준편차 약 3)을 그 시험 파일에 옮겼다. 환생(`rebirthCyborg`)은 같은 굴림을 그대로 쓴다. 팩은 core 13.
- 세력·도시: 고정 NPC 세력의 시작 도시(`world_cities.start`)이고 그 2차맵이 이 서버에 떠 있어야 한다. 아니면 `unknown_faction`·`unknown_city`.
- 계정당 하나: 이미 있으면 `already_created`. 굴림 없이 만들면 `roll_required`. 굴림을 다 쓰면 `rolls_exhausted`(마지막 값으로 만들 수 있다).

### 4. 프로토콜 4 (WebSocket, `packages/protocol/src/cyborg.ts`)
- 기기 → 서버
  - `cyborg_roll { id, temperament }`: 굴린다(남은 횟수를 하나 쓴다).
  - `cyborg_create { id, name, appearance, factionId, cityId }`: 만들고 놓는다.
- 서버 → 기기: `cyborg_result { id, ok: true, roll? } | { id, ok: false, code }`. `roll` = `{ temperament, stats[6], rollsLeft, rollsMax }`. 코드: `sign_in_required`·`busy`·`rate_limited`·`already_created`·`roll_required`·`rolls_exhausted`·`name_invalid`·`name_reserved`·`name_taken`·`appearance_invalid`·`unknown_temperament`·`unknown_faction`·`unknown_city`·`no_room`·`internal_error`.
- `PROTOCOL_VERSION` 3 → 4. 받는 가장 낮은 판은 3 그대로(3판 기기는 이 메시지를 보내지 않는다). 3으로 인사한 연결이 보내면 `invalid_message`(2차맵 메시지와 같은 방식).
- 사용자별 속도 제한(분당 30, 순간 10), 같은 사용자의 요청은 차례로 처리한다.
- 조회(tRPC, `cyborg.*`): `status`(사이보그 있음·없음, 이름·외형 — 틀 길잡이·위 띠 얼굴), `creation`(굴림 상태·규칙·성향·세력·도시·붐빔), `nameCheck({ name })`. `cyborg.get`은 사이보그가 있으면 실제 이름·본체(레벨 1, 초기 스탯 × 성장, 빈 장비·인벤토리)를 보낸다.

### 5. 사이보그가 없는 화면

## 바뀜 (D-450~D-453, 2026-11-01)
기획 D-450(속성값 출처)·D-451(신앙도·신앙 포인트)·D-453(사이보그 유지비, D-445 178 대체). 규칙(환생·신앙·인공장기)은 ADR `2026-10-31-faction-society-core.md` 같은 이름 절. 작업 기록 `docs/worklog/2026/11/01-1300-d450.md`, 후속 질문 184~191 `docs/questions/2026-11-01-d450-followup.md`(184~190 → D-455, 아래 "바뀜 (D-455)").

### 1. 속성 분배 단계 (D-450, 49 N36)
- 흐름: 이름 → 외형 → 초기 스탯 → **속성** → 세력 → 시작 도시 → 강하(일곱 단계). 속성 단계는 기본 4원소(물·불·바람·땅) 가운데 N36 칸 수(2)까지 골라 N36 점수(10)를 정확히 나눈다. 한 칸에 모두 넣어도 된다(단추 [모두]). 10점을 다 나눠야 [다음]이 열리고, 강하 요약에 한 줄("불 6 · 바람 4")이 보인다. 화면 `apps/game/src/start/elementsStep.tsx`·`elements.css`(start.css와 나눔, 막대 색은 지금 있는 색 토큰을 빌려 씀).
- 규칙 함수 하나(`packages/shared/src/cyborgElements.ts` `checkElementAllocation`)를 기기(다음 단추)·서버(만들기·분배 판정)·판정 코드(환생 다시 나누기)가 함께 쓴다. 이름 규칙과 같은 자리다. 칸 수·점수는 팩 tuning `n36_element_cells`·`n36_element_points`(구조 값, D-5054)이고 `cyborg.creation` `rules.elementCells`·`elementPoints`로 보낸다. 칸마다 상한 10(D-182)은 구조 상수 `ELEMENT_MAX`.
- 저장: 표 `cyborgs`에 `elements smallint[]`(12칸, D-167 코드 차례 = 전투 공식 칸 차례 = `@terra/shared/roster` `ELEMENT_CODES`). **null = 아직 나누지 않음**. 검사 `cyborgs_elements`(null이거나 12칸·0~10). 마이그레이션 `20261101032420_cyborg_elements_faith_upkeep`(열 더하기만 → 직전 판 앱이 그대로 돈다: 옛 앱이 만든 사이보그는 null로 남는다).
- 조회: `cyborg.status`·`cyborg.creation`에 `elementsPending`, `cyborg.get` 본체 `elements`(화면 줄기가 0으로 만들어 둔 12칸 배열 하나를 채운다: 생성·환생 값 + 장비·인공장기·신앙 출처의 합, 칸마다 10에서 자름 — 출처는 아직 없어 데이터 고리만, 분배 전이면 모두 0).

### 2. 프로토콜 5
- `cyborg_create.elements`(코드 → 0~10, 모양만 프로토콜이 보고 칸 수·합·4원소인지는 서버). **5판 연결은 꼭 보낸다**(없으면 `elements_invalid`, gateway가 본다).
- `cyborg_elements { id, elements }`: 분배가 없는 내 사이보그에 한 번 나눈다. 이미 나눴으면 `elements_locked`(다시 나누기는 환생 때), 사이보그가 없으면 `no_cyborg`.
- 결과 코드 셋 더함: `elements_invalid`·`elements_locked`·`no_cyborg`. 이 코드를 부르는 메시지는 5판만 보내므로 4판 기기는 새 코드를 받지 않는다.
- `PROTOCOL_VERSION` 4 → 5, 받는 가장 낮은 판 3 → 4(현재 + 직전 1개, ADR 7). **4판 기기의 만들기(elements 없음)는 받고 "분배 기다림"(null)으로 만든다** — PWA 강제 적용으로 새 앱이 오면 아래 3으로 한 번 나눈다. 4판 연결이 `cyborg_elements`를 보내면 `invalid_message`(2차맵·만들기 메시지와 같은 규칙).

### 3. 분배가 없는 사이보그 (NAS 기존 계정)
- 프로토콜 5 전에 만든 사이보그(NAS의 사용자 계정 포함)는 `elements`가 null이다. **모두 0으로 두지 않고, 다음 접속 때 한 번 나누게 했다**: 길잡이(`start/cyborgGate.ts`)가 `elementsPending`이면 사이보그가 없을 때와 같은 예외(설정, dev·admin의 관리자·개발자 도구·지도) 밖의 주소를 `/start`로 보내고, `/start`는 속성 단계만 보인다(`ElementsOnly`, 진행 표시 없음, [속성 정하기] → `cyborg_elements` → 홈). D-445 177("사이보그 없는 기존 계정은 다음 접속 때 생성창")과 같은 결이고, 생성 때의 첫 전략 선택(D-450 영향)을 옛 계정도 한다.
- 까닭: 0으로 두면 옛 계정만 속성이 없는 채 다음 환생까지 간다(환생은 만렙 + 신앙 + 화폐라 멀다).

### 4. 신앙 칸 (D-451)
- 표 `cyborgs`에 `religion text`(신앙 콘텐츠 ID, 없으면 null, 검사 `cyborgs_religion_format`), `faith_points integer default 0`(검사 ≥ 0). 받은 종교 특수 스킬(D-455 187)은 스킬 저장이 서버에 생길 때(환생 명령, R5) 넣는다. 신앙도 `faith`는 그대로(0~100, 쌓이는 문턱 — 환생·개종하면 0). `cyborg.get` 본체에 `religion`·`faithPoints`. 종교를 고르는 길·종교 활동은 아직 없어 모두 null·0이다.
- 휴먼 유닛의 같은 칸(D-451 "유닛(사이보그·휴먼)")은 휴먼 유닛 행이 생길 때 넣는다(지금 세계 유닛 표에 휴먼이 없다, R5). 규칙 모양은 `@terra/sim` `UnitFaith`.

### 5. 본체 생활비 (D-453, 2절 "시험 유지비·직무 정산에 넣지 않는다"를 대체)

- 마지막 유지비 경계(정시)를 못 냈으면 그 시각을 `world_owners.upkeep_unpaid_at_ms`에 적고(냈으면 null), `cyborg.get` 본체 `living = { unpaid, efficiencyPm }`(N38 `n38_living_unpaid` 출발값 700‰)로 보낸다. 본체에 직무·전투가 아직 없어 배율을 곱할 곳은 없다(질문 188, R5).
- 인공장기 내구도는 규칙만 있다(인공장기 아이템 인스턴스가 서버에 없다, R5).
- 결과: 화폐가 없는 새 플레이어는 첫 정시부터 "못 냄"이 된다(정착 지원금 전, 질문 190). 밀린 유지비 수(`upkeep_arrears`)도 본체 몫만큼 는다.

### 6. 화면 시험

### 1. 정착 지원금 (190 다, 49 N39, D-163·D-218·D-445 174)
- 공식: `@terra/sim` `settlementGrant` — NPC 세력 = 기본액(`n39_grant_base` 72) × 세력 배율 ‰(`n39_grant_max` 1500 − `n39_grant_step` 50 × (그 세력 시작 사이보그 수 − 열린 세력 가운데 가장 적은 시작 수), `n39_grant_min` 1000에서 멈춤). 모두 설정값 출발값이다(49 N39 출발값 없음). 기본액 72 = 3일 × 정시 24번 × 시험 유지비 1(본체 하나의 처음 사흘 생활비). 가장 덜 붐빈 세력은 108(4.5일치)을 받는다. 유저 세력은 지도자·의회가 정한 양(같은 함수의 `user` 갈래, 지금은 가입할 유저 세력이 없어 고리만, 정하는 화면 없음).
- 내는 곳: 그 세력의 소유 주체(국고)에서 사용자 주체로, 만들기와 같은 동기 처리(같은 커밋). 원장 거래 `settlement_grant`, 중복 방지 키 `settlement_grant:<사용자 ID>`(사이보그마다 한 번 — 원장이 두 번째를 거절한다). 국고가 모자라면 있는 만큼만 준다(새 화폐를 만들지 않는다). 기획 덧붙임의 "시스템 계정 발행 [임시] 대체"는 원장이 국고에서 꺼낼 수 있어 쓰지 않았다. DB 시험이 발행 계정 잔고가 그대로인지 본다.
- [임시] 세력 화폐가 서버에 없다(첫 접속 ADR 범위 "세력 화폐 없음"). 국고의 시험 화폐 `s3_test_credit`(본체 생활비와 같은 자산)로 낸다. 세력 화폐가 생기면 자산만 바꾼다.
- 기록: `cyborgs.start_grant bigint`(받은 양, null = 받지 않음, 검사 ≥ 0). 세력을 바꾸는 길이 생겨도 이 칸이 있으면 다시 주지 않는다.
- 지원금 전에 만든 사이보그(D-456, 질문 191 나): `start_grant` null인 사이보그는 다음 접속의 한 번 속성 분배(`cyborg_elements`)를 마칠 때 지금 세력의 국고에서 같은 키로 한 번 받는다(양은 만들 때와 같은 규칙, 자기를 뺀 시작 수). 분배와 지급·기록이 한 커밋이다. 다시 나누기는 `elements_locked`라 다시 받을 길이 없고, 다시 켜도 `start_grant`가 남는다.
- 화면: 세력 단계 고르기 칸에 "정착 지원금 n"(`cyborg.creation` `factions[].grant`, 이 사이보그를 세기 전의 시작 수로 정한 양 = 실제로 받는 양). 문구 "정착 지원금은 공식이 정해지면…"을 "덜 붐빈 세력일수록 많고 강하 때 한 번"으로 바꿨다.
- 생활비와 함께: 새 플레이어는 지원금으로 처음 며칠 본체 생활비를 내고, 다 쓰면 미납(효율·피로 회복 불이익)이 된다(DB 시험: 정시 110번 → 108번 내고 2번 미납).

## 바뀜 (기술 성향 스탯, 2026-11-08)
- 사용자 지적(2026-11-08, 사이보그 만들기 화면 사진과 함께, 원문): "사이보그 생성시 agi dex가 아니라 int가 두번이나 존재하는 실수를 할 수 있는가?"
- 기술 성향의 치우침 스탯을 INT·DEX에서 **DEX·AGI**로 바꾼다. 균형(없음)·전투(STR·VIT)·교역(INT·WIS)은 그대로다. 이제 여섯 스탯이 세 성향에 한 쌍씩 겹치지 않고 나뉜다.
- 바꾼 곳은 계수표 한 줄(`packages/sim/src/society/coefficients.ts` `cyborg.temperaments`)이다. 화면(`statsStep.tsx`)은 서버가 주는 성향 목록을 그대로 보여서 따로 바꾸지 않는다.
- 이미 만든 사이보그와 저장된 굴림 값은 그대로 둔다(저장된 것은 숫자뿐이다). 프로토콜·DB·팩 판은 그대로다.
- 기획 D-445 168(기본안 "기술(INT·DEX)")을 바꾸는 것이라 기획 세션에 알려 기록을 맡긴다.

## 바뀜 (2026-11-11, 다시 굴리기·속성 옮기기·나라 카드)
- 사용자 요청(2026-11-11, 원문): "개선1. 다시돌리기 5회로 늘리고 운영자는 횟수제한 없다." "개선2. 속성 10일때 다른 속성을 +를 눌러 기존속성을 9로 낮추고 누른 속성을 올림" "개선3. 시작 세력 고를때 더 자세한 정보(인구수, 정책, 간단소개 등)를 제공하라."
- **다시 굴리기**: 설정 칸 N9 `n9_initial_rerolls`의 팩 값을 3 → 5로 바꾼다(굴림 상한 = 처음 1 + 5 = 6). 기획 49 N9 표의 값(3번)과 다르다 — 사용자 지시라 팩 값이 먼저다. "팩 설정 칸 = TEST 계수표" 검사(`world/combatCatalog.test.ts`)를 지키려고 계수표 기본값(`packages/sim` `TEST_SOCIETY_COEFFICIENTS.cyborg.initialRerolls`)도 5로 맞췄다(시뮬레이터 실행은 이 값을 쓰지 않아 SIM_VERSION은 그대로). 같은 칸을 환생 다시 굴리기도 쓴다(질문 1011).
- **운영진은 제한 없음**: 운영진 = 역할 gm·admin·dev(`@terra/shared` `hasStaffRole`, 지도 성능 판의 운영진과 같은 묶음). 판정은 서버다: WebSocket `cyborg_roll`을 받은 연결의 로그인 역할로 정해 서비스 `roll(…, { unlimited })`에 넘긴다(`cyborg/gateway.ts`). 쓴 굴림은 그대로 센다(역할을 잃으면 그때부터 상한이 걸린다). 프로토콜은 그대로다: 운영진의 굴림 결과는 늘 "남은 = 상한"이고, 화면은 tRPC `cyborg.creation`의 새 선택 칸 `rules.rollsUnlimited`(부르는 사람에 따라)로 "다시 굴리기 (제한 없음)"을 보인다. 속도 제한(순간 10·분당 30)은 운영진에게도 그대로다.
- **속성 옮기기**: 10점을 다 쓴 뒤 다른 속성의 [+]는 이미 고른 다른 속성 가운데 점수가 가장 많은 것(같으면 화면 차례 물·불·바람·땅에서 앞)에서 1점을 옮겨 온다(불 10 → 불 9·물 1). 옮긴 뒤 고른 칸이 칸 수(N36, 기본 2)를 넘으면(두 칸을 고른 채 세 번째 속성) 옮기지 않고 단추를 끄며 힌트를 보인다. 화면 규칙만이다(`apps/game/src/start/elementDraft.ts`) — 옮긴 값은 늘 같은 분배 규칙을 지켜 서버 판정(`checkElementAllocation`)은 그대로다.
- **나라 카드 자세한 정보**: `CreationFaction`에 선택 칸 `profile`(`CreationNationProfile`)을 더했다 — 국력 등급(프리셋 `powerTier`), 인구(그 나라 도시에 사는 휴먼 수 — 정부 판과 같은 셈), 가진 도시 수, 체제, 기술 단계, 거래세(도시 경제 세율, 없으면 팩 값), 화폐(이름·기호·약어), 지도자, 국가 마크(만든 마크 + 이 세계에 올린 그림), 한 줄 소개. 서버가 이미 가진 값(실효 프리셋 + NPC 사회 런타임 거울 세계)을 읽기만 한다(`cyborg/nationProfile.ts`). 런타임이 없으면 거울 세계 칸은 null.
- **한 줄 소개**: 국가 프리셋에 선택 칸 `intro {ko,en}`(언어마다 160자까지)를 더하고 16개 프리셋에 [임시] 글(가상 나라 분위기, 실제 나라·인물 없음)을 넣었다. 팩 core@66. 국가 편집기(`/dev/nations`) 정체성 칸에서 보고 고친다.
- **추천**: 옛 규칙("사이보그가 가장 적은 세력")은 빈 세계에서 모든 카드가 추천이었다. 새 규칙: 시작 도시 하나당 시작한 사이보그 수가 적은 차례 → 시작 도시가 많은 차례 → 세력 ID 차례로 앞의 3곳, 열린 나라가 3곳 이하면 1곳(`recommendedNations`). 새로 온 사람에게 자리가 넉넉하고 지원금(덜 붐빈 나라일수록 많다, N39)이 큰 나라다. 기본 선택은 그대로 첫 추천 나라다(질문 1012).
- **카드 모양(390px)**: 카드마다 마크·이름·등급·추천, "인구 · 도시 n곳(시작 도시와 다를 때만 괄호) · 시작한 사이보그"(사이보그 수는 어느 나라든 1 이상일 때만 — 빈 세계의 "사이보그 0"은 정보가 없다), 한 줄 소개, 정착 지원금. 고른 카드만 펼쳐 지도자·체제·거래세·화폐·기술 단계·시작한 사이보그를 보인다(16장이 너무 길지 않게).
