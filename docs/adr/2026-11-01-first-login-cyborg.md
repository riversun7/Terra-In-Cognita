## 배경
- 사용자(2026-11-01, NAS에서 새 계정으로 들어간 뒤, 원문): "신규 로그인시 사이보그가 없다면 캐릭터도 없고 스타팅포인트도 선택되지 않아 메뉴들을 이용할수 없고 오류가난다(2차맵이 아예 안보이는 등) / 신규는 로그인시 사이보그 생성창부터 구현해야한다 / 지금처럼 필요한 질문은 기획서 제작을 통해 질문해서 결정한다".
- 지금 코드(Verified: main `9900b52`)
  - 사이보그 표가 없다. 사이보그 화면(`/cyborg`)은 계정 이름만 실제이고 본체는 dev·admin 시안 자료뿐이다("본체 자료는 첫 접속(외형·초기 스탯)을 마치면 보입니다").
  - 2차맵은 내 유닛이나 탐사한 칸이 없으면 열리지 않는다(`not_visible`, S3 ADR 3절, 사용자 결정 U3). 새 플레이어는 둘 다 없어서 2차맵이 까맣다.
  - 시작 도시는 시험 NPC 세력(`s3_test_npc`, 고정)에게 시험 2차맵마다 하나(가운데 칸)다(`apps/server/src/world/cities.ts`). 세력 가입 표(`faction_members`)는 있으나 넣는 길이 없다.
  - 유닛을 주는 길은 개발 시험 명령 [시험 일꾼 받기](`dev_spawn_units`, `settlement.giveWorkers`)뿐이다.
  - ADR 37은 첫 접속 주소를 `/start`로 예약했고, "사이보그가 없는 계정은 6-6 뒤에 `/start`로 보낸다(Assumed)"고 적었다.
- 기획 흐름(60 7.1): 이름(서버 고유, D-134) → 외형(프리셋 → 무작위 → 부위 → 색, D-6040) → 초기 스탯(성향 → 무작위 합 60 → 다시 굴리기 몇 번, D-6039) → 세력(추천 지역, D-218) → 시작 도시(세력의 안전 도시 2~4곳, 자원·기후·붐빔, D-6041) → 강하(D-058) → 튜토리얼(D-6042·D-6043) → 대시보드. 성인 인증은 게임 안에 없다(D-6044).

## 결정
### 1. 흐름과 주소
- 주소 `start` = `/start`, 틀 숨김(편집기와 같다), 누구나. 부모 `home`.
- 길잡이(틀 `Shell.tsx`): 로그인 뒤 `cyborg.status`를 읽는다. 사이보그가 없으면 아래 예외 밖의 모든 주소를 `/start`로 바꾼다(replace). 사이보그가 있으면 `/start`는 홈으로 바꾼다. 읽는 동안은 화면을 그리지 않고 "확인 중"을 보인다. 읽기에 실패하면 막지 않는다(화면들은 사이보그가 없어도 빈 상태로 돈다, 4절).
  - 예외(사이보그 없이 여는 주소): `settings`(언어·테마·로그아웃). dev·admin 역할은 더 `admin`, `dev`·`dev_*`, `map`·`map_planet`(전체 보기·시험 일꾼은 지도 안의 개발 도구다).
- 단계(한 화면 안 상태, 기록 칸은 쌓지 않는다. 단계 사이는 화면 안 [뒤로]·[다음])
  1. 이름: 글자 규칙을 기기에서 바로 보이고(같은 규칙 함수), [다음] 때 서버에 묻는다(`cyborg.nameCheck`). 최종 확인은 강하 때 서버가 한다.
  2. 외형: 프리셋 4개 → [무작위] → 부위 4곳(머리·얼굴·몸통·팔다리) 넘기기 → 색 2칸(주색·포인트). 2D 그림(SVG). 무작위는 기기 난수(꾸밈이라 판정이 아니다), 서버는 ID만 확인한다.
  3. 초기 스탯: 성향 고르기 → [굴리기](서버) → 여섯 스탯·합 → [다시 굴리기(남은 n번)]. 성향을 바꿔 굴려도 한 번으로 센다(질문 169).
  4. 세력: 가입할 수 있는 NPC 세력(고정 세력 + 시작 도시 ≥ 1). "추천"은 사이보그가 가장 적은 세력(D-218, 금액은 질문 174).
  5. 시작 도시: 그 세력의 시작 도시, 붐빔(그 도시에서 시작한 사이보그 수), 기본 선택 = 가장 덜 붐빔(D-6041). 자원·기후는 "곧 보임"(질문 175).
  6. 강하: 요약(얼굴·이름·스탯·세력·도시) → [강하] → 서버가 만들고 놓는다 → 짧은 연출(움직임 줄이기면 없음) → 홈.
- 로그아웃·설정 단추를 `/start` 머리에 둔다(틀이 없다).

### 2. 자료 모델 (마이그레이션 하나, 모두 새 표라 직전 판 앱이 그대로 돈다: ADR 22)
| 표 | 내용 |
|---|---|
| `cyborgs` | `user_id`(기본 키, 계정당 하나 D-096), `name`(보이는 이름, NFC), `name_key`(유일: 대소문자 무시 열쇠), `temperament`, `initial`(int2[6] STR·DEX·AGI·VIT·INT·WIS), `k_pm`(int2[6], 숨김 D-417), `appearance`(jsonb: 프리셋·부위 4·색 2의 ID), `faction_id`, `start_city_id`, `unit_id`(세계 유닛, 외래 키 없음: 유닛 행을 지우는 정리가 있다), `level`·`exp`·`rebirths`·`faith`(기본 1·0·0·0), `created_at_ms` |
| `cyborg_rolls` | 만드는 중인 굴림: `user_id`(기본 키), `temperament`, `stats`(int2[6]), `rolls_used`, `seed`(마지막 굴림, 감사용), `updated_at_ms`. 만들면 지운다 |
- 세력 가입은 지금 표 `faction_members`(사용자당 한 줄)에 넣는다. 시야 묶음은 아직 사용자 한 명이다(S3 3절, `groupKeyOf`). 그래서 가입해도 NPC 유닛을 보지 않는다.
- 세계 유닛: 종류 코드 `UNIT_KIND_CYBORG = 3`(`unitKinds.ts`, 저장값), 크기 1, 걷기 속도, 소유 주체 = 그 사용자. 시작 도시 칸에서 나선으로 빈 칸을 찾아 놓는다. 직무 없음.
  - 시험 유지비·직무 정산에 넣지 않는다(D-445 178: 본체는 생필품 유지비 D-150 없음). 유닛 화면 목록·보유 유닛 수(주거 상한 D-153)에도 넣지 않는다(본체는 사이보그 화면). 피로 회복은 주거에 따른다(D-430) — 피로·주거 규칙이 서버에 들어올 때 본체에도 건다.
- 쓰기: 만들기 한 번 = 한 번의 동기 처리로 소유 주체·유닛·사이보그 행·가입·굴림 지우기를 월드 쓰기 대기열에 넣고 `durable()`을 기다린 뒤 답한다(소유는 커밋 뒤 답, U2). 굴림도 대기열로 쓰고 커밋 뒤 답한다.
- 부팅: 사이보그·굴림을 메모리로 읽는다(이름 열쇠 → 사용자). 유닛이 없는 사이보그(옛 시험 2차맵 정리 등)는 시작 도시에 다시 놓는다(불변 조건 I9 "사이보그마다 세계 유닛 하나").
- 이름 고유는 메모리 표가 먼저 막고(쓰는 프로세스 하나, ADR 3), DB 유일 색인이 뒤를 받친다.

### 3. 규칙 (서버 권위)
- 이름(`packages/shared/src/cyborgName.ts`, 기기·서버 같은 함수, 질문 170·171): NFC로 바꾼 뒤 한글 완성형(가~힣)·영문·숫자만. 빈칸·기호 없음. 글자가 하나는 있어야 한다(숫자만 안 됨). 길이는 한글 1자 = 2칸, 영문·숫자 = 1칸으로 3~16칸(한글만 2~8자, 영문만 3~16자 = D-134, D-445 170). 열쇠 = 소문자(대소문자 무시). 사칭 목록(운영·관리자·admin·gm·system·moderator 등, 데이터 `CYBORG_NAME_RESERVED`)을 막는다. 욕설은 나중에 같은 자리에 더한다(외부 목록은 라이선스 확인 뒤, D-445 171). 다른 나라 글자는 처음부터 받지 않아 혼동 문자 섞기(D-134, UTS #39)가 생기지 않는다.
- 초기 스탯(`packages/sim/src/society/cyborgStats.ts` `firstStatRoll`·`rerollStats`·`rollStatSpread`, 질문 168): 고른 성향 칸의 평균을 `initialFavorMilli`만큼 올리고 나머지 칸은 합이 그대로가 되게 내린다. 잡음 = 균등 굴림 12개 합(어윈-홀, 표준편차 `initialSpreadMilli`, 초월함수 없음), 칸 범위로 자른 뒤 합 60에 비례로 맞춘다(가장 큰 나머지). 합·칸 범위는 팩 tuning N9(`n9_initial_*`). 시드는 서버가 `crypto`로 뽑아 굴림 행에 남긴다(같은 시드 = 같은 값).
  - 성향(D-445 168): 균형(치우침 없음)·전투(STR·VIT)·기술(INT·DEX)·교역(INT·WIS). 치우침은 설정값이고 출발값은 D-445 168이 받은 값이다: `n9_initial_favor` 4000(고른 두 칸 평균 14, 나머지 넷 8, 균형 10), `n9_initial_spread` 3000(표준편차 약 3). 굴림 상한 = 처음 1 + 다시 굴리기 `n9_initial_rerolls`(출발값 3, D-445 169 — 생성과 환생이 같은 칸, D-444 164). 시작 도시 붐빔 문턱 `d6041_crowd_normal`·`d6041_crowd_busy`(20·50)도 같은 계수표(`cyborg.startCrowd*`)다.
  - K(N6 800~1200‰ 균등, 여섯)는 만들 때 굴린다(환생과 같은 `kFromRolls`).
  - 합치기(2026-11-01, `work/d444` = main 8e1faae): 처음에는 이 줄기가 `packages/sim/src/cyborg/initialStats.ts`(어윈-홀 셋 + 한 칸씩 ±1, 팩 `n9_rerolls`·`n9_bias_*`·`n9_spread`)를 만들었고, 같은 때 세력 줄기가 환생용 `society/cyborgStats.ts`(어윈-홀 12개 + 비례 맞춤, 치우침 출발값 +3)를 만들었다. 굴리기 규칙·다시 굴리기 횟수를 한 곳에 두려고 이 줄기의 파일·팩 항목을 지우고 `cyborgStats.ts`를 쓴다. 치우침 출발값은 D-445 168 값(4000)으로 바꾸고, 이 줄기의 시험 생각(시드 2000개의 합·칸 범위, 평균 14·8·10, 표준편차 약 3)을 그 시험 파일에 옮겼다. 환생(`rebirthCyborg`)은 같은 굴림을 그대로 쓴다. 팩은 core 13.
- 세력·도시: 고정 NPC 세력의 시작 도시(`world_cities.start`)이고 그 2차맵이 이 서버에 떠 있어야 한다. 아니면 `unknown_faction`·`unknown_city`.
- 계정당 하나: 이미 있으면 `already_created`. 굴림 없이 만들면 `roll_required`. 굴림을 다 쓰면 `rolls_exhausted`(마지막 값으로 만들 수 있다).

### 4. 프로토콜 4 (WebSocket, `packages/protocol/src/cyborg.ts`)
- 기기 → 서버
  - `cyborg_roll { id, temperament }`: 굴린다(남은 횟수를 하나 쓴다).
  - `cyborg_create { id, name, appearance, factionId, cityId }`: 만들고 놓는다.
- 서버 → 기기: `cyborg_result { id, ok: true, roll? } | { id, ok: false, code }`. `roll` = `{ temperament, stats[6], rollsLeft, rollsMax }`. 코드: `sign_in_required`·`busy`·`rate_limited`·`already_created`·`roll_required`·`rolls_exhausted`·`name_invalid`·`name_reserved`·`name_taken`·`appearance_invalid`·`unknown_temperament`·`unknown_faction`·`unknown_city`·`no_room`·`internal_error`.
- `PROTOCOL_VERSION` 3 → 4. 받는 가장 낮은 판은 3 그대로(3판 기기는 이 메시지를 보내지 않는다). 3으로 인사한 연결이 보내면 `invalid_message`(2차맵 메시지와 같은 방식).
- 사용자별 속도 제한(분당 30, 순간 10), 같은 사용자의 요청은 차례로 처리한다.
- 조회(tRPC, `cyborg.*`): `status`(사이보그 있음·없음, 이름·외형 — 틀 길잡이·위 띠 얼굴), `creation`(굴림 상태·규칙·성향·세력·도시·붐빔), `nameCheck({ name })`. `cyborg.get`은 사이보그가 있으면 실제 이름·본체(레벨 1, 초기 스탯 × 성장, 빈 장비·인벤토리)를 보낸다.

### 5. 사이보그가 없는 화면
- 길잡이가 막지만, 화면들은 사이보그가 없어도 깨지지 않는다(빈 상태 문구). 지도는 지금처럼 "볼 수 없음" 안내다.

### 6. 화면 시험
- 전역 준비가 player·dev·admin을 실제 프로토콜(`cyborg_roll` → `cyborg_create`)로 만든다(다른 시험은 사이보그가 있는 계정 화면을 본다). 새 계정 `fresh`(만들기 끝까지 → 홈 → 2차맵이 까맣지 않음)와 `fresh_shots`(단계 사진만, 만들지 않음)를 더한다.
- 사진: 390px × 파스텔·다크 × 한국어·영어, 단계마다.

## 이유
- 굴리기를 sim 순수 함수 하나로: 판정 코드 규칙(시드 난수·초월함수 없음)을 그대로 쓰고, 환생(D-444 164 "생성과 같은 규칙")과 첫 접속이 같은 함수를 부른다(두 규칙이 갈라지지 않게).
- 굴림 횟수를 DB에: 다시 켜거나 새로고침해도 횟수가 돌아오지 않는다(좋은 값을 노린 반복을 막는다, D-6039 영향).
- 월드 쓰기 대기열: 유닛과 사이보그 행이 한 커밋이라 "사이보그는 있는데 유닛이 없다"가 저장에서 생기지 않는다(그래도 부팅이 고친다).
- 시작 도시에 유닛으로 놓기: 시야·탐사(S3 3절)가 그대로 돌아 2차맵이 열리고, 진 유닛의 돌아갈 곳(`nearestSafeCity`)과도 맞는다.
- 외형을 이번에는 공용 상수로: 3D 부위가 없어 그림이 코드다. ID 묶음(D-6040 기술 전달) 모양은 지금 정해 두고 목록만 나중에 팩으로 옮긴다.
- 새 런타임 의존성은 없다.

## 결과
- 좋은 점: 새 계정이 메뉴·2차맵을 쓸 수 있다. 이름·스탯·소유는 서버가 정한다. 환생이 같은 굴리기를 쓴다.
- 감수할 점
  - 세력 하나·도시 하나(시험 세계)라 고르는 단계가 거의 비어 보인다(질문 173).
  - 지원금·자원·기후가 아직 없다(질문 174·175).
  - NAS의 기존 계정(사용자의 admin 계정 포함)은 배포 뒤 처음 들어갈 때 `/start`로 간다. admin은 관리자·개발자 화면·지도를 그 전에도 연다.
  - 프로토콜 4: 3판 기기는 새 앱을 받기 전까지 만들기를 못 한다(PWA 강제 적용으로 곧 풀린다).
