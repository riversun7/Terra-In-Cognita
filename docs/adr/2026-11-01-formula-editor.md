## 선택지
### 식을 어떻게 읽고 셈하나
1. **손으로 쓴 재귀 하강 해석기 + 고정 소수점 정수 셈(`@terra/shared/formula`)**: eval 없음, 새 의존성 없음, 엔진과 무관하게 같은 값.
2. 식 라이브러리(mathjs 등): 새 런타임 의존성(ADR 필요), 실수 셈이라 결정성이 깨지고 `Math.pow` 등 초월함수를 쓴다.
3. `Function`/`eval`: 금지(보안·결정성).

### 2차 스탯 행을 어떻게 식으로
- 가. **행에 선택 칸 `formula`**: 없으면 그 행 가중치에서 만든 식이 출발 식(같은 결과). 식이 있으면 가중치 대신 식. 가중치 칸(밸런스 화면)은 식이 없는 행에서 그대로 듣는다.
- 나. 모든 행을 식으로 바꿔 팩에 넣는다 → 가중치 칸이 죽어 밸런스 화면 칸 편집이 듣지 않는다.
- 다. 가중치 칸을 없앤다 → 밸런스 화면을 다시 만든다(다른 줄기가 고치는 중).

### 식 덮어쓰기를 어디에
- ㄱ. **새 표 `formula_overrides`(글 값) + 같은 판(`tuning_revision`)·같은 감사 줄(`tuning.*`의 `formulas` 칸)·같은 묶음(`tuning.save`의 `formulas`)**.
- ㄴ. `tuning_overrides`에 글 칸을 더함 → `value`가 NOT NULL int8이라 열을 느슨하게 바꿔야 하고, 직전 판 앱이 읽는 모양이 흔들린다.
- ㄷ. 따로 판·감사·저장(같은 일을 두 벌).

### 맨손 피해 굴림
- (i) **맨손 일반 공격일 때만 굴림을 하나 더 뽑는다(`damagePos`)**: 무기 공격의 굴림 흐름은 그대로.
- (ii) 늘 다섯을 뽑는다 → 모든 전투의 굴림 흐름이 밀려 무기 전투 결과까지 바뀐다(사용자가 고르지 않은 변경).
- (iii) 크리 배율 자리 굴림을 같이 쓴다 → 크리 때 피해 자리와 배율 자리가 묶인다.

## 결정
식은 1, 행은 가, 덮어쓰기는 ㄱ, 맨손 굴림은 (i).

### 1. 식의 문법 (`packages/shared/src/formulaParse.ts`)
- `식 목록 := (이름 '=' 식 [';'])* 식 [';']` — 앞 줄은 중간값(지역 이름), 마지막 식이 결과. 연산자 우선순위: 비교(`< <= > >= == !=`, 참 1·거짓 0, 잇달아 못 씀) < `+ -` < `* /` < 단항 `- +` < 수·이름·함수·괄호. `× ÷ − ≤ ≥ ≠`와 전각 괄호·쉼표도 받는다. `#` 뒤는 줄 끝까지 설명.
- 수는 10진, 소수 셋째 자리까지(넷째부터 오류). 정수 부분 10^12 미만.
- 함수: `min`·`max`(1개 이상), `floor`·`ceil`·`round`(0.5는 올림)·`trunc`·`abs`, `clamp(값, 아래, 위)`, `if(조건, 참, 거짓)`(고른 쪽만 셈), `curve(점수, 상한, 반감)`(점수 ≤ 0이면 0, 아니면 상한 × 점수 ÷ (점수 + 반감): 확률 모양), `lerp(처음, 끝, 비율)`.
- 이름은 그 칸의 변수(대문자)·앞에서 만든 중간값·함수뿐이다. 모르는 이름·함수, 함수처럼 쓴 변수, 괄호 없는 함수, 인자 수, 중간값이 변수·함수 이름과 겹침·두 번 만듦, 결과 없음은 오류다. 문법 오류는 처음 하나에서 멈추고 이름 오류는 모두 모은다(위치 s·e, 비슷한 이름 권함: 대소문자만 다르면 그것, 아니면 편집 거리 2 이하). 쓰지 않은 중간값은 경고.
- 기술 상한: 2,000글자, 깊이 40, 마디 400. 설명 안의 제어 글자·짝 없는 대리 문자는 오류다(DB text·jsonb가 못 담는다).

### 2. 수의 모양과 내림 (`formulaFixed.ts`, 결정성)
- 모든 값은 1000배 정수(밀리)다. 곱 = ⌊a × b ÷ 1000⌋, 나눗셈 = ⌊a × 1000 ÷ b⌋, 둘 다 음의 무한대 쪽 내림. 0으로 나누면 0(미리 보기에 경고, 판정은 던지지 않는다). 곱이 2^53을 넘으면 BigInt로 셈하고 결과는 ±(2^53 − 1)에서 자른다(기술 보호). 실수 나눗셈의 반올림은 나머지로 바로잡는다(`floorDiv`, 시험이 큰 수에서 BigInt와 견준다).
- 결과: 정수 칸(2차 스탯·공격력·명중 등)은 마지막에 내림, 스태미나 소모는 밀리점 그대로.
- 사칙연산과 `Math.floor/min/max/abs/trunc`만 쓴다. 경계 검사의 결정성 대상에 `packages/shared/src/formula*.ts`를 더했다.
- 읽은 식(구문 나무)은 직렬화할 수 있는 값이다. 판정은 처음 한 번 마디마다 닫힌 함수로 바꿔 WeakMap에 둔다(eval 없음).

### 3. 식 칸 (`formulaSlots.ts`)
| 칸 키 | 변수 | 결과 | 기본 식(출발값) |
|---|---|---|---|
| `<행 ID>.formula` ×18 | STR DEX AGI VIT INT WIS LV GEAR BUFF | 정수 | 그 행 가중치에서 만든 식(양: `기본 + Σ 1차 × 배 + GEAR + BUFF`, 확률: `curve(floor(Σ 1차 × 배) + GEAR, 상한, 반감)`) |
| `real_attack`·`real_hit`·`real_crit` | W S A CAP | 정수(점·‰·‰) | `if(A <= 0, W, floor(W * min(CAP, max(0, S) / A)))` |
| `bare_attack` | 1차 6개 LV W S A CAP ROLL | 정수 | 옛 맨손 규칙(아래 5절) |
| `crit_multiplier` | M SPREAD ROLL | ‰ | `max(0, M) + floor(SPREAD * ROLL / 10000)` |
| `attack_interval` | I SPD A | ms | `max(1, floor(I / max(0.001, min(2, max(1, SPD) / max(1, A)))))` |
| `stamina_score` | 1차 6개 W_AGI W_VIT | 정수 | `floor(AGI * W_AGI + VIT * W_VIT)` |
| `stamina_cost` | B SC APP MIN | 밀리점 | `B * if(SC <= 0, APP, max(MIN, APP / SC))` |
| `evade_chance` | E DA AA FAVOR_SLOPE FAVOR_CAP UNFAVOR_SLOPE UNFAVOR_CAP | ‰ | 상대 보정 N11 그대로(중간값 r·favor·unfavor) |
- 설정 칸(N10 CAP, N11, N12 SPREAD, N13 W·APP·MIN)은 식의 변수로 들어간다(D1 칸 그대로). ROLL은 0~9999 정수다(소수로 바꾸면 크리 배율 자리가 1/10로 거칠어진다).
- 변수 값은 `…Scope` 함수 하나가 만든다: 판정(sim)과 화면 미리 보기가 같은 함수를 부른다.
- 건물 피해는 `real_attack`(상한 2000‰ 그대로, 굴림 없음)이라 맨손 건물 피해는 바꾸기 전과 같다(질문 279).
- 공격 간격의 상한 2는 지금 코드처럼 N10과 따로다(같은 결과를 지키려고, 식에서 바꿀 수 있다).

### 4. 판정 코드 (`packages/sim/src/combat/formulas.ts`)
- 계수표 `CombatCoefficients.formulas`(선택)에 전투 식 묶음을 싣는다. 없으면 기본 묶음. `combatCoefficientsFrom(values, base, formulas)`은 식 나무를 깊게 복사하지 않는다(같은 객체 = 같은 캐시). 스태미나 소모는 (식, 기본 소모, 점수)마다 한 번 셈한다(틱마다 부른다).
- 2차 스탯: `StatRow.formula`(선택)가 있으면 그 식(`computeSecondary`·`explainSecondary`에 LV 인자, 없으면 1. 시뮬 유닛은 레벨이 없어 1). `statTableProblems`(가치 없는 1차)는 식 행이면 식이 쓰는 1차 변수로 본다.
- `SIM_VERSION` 4 → 5(맨손 규칙 때문. 무기 전투·시뮬 지표는 그대로, 아래 "같은 결과 증명").

### 5. 맨손 일반 공격 (사용자 결정 D-488)
- 사람형(팩 `unit_kinds` 사이보그·휴먼·안드로이드 `naturalWeapon.unarmed: true`)이 맨손으로 **기본 공격**할 때만 `bare_attack` 식이다. 크리쳐 발톱(표시 없음)은 무기 틀 그대로(질문 275). 스킬 사양에는 쓰지 않는다(D-490, 스킬 편집기 몫). 맨손 속성 자료(스킬 대체만 씀)는 D-490으로 없어질 길이라 식 칸을 두지 않았다.
- 기본 식 = 옛 프로젝트 `calcUnarmedDamage`(AntiGravt01 `terra-server/combat/formulas.js`): 적정 DEX = LV × 1.5 + 10, r = DEX ÷ 적정, 최소 = STR × max(0.1, r × 0.5), 최대 = STR × min(1.5, r), 둘을 작은·큰 쪽으로 맞추고 `max(1, ⌊최소 + (최대 − 최소) × ROLL ÷ 10000⌋)`. 숫자는 [임시](질문 278). 고정 소수점이라 옛 실수 값의 내림과 1 이내(시험 2,000번).
- 굴림: 맨손 일반 공격일 때만 굴림 넷(명중·회피·크리·크리 자리) 뒤에 피해 자리를 하나 더 뽑는다(같은 틱 흐름). 무기 공격의 굴림 흐름은 바뀌지 않는다.
- 레벨: `UnitBody.level`(없으면 1)이 맨손 공격 사양에 실린다. 서버 유닛·사이보그 화면은 계정 레벨을 넘긴다.

### 6. 팩 (core@20 → core@21, `formatVersion` 그대로)
- 새 분류 `formulas`(`content/core/formulas.json`, 항목 `{id, name{ko,en}, expression}`, ID = 전투 식 칸). 빠진 칸은 기본 식. 지금 값 = `DEFAULT_COMBAT_FORMULAS`(서버 시험이 같은지 본다).
- `stat_rows` 선택 칸 `formula`, `unit_kinds.naturalWeapon` 선택 칸 `unarmed`. 기존 팩이 그대로 통과하므로 형식 판은 그대로다(ADR 24).
- 팩 검사 2단계 뒤 `checkFormulas`: 전투 식 ID는 칸이어야 하고 식은 그 칸 변수로 읽혀야 한다(행 식도).

### 7. D1 덮어쓰기 넓힘 (서버)
- 표 `formula_overrides`(id 검사 `^[a-z][a-z0-9_]{1,47}(\.formula)?$`, 글 2,000자, 저장 때 팩 식·팩 판·메모·사람·시각). 마이그레이션 하나, 더하기만. 직전 판 앱은 표를 모른 채 팩 식으로 돈다(다시 새 판을 켜면 줄을 다시 고른다).
- 같은 세계 설정 판: `tuning.save`가 `formulas: [{id, source | null}]`(40개까지)를 칸과 한 묶음으로 받는다(판 확인 → 바꾼 뒤 전체 검사 → 한 트랜잭션 → 스냅숏 바꿔 끼우기). 팩 식과 같은 글(앞뒤 빈칸 무시)·null은 되돌리기. 읽히지 않는 식은 `invalid_formula`(`data.details` = `코드@위치`), 없는 칸 `unknown_entry`, 같은 칸 두 번 `duplicate_entry`, 행 식이 1차 하나를 모든 행에서 빼면 `rules_conflict`(`stat_primary_unused`).
- 감사 기록은 같은 `tuning.apply`·`revert_all`·`pack_won`·`dropped` 줄에 `formulas` 칸(앞뒤 글·팩 식·까닭). 최근 바꿈(`tuning.history`)에 `formulas`. 서버 기록 `tuning change`에도.
- 켤 때 고르기(D-461 "가장 나중에 바꾼 것이 이긴다", 시작을 막지 않음): 칸이 없음 → `unknown_entry`, 저장 때 팩 식 ≠ 지금 팩 식 → 팩 이김, 새 변수로 읽히지 않음 → `invalid_formula`(새 까닭), 저장 차례로 얹다 규칙 문제 → `rules_conflict`. 칸 값을 먼저 고른 뒤 식을 얹는다.
- 실효 값: `TuningState.combatFormulas()`(스냅숏마다 한 번)는 서버의 전투 계수(밸런스 대결, 정원사 웨이브 `combatRules`)에, 행 식은 `statTable()`(유닛·사이보그 화면, 밸런스 기여·대결)에 든다. 행 식이 없는 행의 실효 글은 덮어쓴 가중치에서 만든다.
- 모두 되돌리기는 식 덮어쓰기도 지운다. `/health`·지표의 덮어쓴 칸 수에 식도 든다.
- 내보내기 차이에 선택 칸 `formulas: [{id, from, to}]`(from = 팩 식). `pnpm tuning:apply`가 `formulas.json` expression·`stat_rows.json` formula를 바꾸고(지금 팩 식 = from, 그 칸 변수로 읽히는 식만), 시뮬레이터 `--tuning`도 같은 차이를 얹는다. 옛 도구는 이 칸이 있는 차이를 형식 오류로 거절한다.

### 8. 화면 (밸런스 화면 안 "계산식" 탭)

## 이유
- 1: 결정성(엔진·기기와 무관한 같은 값)과 서버 권위가 이 프로젝트의 바닥이다. 정수 고정 소수점은 기존 ‰ 관례와 같고, 가중치(‰)·설정 칸(‰)을 정확히 담는다. 해석기는 400줄쯤이라 의존성을 들일 까닭이 없다.
- 가: 밸런스 화면(가중치 칸)과 계산식 탭이 같이 산다. 식이 없는 행은 가중치에서 만든 식을 보여 같은 것을 두 모양으로 보게 하고, 식을 저장하면 그 행만 식으로 넘어간다.
- ㄱ: 판·감사·켤 때 고르기·내보내기가 한 벌이다(D1의 꼬임 점검을 그대로 받는다). 값 모양만 달라 표만 나눴다.
- (i): 사용자가 고른 것은 맨손 규칙뿐이다. 무기 전투의 결과(시드 흐름)는 바꾸지 않는다.

- 판정: 공격 사양 `AttackProfile.unarmed`(맨손 자료일 때만 칸을 둔다 — 무기 사양·옛 스냅숏은 그대로)가 참이면 `realCritPm`·`realHitPm`이 맨손 칸을 쓴다(`packages/sim/src/combat/formula.ts`). 맨손 스킬 사양(타고난 무기·맨손 속성 자료)도 맨손 자료라 같은 규칙(질문 1254). 크리쳐 발톱(unarmed 없음)은 무기 틀 그대로.
