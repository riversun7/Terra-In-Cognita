## 선택지
### 덮어쓰기 모양
1. **항목 통째(JSON) 덮어쓰기, 새 표** — 실효 항목 = 팩 항목 위에 그 세계의 덮어쓰기 항목. 검사는 실효 팩 전체를 팩 검사기(`validatePack`)로.
2. 칸마다(경로 + 값) 덮어쓰기 — 부품 목록 더하기·빼기·차례를 경로로 적기 어렵고, 묶음 검사도 결국 항목을 다시 만들어야 한다.
3. `tuning_overrides`에 JSON 칸을 더함 — 판·감사·켤 때 고르기가 정수 칸과 섞여 두 화면이 서로 판 충돌을 낸다.

### 맨손 판정 자리
- 가. 사양을 만들 때 쓸 수 없는 스킬을 목록에서 뺀다 — 화면·AI는 맞지만 "명령을 거절"할 자리가 없다.
- 나. **사양에 든 무기의 칸 목록을 적고, 판정(`skillUsable`)이 AI·지속형·(앞으로의) 스킬 명령에서 거른다**.

## 결정
덮어쓰기는 1(통째, 새 표 둘), 맨손은 나.

### 1. 전투 규칙 고침 (D-490)
- **쉴드 재생은 맞는 중에도 일정하게 찬다.** `shieldRegenDelayMs`·`lastHitMs`를 없앴다(`packages/sim/src/combat/`). 팩 `n40_shield_regen_delay`를 지우고 `id-changes.json`에 `removed`(since 21, 보상 없음)로 뒤에 더했다. 세계에 남은 그 칸 덮어쓰기는 D1이 켤 때 `unknown_entry`로 지운다.
- **효과 사전 수치 `shield_regen`** (버프·디버프, ‰): 분당 쉴드 재생 × max(0, 1000 + 합 ‰) ÷ 1000(버림, −1000 이하면 멈춤, `effects.ts shieldRegenPerMinute`). 재생 단계가 쓴다. 지금 팩 스킬은 이것을 쓰지 않는다(콘텐츠는 그대로).
- **맨손은 스킬을 쓸 수 없다(맨손 스킬 제외).** 스킬 칸 둘을 더한다(팩 선택 칸, `formatVersion` 그대로):
  - `weaponField`: 필요한 무기 칸 `physical`·`elemental`·`any`. 없으면 기반(`base`)과 같은 칸. 피해를 주는 스킬은 기반과 같은 칸만(그 칸의 공격력으로 피해를 센다, 팩 검사). 피해 없는 스킬(회복·버프·디버프)은 `any`나 다른 칸도 된다.
  - `bareHand`: 참이면 맨손 스킬 — 무기 없이 쓰고, **든 무기와 상관없이 늘 유닛 종류의 타고난 무기(물리 기반)·맨손 속성 자료(속성 기반)로 센다**(든 무기의 옵션 계수는 붙지 않는다). `weaponField`와 같이 적지 않는다.
  - 판정: 사양(`CombatUnitSpec`)에 `weaponFields`(스킬에 쓸 든 무기의 칸 목록, 맨손이면 빈 목록)와 `bareHandAttack`(맨손 스킬 공격 사양)을 더한다. `skillUsable` = 맨손 스킬이거나 `weaponFields`에 필요한 칸이 있음(`any`면 칸 하나라도). AI(`pickSkill`)와 지속형(`applyPassives`)이 거른다. **지금 서버에 스킬 명령이 없다**(전투 명령은 이동·공격·퇴각, Verified: `battleTypes.ts Command`·`packages/protocol`). 스킬 명령이 생기면 같은 `skillUsable`로 거절한다. `weaponFields`가 없는 사양(시험 유닛·옛 스냅숏)은 모든 스킬을 쓴다(되돌림·복구 호환).
  - 맨손 = 무기 칸에 무기가 없음(`loadoutOf` `bareHanded`). 든 무기에 그 칸이 없으면 그 기반 스킬은 못 쓴다("맨손 자료로 셈"을 없앴다). 두 칸 무기·기본 공격 칸·옵션 계수 공용(D-466)은 그대로다.
- **유닛 종류 칸 `naturalWeaponIsWeapon`**(타고난 무기를 스킬용 무기로 치나, 팩 선택 칸): 데이터로 정한다. 적지 않으면 무기 칸이 없는 종류만 참(기술 기본값). 팩에 적은 값: **크리쳐 참(발톱·이빨로 물리 스킬을 씀), 사이보그·휴먼·안드로이드 거짓(맨손 = 맨손 스킬만)**. 참이면 무기 칸이 비어도 타고난 무기의 칸(물리, 있으면 속성)이 스킬용 무기 칸이다.

### 2. 저장: 팩 항목 통째 덮어쓰기
- 표 `content_overrides`(PK 분류·ID): `category`(`skills`·`items`·`unit_kinds`), `id`, `entry`(jsonb, 팩 파일 한 줄 모양), `pack_hash`(저장 때 팩 항목의 정규 JSON SHA-256, 팩에 없던 항목 = 편집기에서 만든 항목이면 null), `content_version`, `note`(0~200자), `updated_by`, `updated_at`. 표 `content_override_revision`(줄 하나, 판). 마이그레이션 하나, 더하기만. 표 정의는 `db/contentEditSchema.ts`(schema.ts가 다시 내보냄, 파일 크기 상한).
- 실효 항목 = 팩 항목(파일 차례)에 덮어쓰기를 바꿔 넣고, 팩에 없는 ID는 분류 끝에 ID 차례로 붙인다. 끄기 = `enabled: false` 항목, 지우기 = 만든 항목의 덮어쓰기를 지움, 되돌리기 = 덮어쓰기를 지움(팩 항목). 팩 항목과 같은 내용이면 덮어쓰기를 두지 않는다.
- 묶음 검사: 묶음을 얹은 **실효 팩 전체를 팩 검사기**(스키마·참조·ID 변경표)로 본다(약 8~20ms, Verified: 개발 컨테이너). 하나라도 틀리면 묶음 전체를 받지 않는다(`invalid_entry` + `data.details` 팩 검사 문제 줄). 그 밖: `retired_id`(한 번 쓰고 지운 ID), `duplicate_entry`, `unknown_entry`(소모를 바꿀 무기 칸이 없음), `invalid_note`, jsonb가 못 담는 글자.
- 쓰기·판·감사는 D1과 같은 결이다: 한 프로세스 안 차례(`serial`) → 판 확인 → 검사 → 트랜잭션(판 조건부 +1·덮어쓰기·감사 `content.apply`, 앞뒤 항목 통째) → 스냅숏 바꿔 끼우기 → 서버 기록 `content change`. 판은 D1(`tuning_revision`)과 따로 센다(두 화면이 서로 판 충돌을 내지 않게).
- **켤 때(가장 나중에 바꾼 것이 이긴다, D-461)**: 저장 때 팩 해시 = 지금 해시 → 덮어쓰기가 든다. 다르면(저장 뒤 배포가 그 항목을 바꿈) 또는 저장 때 팩에 없던 항목이 팩에 생겼으면 → **팩이 이김**(지우고 감사 `content.pack_won`). 저장 때 팩에 있던 항목이 새 팩에서 빠졌으면 `unknown_entry`, 검사에 걸리면(한꺼번에 안 맞으면 저장 차례로 하나씩 얹어) `invalid_entry`로 지우고 `content.dropped`. **시작은 막지 않는다**(정리·고르기가 실패해도 팩 항목으로 돈다).
- **켤 때 잠재우기, 지우지 않음**(아이템 편집기 설계안 `docs/research/2026-11-01-item-editor-design.md` 4.5 WP-0 a): 줄의 판(`content_version` `core@N`)이 지금 팩보다 새로우면(팩 ID가 같고 N이 크다 = 되돌림 배포로 옛 앱이 켜짐) 먼저 이 규칙을 본다.
  - 지금 팩에 그 항목이 있고 해시가 저장 때와 다르면 → 팩이 이긴다(되돌림 배포가 그 항목을 바꿨다, 위와 같다).
  - 그 밖(만든 항목, 해시가 같은 고친 항목, 지금 팩에 없는 항목)은 검사를 통과하면 쓰고, 못 통과하면(새 칸·새 참조 등) **지우지 않고 잠재운다**: 적용하지 않고 DB에 두며 감사 `content.slept`(까닭 `newer_pack`)와 서버 기록 `content overrides`의 `slept`를 남긴다. 이 판이 모르는 분류의 줄(새 판이 더한 분류)도 읽지도 지우지도 않고 `content.slept`(까닭 `unknown_category`)로 적는다. 지울 줄이 없으면 판을 올리지 않는다.
  - 그 판(N+1)을 다시 켜면 잠든 줄을 보통 규칙으로 다시 고른다 → 해시가 같으니 다시 든다. **자동으로 다시 드는 것은 되돌림이 그 팩 항목을 바꾸지 않은 줄뿐**(만든 항목, 해시가 같은 고친 항목)이다. 되돌림이 바꾼 항목은 D1처럼 팩이 이기고, 화면에서 다시 담아야 되살아난다.
  - 옛 판에서 잠든 줄과 같은 키를 다시 저장하면 그 판으로 덮어써 깨어난다(옛 판 내용). 판이 같거나 옛것인 줄은 위 규칙 그대로다.
  - 시험: `contentEdit/contentEditBoot.db.test.ts`(N+1 세 줄이 N에서 남고 적용되지 않음, N+1을 다시 켜면 다시 듦, N+1에서 바뀐 팩 항목은 N에서 팩이 이김).
- **꺼진 참조 거르기**(같은 설계안 WP-0 b): 전투 자료 변환(`@terra/sim` `combatCatalogFrom`, 서버·시뮬 실행 도구가 같이 쓴다)은 켜진 장비가 가리키는 꺼졌거나 없는 스킬 ID와, 켜진 스킬이 가리키는 꺼졌거나 없는 효과 줄을 뺀다. 편집기로 `fire_bolt`를 끄면 정원사 웨이브(시험 지팡이)가, `flame_burst`를 끄면 다시보기 시범(불 지팡이)이 사양을 만들다 던지던 것을 막는다. 뺀 참조는 스냅숏마다 서버 기록 한 줄(`content references dropped`, `droppedReferences`). 지금 팩에는 꺼진 것이 없어 시뮬 요약이 바이트까지 같다. 시험: `packages/sim/src/combat/catalog.test.ts`(장비 → 스킬, 스킬 → 효과).
- `/health`에 `contentOverrides`(덮어쓴 항목 수)·`contentRevision`.

### 3. 바로 듦(D-461)과 읽는 곳
- 접근자 `ContentEditState.effective()`(스냅숏마다 같은 객체). 유닛·사이보그 화면 자료(`rosterCatalogOf`)의 `combat`·`names`·`baseValue`가 읽을 때마다 접근자를 부르고, 실효 항목이나 가중치 표가 바뀌면 묶음을 새로 만든다. 정원사 웨이브 전투(NPC 런타임·전투 서비스)는 전투를 열 때마다 `combatCatalog()`를 부른다(켤 때 받아 두지 않는다). 밸런스 화면도 같은 `roster.combat`를 읽는다.
- 진행 중인 전투: 전투는 시작·참전 명령 순간의 사양(`BattleInit`)으로 돈다 → 바꿔도 진행 중인 전투는 그대로, 다음 전투부터 든다(밸런스 화면 꼬임 점검과 같은 결).

### 4. 화면 `/dev/skills`
- 주소 줄 `dev_skills`(부모 `dev`, 틀 있음, dev·admin), 개발자 홈 도구 줄. 촘촘, 모바일 먼저, 토큰만. 조각 `SkillEditorScreen-*`, 미리 캐시에서 뺀다(`DEV_ONLY_CHUNK` `[Ss]killEditor`, `DEV_ONLY_SOURCE` `src/editor/skills/`, `globIgnores`).
- 칸 [스킬]: 목록(찾기 ID·이름, 거르기 전체·고침·새로 만듦·꺼짐, [새 스킬] ID 입력) + 한 스킬의 모든 칸: 이름 ko·en·설명·켜기 / 기반·피해 종류·필요한 무기 칸·맨손 스킬 / 모양·발동·대상·사거리·반지름·연쇄(대상 수·튐 거리·배율) / 자원·소모·시전·쿨 / 공식 부품(공격 배율·무기 공격력·속성 계수 12칸·관통·고정 피해·회복·쉴드) / 조건 / 특수 효과(효과 사전에서 골라 확률·지속·세기) / 등급 배율 1~10. 모양을 바꾸면 판정 칸을 그 모양에 맞춘다(팩 검사 규칙과 같다). [저장]·[편집 취소]·[복제](빈 ID `<ID>_copy`)·[끄기/켜기]·[팩 값으로]·[지우기](확인).
- 칸 [행동별 소모](D-491): 걷기·퇴각 이동(무료, D-418), 무기 아이템마다 기본 공격 스태미나·MP(MP는 기본 공격 칸이 속성일 때만 든다), 유닛 종류마다 맨손(타고난 무기) 기본 공격, 건물 공격(기본 공격 값을 씀), **회피 기동(미구현)**, 스킬마다 자원·소모. 줄마다 [적용]이 바로 보낸다. 실제 소모 배율(STA 점수 N13 식)은 설정 칸 쪽이고 이 화면은 기본값만 바꾼다(`work/formulas`가 식을 연다).
- [내보내기]는 `tuning.export`(D1 차이에 `entries` 칸을 더함). 최근 바꿈(감사 기록 30줄).

### 5. 내보내기 → 팩
- 차이 형식(`terra-tuning-diff` 판 1)에 선택 칸 `entries: [{ category, id, from, entry }]`(`from` = 내보낼 때의 팩 항목 해시, 만든 항목이면 null). 덮어쓰기가 없으면 칸을 넣지 않는다(옛 모양 그대로).
- `pnpm tuning:apply`가 분류 파일의 그 항목을 통째로 바꾸거나(지금 팩 항목 해시 = `from`, 아니면 건너뜀·`--force`) 끝에 붙인다(`from` = null이고 팩에 없음). 항목 모양은 그 분류 스키마로 보고(틀리면 건너뜀), 판은 한 번 올린다. 함수는 `@terra/content/node` `applyEntriesDiff`·`hashEntry`(해시라 Node 전용 부분). 시뮬레이터 `--tuning`은 이 칸을 아직 얹지 않는다(TODO).

### 6. 권한·tRPC `skills.*`
- `list`(조회)·`history`(조회)·`save`(쓰기, `{expectedRevision, changes: [put_skill | revert | set_cost], note?}` 1~100개). 권한·속도 제한은 D1 그대로(`tuning:read`·`tuning:write` 두 겹 + 사용자별 제한기). 스킬 항목 입력은 객체·ID만 보고 칸 규칙은 서버가 팩 스키마로 본다(검사기 하나).

## 이유
- 통째 덮어쓰기: 편집기가 스킬 하나를 한 번에 저장하고, 검사·내보내기·켤 때 고르기가 "항목 하나"로 한 벌이다. 팩 검사기를 그대로 쓰니 팩 규칙(모양·참조·ID 다시 쓰기)이 편집기에도 똑같이 든다.
- 저장 때 팩 해시로 "가장 나중에 바꾼 것" 판정: D1의 `pack_value`와 같은 결이고, 켤 때 오류가 날 길이 없다.
- 맨손 판정을 사양 칸 + 판정 함수로: 스킬 명령이 생겨도 같은 함수로 거절하고, 화면이 "왜 못 쓰나"를 보일 수 있다. 옛 사양은 그대로 돈다.
- `naturalWeaponIsWeapon` 기본값(크리쳐 참·사람형 거짓): 크리쳐는 무기 칸이 없어(D-422) 거짓이면 스킬을 하나도 못 쓴다. 사람형 맨손은 사용자 원문 "맨손은 스킬을 쓸수없다"다. 데이터 칸이라 편집·팩으로 바꾼다(묻지 않음, 사용자 지시).

## 결과
- 좋은 점: 스킬·무기·유닛 종류를 재배포 없이 고치고 바로 든다(유닛 화면·정원사 웨이브·밸런스 화면). 누가·언제·무엇을(앞뒤 항목) 감사 기록에 남고 한 명령으로 팩에 넣는다. 쉴드 저주를 콘텐츠로 만들 수 있다. 맨손 유닛이 스킬을 쓰지 않는다.
- 시뮬레이터(war16 30일, stub16·econ16 180일, 시드 1, 두 번씩, 위반 0): 시뮬 유닛은 늘 칼(물리 칸)을 들고 물리 기반 스킬 셋(강타·쇠 피부·응급 처치)을 써서 war16·stub16의 하루·전투 줄은 그대로다. econ16은 정원사 웨이브의 마법형 크리쳐(같은 스킬 셋에 무기만 지팡이 = 속성 칸만)가 물리 기반 스킬을 더는 쓰지 않아 웨이브 전투 줄부터 달라진다(Verified: 처음 다른 줄 = 13일 웨이브 전투 틱 750 → 700). 같은 입력의 결과가 바뀌므로 `SIM_VERSION` 4 → 5(작업 기록에 줄 해시·지표). 마법형 크리쳐에 지팡이 스킬을 줄지는 시뮬 [임시] 장비의 일이다(`work/battle-lab` 프리셋과 같이).
- 감수할 점: 세계가 팩과 다른 항목으로 돌 수 있다(`/health`가 보인다). 팩 항목이 바뀌면 그 항목의 세계 덮어쓰기는 통째로 진다(칸 하나만 바꿨어도). 판은 화면 둘(D1·스킬)이 따로라 서로 충돌하지 않지만 묶음 하나에 섞을 수 없다. 스킬 명령이 없어 "명령 거절"은 함수만 있다. 시뮬레이터 `--tuning`이 `entries`를 아직 얹지 않는다.
- 다시 볼 조건: 스킬 명령(유저 개입)이 생길 때(`skillUsable`로 거절), 크리쳐 에디터(D-5024)가 생길 때(`naturalWeaponIsWeapon`·타고난 무기를 그쪽으로), 회피 기동이 생길 때(행동별 소모 표에 값 칸).
