# 화면 가시성: 톤은 그림에, 화면은 옛 프로젝트처럼 더 보이게 · 스탯 색 · 정거장 네온 테마

- 상태: 확정 (사용자 결정 2026-11-01 · 기획 D-448·D-454, 구현 가지 `work/cyborg-ui`) (일부 대체됨: 2026-11-01-cyborg-sheet-old-look.md — 사이보그 화면의 상세 전투 스펙·핵심 사양 모양(옛 프로젝트 그대로), 2차 스탯 색 `--color-sec-*`)
- 날짜: 2026-11-01
- 관련: ADR `2026-10-28-design-system.md`(디자인 시스템, 일부 바뀜 → 이 ADR), `2026-10-29-app-shell.md`(37, 첫 화면 JS 상한 11절), `2026-11-01-first-login-cyborg.md`(첫 접속·2D 사이보그 그림), 기획 D-064·D-070·D-414·D-417·D-448·D-449·D-450·D-451·D-454, 48 §3.1·§3.2, 질문 `docs/questions/2026-11-01-cyborg-ui.md`(181~183), AGENTS.md 8장

## 배경
- 사용자(2026-11-01, 휴대폰으로 첫 접속을 써 본 뒤, 원문): "사이보그 생성시 스탯 배치 오류. 힘 체력은 같은 계열인데 너무 떨어져있다 / 사이보그 스탯창이 이전 /chracter 페이지에 비해 매우 빈약하다 / 스탯은 두쌍씩 묶이며 고유 색상이 있다 / 캐릭터도 너무 허접하다 톤앤매너는 맵구현이나 캐릭터등 이미지에 한정되고 ui에는 이전 프로젝트처럼 더 가시적이게 가도 좋다 너무 톤을 헤치지는 않고."
- 같은 날 덧붙임(원문): "테마 중에 선명은 일단 더 만들지말고, 정거장은 기존프로젝트처럼 고대비 모드로 sf나 네온사인색처럼 선명한 테마로 해달라".
- 지금(Verified: main `7671c05`): 디자인 시스템(후보 A "새싹 장난감")이 그림과 화면 모두에 같은 부드러운 톤을 쓴다. 초기 스탯은 D-414 차례(STR·DEX·AGI·VIT·INT·WIS)를 두 열로 놓아 힘과 체력이 멀다. `/cyborg`는 숫자 3열 + 2차 스탯 목록뿐이고, 2D 그림은 원·선 몇 개다. 정거장 테마는 청록 홀로그램이다.
- 옛 프로젝트(AntiGravt01 `terra-client/src/app/character/page.tsx`·`components/character/CyborgProfile.tsx`·`StatBar.tsx`·`SecondaryStatsCard.tsx`, 읽기만 함): 스탯 두 개씩·고유 색(STR 진홍·VIT 주황빨강·INT 파랑·WIS 보라·DEX 호박·AGI 초록), 빛나는 큰 로봇 얼굴, 인공장기·장비 칸 격자, "상세 전투 스펙"(줄마다 막대 + 누르면 "공식 … | 캡 …"·입력·결과), "핵심 사양"(출처별 쌓은 막대). 테마 Magitech Dark: 바탕 `#030308`, 네온 시안 `#00f0ff`, 네온 보라 `#bc13fe`, 금 `#ffb800`.

## 선택지
1. 톤을 화면 전체에 그대로 둔다(지금).
2. 톤은 그림(지도·캐릭터)에만, 화면은 수·색·칸을 더 보인다(디자인 시스템 토큰 규칙은 그대로).
3. 옛 프로젝트 화면을 그대로 옮긴다(Tailwind·framer-motion 등, 새 런타임 의존성).

## 결정
선택지 2.

### 톤과 화면
- 디자인 시스템 톤(ADR `2026-10-28-design-system.md`, D-064 스타일라이즈드 파스텔)은 **그림**에 적용한다: 지도, 캐릭터·유닛 그림, 아이콘. 그림은 둥글고 부드럽되 다듬는다(명암·광택·빛).
- **화면(UI)은 옛 프로젝트처럼 더 가시적으로** 간다(D-448): 빽빽한 수, 색 막대, 누르면 펼치는 공식 풀이, 더 강한 포인트 색. 톤을 크게 해치지 않는다(같은 글꼴·모서리·간격 단계).
- 화면 CSS는 그대로 `apps/game/src/styles/tokens.css`의 `var(--…)`만 쓴다(`pnpm check:contrast`). 새 런타임 의존성은 없다.
- 색만으로 뜻을 전하지 않는다: 스탯은 약자·이름을 늘 함께 쓴다.

### 스탯 묶음과 색(D-448, 질문 181 가)
- 화면 차례 = STR·VIT, INT·WIS, DEX·AGI(두 칸씩 한 판, 묶음 이름 없음). `@terra/shared/roster` `PRIMARY_STATS`·`PRIMARY_STAT_PAIRS`. 판정 코드의 차례(`RULE_STAT_ORDER`, 가중치 열)는 그대로다.
- 스탯 색 토큰 `--color-stat-{str,vit,int,wis,dex,agi}`(테마 넷마다). 바탕·판·둘째 판 위 글자 4.5:1을 대비 검사가 잰다(`scripts/design-tokens.mjs`).

  | 테마 | STR | VIT | INT | WIS | DEX | AGI |
  |---|---|---|---|---|---|---|
  | 파스텔 | `#c0233e` | `#b23f0a` | `#1f5bc4` | `#7a3fc8` | `#8a5a00` | `#1a7236` |
  | 다크 | `#ff8fa2` | `#ffa36e` | `#8cb9ff` | `#c9a8ff` | `#f5c665` | `#7fdc97` |
  | 선명 | `#a3102b` | `#9e3300` | `#0b4fb3` | `#5a1fb0` | `#6f4500` | `#11602b` |
  | 정거장(네온) | `#ff4f6e` | `#ff8f3f` | `#40b9ff` | `#c770ff` | `#ffc933` | `#3dff9e` |

- 쓰는 곳: 첫 접속 초기 스탯·강하 요약, 사이보그 화면 핵심 사양, 유닛 상세(공용 부품 `apps/game/src/roster/StatPairs.tsx`), 전투 스펙 풀이의 항·막대.

### 사이보그 화면(옛 /character 기준, 우리 규칙에 있는 자료만)
- 머리 판: 큰 그림(포인트 색 빛 고리) + 인공장기·장비 칸(팩 `unit_kinds` 칸) + 경험치·피로·신앙도.
- 핵심 사양: 스탯 묶음 + 막대. 평소 두 칸(몸 값 = 처음 값 + 레벨 성장, 장비·인공장기 보너스). 만렙이면 서버가 처음 값·K(‰)를 보내고 세 칸(처음 값·레벨 성장·장비) + 스탯마다 "K 0.97"(D-449: K는 환생 시설·생명공학 시설·만렙에서만, 표시 형식은 기술 기본안 = 값). "투자" 칸은 없다(D-024 자유 포인트 없음).
- 상세 전투 스펙: 48 §3.2 묶음(생존·공격·정확·속도·자원)과 §3.3 활동. 줄마다 막대(양 모양 = 기본·스탯 항·장비 몫, 확률 모양 = 상한까지의 몫)와 누르면 풀이(공식, 상한·반감 상수, 1차 × 가중치 항, 가중합·내림, 장비, 확률 곡선, 결과). 풀이는 서버가 팩 `stat_rows` 식으로 계산해 보낸다(`@terra/sim` `explainSecondary` — 값은 `computeSecondary`와 같다는 시험이 있다). 기기는 다시 계산하지 않는다.
- 스킬 칸(팩 `skillSlots`: 처음 + 환생마다, 최대 — 닫힌 칸이 열리는 환생 횟수는 서버가 센다), 속성 12칸(6계열 × 기본·강화, 서버 값. 출처 D-450, 저장·규칙은 다음 줄기), 인벤토리·환생(신앙도는 문턱 "50 이상", D-451)·랭킹, 상태 줄.

### 사이보그 그림
- SVG 하나(`apps/game/src/cyborg/CyborgAvatar.tsx`), 저장된 부위·색 ID로 그린다(ID·목록은 그대로). 껍데기 명암 그라데이션, 광택, 짙은 얼굴 화면 위 빛나는 바이저·눈(빛 필터), 관절·리벳, 바닥 그림자. 칠 색은 세계 색(테마와 상관없음), 바깥 테두리만 화면 글자 색. 첫 접속 외형 단계·사이보그 화면이 같이 쓴다. 위 띠 얼굴은 그대로 둔다(첫 화면 JS 상한, 아래 결과).

### 테마
- **정거장 = 네온 SF 테마**(사용자 결정 2026-11-01, 기획 D-454): 거의 검은 바탕 `#05050c`(주소창 색도), 판 `#0e0e1c`·`#17172b`, 주색 네온 시안 `#00f0ff`, 포인트 네온 자홍(초점 `#ff5cf4`)·보라(빛 `#bc13fe`)·호박(`#ffb800`·`#ffc233`)·초록(`#3dff9e`), 위험 `#ff5c8a`. 판에 시안 가는 테두리 + 보라 빛, 조작부·제목에 시안 빛(`--shadow-*` 토큰). 흐림 효과·움직임·새 글꼴은 없다. 모든 쌍이 대비 검사를 통과한다.
- **선명은 지금 그대로 둔다**(사용자 결정 2026-11-01 "일단 더 만들지말고", D-454): 새 작업 없음. 대비 검사 통과와 "기기 설정에 맞추기"(고대비 요청이면 선명)는 그대로다.
- 사진은 기본 둘(파스텔·다크)에 정거장을 더한다(이 작업). 선명은 자동 검사로만 지킨다.

## 이유
- 사용자 결정(위 원문)과 기획 D-448이 톤의 범위를 그림으로 좁혔다. 토큰 규칙을 지키면 테마 넷·대비 검사가 그대로 돈다(Verified: `pnpm check:contrast` 테마 4개 대비 쌍 통과).
- 옛 프로젝트 차례·색은 사용자가 익숙한 배치다(질문 181 가 → D-448).
- 풀이를 서버가 만드는 까닭: 게임 앱은 판정 코드(`packages/sim`)를 가져오지 않는다(AGENTS 4장). 같은 함수 옆에 풀이 함수를 두고 값이 같다는 시험으로 묶었다.
- 처음 값·K를 평소 숨기는 까닭: 처음 값과 레벨 성장을 나눠 보이면 K를 거의 계산할 수 있다(성장 ÷ (처음 값 × 성장률 × (Lv − 1))). D-449가 보이는 곳을 셋으로 정했다.
- 정거장을 네온으로: 옛 프로젝트 Magitech Dark가 사용자가 원하는 "SF·네온사인" 모양이다. 기본 톤(파스텔·다크)은 그대로라 새싹 장난감 디자인은 남는다.

## 결과
- 좋은 점: 스탯·전투 수치가 한눈에 보이고, 공식이 화면에서 바로 풀린다. 스탯 색이 첫 접속·사이보그·유닛에서 같다.
- 첫 화면 JS: 그림과 새 화면 코드는 지연 조각(`/start`·`/cyborg`·`/units`)에만 있다(Verified: `pnpm check:bundle`, 작업 기록). 위 띠 얼굴을 새 그림으로 바꾸면 그림 코드가 첫 화면에 들어가 상한(남음 약 400B)을 넘을 수 있어 미뤘다.
- 감수할 점: 화면이 빽빽해졌다. 좁은 폭(390px)에서 긴 영어 스탯 이름은 말줄임(…)으로 자른다(약자가 늘 보인다).
- 다시 볼 조건: 3D 캐릭터가 생기면(그림 → 모델), 환생 시설·생명공학 시설 화면이 생기면(K 세 칸 막대를 거기서도), 속성값 저장(D-450)이 들어오면(속성 판의 눈금이 찬다).
