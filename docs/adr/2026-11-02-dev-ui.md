# 개발·운영 화면 UI: 게임과 따로 둔 촘촘한 개발 화면 층, 테마는 네온 다크·라이트 둘

- 상태: 확정 (사용자 결정 2026-11-01, 구현 가지 `work/dev-ui`)
- 날짜: 2026-11-02
- 관련: ADR `2026-10-28-design-system.md`(디자인 시스템, 일부 바뀜 → 이 ADR), `2026-11-01-ui-visibility.md`(정거장 네온 SF 테마 D-454), `2026-10-29-app-shell.md`(틀·누르는 곳 크기 10절), `2026-11-01-dev-settings-panel.md`(설정 칸 패널), AGENTS.md 8장

## 배경
- 사용자(2026-11-01, 원문): "개발자 페이지 UI는 게임과 별도로 개발자 친화적으로 만들어라 일단 글자가 너무 커서 데이터가 많으면 가독성이 매우 떨어진다. 버튼이나 슬라이드바 등이 쓸데없이 크게 차지한다. 그리고 개발운영은 네온다크(기본)/라이트모드만으로 빠르게 진행한다."
- 예: 설정 칸 패널(`/dev/tuning`)은 칸 하나가 큰 카드(큰 제목, 큰 "지금 10,000 팩 10,000" 줄, 가득 찬 범위 막대, 큰 [바꾸기])라서 1440×900 화면에 7칸만 보였다(Verified: 바꾸기 전 화면에서 잼).
- 개발·관리자 화면은 게임 디자인 시스템(새싹 장난감: 본문 16px, 조작부 52·44px, 턱 있는 버튼, 알약 고르기)을 그대로 썼다. 게임 화면에는 맞지만 표·숫자가 많은 도구 화면에서는 한 화면에 보이는 양이 너무 적다.

## 선택지
1. 화면마다 CSS를 줄인다 — 화면이 열 개가 넘고, 새 도구마다 다시 줄여야 한다.
2. 게임 테마를 하나 더 만든다(설정 화면에서 고름) — 게임 화면까지 바뀌고, 개발자가 아닌 사람에게 보인다.
3. **개발 화면 층**: 개발·관리자 주소일 때만 `<html>`에 표시를 붙이고, 같은 이름의 토큰(글자·간격·조작부·색)을 그 표시 아래에서 다시 정한다. 게임 테마 설정과 상관없이 테마는 둘(네온 다크·라이트).

## 결정
3번.

### 층과 테마
- 틀(`shell/Shell.tsx`)이 개발·관리자 주소(`/dev`, `/dev/…`, `/admin`, `shell/devSurface.ts` `isDevSurfaceRoute`)를 그리는 동안 `<html data-surface="dev" data-dev-theme="neon|light">`를 붙인다. 그리기 전에(useLayoutEffect) 붙여서 게임 테마로 잠깐 그려지지 않게 한다. 떠나면 뗀다.
- 테마는 둘: **네온 다크(기본)** — 정거장(D-454) 계열 색을 촘촘한 화면에 맞게 덜 번지게(격자 바탕·빛 번짐 없음). **라이트** — 밝은 회색 바탕, 흰 판, 파랑 주색, 자홍 초점.
- 개발 화면은 게임 테마 설정(파스텔·다크·선명·정거장)을 보지 않는다. 게임 화면은 그대로다.
- 바꾸기: 틀 위 띠의 [라이트 모드] 단추(`aria-pressed`). 고른 값은 이 기기에만 둔다(`localStorage` `terra.devTheme`, 읽기·쓰기는 try/catch, 못 쓰면 이번 실행 동안만 기억하고 기본 네온으로 그린다). 틀을 숨긴 개발 화면(행성·항성계 편집기, 2차맵 시험, 전투 다시보기)은 단추가 없고 고른 값을 따른다.

### 촘촘함 규칙(토큰, `styles/tokens.css` "개발 화면 층")
- 글자: 본문 13px, 보조 12px, 작은 글 11px(rem). 제목도 본문 글꼴(Jua 안 씀). ID·코드·숫자는 고정폭(`--font-mono`), 숫자는 늘 자리 맞춤(tabular-nums).
- 간격: 4px 단위 → 2px 단위(`--space-1` 2px … `--space-12` 24px). 줄 높이 28px(`--dev-row-h`), 얇은 테두리 1px, 모서리 2~4px, 턱 0.
- 조작부: 높이 26px·작은 것 24px, 누르는 곳 최소 24px(`--tap-size` = WCAG 2.2 2.5.8 최소). 터치 기기(`pointer: coarse`)는 입력칸 16px(iOS 확대 막기)·조작부 32px·누르는 곳 30px·줄 32px.
- 버튼은 기본이 보조 모양(둘째 판 색), 주 동작만 `.button-primary` 하나. 버튼은 늘이지 않는다(글자 폭).
- 카드보다 표·줄: 공용 표 `.dev-table`(고정 머리 = 위 띠 아래, 줄무늬·올림, 숫자 오른쪽 맞춤), 좁은 폭은 표만 상자 안에서 가로로 민다(화면은 밀리지 않는다). 범위 막대 같은 그림은 작게 줄 안에(`--dev-range-w`), 슬라이더는 값을 보는 데 도움이 될 때만.
- 데스크톱 먼저. 390px에서도 쓸 수 있게(가로 넘침 없음, 누르는 곳 검사 통과).
- 기본 부품(버튼·입력·고르기·판·제목·알림)의 개발용 모양은 `styles/dev.css`(`:where(:root[data-surface="dev"])`, 기본 부품보다 뒤에 불러와 같은 우선순위에서 이기고 화면 CSS에는 진다).

### 색 검사
- 개발 화면 층의 색 블록 둘은 게임 테마의 색·그림자 토큰을 **모두** 다시 정한다(빠지면 고른 게임 테마 값이 새어 든다). `pnpm check:contrast`가 빠진 토큰을 막고(`devThemeGaps`), 테마 4개와 같은 쌍 + 개발 전용 쌍(표 머리·줄무늬·올림·고른 줄 바탕 위 글자, 코드 글자색)을 두 테마에서 잰다.

### 범위
- 개발자 홈, 설정 칸 패널(촘촘한 표로 다시 짬: 코드 · 이름·ID · 표지 · 지금 · 팩 · 범위 · 새 값 + [담기] · 되돌리기), 밸런스(전투 실험실·가중치 표·계산식), 스킬 편집기(두 탭), 아이템 편집기(공용 층·`editor/content/contentEditor*`만. 아이템 전용 파일은 다른 가지가 고치는 중), 전투 다시보기, 2차맵 시험, 행성 편집기, 항성계 편집기, 셰이더 측정, 관리자(사용자 = 표 한 줄).
- 동작은 그대로다(모양만). 예외 하나: 설정 칸 패널은 [바꾸기]로 값 칸을 펼치던 단계를 없애고 새 값 칸을 줄마다 늘 보인다(사용자가 요청한 표 모양: "current input"). 담기·적용(한 묶음)·확인 창·되돌리기는 같다.

## 이유
- 토큰 이름을 그대로 두고 값만 바꾸면 화면 CSS를 거의 고치지 않고 모든 개발 화면이 한 번에 촘촘해진다(Verified: 토큰만 바꾼 상태에서 설정 칸 패널 1440 화면 7칸 → 10칸, 스킬 목록 줄 높이 약 43px).
- 게임 테마와 떼면 게임 쪽 결정(새싹 장난감, 기본 두 테마 사진)을 건드리지 않는다. 테마 둘만 두면 사진·검사 양이 준다(사용자: "빠르게 진행").
- 누르는 곳 크기: e2e 도우미(`e2e/helpers/screen.ts` `smallTapTargets`)는 문서 뿌리의 `--tap-size`를 읽는다. 개발 화면 층은 24px(터치 30px)를 기준으로 같은 검사를 그대로 돈다.

## 결과
- 좋은 점: 표·숫자가 많은 화면에서 한 화면에 보이는 양이 늘었다(설정 칸 패널 1440 화면 7칸 → 25칸, 스킬 행동별 소모 13 → 25줄, 가중치 표 15 → 26줄, 수치는 작업 기록 `docs/worklog/2026/11/02-0930-dev-ui.md`).
- 감수할 점: 개발 화면 위 띠·사이드 메뉴도 개발 화면 층 크기로 작아진다(틀은 하나). 틀을 숨긴 개발 화면에는 테마 단추가 없다.
- 개발 화면 사진은 게임 테마 대신 개발 테마 둘(네온·라이트)로 찍는다(e2e `devTheme` 선택). 이 층 밖(게임) 화면 사진 규칙은 그대로(기본 두 테마).
- 새 개발 도구는 `.dev-table`·`--dev-*` 토큰·작은 버튼으로 바로 만든다. 다시 볼 조건: 태블릿·휴대폰에서 개발 도구를 자주 쓰게 되면 터치 크기(`pointer: coarse` 값)를 다시 본다.
