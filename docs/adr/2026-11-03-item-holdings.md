## 배경
- 아이템 편집기(ADR `2026-11-01-item-editor.md`)가 정한 규칙 가운데 285 소급·286 실제로 쓰기·287 전투 중 사용·288 썩기·289 닳기와 D-497 탄약, D-501 효과 교체는 "보유 물건(인스턴스)이 생긴 뒤"로 미뤄져 있었다. 서버에는 가진 물건 표가 없었다(사이보그 화면 인벤토리·장비는 빈 값).
- 옛 프로젝트는 `user_items`(+ `instance_properties`)·`user_equipments`(내구도)로 같은 일을 했다(대조 문서 2장). 기획은 285·286·288·289를 옛 규칙으로 답했다(49 N49, 원본 `3b0e949`, 미러 `80272e5`). 이어서 사용자가 탄약 보충과 물약 쿨을 정했다(D-509, 원본 `1c449b9`, 미러 `662b63f`): "재료로 내구도 회복. 최대내구도 점차 감소", "전투비전투 무관하게, 포션 30초쿨로 통일. 스태미나감소는 없음". 이어서 요리 = 5분 쿨, 물약 고르기 = "HP 문턱 + 알맞은 물약"(D-510, 미러 `f530fbd`).

## 결정
### 1. 모양 (`@terra/sim` `items/holding.ts` `holdingKindOf`)
- 장비(대분류 equipment) = instance: 하나하나, 수량 1(D-5003 스택 1). 신선도(`perish`)가 있으면 lot: 같은 숙성 상태끼리만 쌓인다(D-285·D-289 기술 제안 "창고 안 식품 묶음은 (종류, 신선도 기준 시각)으로"). 사용 효과(`use`)만 있으면 stack: 같은 것끼리 쌓인다(D-496 286). 한 칸 상한 = 팩 `stackMax`(없으면 1,000,000, 장비는 1).
- 그 밖(원자재·가공품 등 쌓이는 물자)은 표에 두지 않는다(`not_holdable`): 원장 위치 계정이다(경제 ADR 3절). 서버 물자 거래소가 열리면 거래소 입고 = 보유 칸 → 원장 에스크로(식품은 포장, 신선도 최대 D-289), 출고 = 새 묶음으로 잇는다(그 줄기에서).

### 2. 표 (`apps/server/src/db/holdingsSchema.ts`, 마이그레이션 `20261103035624_item_holdings` — 표 더하기만)
- `item_holdings`: `id`(서버가 정함), `owner_id` → `world_owners`, `item_id`, `location`(원장 위치와 같은 뜻: 음수 = −유닛 ID [임시], 양수 = 창고 위치), `slot`(입은 칸 번호, 유닛이 들 때만), `quantity`(≥ 1), `stats` jsonb(굴린 [{stat, value, pm}]), `score_pm`(D-5006 등급 점수, 만든 직후), `durability`·`max_durability`(장비 정의에 최대 내구도가 있을 때만, 검사 0 ≤ 내구도 ≤ 최대), `aged_ms`·`aged_at_ms`(신선도 묶음), `created_at_ms`, `source`(dev_grant·spoil 등). 검사 조건과 주인·위치 색인.
- `unit_effects`: (`unit_id`, `effect_id`) 한 줄, `value`, `until_ms`(실제 시간), `exclusive`(배타 묶음), `item_id`. 유닛 행은 옛 시험 2차맵 정리가 지울 수 있어 외래 키를 두지 않는다(사이보그 `unit_id`와 같다).
- `unit_cooldowns`: (`unit_id`, `kind`) 한 줄, `until_ms`. kind = potion(D-509 물약 쿨 30초) · food(D-510 요리 쿨 5분). 끝난 줄은 서버가 지운다. 외래 키 없음(위와 같은 까닭).
- 쓰기는 월드 쓰기 대기열 하나(표 `holdings`·`unitEffects`·`unitCooldowns`, 쓰는 차례는 사이보그 다음·거래 앞). 부팅 때 `loadHoldings`가 읽는다. 직전 판 앱은 이 표를 모른 채 그대로 돈다.

### 3. 판정 (`@terra/sim` `items/holding.ts`, 정수·시드 난수만)
- 굴림(옛 `rollInstanceProperties`): 스탯마다 [최소, 최대] 균등 정수(최대 포함, sim `rollItem`과 같은 굴림), 자리 ‰ = ⌊(값 − 최소) × 1000 ÷ (최대 − 최소)⌋, 범위가 없으면 1000, 점수 = 자리 평균 ‰(스탯이 없으면 1000). 굴린 값은 만들 때 정해지고 다시 굴리기는 개발자 소급 명령만(285·N49, 다음 줄기).
- 전투 닳기(N49): 입은 장비마다 `n49_wear_chance`(250‰) 확률로 `d496_wear_battle`(1), 진 편이면 `n49_wear_loss_chance`(150‰ — 옛 문서 "약 15%", 49 C20) 확률로 `d496_wear_loss`(4 [임시])를 더. 난수는 장비마다 두 번(이김·짐과 상관없이 같은 흐름), 시드 = (전투 시드, 칸 ID). 0이면 벗긴다(옛 `BattleResult`, N49 "0이면 장착 불가"). 탄약 종류(무기 종류 `ammo`) 장비는 빠진다(내구도 = 남은 탄, 질문 325).
- 수리: 인공장기와 같은 `repairDurable`(D-5031·F11·F12, `repairOrgan`이 그 위에 비용을 더한다). 재료 양 `repairMaterialQty` = max(1, ⌈기본 양 × 티어 × 잃은 ÷ 최대⌉)(옛 `enhancement_routes.js`, N49). 파괴(최대 ≤ F12)면 내구도 0·벗김, 다시 수리 못 함(분해만).
- 탄약 보충 `refillAmmo`(D-509, 수리 D-5031과 같은 모양): 줄어드는 최대 = ⌈최대 × `d509_ammo_refill_loss`(50‰ [임시]) ÷ 1000⌉, 새 최대가 F12 이하면 파괴, 아니면 남은 탄 = 새 최대. 재료 양은 수리와 같은 `repairMaterialQty`(보충 전 쓴 탄으로).
- 신선도: 신선도 = max(0, 1 − 숙성 ÷ 실효 유통기한)(N49). 숙성 = 실제 시간 ÷ 보존 배율(‰, 0 = 멈춤)의 합. 0이 되면 실효 정의의 `spoilsTo`로 바뀌고(사슬, 바뀐 시각부터 숙성), 대상이 꺼졌거나 없으면 버린다(질문 321). 옛 코드의 하루 −10% 수량 감소·만료 지우기는 쓰지 않는다(N49).
- 효과 교체 `planEffects`(D-501): 같은 효과는 새 값이 더 높을 때만 바꾼다(같거나 낮으면 쓰지 않음 = 낭비 막기). 같은 배타 묶음의 다른 효과는 `confirm` 뒤 새 것으로. 자동 사용은 다른 효과를 바꾸지 않는다(판단식 = 287 답 대기). 효과량은 `useAmountRange`·`rollUseAmount`(D-501, 상한 N10, 오차 `d496_use_variance`).

### 4. 서버 (`apps/server/src/holdings/`)
- 서비스(`service.ts`)는 동기다: 한 번의 동기 처리 = 한 커밋(S3 U2). 소유는 주체 단위(사용자 주체·세력 주체).
  - `acquire`: 실효 팩의 켜진 아이템만(D-398). 장비는 굴림·내구도 = 지금 정의의 최대. 묶음·쌓임은 같은 주인·아이템·자리·숙성끼리 상한까지.
  - `equip`/`unequip`: 든 유닛(위치 −유닛)·그 유닛의 주인 = 명령한 주체·칸 종류 = 정의의 칸·입을 수 있는 종류(`kinds`)·내구도 > 0. 그 칸의 것은 벗는다. 세계 유닛 종류 → 팩 칸 배치: 사이보그(3) = cyborg, 그 밖 = human.
  - `use`: 든 유닛이 쓴다(질문 326). 쓰는 유닛의 1차 스탯 = 사이보그는 유닛 화면과 같은 셈(성장 + 장비, `realCyborgBody`), 그 밖은 [임시] 1차 모두 10. 전투 밖에서는 시간 버프·디버프만 건다(회복·상태·도트·지속 0 = `battle_only`, 물건은 줄지 않는다 — 287 전투 사용 줄기). 거절(not_better·confirm_replace)은 굴린 값 전체로 보고, 확률(`chancePm`)에 빠진 줄은 걸리지 않지만 물건은 쓴다. 수량 −1, 0이면 칸을 지운다.
  - 쓰기 쿨(D-509·D-510): 쓰기에 성공하면 그 유닛의 쿨 종류가 막힌다 — 식품 중분류(요리·음료) = food `d510_food_cooldown`(300,000ms, 생필품 포만감 N33과 따로), 그 밖 소모품 = potion `d509_potion_cooldown`(30,000ms, 버프 아이템도 potion인지는 질문 331). 두 쿨은 따로다(물약 쿨 중에도 요리를 먹는다). 쿨 중이면 `cooldown`(다시 쓸 시각 `readyAt`), 물건은 줄지 않는다. 전투 밖에서만 쓰는 지금도 같은 쿨이고, 전투 판정이 물약을 쓰게 되면 `cooldownUntil`로 같은 쿨을 본다(전투·비전투 하나). 스태미나는 쓰지 않는다.
  - `applyBattle`: 전투 결과 적용(`world.ts` 전투 서비스 apply)과 같은 동기 처리 → `world_battle_results`와 한 커밋이라 다시 켜도 한 번만 닳는다(DB 시험).
  - 고리: `refillAmmo(칸, 재료 기본 양)`(D-509, 재료 양을 돌려주고 차감은 부르는 쪽 — 재료 기본 양·보충하는 곳은 시설 줄기), `usableNow(유닛, 시각)`(쿨이 끝난 든 소모품), `pickAutoPotion(유닛, {HP, 최대}, 시각, 문턱?)`(D-510: HP가 문턱 아래면 쿨이 끝난 든 물약 가운데 모자란 HP를 가장 덜 넘치게 채우는 것 — 채우는 양 = 회복 줄 효과량 가운데 값, ‰ 회복은 최대 HP 기준, 못 채우면 가장 많이 채우는 것. 판정 `@terra/sim` `belowPotionThreshold`·`pickPotion`. 문턱 기본값 `d510_potion_hp_threshold` 400‰ [임시, D-510 예 40%], 유닛마다의 값은 AI 작전 슬라이더 D-5039가 생기면 넘긴다), `spendAmmo(유닛, 원거리 타격 수)`(입은 탄약 내구도를 줄이고 0이면 벗고 같은 유닛이 든 같은 탄약 종류 — 같은 아이템 먼저, 그다음 많이 남은 것 — 를 입힌다, 옛 자동 교체·D-501 294), `repair(칸, 시설 Lv, 장인 실력‰)`, `spoilDue`(1분마다·목록 읽기 전), `sweepEffects`.
- 세계 잇기(`world.ts`): 부팅 복구가 읽고, 서비스는 사이보그 서비스 뒤에 만든다. 설정(`holdingsConfigOf`): 실효 콘텐츠(아이템 편집기 덮어쓰기가 바로 든다), 설정 칸 실효 값, 사이보그 1차 스탯.
- 조회 tRPC `holdings.list`(로그인한 본인): 물건(이름·모양·수량·든 유닛·창고·칸·굴린 스탯·점수·내구도·신선도‰·썩는 시각·얻은 길)과 그 주체 유닛에 걸린 효과·남은 쓰기 쿨. 월드가 없거나 준비 전이면 빈 목록. 모양은 `@terra/shared/holdings`.

### 5. 프로토콜 6 (`packages/protocol/src/items.ts`)
- 기기 → 서버: `item_equip {holding, slot}`·`item_unequip {holding}`·`item_use {holding, confirm?}`·`dev_grant_item {item, quantity ≤ 1000, unit?}`(dev·admin = `secondMap: dev-spawn` — "내 시험 것 받기"와 같은 권한, 유닛이 없으면 내 사이보그). 서버 → 기기: `item_result {ok, holdings?·effects?}` 또는 `{ok: false, code, effects?, readyAt?}`(confirm_replace면 사라질 효과, cooldown이면 다시 쓸 시각).
- 더하기만 했다: `PROTOCOL_VERSION` 5 → 6, `MIN_SUPPORTED_PROTOCOL_VERSION` 4 → 5(현재 + 직전 1개, ADR 7). 5판 기기는 그대로 받는다. 바뀌면 커밋 뒤 답한다(물건·소유, U2). 사용자별 속도 제한(순간 20·분당 120), 연결마다 차례대로.

### 6. 전투 중 탄약·물약(다음 줄기에 드는 것)
- 지금 전투 판정은 탄약을 모른다(원거리 공격은 그대로, 결과 같음). 서버 고리 `spendAmmo`는 시험만 한다.
- 드는 일(판정 `packages/sim/src/combat/`): ① `CombatUnitSpec`에 남은 탄 `ammo?`(원거리 무기 + 탄약 장비일 때만, 없으면 지금과 같음), ② `battle.ts` `attackUnit`·`attackBuilding`에서 사정거리 > 1 기본 공격이면 0일 때 공격 못 함·쏠 때마다 −1(투사체 스킬도 쓰는지는 질문), ③ 0이 된 유닛의 행동(옛 = 후퇴 `BattleAI.js:62~73`, 전투 중 예비 탄약 교체 D-501 294는 보충 규칙 291·294 답 뒤), ④ `UnitResult`에 쏜 수 → 서버 `applyBattle` 옆에서 `spendAmmo`, ⑤ 판정 상태 스냅숏·다시보기 기록에 칸이 생기므로 `SIM_VERSION`을 올린다(탄약 없는 전투는 결과 같음을 골든으로 확인). 전투 시작 자료(`unitSpec`)에 입은 보유 물건(스탯·탄 수)과 `unit_effects` 버프를 넣는 일도 같은 줄기다(지금 세계 전투 사양은 시험 자료).

- 탄약 보충(D-509)은 정해졌다: 전투가 끝난 뒤(또는 시설에서) `refillAmmo`. 전투 중 예비 탄약 교체는 `spendAmmo`의 자동 교체(옛 규칙)다.

## 이유
- 쌓이는 물자를 원장에 남기면 거래소·생산·운송이 쓰는 계정이 하나로 남는다(경제 ADR 이유 "따로 된 재고 표가 필요 없다"). 표가 필요한 것은 개체·묶음마다 상태가 있는 것과 유닛이 쓰는 소모품뿐이다.
- 굴린 값만 두면 아이템 편집기의 고친 값(무기 사양·속성·유통기한)이 이미 있는 물건에 바로 들고(N49 "기본값은 템플릿을 그때 읽음"), 굴린 값은 새것부터(285)라 산 물건의 성능이 줄지 않는다(D-5008 근거).
- 숙성 ms는 정수라 판정이 결정적이고, 보존 배율이 바뀌는 곳(창고 옮김·거래소 포장)에서 그 시각까지 셈해 두면 된다(D-285 "신선도 수치 + 마지막 갱신 시각"과 같은 뜻).
- 닳기를 결과 적용과 같은 동기 처리에 두면 결과 기록(`world_battle_results`)과 한 커밋이라 두 번 닳지 않는다(전투 ADR 8절과 같은 방법).

- ③ 시설마다 수리 줄: 팩 시설 칸 `repair`(새 선택 칸, `@terra/content` `facilityEntrySchema`) = [{`slots`, `weaponTypes`, `materials`}]. 무기 종류가 맞거나 칸이 맞는 첫 줄로 고친다(`@terra/sim` `items/repair.ts` `repairRuleFor`, 옛 `REPAIR_MAP` 878~883의 무기 칸·방패 갈래를 "무기 종류 또는 칸"으로 적음). 재료 = 줄마다 `repairMaterialQty`(옛 955~960, 같은 아이템은 합침), 파괴되면 재료 없음(인공장기 수리가 파괴 때 비용 0인 것과 같다). 출발값 = 팩 `workshop`의 줄 넷(옛 공방 넷 차례): 근접 무기 종류(검·대검·둔기·창·도끼·권갑) 철 주괴 2, 원거리 무기 종류(활·석궁·총·지팡이·완드) 판자 2 + 철 주괴 1, 머리·몸 칸 + 방패 철 주괴 1 + 사슴 가죽 1, 장신구 칸 [임시] 은 괴 1(옛 "크리스탈 1"이지만 팩에 크리스탈·보석 아이템이 없다). 옛 공방은 넷이지만 팩 시설은 공방 하나라 줄 넷을 그 시설에 두었다. 건물 편집기(`/dev/buildings`)에 [장비 수리] 판을 더해 줄·칸·무기 종류·기본 재료를 고친다(검사: 칸·무기 종류가 하나도 없는 줄은 `repair_targets_empty`). 건물 편집기 목록 응답에 실효 무기 종류(`weaponTypes`)를 더했다.
- ④ 장인 실력‰ = min(1000, 제작 직무 점수 × 1000 ÷ 적정 점수)(D-420 틀, `craftSkillPm`). 제작 직무 점수 = 가중치 표의 제작 직무 행(팩 `stat_rows` 새 행 `job_crafting`, 48 §3.3 "직무 효율 — 직무마다 한 행"·§7.2, 옛 `salary_engine.js:40~47` crafting DEX 0.5·STR 0.2·INT 0.2·WIS 0.1 → STR 200·DEX 500·INT 200·WIS 100‰). 적정 점수 = 새 설정 칸 `f11_craft_appropriate`(계수표 `durability.craftAppropriate`) [임시] 50(새 유닛 1차 평균 10 → 200‰, 48 §3.5 Lv30 예 ≈ 44.5 → 890‰). 실력 1000이면 최대 감소가 반(F11 그대로). 밸런스 화면이 이 행을 고치고, 사이보그 화면 상세 전투 스펙의 "효율" 묶음에 보인다(색은 기타 색).
- 서버: `HoldingService.repair(칸, {facilityLevel, rules, craftsman})` → 끝까지 고치고 `{destroyed, maxLoss, restored, materials, skillPm}`(재료 차감은 부르는 쪽). 그 시설의 줄이 받지 않는 장비는 `wrong_slot`. 장인 1차 스탯은 부르는 쪽이 넘기고, 제작 직무 행은 가중치 표 실효 값(밸런스 화면 덮어쓰기)을 읽는다. 시설·장인 배치·재료 차감이 서버에 없어 수리 명령(WebSocket)은 더하지 않았다(고리·편집기 값·시험만).

### 4. 퇴각과 패배 닳음 (324)
- D-190 "퇴각하면 장비 내구도를 잃지 않는다"를 D-512가 "퇴각한 유닛은 패배 닳음을 받지 않는다"로 읽었다. `battleWearAmount(outcome)`: `won`·`retreated`는 전투마다 닳음만, `lost`만 패배 닳음을 더한다(난수는 늘 두 번 — 같은 시드면 같은 흐름). 서버는 전투 결과 줄(`UnitResult.outcome`)로 가른다: `retreated` = 퇴각, `stays` = 이긴 편, `returned`·`prisoner` = 진 편(`holdings/rules.ts` `wearOutcomeOf`). 전투마다 닳음(이겨도 25%)까지 퇴각에서 빼는지는 D-512 문구가 "패배 닳음"이라 빼지 않았다(아래 결과).

### 5. 버프 지속 (328)
- 아이템 사용 효과 줄 `durationMs`의 1시간 상한을 없앴다(팩 스키마 `ITEM_SCHEMA_LIMITS.useDurationMaxMs` = 365일은 정수 범위를 지키는 기술 범위, 유통기한 상한과 같다). 아이템 편집기 효과 줄의 지속 칸 상한도 같다(`ITEM_LIMITS.useDurationMs`, 효과 줄 편집 칸 `durationMax`). 효과 사전·스킬 효과 줄의 1시간은 전투 효과라 그대로다. 전투 밖 버프는 실제 시간으로 끝난다(지금과 같다, `unit_effects.until_ms`).

### 6. 설정 칸·팩 (core@37)
- 더한 칸: `n49_preserve_unit`(1000)·`n49_preserve_storage`(1000 [임시])·`n49_preserve_fridge`(2000)·`n49_preserve_pickle`(3000)·`n49_preserve_can`(5000)·`n49_preserve_freezer`(0)·`n49_preserve_exchange`(0) — 단위 ‰, 범위 0~100,000, live. `f11_craft_appropriate`(50 [임시], 점, 1~1,000,000, sim — 수리가 고리라).
- 팩: 가중치 표 행 `job_crafting`, 공방 `repair` 줄 넷, 위 칸 여덟, 판 core@37(조정자 지시: 같은 때 도는 줄기와 판을 나눔, main이 core@36을 먼저 씀).

### 결과
- 시뮬레이터는 보유 물건·수리를 읽지 않는다. 가중치 표 시험 표(`TEST_STAT_TABLE`)에 `job_crafting`을 더했지만 전투 사양은 이름으로 행을 골라 결과가 같다(작업 기록에 시뮬 전후 비교). `SIM_VERSION` 그대로.
- 남은 일: 수리 한 번의 장인 직무 시간(D-171 "노동")의 길이 규칙, 수리 명령·재료 차감·시설 배치(시설 직무 줄기), 냉장·냉동 시설과 창고 종류(보관 곳을 넘기는 줄기), 거래소 입출고 포장(D-289), 팩의 크리스탈(보석) 아이템이 생기면 장신구 줄 재료를 바꾼다.
- 해석(사용자 확인 대기): 퇴각도 전투마다 닳음(25%)은 받는다(D-190 문구 "내구도를 잃지 않는다"를 글자 그대로 읽으면 닳음이 아예 없다). 옛 공방 넷을 팩 공방 하나의 줄 넷으로 둔 것.
## 바뀜 (2026-11-07, D-512 — 전투 밖 회복 물약)
- 까닭: 질문 327 답(D-512 사용자 원문 "전투 중이나 후에도 hp,아머,쉴드는 그대로 이고 회복계산도 그대로 적용 …"): HP가 전투 뒤에도 남으므로 회복 물약은 전투 밖에서도 HP를 채운다(D-509 "전투비전투 무관"). 저장·회복은 ADR `2026-10-31-combat-core.md` "바뀜 (2026-11-07, D-512 …)". 작업 기록 `docs/worklog/2026/11/07-0945-vitals.md`.
- 4절 `use`의 "전투 밖에서는 시간 버프·디버프만 건다(회복 … = battle_only)"를 고친다: 한 번에 채우는 HP 회복 줄(효과 사전 `heal`, 주기 0)도 전투 밖에서 쓴다. 효과량은 다른 줄과 같은 굴림(`useAmountRange`·`rollUseAmount`, flat 또는 최대 HP의 ‰), 확률에 든 줄만 저장한 HP를 채운다(생명 수치 서비스 고리 `HoldingWorld.vitals` — 물건 −1·쿨과 같은 동기 처리, 한 커밋). 주기 회복·상태·도트는 그대로 `battle_only`(질문 346). 세계에 생명 수치가 없으면(시험 세계) 회복은 그대로 `battle_only`다.
- 낭비 막기(3절 "같거나 낮으면 쓰지 않음"을 회복에도, 해석): HP가 가득이면 회복 줄만 있는 물건은 `not_better`로 거절한다(물건은 줄지 않는다). 시간 효과도 있는 물건은 HP가 모자라면 시간 효과가 낫지 않아도 회복으로 쓴다(`confirm_replace`는 그대로 묻는다).
- 쿨(D-509·D-510)은 그대로다: 회복 물약도 물약 쿨 30초, 스태미나 없음. 거절 차례는 `battle_only` → `cooldown` → `not_better`(인벤토리 화면 시험의 연고 단계는 막 쓴 물약 때문에 `cooldown`이다).
- 결과 `item_result.effects`에 회복 줄(굴린 양)도 싣는다(프로토콜 모양 그대로, 판 그대로). 화면은 보유 물건 목록이 다시 오면 생명 수치(`vitals.list`)를 다시 받는다.

## 바뀜 (2026-11-07, 입은 장비·버프 → 스탯·전투)
- 까닭: "바뀜 (화면)"과 6절의 하지 않은 것 "장착한 장비·버프를 사이보그 스탯 판(`cyborg.get` → `realCyborgBody`)에 더하기"와 "전투 시작 자료에 입은 보유 물건(스탯)과 `unit_effects` 버프를 넣는 일"을 했다. 칼을 쥐어도 사이보그 화면·전투가 그대로였다. 작업 기록 `docs/worklog/2026/11/07-1150-equip-stats.md`, 질문 353~355 `docs/questions/2026-11-07-equip-stats.md`.
- 옛 규칙(D-507, AntiGravt01 main `0ea5299` 읽기만): 옛 전투는 입은 장비(인공장기 다섯 칸 + 투구·갑옷·무기·보조·장갑·신발·반지 둘·목걸이·토템)의 템플릿 기본값 + 인스턴스 보너스를 **칸마다 더해**(`terra-server/utils/item/equipment.js:115~160` `getEquipmentTotals`, 칸 목록 `:130~136`, 더하기 `:143~157`) 사이보그 1차 스탯·최대 HP·공격·아머 HP·쉴드에 얹었다(`terra-server/routes/map/piximap_routes.js:1104~1145`). 반지 두 칸도 더하기다(같은 합). 옛 캐릭터 화면 응답은 장비 몫을 0으로 두고 화면이 더했다(`terra-server/routes/character/character_routes.js:324~325` "equip은 프론트에서 합산") — 여기서는 서버가 셈한다. 내구도 0인 장비는 전투가 끝날 때 강제로 벗겨져(`terra-server/combat/BattleResult.js:312~346`) 다음부터 합에 들지 않았다. 옛 요리 버프는 1차 스탯 고정값이다(`docs/GDD/Item/Consolidated_Item.md:748~751`).

### 1. 실효 몸 한 벌 (`apps/server/src/roster/unitBody.ts`)
- 바탕 + 지닌 것 → 몸 사양(`bodySpecOf`) → 장비 묶음(`roster/body.ts` `bodyParts` = sim `loadoutOf`) → 화면 자료·전투 사양(`specFromStats`). 새 식은 없다: 2차 스탯 `computeSecondary`, 공격·명중·크리·간격 D-502 식(`realAttackOf`·`realHitPm`·`realCritPm`·`weaponRatioPm`), 실제 스태미나 회복 D-511(`real_stamina_regen`) 그대로다.
- 바탕: 만든 사이보그(저장된 처음 값·K·레벨·환생·속성값) 또는 [임시] 기본 몸(휴먼 칸 배치, 1차 모두 10, 레벨 1 — 저장된 유닛 스탯이 아직 없다, 유닛 상세와 같다).
- 입은 물건(`item_holdings` 입은 칸): 굴린 값(N49 285) + 지금 정의의 무기 사양(공격력 칸·적정 STR·INT·DEX·AGI·명중·크리·간격)·속성·저항·장비 스킬(실효 아이템, 아이템 편집기 덮어쓰기가 바로 든다). **내구도 0인 물건은 아무것도 주지 않는다**(N49 286, sim `wearable`). 굴린 값 가운데 지금 정의의 칸 묶음(D-423 1차·2차)에 맞지 않는 줄은 빼고 읽는다(정의가 바뀐 옛 물건이 던지지 않게). 인공장기·장신구는 1차 스탯, 무기·방어구는 2차 행(loadoutOf 그대로), 같은 종류 두 칸(장신구 둘·인공장기 셋)은 더한다(옛 `getEquipmentTotals`와 같다).
- 걸린 효과(`unit_effects` + 효과 사전 칸, 켜진 효과만): 1차 스탯 버프·디버프(고정값)는 성장값 뒤에 더한다(48 §2.3). 사이보그 화면 1차 출처에 "효과" 칸으로 보인다(`RosterPrimarySource` `effect`, 화면 칸은 이미 있었다). 1차 스탯 ‰ 버프는 곱할 바탕 규칙이 없어 넣지 않는다(질문 353). 전투 수치 버프는 아래 3절.
- 타고난 무기: `bodyParts`가 유닛 종류의 타고난 무기·"타고난 무기를 무기로 치나"를 쓴다(이전에는 sim `UNARMED` 고정 — 화면 스탯은 같다).

### 2. 쓰는 곳
- 사이보그 화면 `cyborg.get`(`realCyborgBody(…, gear)`): 1차·2차 스탯·장비 칸·스킬 칸·1차 출처. 새 칸 `CyborgBody.combat`(선택 칸, `@terra/shared/roster` `RosterCombat`): 든 무기 ID(맨손 null), 실제 공격력(스탯 공격력 + 무기 공격력 × 비율, 보는 1차·적정·비율), 명중·크리(무기 값 × DEX 비율), 공격 간격(무기 간격 ÷ AGI 비율), 스태미나 회복(행 값·STA 점수·적정 STA·실제). 시안 본체·옛 서버는 칸이 없다(화면은 2차 행만 보인다).
- 유닛 상세 `units.list`(`realUnit(…, gear)`): 기본 몸 + 그 유닛이 입은 것·걸린 1차 버프.
- 생명 수치 최대(`vitals/config.ts`): 사이보그·그 밖 유닛 모두 같은 몸의 2차 스탯(최대 HP·아머 HP·쉴드 HP·쉴드 재생). 조끼를 입으면 최대 아머가 오른다(DB 시험). 몸 자료는 그 시각의 효과로 셈한다(`VitalsWorld.bodyOf(unitId, nowMs)`).
- 보유 물건 효과량의 1차 스탯(`holdings/config.ts` `cyborgPrimaries`·새 `defaultPrimaries`): 같은 몸(입은 장비·지금 걸린 1차 버프 포함). 이전에는 장비를 빼고 셈했다.
- 세계 전투 시작(`apps/server/src/world/battleBodies.ts`, NPC 런타임 `startBattle` = 정원사 웨이브 공성이 거친다): 시작 자료의 세계 유닛 가운데 사이보그는 늘, 그 밖 유닛은 쓸 수 있는 입은 물건이나 걸린 효과가 있을 때만 같은 몸으로 다시 만든다(자리·편·파티·이동 간격·건물 피해 배율·시선 높이·공중·지휘 정원은 시작 자료 그대로). 차례 = 몸 → 생명 수치(남은 HP·아머·쉴드를 새 최대로 자름) → 전투 서비스. 지닌 것이 없는 NPC 휴먼 수비대는 그대로 시뮬과 같은 [임시] 사양(sim `specOf`)이다. 월드 설정에 `roster`(유닛 화면 전투 자료)를 더했다. 전투 실험실·밸런스 화면은 자기 자료 그대로다.
- 계수표: 유닛 화면 자료(`RosterCatalog`)에 `coefficients`(설정 칸·계산식 실효 값, 읽을 때마다)를 더했다 — 화면 값과 세계 전투 사양이 판정과 같은 계수로 셈한다.

### 3. 전투 수치 버프 → 걸린 효과 (sim `CombatUnitSpec.startEffects`)
- 아이템 버프 가운데 전투 수치(공격 ‰·방어율·회피·관통·크리 배율·이동 속도·쉴드 재생, 효과 사전 `EFFECT_COMBAT_STATS`)는 전투 시작 때 판정의 걸린 효과(`ActiveEffect`)로 넣는다. 남은 시간 = 끝나는 실제 시각 − 전투 시작(빨리감기 전투도 실시간으로 끝나는 시각에 적용하므로 전투 시각 = 실제 시각 − 시작, D-189). 효과 ID 차례. 판정 쪽 바뀜은 ADR `2026-10-31-combat-core.md` "바뀜 (2026-11-07, 입은 장비·버프로 전투 시작)".
- 사이보그 화면의 실제 공격력·방어율 줄에는 넣지 않는다(판정의 ⑥ 버프 몫, 질문 354). 걸린 버프는 보유 물건 판의 걸린 효과에 보인다.

### 4. 맨손과 스킬 (D-490)
- 전투 사양의 `bareHanded`·`weaponFields`는 장비 묶음 그대로다: 무기 칸이 비거나 그 무기가 부서졌으면(내구도 0) 맨손 = 맨손 스킬만 쓴다(sim `skillUsable`이 이미 막는다). 무기를 쥐면 그 무기의 공격력 칸(물리·속성) 스킬과 장비 스킬(지팡이의 불꽃 폭발 등)이 들어온다(서버 시험). 사이보그 화면 공격 줄은 "맨손 — 맨손 스킬만 씁니다" 또는 "든 무기: …"를 보인다.

### 5. 화면
- 사이보그 상세 전투 스펙: OFFENSE 묶음 끝에 실제 공격력·명중·크리 확률·공격 간격 네 줄(같은 줄 모양, 펼치면 "공식 스탯 공격력 + 무기 공격력 × min(1, STR ÷ 적정)"·든 무기·"STR 9 ÷ 적정 25 → 36%"·"= 스탯 8 + 무기 20 × 36% = 15"). 스태미나 회복 줄 값 = 실제 회복(D-511, 작업 기록 `03-1330-stamina.md`의 "풀이는 행 값 720" 한계를 닫음), 펼치면 행 풀이 뒤에 "= 720/분 × min(2, 14 ÷ 10) = 1,008/분".
- 보유 물건 목록이 다시 오면(장착·해제·사용 뒤) 사이보그 화면은 `cyborg.get`을, 유닛 화면은 `units.list`·생명 수치를 다시 받는다(받는 동안 앞 자료를 그린다).
- 유닛 상세 2차 스탯 줄에 `data-stat`(시험 표지).

### 3. 전투 밖 주기 회복 (346)

HP가 가득이면 주기 회복만 있는 물건은 `not_better`. 걸린 주기 회복은 전투 안에서는 틱하지 않는다(전투 끝 값이 덮어쓰고, 끝난 뒤 남은 시간만 분 단위로 이어짐 — 확인 대기).

## 바뀜 (2026-11-07, 사이보그 판 버프 몫·꺼진 아이템 — 질문 354·355 답 D-515)

### 1. 버프 몫(354)
- 사이보그 화면 `cyborg.get` 몸: 2차 스탯 풀이(`breakdown`)와 판정 값(`combat`)은 **걸린 효과를 뺀 몸**으로 셈하고(1차 스탯 버프 없음), 새 선택 칸 `CyborgBody.buffs`(`@terra/shared/roster` `RosterBuffs`)에 몫을 싣는다. 줄 값 + 몫 = 판정 값. `stats`(1차·2차)·`primarySources`는 든 몸 그대로다(1차 줄의 몫은 출처의 `effect` 칸). 버프가 없으면 전과 같다. 부상 불이익(D-514, 1차 출처 효과 "injury")도 걸린 효과의 몫으로 센다(뺀 몸 = 1차 버프·부상 불이익 없음 — 1차 줄 몫과 2차 줄 몫이 같은 것을 센다).
- 몫은 판정과 같은 함수로만 셈한다(`roster/unitBody.ts` `buffSharesOf`, 새 식 없음): 2차 행 = 든 몸 − 뺀 몸(1차 스탯 버프가 가중치로 바꾼 몫) + 그 행을 바꾸는 전투 수치 버프(방어율·회피 `withDefenseModifiers`, 크리 배율 `withAttackModifiers`, 쉴드 재생 `shieldRegenPerMinute`). 실제 공격력 = 공격 ‰가 피해에 곱하는 버프 항(`buffPm`)까지 공격력 단위로(⌊실제 × 버프 항 ÷ 1000⌋ − 기본). 명중·크리·간격·실제 스태미나 회복 = 든 몸 − 뺀 몸. 관통(2차 행 없음) = 장비 몫(기본) + 버프, 이동 속도 = 판정 하한(`MIN_MOVE_SPEED_PM`)을 넣은 ‰ 몫, `modifiers` = 효과 합(`modifiersOf`). 걸린 효과는 전투 시작 때와 같은 변환(sim `activeStartEffects`, 읽는 시각 기준 남은 것만).
- sim은 시작 효과 변환(`activeStartEffects`, battleState 안에 있던 것)과 `withAttackModifiers`·`withDefenseModifiers`·`EffectHolder`·`Modifiers`를 내보내기만 했다(출력 그대로, `SIM_VERSION` 12).
- 화면: 핵심 사양 1차 줄 합계 칸 = 기본(몸 값 + 장비) + 몫 알약(버프 = 상태색 성공, 디버프 = 상태색 위험, 읽기 "버프"·"디버프"), 막대의 효과 칸은 버프 색 빗금, 디버프는 기본 막대 끝에서 깎인 몫을 디버프 색 빗금으로(범례 "디버프로 깎임"은 디버프가 있을 때만). 상세 전투 스펙의 2차 줄·판정 값 줄은 기본값 옆 알약과 막대 몫 칸(앞 = 작은 값, 뒤 = 차이), 펼치면 공식 끝에 "전투 수치 버프 +n%"(그 행의 ‰)와 "버프 +n → 전투 m". 관통 줄(공격 묶음)·이동 속도 줄(기동 묶음)은 값이 있을 때만 더한다. 몫이 하나라도 있으면 카드 머리 아래에 알약의 뜻. 새 토큰 없음(상태색 `--color-success`·`--color-danger`와 알림 바탕 — 대비 검사 쌍, 스탯 색이 색상환을 다 써서 모양(알약·빗금)으로도 가른다). 문구 10개 ko·en.
- 랭킹은 버프를 뺀 값(D-7022)이라 줄 값을 기본으로 둔 것과 맞다. 유닛 상세 스탯 판은 그대로(든 몸 값, 몫 표 없음).

### 2. 꺼진 아이템을 입고 있으면(355)
- 몸 묶음(`roster/body.ts` `bodyParts`)이 칸의 물건을 유닛 화면 자료의 새 칸 `RosterCatalog.heldEquipment`(모든 아이템의 장비 정의, 꺼진 것 포함 — 변환은 `combat.equipment`와 같은 `equipDefOf`, 꺼진 스킬은 뺀다)에서 찾는다. 이름 표(`names.items`)도 모든 아이템. 그래서 이미 입은 꺼진 물건이 사이보그 화면·유닛 상세·생명 수치 최대·세계 전투 시작(같은 몸, `unitBody.ts`)에 스탯·무기 사양을 준다(서버 시험).
- 이미 걸린 효과도 효과 사전 항목이 꺼져도 몸을 바꾼다(`holdings/world.ts` `gearOf`, 사전에서 사라진 효과만 뺀다) — 같은 뜻("이미 가진 것은 그대로", D-5008·285).
- 새로 생기는 길은 그대로다: 보유 물건 받기(`acquire`)는 켜진 물건만(`unknown_item`), 전투 실험실·밸런스 무기 목록(`combat.equipment`)과 시뮬은 켜진 것만. D-512가 콘텐츠 켜고 끄기 자체를 없애는 일(팩 `enabled` 칸·편집기 스위치)은 이 줄기 밖이다.

### 결과
- 팩·프로토콜·시뮬 판은 이 줄기에서 바꾸지 않았다(합친 main 기준 core@38, 프로토콜 9, `SIM_VERSION` 13 그대로). 조회 응답 `cyborg.get`에 선택 칸 하나(`buffs`), 그 몸의 `breakdown`·`combat` 값의 뜻이 "걸린 효과를 뺀 기본"으로 바뀜(버프가 없으면 같음).
