## 결정

### 1. 판과 주체
- **경로 판**(경로마다 하나): 주체 = 소유 주체(`world_owners`) — 유저(사이보그) 주체와 세력 주체(NPC 국가·유저 세력)가 **같은 판, 같은 규칙**이다(D-043 "NPC도 유저와 동일하게"). NPC 개인(NPC 휴먼)은 소유 주체가 아니라 판에 없다(확인 대기 425).
- **세력 판**(하나): 주체 = 사라지지 않은 세력(`factions`), 점수 = 집계 때의 규모(감쇠 없음 — 아래 5절). 경로 판과 따로다.
- 이름: 유저 = 사이보그 이름(다른 사람에게 보이는 이름은 이것뿐, D-134 — 없으면 "이름 없음"), 세력 = 국가 프리셋 이름(세력 code가 프리셋 ID인 시험 국가) → 서버 코드 → `#번호`([임시] 세력 이름 칸이 아직 없다, 세력 화면과 같다). 유저 줄에는 소속 세력 이름을 붙인다.

### 2. 집계(스냅숏)와 감쇠
- 주기 = 설정 칸 `ranking_period`(출발값 하루 [임시], 최소 1분 — 측정용), 경계 = 주기의 배수(UTC) → 하루면 UTC 0시(NPC 하루 끝과 같은 때). 서버는 1분마다(켜진 직후 한 번) 마지막 집계의 끝(to) 다음 경계가 지났는지 보고, 지났으면 쓰기 대기열이 DB에 닿은 뒤(`writer.durable()`) 센다. 처음이면 [경계 − 주기, 경계)를 센다.
- 서버가 꺼져 경계를 여럿 놓쳤으면 감쇠는 그 수만큼, 이번 기간 점수는 [to, 경계) 전체를 한 번 센다.
- 점수(t) = ⌊점수(t − 1) × (1000 − 감쇠‰) ÷ 1000⌋(놓친 경계 수만큼) + 이번 기간 점수(20 §8.2). 감쇠 = 설정 칸 `ranking_decay` 18‰/집계 [임시](D-037 "주 10~15%" 예 → 하루 18‰ ≈ 주 12%). 점수가 0이 되면 판에서 빠진다(줄을 지운다).
- 이번 기간 점수 = Σ ⌊지표 값 × 가중치‰ ÷ 1000⌋(가중치 = 팩 경로 항목, [임시] 1000).
- 같은 점수는 같은 순위(1·2·2·4), 차례는 점수 높은 순·같으면 주체 ID 작은 순(결정적). 지난 집계 순위를 남겨 오름·내림을 보인다(D-7026 "강대국 순위 변화" 지표 재료).
- 셈은 정수만이다(실수 로그 없음): 1000 × log2(x) = 비트 길이 + 가수 제곱 되풀이(이진 10자리, 오차 1/1024 안) — `@terra/sim` `log2Milli`. 순수 함수는 `packages/sim/src/ranking/score.ts`(시뮬레이터가 나중에 NPC 판단에 쓸 수 있게 판정 코드 규칙대로), 계수표는 세력·사회 계수표 `ranking` 칸.

### 3. 지표(D-392 "원장·전투 기록에서 바로 나오는 것")
| 지표 | 무엇을 | 종류 | 변환 |
|---|---|---|---|
| `war_wins` | 결과를 적용한 전쟁 전투(`world_battles.war`)마다 이긴 편의 소유 주체(편 faction = 소유 주체 ID)에 언더독 ‰ | 흐름 | 그대로(합) |
| `battle_wins` | 전쟁이 아닌 전투(웨이브 방어 포함, 보호 레이드는 뺌 — D-500)의 같은 셈 | 흐름 | 그대로(합) |
| `cities_held` | 세력이 가진 도시(도시마다 1 + 발전도 ÷ 100) → 그 세력의 소유 주체 | 재고(집계마다 = "유지 일수") | 1000 × log2(1 + Σ) |
| `production` | 원장 거래 종류 `job_output`·`produce`가 소유 주체 계정에 넣은 양(+)의 합, 자산을 가리지 않음 [임시] | 흐름 | 1000 × log2(1 + 양) |
| `facilities` | 지은 사람(`world_facilities.built_by`)의 소유 주체에 Σ 레벨 × 상태(다 지은 것만) | 재고(가동·내구 유지) | 1000 × log2(1 + Σ ÷ 가득) |
- 언더독(D-042 ①) = min(상한, ⌊1000 × 상대 편 유닛 수 ÷ 내 편 유닛 수⌋), 상한 = 설정 칸 `ranking_underdog_cap` 4000‰ [임시]. 전력 = 시작 자료의 편 유닛 수(버프가 들지 않는 값, D-7022) [임시]. 도중 참전(입력 join)은 세지 않는다. 정원사 편(소유 주체가 아님)은 받지 않는다.
- 모든 지표가 성과·소유라 시간제 버프 수치를 쓰지 않는다(D-7022). 스탯을 재는 지표는 없다.
- 흐름 지표는 기록 시각으로 기간을 가른다: 산출 = 원장 거래 시각(정산은 게으르게 하지만 1시간마다 쓸어 담는다 — `SETTLE_EVERY_MS`), 전투 = 결과 적용 시각.

### 4. 경로 목록(콘텐츠 팩 `ranking_paths`, core@43)
- 새 분류 `ranking_paths`(`packages/content/src/schema/ranking.ts`): 항목 = ID·이름(ko·en)·영역(20 §7.2의 7)·공개(`open`, D-392)·재는 것(지표 + 가중치‰, 최대 8, 같은 지표 두 번 안 됨, 연 경로는 하나 이상). 파일 차례 = 화면 차례.
- 26경로를 다 넣고(20 §7, D-481), **연 경로 넷**: 정복자(`war_wins` + `cities_held`), 용병·투사(`battle_wins`), 대지주(`production`), 건축가(`facilities`). 나머지 22는 `open: false`(화면 "곧 열림"). 경로를 열거나 지표를 바꾸는 것은 팩 자료다(편집기는 다음 줄기).

### 5. 세력 판
- 점수 = 도시 × `ranking_faction_city`(1000) + 발전도 합 × `ranking_faction_development`(10) + 휴먼(그 세력 도시에 사는) × `ranking_faction_human`(100) + ⌊국고(시험 화폐) ÷ `ranking_faction_treasury_unit`(1000)⌋ [임시] — D-322(웨이브 세기 = 세력 규모)와 같은 재료. 감쇠 없이 집계 때의 값이다(규모 순위).
- 명성 칸(`renown`) = 집계 때의 **세력 명성**: 정원사 2(main `8cb4529`에 합쳐짐, 작업 지시 때는 없었다)가 막아 낸 도시 웨이브마다 `npc_society.gardener.renown`(= [세력 소유 주체 ID, 값] 쌍)에 쌓는 값을 소유 주체 → 세력으로 바꿔 싣는다. 쌓은 적 없는 세력은 null(화면 "명성 아직 없음"). 점수에는 더하지 않는다(확인 대기 427).

### 6. 백분위 등급·최상위
- 등급 = 순위 × 1000 ≤ 참가자 × 문턱(‰)인 가장 작은 문턱. 문턱 = 설정 칸 `ranking_tier_1~4`(10·50·200·500‰ = 상위 1·5·20·50%, D-041 예) [임시]. 어느 문턱에도 들지 않으면 "등급 밖". 참가자가 적으면 위 등급에 아무도 들지 않는다(예: 참가자 셋이면 1위만 상위 50%) — 확인 대기 429.
- 최상위 = 순위 ≤ `ranking_top_ranks`(3 [임시]) 표시만. 혜택 내용(D-041)은 기획 미정이라 두지 않는다.
- 판마다 문턱마다 그 등급에 드는 가장 낮은 점수(문턱 점수)를 보인다.

### 7. 저장(표 3, 더하기만 — 직전 판 앱은 모른 채 돈다)
- `ranking_state`(한 줄): 마지막 집계 기간 [from, to)·센 시각. `ranking_path_scores`(경로 × 소유 주체: 점수·이번 점수·순위·지난 순위·등급 문턱), `ranking_faction_scores`(세력: 점수·순위·지난 순위·등급·도시·휴먼·명성). 외래 키 없음(세력이 사라져도 다음 집계에서 빠진다). 표 정의는 `apps/server/src/db/rankingSchema.ts`(schema.ts가 다시 내보낸다), 마이그레이션 `20261107061337_ranking`.
- 원장·전투 기록에서 다시 셀 수 있는 파생 자료라 월드 쓰기 대기열을 거치지 않고, 집계가 한 트랜잭션으로 두 판을 통째로 바꾸고 상태 줄을 앞 값과 맞을 때만 고친다(`for update`, 두 번 세지 않는다).

### 8. 조회(tRPC, 로그인한 본인)
- `ranking.board({ board: { kind: "path", path: <ID> | null } | { kind: "faction" }, preview? })` → 마지막 집계 정보·경로 목록·판 상태(ready·closed·unknown)·참가자 수·위 50줄([임시] 옛 LIMIT 50)·내 줄(밖이어도 같이)·문턱 점수. 경로가 null이면 서버가 고른다: 내 점수가 가장 높은 경로 → 연 경로의 첫째.
- `ranking.mine({ preview? })` → 경로마다 내 자리(점수 있는 것만, 점수 높은 순)·내 세력 자리·규모·세력 명성·유저 명성(null). `ranking.board`도 유저 명성 칸(null)을 싣는다.
- `cyborg.get`의 랭킹 칸(`CyborgBody.rankings`)을 같은 표에서 채운다(질문 134 가 모양 그대로, 상위 % = 등급 문턱 ÷ 10, 등급 밖 = 100).
- 시안 자료(dev·admin, 홈과 같은 스위치): 고정 시안(참가 1,284, 내 순위 63 — 위 50 밖, 세력 16).
- 집계·순위·등급은 서버만 정한다(서버 권위). WebSocket 메시지는 없다(바꾸는 명령이 없다).

## 이유
- 하루 한 번 스냅숏: 감쇠형 점수는 앞 점수가 있어야 해서 요청마다 셀 수 없다(옛 랭킹은 요청마다 셌지만 누적이 없었다). 같은 기획의 백분위 재계산(F6)이 "하루 1번"이라 꼴을 맞췄다. 조회는 집계 표만 읽어 싸다.
- 소유 주체 하나로 판을 만들면 원장·전투 기록이 이미 그 단위라(정산·탈취·전투 편) 새 연결이 없다. NPC 국가가 소유 주체라 D-043(같은 판)을 바로 지킨다.

- 정수 로그: 판정 코드 규칙(초월함수·`**` 금지)을 지켜 시뮬레이터가 같은 함수를 쓸 수 있다.

## 결과
- 서버가 켜져 있으면 하루 한 번 경로 판 넷·세력 판이 갱신되고, 사이보그·세력 화면과 순위표에서 내 순위·백분위를 본다. 집계 한 번 = 원장(산출 종류)·전투 결과(기간)·도시·시설·세력 표를 읽는 질의 몇 개(측정 안 함 — 미실행, 운영 규모에서 재지 않았다).
- 감수: 산출은 정산 시각으로 가르므로 오래 정산되지 않은 주체는 한 집계에 몰린다(로그라 덜 유리). `ledger_transactions`에 (kind, at_ms) 색인이 없어 집계가 거래 표를 훑는다 — 원장이 커지면 색인 마이그레이션.
- 하지 않은 것: 보상(어드밴티지·칭호·연대기·기념비, D-038), 최상위 혜택, 영향력·천적·서버 최초 장치(D-042 ②③), 언더독의 실제 전력(유닛 수 대신), 품목 다양성·면적당 생산성 등 경로 지표의 나머지 구성요소, 경로 편집기, NPC가 랭킹을 보고 판단(D-043 영향), 개인 명성 저장.
