## 배경
- 처음 지시(기획 답 395 나, 기획 커밋 `71e7136`): "수명이 다한 유저 휴먼은 망령처럼 일을 멈추고 일정 시간 기다린다 — 그동안 신전 환생·신격화를 고를 수 있고, 안 고르면 떠난다(유전자는 떠날 때)".
- **작업 중에 바뀜 — 기획 D-517**(사용자 답, 기획 커밋 `ccf1466`, 조정자 전달. 미러는 다음 묶음에서 동기화하므로 아래 원문은 조정자 메시지에서 옮겼다):
  - 사용자 원문: "수명이다하면 비활성 상태가 되어 환생(종교시설)이나 유전자 조각(생명과학연구소)으로 변환".
  - 기획 정리: 수명이 다하면 비활성(일하지 않음). 고르지 않으면 비활성으로 남는다(떠나지 않음 — 395 나의 "안 고르면 떠남"을 바꿈). 기다리는 기간 상한은 설정 칸, 출발값 없음(상한 없음). 비활성 유닛은 ① 종교 시설에서 환생(비용 = 신앙도·화폐(+ 종교 아이템), 유전자는 들지 않음 — D-311에서 유전자 빠짐, 신격화도 종교 시설 쪽) 또는 ② 생명과학 연구소에서 유전자 조각으로 변환(스탯 유전자 + 스킬 유전자, 유닛은 사라짐). 유전자 2 줄기의 "수명이 다하면 유전자를 저절로 남기고 바로 떠남"을 위 두 명령으로 바꾼다. 유전자 만드는 함수·지닌 물건·화물 처리는 유전자 2 코드를 그대로 다시 쓴다(변환할 때). 함께 바뀐 결정: D-311, D-478·D-516(유전자는 변환 때 나옴), D-441, 49 N47.
  - 이 결정으로 처음 확인 대기("유닛 환생 재료에 유전자가 드는지", D-311 ↔ D-441)는 **답이 났다: 들지 않는다.**
- 사용자 지시(2026-11-07, 기획 D-515 원문): "정확한 수치는 밸런싱 단계에서 하는거고 빠르게 시스템을 구축해라". 수치는 모두 설정 칸 [임시], 모양이 빈 것은 옛 규칙(D-507)이나 가장 단순한 기본안 + 질문(450~459, 모양만). 콘텐츠 켬·끔 스위치는 만들지 않는다.

## 결정
### 1. 판정(`@terra/sim` `society/temple.ts`, 정수만)
- `inactiveWindow(태어난 시각, 수명, c)` = {비활성 시작 = 수명 끝, 떠남 = 상한 > 0이면 수명 끝 + 상한, 아니면 null}. `isInactiveAt`.
- `riteCost(의식, c)` = {신앙도 문턱, 화폐}. `riteBlockers({의식, 지금, 구간, 신앙도, 잔고, 그 도시 수호신 수}, c)` = not_inactive·faith·currency·guardian_cap.
- `rebirthHuman(휴먼, 지금, 수명 굴림, society)` = 레벨 1, 태어난 시각 = 지금, 수명 = T4 굴림(`lifespanMs`), 환생 +1, 신앙도 0(D-451). 스탯·속성·배운 스킬은 그대로 [임시](455, 휴먼 행에 K가 없다).
- `devotionGain(종류, 헌금액, c)`: 기도 = `prayFaith`, 헌금 = max(1, ⌊금액 ÷ `offeringPerFaith`⌋)(옛). `addDevotion(신앙도, 포인트, 얻음)`: 신앙도는 100에서 멈추고(D-455 186) 포인트는 다 쌓인다(D-451).
- 계수 = 세력·사회 계수표 `temple` 칸(팩 tuning 경로 `temple.*`)과 `fusion.geneConvertCurrency`. 시뮬은 읽지 않는다(NPC는 D-395 확률 그대로).

### 4. 서버
- 비활성(`temple/service.ts sweep`, 융합 서비스의 1분 수명 타이머): 유저 휴먼(유닛 종류 4) 가운데 수명이 끝난 것을 읽어 메모리 표(유닛 → 주체)를 다시 만든다. 새 비활성은 그 주체를 수명 끝까지 정산한 뒤 표에 넣고 지금까지 정산한다 → 노동 계약 서비스가 그 계약을 수명 끝에 "유닛 사라짐"(`unit_gone`)으로 끝낸다(새 고리 `unitAway`, world.ts에서 잇는다). 비활성은 노동 계약·구인 받기·건물 작업 일꾼이 `unit_busy`(노동 계약 서비스 `unitBusy`), 융합·주입이 `wrong_kind`(DB 행으로 바로 본다). 상한이 있을 때만 `expireDue`가 수명 끝 + 상한이 지난 휴먼을 유전자를 남기고 떠나보낸다.
- 시설 판단·자리·요금(`temple/places.ts`, 신전·연구소 공용): 시설 줄이 있고 실효 팩 시설 단계가 맞고(religion·biotech), 다 지었고 30% 이상(건물 서비스 `works`). 그 유닛이 선 칸의 도시 = 시설이 선 도시(361 재료 자리와 같은 "같은 2차맵의 가장 가까운 도시"). 요금은 남의 시설 = 주인 수입, 내 시설·주인 없음 = 소각 [임시](454). 누구의 시설이든 쓴다(D-311 유저·NPC 시설 모두 — 서버에는 아직 유저 시설만 있다).
- 신전(`temple/service.ts`), 명령 하나 = 읽기(쓰기 대기열이 따라잡은 뒤) → 메모리로 다시 확인 → 한 번의 동기 처리 → 커밋 뒤 답(U2):
  - 의식(`temple_rite`): 내 휴먼(종류 4, 포로 아님)·비활성·선 도시 = 신전 도시·본 화폐 = 지금 설정 칸·신앙도 ≥ 문턱·화폐 ≥ 비용·(신격화) 그 도시 수호신 < 상한 → 요금 → 환생: 휴먼 행(레벨 1·태어난 시각·수명·환생 +1)·신앙도 0(포인트는 남음) / 신격화: 수호신 줄 + 유전자 2 `retire`(유전자 없이: 지닌 물건 → 본체, 화물 → 소유자 장부, 배운 스킬·신앙·휴먼 행·유닛 지움).
  - 기도(`temple_pray`): 쓸 수 있는 신전, 쿨다운 → 내 사이보그와 내 휴먼 모두(비활성 포함 — 고르기 전에 신앙도를 채울 수 있다, 457)에 신앙도·포인트 + `prayFaith`.
  - 헌금(`temple_offer`): 금액(10진 문자열) > 0, 잔고 → 요금과 같은 곳으로 → 같은 얻음 max(1, ⌊금액 ÷ 50⌋).
  - 개발 시험(`dev_inactivate_unit`, dev·admin): 내 휴먼의 수명 끝을 지금으로(태어난 시각 = 지금 − 수명) → 바로 비활성.
  - 재료는 들지 않는다(신앙도·화폐, D-441·D-517). 종교 아이템(D-441 "+ 종교 아이템")은 신앙 목록·종교 코드가 생기면 같은 자리(361: 신전 도시 창고 → 그 도시 창고 시설 → 그 2차맵 화물)에서 뺀다.
- 유전자 변환(`fusion/geneCommands.ts convert`, `gene_convert`): 내 휴먼·연구소(biotech)·비활성·선 도시 = 연구소 도시·본 값 = `n47_convert_currency` → 요금 → 유전자 2 `retire` 그대로(스탯 유전자 1 + 배운 스킬마다 스킬 유전자 1, 지닌 물건 → 본체, 화물 → 소유자 장부, 유닛 떠남). 개발 시험 `dev_expire_unit`은 "바로 변환"(연구소·비활성·값 없이 같은 처리)으로 남긴다.
- 사이보그 신앙: 사이보그 서비스에 `addFaith`(메모리 기록 + `cyborgs` 행).
- 조회 tRPC `temple.overview`(로그인한 본인): 규칙 값(상한·환생·신격화·변환·기도·헌금), 내 사이보그 신앙도·포인트·다음 기도 시각, 신전·연구소 목록(건물·도시·레벨·상태·일함·내 것·수호신 수), 내 휴먼(신앙도·수명 끝·떠남·비활성·선 도시·칸·포로), 수호신. 모양 `@terra/shared/temple`. 융합 조회 휴먼 칸에 `departsAtMs`(상한이 없으면 null).

## 이유
- 비활성을 셈으로 두면 표·불변 조건이 늘지 않고, 상한 칸을 바꾸면 그대로 따른다(설정 칸 live).
- 계약 끝은 옛 규칙이고, 노동 계약 서비스의 "유닛 사라짐" 길을 그대로 써서 임대형 유예·보증금 반환이 따로 일 없이 맞는다.
- 시설 단계로 고르면 교단별 신전(D-411 신앙 목록)·다른 연구소가 더해져도 서버 코드는 그대로다.
- 변환은 유전자 2 `retire`(유전자·지닌 물건·화물·스킬 지우기)를 그대로 불러 같은 결과를 낸다(D-517 "유전자 2 코드를 그대로 다시 쓴다").
- 수호신을 기록으로 두면 도시당 상한(S15)과 화면 표시는 지금 되고, 유닛·버프·방어전은 기획이 모양을 정하면 같은 줄에서 잇는다.
