## 배경
사용자 지적(2026-11-07 원문): "문제점1. 유저는 맵 진입시 본인의 유닛만 움직일 수 있어야함. 사이보그 포함 유닛 목록을 통해 선택하여 명령. 운영자는 다른 유닛 조종이나 시야 자유이동이 가능."

이 줄기를 시작할 때 코드(main `51c59a9`, Verified: 코드):

| 무엇 | 지금 코드 |
|---|---|
| 서버 이동 명령(`move_unit`) | 내 유닛(수호신 빼고)이거나 권한 표 `secondMap: move-unit`(admin만). 거절은 모두 `forbidden` |
| 멈추기 | 2차맵 안 멈추기 명령이 없다(2차맵 사이 이동의 `travel_cancel`만) |
| 2차맵 화면 명령 | 기기가 `canCommand = admin`일 때만 모든 유닛, 아니면 시야 전송의 `own` 표시 유닛만 보냈다. 하지만 안내 문구는 플레이어에게 "보기 전용입니다. 유닛은 관리자만 옮길 수 있습니다"였고, 내 유닛을 고르는 길은 지도에서 그 유닛을 정확히 누르는 것뿐이었다 |
| 유닛 목록 | 2차맵 화면에 없다(유닛 화면 `/units`의 목록은 사이보그 본체를 빼고, 어느 2차맵에 있는지 고르지 않는다) |
| dev 권한 | 전체 보기(`observe`)·시험 일꾼(`dev-spawn`)만. 남의 유닛은 못 옮겼다 |
| 전체 보기 | dev·admin의 [전체 보기] 단추(안개 없음, 거르지 않은 전송) |

기획에서 정한 것(미러, 고치지 않음): 지도는 2차맵의 내 사이보그 위치에서 연다(D-6017), 데스크톱은 지도 옆에 유닛 목록 판(§2.4), 자동화 다중 선택(§3.3 D-6016), 수호신은 그 도시에 머문다(456 가). 2차맵에서 유닛을 고르고 명령하는 화면 모양·운영자 조종은 정해진 것이 없다(Unknown — 결정 로그에 "유닛 목록"·"운영자 조종" 결정 없음, 2026-11-07 검색).

## 선택지
| 무엇 | 선택지 | 고른 것 |
|---|---|---|
| 남의 유닛 거절 코드 | 1. 그대로 `forbidden` / 2. `not_owner` 새 코드 / 3. 남의 유닛 `not_owner` + 없는 유닛 `unknown_unit` | 2: 없는 유닛도 `not_owner`(시야 밖 유닛이 있는지 새지 않게) |
| 수호신 | 1. `forbidden` / 2. `unit_stays` 새 코드 | 2 |
| 멈추기 | 1. 지금 자리를 목표로 `move_unit` / 2. 새 `stop_unit` | 2: 길 찾기 없이 바로 서고(2차맵 `halt`, WP9가 만든 것), 가는 중인 2차맵 사이 이동도 "길에서 벗어남"으로 끝난다 |
| 운영자 | 1. admin만(지금) / 2. dev·admin(권한 표 `move-unit`을 dev에도) | 2: 사용자 원문 "운영자"는 개발·운영 계정(지금 dev·admin)이다 |
| 운영자 모드 | 1. 늘 켬 / 2. 단추로 켜고 끔(전체 보기와 하나로) / 3. 명령·보기 단추 따로 | 2: [전체 보기]를 [운영자 모드]로 바꿨다 — 켜면 모든 유닛 명령 + 안개 없는 전체 보기 + 위 판 "운영자". 끄면 dev·admin도 플레이어처럼 보인다(자기 계정으로 놀 때) |
| 목록 자료 | 1. 시야 전송의 `own`만으로 기기가 만든다 / 2. 유닛 화면 조회(`units.list`, 정산·DB) / 3. 새 조회(메모리만) | 3: 종류·직무·부상·명령할 수 없는 까닭이 필요하고, 5초마다 물어도 가볍다. 사이보그 본체를 넣는다 |
| 목록 범위 | 1. 이 2차맵의 내 유닛 / 2. 모든 2차맵의 내 유닛 | 1(질문 632) |
| 운영자 감사 기록 | 1. 없음 / 2. 남의 유닛에 된 명령만 감사 기록 | 2: 전체 보기를 켤 때와 같은 틀(`second_map.observe`) |

## 결정
1. **서버 권위(명령 판정, `apps/server/src/world/unitControl.ts`)** — 게이트웨이(`move_unit`·`stop_unit`)와 목록 조회가 같은 함수를 쓴다.
   - 운영자 = 권한 표 `secondMap: move-unit` = dev·admin(`auth/permissions.ts`, dev에 더함). 모든 유닛에 명령한다(수호신 포함).
   - 플레이어 = 내 소유 주체의 유닛만. 남의 유닛·없는 유닛은 `not_owner`, 내 수호신은 `unit_stays`. 포로·중태는 전처럼 2차맵이 `invalid_request`(질문 634).
   - 새 결과 코드 둘은 프로토콜 17 연결에만 가고 16판 연결은 전처럼 `forbidden`(연결이 인사한 판을 게이트웨이가 안다, `SocketLink.protocolVersion`).
   - 운영자 권한으로만 된 명령(남의 유닛·수호신, 결과 ok)은 감사 기록 `second_map.operator_command`(유닛·주인·2차맵, `app.ts`).
2. **멈추기 `stop_unit`(프로토콜 17, 최소 16)** — `{ id, mapKey, unitId }` → `result`. 권한은 이동과 같다. 2차맵 `halt`(지금 자리에 세움, 기다리던 길 찾기는 `superseded`). 서버 봇은 판단 예약이 끊기지 않게 세우지 않는다(`invalid_request`). 2차맵 사이를 가는 중이었으면 이동 서비스가 다음 확인에서 "길에서 벗어남"(WP9 그대로, 이동 서비스 코드는 고치지 않음).
3. **내 유닛 목록 조회 `world.mapUnits({ mapKey })`(tRPC, 읽기만, `apps/server/src/worldMap/mapUnits.ts`, 응답 `@terra/shared/mapUnits`)** — 그 2차맵 메모리 유닛 중 내 것: 유닛 ID·종류(사이보그 본체·사이보그 유닛·휴먼·수호신·시험)·사이보그 이름·지금 배치 칸·가는 중·직무·부상·명령할 수 없는 까닭(머묾·포로·중태). 사이보그 본체 먼저, 그다음 ID 차례. `operator`(권한 표). DB를 읽지 않는다.
4. **2차맵 화면(`map/SecondaryMapScreen.tsx` + `UnitControlPanels.tsx`·`mapUnits.ts`·`useMapUnits.ts`)**
   - [내 유닛 N] → 목록(아래 판 맨 위, 판 너비, 화면 높이 3분의 1까지 스크롤). 줄 = 이름(사이보그 "이름 · 내 사이보그", 그 밖 "종류 #번호") + 상태 한 마디(머묾·포로·중태 > 이동 중 > 부상 > 직무 > 대기, 이동 중은 엔진의 지금 값). 줄을 누르면 그 유닛을 고르고 카메라를 그 자리로, 좁은 화면이면 목록을 접는다(땅을 누를 수 있게). 넓은 화면(64em 이상)은 펼친 채 열고 접지 않는다(기획 60 §2.4).
   - 고른 유닛 다룸(`unitControlOf`): 운영자 모드면 무엇이든, 아니면 내 유닛(목록 줄 또는 시야 전송 `own`)만. 내 유닛이면 땅을 누르면 이동, 가는 동안 [멈추기]. 까닭이 있으면(수호신·포로·중태) 보내지 않고 까닭을 알린다. 남의 유닛은 "다른 주인의 유닛 #N(이동 중/서 있음)입니다. 정보만 볼 수 있습니다", 땅을 눌러도 보내지 않는다.
   - [운영자 모드](dev·admin, 전 [전체 보기] 자리): 켜면 다시 구독(전체 보기 — 안개 없음), 모든 유닛 명령, 위 판 제목 옆 "운영자" 알약(글자, 경고 색). 카메라는 플레이어와 같이 2차맵 전체(경계 너머 이웃 포함)를 움직이고, 운영자는 안개가 없어 어디든 보인다. 플레이어 안개는 그대로.
   - 파일 크기: 화면 파일이 600줄을 넘지 않게 명령 안내(`commandNotice.ts`)·성능 숫자 판(`MapPerfPanel.tsx`)을 나눴다(동작 같음).

## 이유
- 서버가 판정한다(AGENTS 4장 "소유권 판정은 서버만"): 기기의 다룸 판단은 단추를 고르는 데만 쓰고, 명령마다 서버가 같은 함수로 다시 본다. 목록이 "명령할 수 있음"으로 보인 유닛을 서버가 거절하지 않게 같은 함수를 쓴다(Verified: 서버 시험 `gateway.test.ts`·`mapUnits.test.ts`).
- 없는 유닛과 남의 유닛을 같은 코드로: 유닛 ID를 넣어 보며 시야 밖 유닛이 있는지 알아내는 길을 막는다(시야 전송 S3 3절 "누출 없음"과 같은 생각).
- 새 메시지 하나(멈추기)와 코드 둘만 더했다: 이동은 이미 서버 권위였다. 판을 올린 까닭은 새 코드가 16판 기기의 결과 스키마(`z.enum`)에 없어서다(16판 연결은 `forbidden`).
- 목록 조회를 따로 만든 까닭: 유닛 화면 조회(`units.list`)는 주체 정산과 쓰기 대기열을 기다리고 DB를 읽어 5초마다 묻기에 무겁고, 사이보그 본체를 뺀다(D-445 178). 2차맵 화면은 그 2차맵의 지금 유닛만 있으면 된다.
- 운영자 모드를 끌 수 있게: dev·admin 계정도 자기 사이보그로 플레이한다(시험 계정). 늘 켜면 그 계정의 플레이 화면(안개·내 유닛만)을 볼 수 없다.

## 결과
- 판: 프로토콜 17(최소 16) — `stop_unit`, 결과 코드 `not_owner`·`unit_stays`. 팩 그대로, `SIM_VERSION` 그대로, 마이그레이션 없음. 권한 표: dev에 `secondMap: move-unit`.
- 좋은 점: 플레이어가 2차맵에 들어가면 [내 유닛]에서 사이보그를 골라 바로 명령할 수 있다(지도에서 작은 유닛을 찾아 누르지 않아도 된다). 남의 유닛을 움직이려 하면 서버와 화면이 같은 까닭으로 막는다. 운영자는 모드 하나로 모든 유닛·안개 없는 보기를 쓰고, 남의 유닛을 옮긴 일은 감사 기록에 남는다.
- 감수할 점
  - 목록은 이 2차맵만이다(다른 2차맵의 내 유닛은 유닛 화면에서, 질문 632). 5초마다 다시 묻는다(사이에 생긴 유닛은 시야 전송 `own`으로 고를 수 있다).
  - 한 번에 한 유닛만 명령한다(다중 선택·파티는 질문 633).
  - 남의 유닛 정보는 번호와 움직임만이다(주인·종류는 질문 636).
  - 운영자 모드는 화면마다 꺼진 채 연다(기억하지 않음, 질문 631).
  - 포로·중태 거절은 아직 `invalid_request`(질문 634).
- 시험: 프로토콜 `secondMap.test.ts`(멈추기·새 코드), 서버 `world/gateway.test.ts`(17판 플레이어 not_owner·unit_stays·내 유닛 옮기고 세움, 16판 forbidden, 운영자 dev·없는 유닛·봇·감사 기록), `worldMap/mapUnits.test.ts`, `auth/permissions.test.ts`, 게임 `map/mapUnits.test.ts`·`mapFeed.test.ts`(멈추기), 화면 `e2e/unit-control.spec.ts`(사진 390 × 파스텔·다크).
- 다시 볼 조건: 질문 630~637 답, 파티·진형(다중 선택), 전투 화면(포로·중태 전용 코드), 두 지도가 한 화면이 될 때(511).

### 이유
- 기획 정리 630은 "보이는 곳"을 묶는다. 서버는 이미 시야 밖 남의 유닛을 보내지 않고 건물은 탐사한 칸만 보내므로, 카메라를 묶는 것은 화면 편의(멀리 끌어 빈 안개만 보는 일을 막음)이고 보안 경계가 아니다. 그래서 서버 시야 규칙은 고치지 않았다.
- 원 목록은 유닛을 따라간다(1초마다 엔진의 지금 자리). 상자 범위는 흩어진 유닛 사이 빈 땅까지 열어 "둘레"가 아니게 된다.
- 한눈 정보를 시야 전송 메시지에 싣지 않은 까닭: 모든 유닛 메시지가 커지고 프로토콜 판이 바뀐다. 누른 하나만 묻는 편이 가볍고, 서버가 시야를 다시 본다.

### 결과
- 좋은 점: 플레이어는 내 유닛 둘레만 둘러보고, 운영자 모드를 켜면 어디든 본다(켠 채 다시 열면 그대로). 목록이 손이 필요한 유닛부터 보이고 다른 곳 유닛 수를 안다. 시야 안 남의 유닛이 어느 세력의 무엇인지 안다.
- 감수할 점
  - 카메라 범위는 화면 값이다: 새 유닛은 목록을 다시 받을 때(5초)까지 원이 없다. 원은 1초마다 따라간다.
  - 내 국가의 다른 플레이어·NPC 시야는 범위에 들지 않는다(질문 701). 유닛·건물이 없는 2차맵은 탐사 칸 둘레(질문 702).

  - 다른 곳 수는 15초까지 늦을 수 있다. 유저 세력(코드 없음)의 이름은 "세력 #ID"다(유저 세력 이름 짓기가 생길 때).

  - **운영자 모드(Verified: 재현)**: "바뀜 (2026-11-09)"가 운영자 모드는 옛 동작으로 남겼다("운영자 모드는 그대로"). 운영자 모드에서 남의 유닛을 누르면 그 유닛이 명령 유닛이 되고 다음 땅 누르기는 그 유닛을 보냈다(`move_unit`의 `unitId`가 남의 유닛). 사용자는 주로 운영자 모드를 켠 admin 계정으로 본다(사진의 "운영자" 표시 — 그 기기가 그때 운영자 모드였는지는 Assumed).
  - **지도자 이름표(Verified: 코드·화면 시험 사진, 플레이어도 해당)**: "바뀜 (2026-11-09)"가 지도 유닛·근처 판 줄만 고쳤고 이름표 길을 빠뜨렸다. 이름표를 누르면 화면 판단(작은 창)과 상관없이 엔진 고른 표시가 지도자로 옮겨 가고(`mapSession.ts`), 1초 요약이 그 지도자를 고른 유닛으로 맞췄다 → 안내 줄 "정보만 볼 수 있습니다", 다음 땅 누르기는 `view_only`. 사용자가 이름표를 눌렀는지는 Unknown.
  - **손가락 누르기(Verified: 재현, 까닭 아님)**: 터치 흉내(412×915)로 플레이어 흐름은 어제 코드에서도 됐다(창 열림 → 땅 = 닫고 내 유닛 `move_unit`).
  - **누르는 반경(Verified: 셈, 거듦)**: 최대 확대(5/5)에서 휴먼 하나의 누르는 원이 반지름 약 30px(22px + 몸 반 높이)이라, 걷는 휴먼 둘레 땅을 누르면 유닛이 걸려 창이 다시 열렸다.
  - **옛 기기 묶음(Unknown)**: 플레이어가 지금 쓰는 빌드를 볼 곳이 없었다. 프로토콜 19 기기(어제 고침 전 묶음 포함)는 서버가 그대로 받는다.

### 결정
1. **누르기만으로 명령 유닛이 바뀌지 않는다(운영자 모드 포함)**: 누구든 남의 유닛을 누르면(지도 유닛·지도자 이름표·근처 판 유닛 탭) 명령 유닛은 그대로 두고 작은 창을 연다(`anchorUnit.ts unitTapOf` — 내 유닛·이미 명령 유닛이면 고르기, 그 밖은 작은 창. 규칙에서 운영자 값을 뺐다).
   - 운영자 모드의 작은 창에는 **[이 유닛 조종]**이 있다. 이 단추만 남의 유닛을 명령 유닛(기준 유닛 — 카메라가 따라간다)으로 삼는다. 운영자 자유 시점도 같다(작은 창 + 같은 단추, 카메라는 따라가지 않는다).
   - 운영자 모드를 끄면 조종하던 남의 유닛을 놓는다(고르기를 풀어 기준 유닛 = 내 유닛을 다시 고른다).
   - 지도자 이름표도 같은 판단을 따른다: 화면이 고르지 않으면(`onPickLeader`가 `false`) 엔진 고른 표시를 옮기지 않는다.
2. **땅 누르기는 내 유닛을 보낸다**: 보낼 유닛 = 고른 유닛을 다룰 수 있으면 그 유닛, 고른 유닛이 남의 유닛이면 무시하고 기준 유닛(`mapUnits.ts tapCommandOf`, 이웃 2차맵 땅도 같다). 남은 "남의 유닛이 골라진 채 땅을 눌러 `view_only`"는 이 맵에 내 유닛이 없을 때뿐이다.
3. **작은 창(상호작용 메뉴)**: `PeekCard` — 이름, 주인·움직임 한 줄, 지금 할 수 있는 일(지도자: 지도자와 이야기 → 정부 대화상자, 운영자: [이 유닛 조종]), 없으면 "이 유닛에게 할 수 있는 일이 아직 없습니다" 한 줄, 닫는 법 안내, [닫기]. 새 게임 행동은 더하지 않았다. 아래 판 자리 하나 규칙은 그대로이고(건물 > 작은 창 > 내 유닛 목록 > 근처), 떠 보이게 그린다(강조 테두리·큰 그림자·뜨는 움직임, 동작 줄이기면 움직임 없음).
   - **닫기**: 다른 곳을 누르면 닫힌다 — 지도의 땅·이웃 땅(같은 누르기로 명령 유닛이 간다, "바뀜 (2026-11-09)" 그대로)·아무것도 없는 곳(엔진 `onTapMiss`), 위·아래 판과 단추(누른 단추의 일은 그대로 한다), Esc. 지도 끌기·두 손가락은 닫지 않는다. 다른 남의 유닛을 누르면 그 유닛 창으로 바뀐다.
4. **남의 유닛은 몸 위를 눌러야 걸린다**(엔진 `picking.ts pickUnit`, 화면이 `wideUnitTap`으로 내 유닛을 알린다):
   - 내 유닛: 몸 가운데에서 화면 거리 22px + 몸 반 높이 안(앞 규칙 그대로 — 작은 내 유닛도 쉽게 고른다).
   - 남의 유닛: 화면에 보이는 몸 상자(반 너비 = 몸 반지름, 반 높이 = 키 × cos 기울기 ÷ 2) + 6px 안. 상자가 작으면 반 14px(28px 네모)까지 키운다. 빗나간 누르기는 땅 누르기다.
   - 최대 확대의 휴먼(412×915, 1m ≈ 10.3px): 누르는 넓이가 원 반지름 30px(약 2,830px²) → 28px 네모(784px²), 약 28%. 남의 유닛을 꼭 집어 누르기 어려우면 근처 판 유닛 탭 줄로 연다.
   - 규칙에 든 유닛이 여럿이면 몸 가운데가 가장 가까운 유닛.
5. **설정 화면에 앱 빌드 한 줄**("앱 정보 — 빌드 <배포 커밋 앞 12자>", 개발 실행은 dev): 고친 것이 안 보일 때 옛 묶음인지 가린다. 새 버전 적용 규칙(`pwa/updates.ts`)은 바꾸지 않았다.

## 바뀜 (2026-11-12, 운영자 빠르기를 모든 유닛 명령에)
- 날짜: 2026-11-12(KST), 가지 `work/operator-speed`(main `0864282`에서), 작업 기록 `docs/worklog/2026/11/12-2105-operator-speed.md`, 질문 1246~1248(`docs/questions/2026-11-12-operator-speed.md`).
- 사용자 지적(원문): "운영자모드에서 이동시 맵을클릭할때는 빠른속도가 적용되나 작업이나 다른 명령시엔 원래느린속도다".
- 전(Verified: 코드): 운영자 빠르기(`OPERATOR_SPEED_FACTOR` 100, ADR `2026-11-08-seamless-second-map.md` "바뀜 (2026-11-09)")는 두 길에만 붙었다 — 그 2차맵을 전체 보기로 구독한 연결의 `move_unit`, 같은 연결의 2차맵 사이 이동(`travel_start`). 채집(`gather_start`)·들어가기(`unit_enter`)·운반꾼 걸음은 `SecondMap.moveUnit`을 빠르기 없이 불러 보통 빠르기였다.

### 결정
1. **유닛마다 운영자 빠르기 표시(서버, `apps/server/src/world/operatorPace.ts`)**: 2차맵(`SecondMap`)이 유닛마다 표시를 든다(`setPace`·`paceOf`, 메모리). `moveUnit`에 빠르기를 따로 주지 않으면 표시를 읽는다 — 채집 줄 왕복(오브젝트·넣는 곳)·들어가기·운반꾼 걸음 등 유닛을 걷게 하는 길이 모두 한 곳에서 빨라진다. 길마다 매개변수를 더하지 않았다. 건물이 남은 길을 막아 다시 찾은 길도 하던 이동의 빠르기를 그대로 쓴다(전에는 운영자 이동·2차맵 사이 이동이 다시 찾으면 보통으로 떨어졌다).
2. **다는 규칙**: 유닛 명령을 받는 게이트웨이(2차맵 이동·멈추기, 2차맵 사이 보내기·멈추기, 채집·채집 멈추기·들어가기, 직무 배치·풀기·일자리 받기)가 명령마다 단다. 운영자 모드(같은 연결이 2차맵 전체 보기 구독 + `canCommandAnyUnit` — dev·admin)면 100배, 아니면 지운다. 명령이 거절되면(결과 ok가 아니거나 던짐) 앞 표시로 되돌린다. 2차맵 이동 명령은 전처럼 그 2차맵의 전체 보기 구독을 보고, 다른 명령은 그 연결의 아무 2차맵 전체 보기 구독을 본다(2차맵 사이 이동과 같다).
3. **운반꾼(채집소 → 도시 창고)**: 표시가 달린 운반꾼은 걸음뿐 아니라 나르는 시간(옛 셈 `haulMs`)도 배수로 나눈다(올림) [임시, 질문 1247].
4. **바꾸지 않은 것**: 캐기·짓기 등 일하는 시간(질문 1246), 유닛 속도와 표시 종류(`unitKinds.ts wireKindOf` — 기기는 움직임 빠르기로 탈것을 가르지 않는다, ADR `2026-11-11-character-3d.md` "바뀜 (2026-11-12, 유닛 겉모습)"), 소유 판정(채집·2차맵 사이 이동은 전처럼 내 유닛만). 2차맵 사이 이동은 길마다 자기 빠르기를 든다(`travel/service.ts journey.speedFactor`). 표시는 2차맵을 넘으면 따라가지 않고, 다시 켜면 없다(질문 1248).
