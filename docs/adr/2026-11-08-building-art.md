# 2차맵 건물 모델: 시설 종류별 로우폴리 조각 + 도형별 인스턴싱 + 겉모습 조회

- 상태: 확정 (2026-11-08, 사용자 결정 — 진행상황 세션 ADR 검토 — 사용자 원문 "대체로 맞으나 최대한 잘 만들기": 구조 확정, 모델 품질은 계속 높인다)
- 날짜: 2026-11-08
- 관련: docs/PLAN.md 5.7·11장(p95 ≤ 33ms), `2026-10-28-design-system.md`(새싹 장난감, D-070 세계 색은 테마와 상관없음), `2026-10-28-s1-second-map.md`(건물 배치·렌더링), `2026-10-31-second-map-from-planet.md` 5절(소품 모델: 모양마다 InstancedMesh), `2026-11-07-buildings-runtime.md`(시설 레벨·상태), `2026-11-07-gather-objects.md` 6절(건물 판), 질문 `docs/questions/2026-11-08-building-art.md`(760~763)

## 배경
- 사용자 지적(2026-11-08): "건물이 너무 단순하게 생김". 2차맵 건물은 모두 상자 하나 + 문 상자였다(S1 임시 도형, `packages/engine/src/buildings/buildingView.ts`). 색·높이는 건물 ID로 정한 임시 값이었다(`apps/game/src/map/mapWire.ts` `toFootprint`).
- 지도 자료(WebSocket `map_snapshot`·건물 갱신)의 건물에는 칸·크기·돌림만 있다. 시설 종류·레벨·상태·주인 국가는 없다. 서버 2차맵 런타임(`SecondMap`)도 시설을 모르고, 시설 줄은 건물 서비스(`FacilityService.facilities`)에 있다. 레벨업·손상은 지도 갱신을 내지 않는다.
- 팩 core 51의 2차맵 시설은 16종이다(영토 비콘은 1차맵). 바닥은 2×2 ~ 5×5 배치 칸(칸 약 5.86m → 약 12 ~ 29m).

## 선택지
모델 원천
1. glTF 파일(에셋): 로더(새 의존성)·파일 크기·에셋 규칙(PLAN 9.8)이 붙는다. 시설이 늘 때마다 그림을 따로 만들어야 한다.
2. 코드로 만드는 로우폴리 조각(단위 도형 목록): 새 의존성·파일이 없다. 바닥 크기·레벨·상태에 맞춰 바로 만든다. 시험할 수 있다.

그리기
1. 도형마다 InstancedMesh 하나(모든 건물의 조각을 함께): 그리기 호출 = 쓰는 도형 수(최대 7), 건물 수와 상관없다.
2. 종류마다 합친 지오메트리를 인스턴싱: 그리기 호출 = 종류 수 × 재질 수(최대 수십), 상태·레벨마다 지오메트리가 더 는다.
3. 건물마다 메시: 그리기 호출이 건물 수에 비례한다.

자료
1. 프로토콜 `buildingSchema`에 칸 더하기: 프로토콜 판 올림, 서버 2차맵 런타임이 시설을 알아야 하고, 레벨·상태가 바뀔 때 지도 갱신을 새로 내야 한다.
2. tRPC 조회(`facilities.mapLooks`)를 화면이 묻는다: 프로토콜·시뮬·DB를 바꾸지 않는다. 늦게 바뀌는 그림 자료라 30초 간격이면 된다.
3. 기기가 `facilities.overview`(내 시설만)로 맞춘다: NPC 도시 건물(도시 2차맵의 대부분)을 모른다.

## 결정
모델 원천 2, 그리기 1, 자료 2.

### 엔진(`packages/engine/src/buildings/`)
- `buildingLook.ts`: 겉모습 입력 `BuildingLook`(시설 ID·레벨·상태·레벨 올리는 중·국가 색 번호) — `BuildingFootprint.look`(선택). 시설 ID → 모델 종류 표(창고 넷은 크기만 다름: `warehouse`·`grand_warehouse` = 한 모델). 모르는 ID·없음 = 일반 집. 레벨은 1~5로 자른다(0 = 짓는 중).
- `buildingParts.ts`: 조각 = 단위 도형(상자·박공 지붕·사각뿔·원기둥·원뿔·반구·창문 빛) + 바닥 가운데 자리·크기·세로축 돌림·눕힘·색. 공용 도우미(집 한 채 = 벽·지붕·문·창문, 깃발, 상자 더미, 통나무 더미, 돌 조각, 짓는 중 뼈대, 비계).
- `buildingModels.ts`(입력·상태·판 안 맞추기)·`buildingKinds.ts`(종류별 몸체): 종류별 모델. 모든 조각은 바닥 판 안에 든다(마지막에 안으로 맞춤). 씨앗(건물 ID)으로 좌우 뒤집기·지붕 색 고르기.

| 공방 `workshop` | 나무 벽·청회색 지붕 + 넓은 문 + 톱니바퀴 간판 + 모루·작업대. 레벨 2: 통 |
| 제재소 `sawmill` | 긴 헛간 + 옆면 큰 둥근 톱 + 통나무 들이는 더미 + 널빤지 더미. 레벨 2: 더미 둘 |

- 레벨: 2부터 종류마다 덧붙는 것(위 표), 3부터 본채가 한 층(3m)씩 높아지고 창문 줄이 는다(5까지 같은 규칙).
- 상태: 짓는 중(레벨 0) = 본채 자리 뼈대(기둥·들보·낮은 벽) + 재료 더미, 손상(70% 아래) = 색 × 0.82 + 돌 조각 3, 멈춤(30% 아래) = 색 × 0.66 + 돌 조각 6 + 창 불 꺼짐 + 깃발 없음, 폐허(0) = 낮은 벽 토막 + 돌 더미(색 × 0.52), 레벨 올리는 중 = 본채 둘레 비계. 상태 셈은 건물 화면과 같다(`@terra/shared/facilityRuntime`).
- 국가 색: 지도 국가 색 번호 0~5(1차맵 도시 판 `data-nation`과 같은 차례)를 3D 색 표 `NATION_ACCENTS`로 깃발·박공 용마루 띠에 쓴다. 세계 색이라 테마와 상관없다(D-070). 국가가 없으면 깃발·띠가 없다.
- 색은 색 표 하나(`buildingPalette.ts`)에서만 가져온다. sRGB 값으로 넣어 표의 색이 화면에 그대로 보인다.
- 밤: 몸 재질에 밤 빛(자기 색 × 0.16 × 밤 정도, 유닛 0.3보다 낮게) + 창문은 빛을 받지 않는 재질(색 = 낮 유리 ~ 밤 불빛, 인스턴스 색 = 그 창의 밝기). 장면 빛의 유닛 밤 빛 고리로 밤 정도를 받는다(`sceneLight.ts`는 그대로).
- 그리기(`buildingView.ts`): 도형마다 InstancedMesh 하나, 재질 둘(몸 Lambert flatShading + 창문 빛 MeshBasic)을 모든 건물이 함께 쓴다. 정적이라 목록이 바뀔 때만 행렬·색을 쓴다(프레임마다 하는 일 없음). 비탈: 모델은 가장 높은 모서리 땅에 서고 바닥 판은 가장 낮은 모서리 − 0.5m까지 내려 기단이 된다.
- 소품: 건물이 차지한 배치 칸에는 소품 모델(나무·바위 등)을 세우지 않는다(`footprintMask` → `PropView.setBlocked`, 지금 2차맵만). 상자일 때는 상자가 나무를 덮었지만 마당·밭·벽 없는 헛간이 생겨 나무가 뚫고 나왔다(화면 시험 사진). 먼 거리 땅 색 섞기는 그대로다(바닥 판이 덮는다).
- 누르기: 조각마다 세계 경계 상자(바닥 판 포함)와 시선의 거리(`picking.ts` `rayBoxDistance`). 건물이 땅 닿는 점보다 앞(0.6m 여유)이면 그 건물 판 안 칸을 `onGroundTap`으로 준다 → 화면(`gatherState.tapCell`)이 지금처럼 그 칸의 건물 판을 연다. 전에는 지붕을 누르면 그 뒤 땅 칸이 갔다.

### 자료
- 새 tRPC `facilities.mapLooks({ mapKey })` → `@terra/shared/mapLooks` `MapLooksResponse`(건물마다 시설 ID·레벨·상태·레벨 올리는 중·주인 국가 ID). 서버 `apps/server/src/facilities/mapLooks.ts`(읽기만), 주인 → 국가는 건물 공격 대상과 같은 `ownerFactionsOf`(NPC 세력 주체는 메모리, 플레이어는 가입 국가를 DB 한 번). 띄우지 않은 2차맵은 `unknown_map`. 보는 건물만 준다: 시야 전송(`world/vision.ts`)이 건물을 보내는 규칙과 같다(전체 보기 권한, 내 건물, 아는 시야 칸 = 탐사 ∪ 지금 시야에 발자국 가운데가 든 건물 — `buildingCell`을 내보내 같은 셈을 쓴다, 질문 760). 그래서 `SecondMap.forEachBuilding`이 건물 칸·크기·돌림(`placement`)도 준다.
- 화면 `apps/game/src/map/buildingLooks.ts`: 엔진 앞에 끼우는 자료 받는 쪽. 처음·건물 ID 묶음이 바뀌면 0.8초 뒤·그 밖에는 30초마다(숨긴 탭은 쉼) 묻고, 답이 바뀌었을 때만 엔진에 다시 넣는다. 국가 색 번호는 `world.cities`의 국가 차례(없는 국가는 세력 ID로 돌려 씀). 답이 실패하면 일반 집 그대로다. `SecondaryMapScreen.tsx`는 네 줄(만들기·끼우기·멈추기·import)만 바뀐다.
- 프로토콜·콘텐츠 팩·시뮬·DB는 바꾸지 않는다(판 올림 없음).

## 이유
- 조각 모델은 새 의존성·에셋 없이 시설 16종 × 레벨 × 상태를 바로 만들고, 바닥 크기(편집기가 바꿀 수 있다)에 맞춘다. 소품 모델(나무·바위)과 같은 방식이라 톤이 맞는다(Verified: `props/propView.ts`).
- 도형별 인스턴싱은 그리기 호출이 건물 수와 상관없다. 잰 값(Verified, 이 작업 측정 — 작업 기록 `docs/worklog/2026/11/08-1100-building-art.md`):
  - 시설 16종을 돌려 쓴 빽빽한 도시 64채(Node, three 0.186.1): 조각 1,560개, InstancedMesh 7개, 삼각형 24,048개(건물당 약 376), 목록 넣기(`set`) 중앙값 2.0ms(첫 실행 29ms, 목록이 바뀔 때만), 누르기 1번 약 0.11ms.
  - 같은 도시를 헤드리스 Chromium(SwiftShader, 390×844, 픽셀 비율 1)으로: 그리기 호출 3~4 → 8~9(지형·건물 도형 포함 장면 전체), 장면 삼각형 35,328 → 57,840. 옛 상자 그리기는 건물 그리기 호출 2(상자·문), 64채 삼각형 1,536.
  - 프레임 시간은 이 컨테이너(부하 평균 5~9, 소프트웨어 WebGL)에서 재면 흔들려(엔진 p95 0.5 ~ 73ms가 같은 장면에서 오갔다) 휴대폰 값으로 쓰지 않는다(Unknown — 휴대폰 확인 필요).
- 자료를 tRPC 조회로 둔 것은 지도 프로토콜(유닛 위치처럼 자주 바뀌는 자료)과 그림 자료(늦게 바뀜)를 나누고, 다른 줄기와 겹치는 서버 2차맵 런타임·프로토콜 판을 건드리지 않으려는 것이다.

## 결과
- 좋은 점: 시설마다 알아볼 수 있는 모양(밭·통나무·갱도·굴뚝·첨탑·십자·기둥), 레벨·상태가 보인다. 밤에도 창 불빛으로 건물이 읽힌다. 건물 모델 위를 눌러도 건물 판이 열린다.
- 감수할 점: 그리기 호출 +5(건물 2 → 최대 7), 건물당 삼각형 약 12 → 약 376. 겉모습을 받기 전 약 1초는 일반 집으로 보인다. 레벨·상태 바뀜은 최대 30초 늦게 보인다.
- 다시 볼 조건: 휴대폰에서 도시 2차맵 p95가 33ms를 넘으면 먼 거리에서 작은 조각(창문·상자·깃발)을 빼는 거리 단계를 넣는다. 시설이 크게 늘면 종류별 모델을 콘텐츠 팩 `look` 칸(모델 종류·지붕 색)으로 옮긴다(그때 팩 판 올림). 지도 갱신에 겉모습을 실어야 할 만큼 자주 바뀌게 되면 프로토콜로 옮긴다.
