# 2차맵 지도 조작: 끌기·누르기 구분, 고른 유닛 따라가기, 확대 단계 표시

- 날짜: 2026-11-08
- 관련: docs/PLAN.md 5.7·14장, ADR `2026-10-28-s1-second-map.md`("카메라와 조작"), `2026-11-07-gather-objects.md`(6절 덧그림), `2026-11-07-unit-control.md`("바뀜 (기획 답 630~637)" 카메라 묶기), `2026-11-07-planet-view.md`(1·2절 확대 단계·끝 너머 밀기), `2026-11-07-play-flow.md`(WP9 [따라가기]), 기획 D-6018, 질문 `docs/questions/2026-11-08-map-input.md`(720~725)

## 배경
- 사용자 지적(2026-11-08, NAS 빌드 휴대폰 사진, 원문): "맵조작시 오브젝트가 걸려 드래그가 안되고 계속 오브트가 잘못눌린다." / "화면은 선택된 유닛으로 고정되어야함." / "화면 축소확대배율 표시 없음".
- 그 전 모습(Verified: 코드, main `a366ef2`):
  - 채집 오브젝트 표시(화면 가운데 가까운 40개)·건물 표시(12개)는 지도 위 HTML 단추였다(`pointer-events: auto`). 단추에 손가락을 대면 캔버스가 `pointerdown`을 받지 못해 끌기가 시작되지 않았다. 숲 2차맵은 표시가 빽빽해 거의 어디서나 걸렸다(통합 기록 `docs/worklog/2026/11/08-0748-feedback-batch-merge.md` — vision 시험은 표시를 피해서 끌게 고쳤다).
  - 땅을 누르면(엔진 누르기 판정 뒤 `onGroundTap`) 누른 칸 둘레 ±2 배치 칸(5×5칸, 약 29m — 휴대폰 처음 보기에서 약 160px 네모) 안에 오브젝트가 있으면 그 판을 열었다. 고른 유닛을 보내려고 누른 땅이 오브젝트 판을 열었다("계속 오브젝트가 잘못 눌린다").
  - 카메라는 목록에서 고를 때 한 번 그 자리로 갔을 뿐, 유닛이 걸어가면 화면 밖으로 나갔다.
  - 2차맵 확대 사다리는 "2차맵" 글자만 있었고 [+]·[−]는 거리 ÷ 2·× 2였다.

## 선택지
1. 끌기·누르기: (a) 표시 단추는 그대로, 단추에서 시작한 포인터를 캔버스로 넘김 / (b) 표시는 손가락을 받지 않고(`pointer-events: none`) 엔진 누르기 판정 뒤 화면 거리로 한 곳에서 고름 / (c) 표시를 WebGL로 그리고 엔진이 고름.
2. 누르기 차례: (a) 유닛 → 표시 → 땅 / (b) 표시 → 유닛 → 땅 / (c) 화면 거리가 가장 가까운 것.
3. 표시 보이기: (a) 지금대로(1m ≥ 1px일 때, 가운데 40개) / (b) 확대 4~5단계만 / (c) 고른 유닛 둘레만.
4. 따라가기 구현: (a) 화면(React)이 1초·프레임마다 `setView` / (b) 엔진 안 프레임마다(유닛 보간 자리로).
5. 따라가기를 끊는 손짓: (a) 끌기(누르기 거리 넘게)만 / (b) 끌기 + 두 손가락 확대 / (c) 어떤 손짓이든.
6. 2차맵 배율 표시: (a) 거리 한계를 로그 눈금으로 다섯 등분한 단계(1차맵과 같은 식) / (b) 고정 화면 폭(40·80·160…m) 단계 / (c) 축척 막대(m).

## 결정
### 1. 끌기와 누르기(1b, 2a, 3a)
- 엔진 조작(`packages/engine/src/camera/controls.ts`): 누르기 = 움직임이 누르기 거리(손가락 10px·마우스 5px) 안이고 0.5초 안에 뗀 한 손가락·왼쪽 단추(그대로). 두 손가락은 누르기가 아니다(그대로). 새로: 한 손가락 끌기가 누르기 거리를 넘으면 `onDragStart`를 한 번 부른다(따라가기 끊기).
- 채집 오브젝트 표시·건물 표시는 손가락·마우스를 받지 않는다(`gather.css` `pointer-events: none`). 표시 위에서 시작한 끌기도 지도를 끌고, 끄는 동안 표시가 눌리지 않는다(캔버스가 포인터를 붙잡는다).
- 누르기 차례(엔진 `onTap`): 유닛(화면 거리 22px + 실제 크기 몸) → 덧그림 층 `tap()`(새 `EngineLayer.tap`, `render/engineLayers.ts`) → 건물 모델(조각 상자, 건물 모델 줄기 `buildings/buildingView.ts pick` — 땅보다 앞이면 그 건물 칸) → 땅. 끌기는 누르기가 아니므로 건물 판도 열지 않는다. 채집 덧그림(`gather/gatherOverlay.ts`)은 마지막 프레임에 놓은 표시 자리에서 화면 거리 22px(누름 영역 44px의 반) 안 가장 가까운 표시의 판을 연다.
- 땅 누르기(`onGroundTap` → `gatherState.tapCell`)는 그 칸이 든 건물의 판만 연다. 칸 둘레 오브젝트는 잡지 않는다 — 오브젝트는 표시를 눌러야 열린다.
- 접근성: 표시는 그대로 단추다(Tab·Enter로 판, 읽는 이름 "… — 채집할 수 있음"). 누르는 크기 44px 규칙은 DOM 상자가 아니라 화면 반경으로 지킨다(단추 상자도 44px 그대로라 포커스 고리는 같다).
- 표시 보이기는 지금대로(3a). 문제는 표시 수가 아니라 표시가 손가락을 받는 것이었다. 고른 유닛 둘레만 보이기 등은 확인 대기(720).
- 같은 규칙을 2차맵 위 다른 HTML 표시에도 쓴다: 표시는 `pointer-events: none`, 누르기는 그 덧그림 층의 `tap()`.

### 2. 고른 유닛 따라가기(4b, 5a)
- 엔진 `follow(unitId | null, { instant })`(`camera/cameraGlide.ts`): 프레임마다 그 유닛의 지금 자리(서버 시계로 보간)로 목표점이 지수 감쇠(160ms)로 붙는다. 멀리 있는 유닛은 약 0.5초에 걸쳐 날아가고, 걷는 유닛은 거의 붙어서 간다. 동작 줄이기면(`instant`) 바로 붙는다. 목표는 보기 범위(630)로 묶고 가는 중간은 묶지 않는다(떨어진 두 원 사이에서 튀지 않게).
- 끊기: 끌기가 누르기 거리를 넘으면(`onDragStart`), 또는 `setView`(다른 곳으로 옮김) — 엔진이 `onFollowBreak(unitId)`를 부른다. 따라가는 동안 끌기는 누르기 거리를 넘기 전에는 화면을 움직이지 않고(누르다 떨려도 흔들리지 않게), 넘으면 그 점에서 다시 붙잡아 끈다(튐 없음). 두 손가락·휠 확대·회전과 [+]·[−]는 끊지 않고 화면 가운데(그 유닛) 기준이다.
- 화면(`apps/game/src/map/UnitFollow.tsx`): 다룰 수 있는 유닛(내 유닛 — 명령을 못 하는 머묾·포로·중태도 —, 운영자 모드면 아무 유닛)을 고르면 따라간다. 남의 유닛은 따라가지 않는다(플레이어 카메라는 내 유닛 둘레, 630). 끊기면 아래 판에 [따라가기](2차맵 사이 이동의 [따라가기]와 같은 글·모양, 메시지 키 `map_travel_follow`)가 보이고, 누르거나 목록·지도에서 그 유닛을 다시 고르면 다시 따라간다. 고르기를 풀면 그만. [내 사이보그]는 고른 유닛이 내 사이보그면 다시 따라가고, 아니면 그 자리로 옮긴다(따라가기는 끊김).
- 목록에서 고르면 그 자리로 뛰지 않고 따라가기로 날아간다(엔진이 아직 모르는 유닛이면 목록의 칸으로 한 번).
- 시험 값: `.map-screen[data-follow]` = `on`·`lost`.

### 3. 2차맵 확대 단계(6a)
- 엔진 `camera/secondMapZoom.ts`(순수 함수): 1차맵(`planet/zoomStages.ts`)과 같은 식 — 지금 거리 한계 [가장 가까이(화면 짧은 변 40m), 가장 멀리(2차맵 전체, 플레이어는 내 유닛 원 지름 × 2까지)]를 로그 눈금으로 다섯 등분, 1 = 가장 멀리 ~ 5 = 가장 가까이. 행성 모듈을 가져오지 않으려고 따로 둔다(2차맵 진입점에 행성 타일 코드가 묶이지 않게).
- `zoomStep`: 이웃 단계의 대표 거리(1단계 = 가장 멀리, 2~5단계 = 띠의 기하 평균)로 약 0.3초 미끄러진다(로그 거리 지수 감쇠 90ms). 움직이는 중이면 그 목표에서 센다(거듭 누르면 한 단계씩). 가장 멀리에서 [−] 한 번 더 = 이 2차맵 자리의 1차맵 5단계(D-6018 그대로), 가장 가까이에서 [+]는 그대로. 손가락·휠 확대는 미끄러짐을 멈춘다.
- `onZoomStage`·`stats().zoomStage`: 사다리(`ZoomLadder.tsx`)가 "2차맵 3/5" + 점 다섯을 보인다(1차맵 "1차맵 3/5"과 같은 모양, 새 메시지 키 `zoom_caption_local` ko "2차맵"·en "Local"). `data-rung`은 그대로 `local`, `data-stage`를 더했다.
- 휴대폰 세로(390×844) 화면 짧은 변 기준 단계(Assumed: 배치 칸 약 5.85m, 내 유닛 원 반지름 40칸 ≈ 234m로 계산): 플레이어 5단계 40~75m, 4단계 ~141m, 3단계 ~265m, 2단계 ~498m, 1단계 ~936m. 처음 화면(70m)은 5단계. 운영자(묶음 없음, 2차맵 한 변 약 1,500m)는 40~89·~197·~438·~973·~2,160m.
- 축척 막대(m)는 넣지 않았다(확인 대기 721).

### 판·마이그레이션
- 프로토콜·콘텐츠 팩·SIM 판 바뀜 없음, 마이그레이션 없음. 엔진 API에 `follow`·`onFollowBreak`·`onZoomStage`·`stats().zoomStage`·`stats().following`·`EngineLayer.tap`이 늘었다(쓰지 않는 화면은 그대로).

## 이유
- 1b: 한 곳에서 고르면 끌기·두 손가락·누르기 판정이 엔진 조작 하나로 모인다(유닛 고르기가 이미 그렇다). 1a는 단추마다 포인터 붙잡기를 흉내 내야 하고 브라우저 기본 손짓(`touch-action`)과 겨룬다. 1c는 글자·포커스(접근성)를 잃는다.
- 2a: 지적이 "오브젝트가 잘못 눌린다"이고, 유닛은 적고(내 유닛 수십) 오브젝트는 많다(2차맵 하나에 많아야 1,024개). 유닛을 먼저 보면 오브젝트가 유닛 고르기를 빼앗지 않는다.
- 4b: 유닛 자리는 엔진 안에서 서버 시계로 프레임마다 보간된다. 화면이 `setView`를 부르면 한 프레임 늦고 React를 프레임마다 깨운다(PLAN 5.7 "고빈도 상태는 엔진 안").
- 5a: 지도 앱 길 안내와 같은 조작이다(Assumed: 흔한 조작) — 손으로 끌면 둘러보기, 확대는 따라가며. 확대까지 끊으면 따라가며 가까이 보기를 할 수 없다.
- 6a: 1차맵과 같은 사다리 모양과 같은 느낌([+] 한 번 = 같은 거리 비). 6b는 화면 크기·보기 범위에 따라 단계 수가 바뀌어 "n/5"로 보일 수 없다.
- Verified(화면 시험 `e2e/map-input.spec.ts`, 헤드리스 Chromium 마우스): 표시 위에서 시작한 끌기 → 카메라가 움직이고 고른 것·판 없음, 표시를 짧게 누르면 그 오브젝트 판, 고른 사이보그가 걸어가는 동안 카메라 목표 = 사이보그 자리, 끌면 `lost` → [따라가기] → 다시 붙음, 사다리 단계 [−]·[+].

## 결과
- 표시 위에서도 지도가 끌리고, 끄는 중 표시·유닛이 눌리지 않는다. 두 손가락은 고르지 않는다. 유닛을 보내려고 누른 땅이 오브젝트 판을 열지 않는다(표시 22px 안을 눌러야 연다).
- 고른 내 유닛이 화면 가운데에 머문다. 끌면 둘러보고 [따라가기]로 돌아온다.
- 2차맵 사다리가 1차맵처럼 단계를 보인다.
- 감수할 점:
  - 채집 중인 내 유닛 바로 옆 오브젝트 표시는 유닛이 먼저 골라진다(조금 떨어져 누르거나 키운다).
  - 표시 위에서 마우스 커서가 손가락 모양이 되지 않는다(누르기는 캔버스가 받는다).
  - 따라가는 동안 끌기 첫 10px는 화면이 움직이지 않는다.
  - `SecondaryMapScreen.tsx` 662줄, `secondMapEngine.ts` 612줄(600줄 경고). 다음에 더하는 줄기는 나눈다.
- 다시 볼 조건: 질문 720~725 답, 여러 유닛 고르기(633)가 생기면 따라가기 대상(가운데·묶음), 실제 휴대폰에서 누르기 거리 10px가 맞는지(헤드리스 시험은 마우스만).
