# 운영자 콘솔: 유저·NPC·유닛 감시와 통제, 운영 역할 둘과 권한 체크박스

- 상태: 확정 (범위·역할 구성은 사용자 결정 2026-11-08. 3절 tRPC 예외·4절 유닛 지우기 미룸은 사용자가 맡김 — 2026-11-08 "알아서 해달라")
- 날짜: 2026-11-08
- 관련: docs/PLAN.md 4.8(계정·권한), ADR `2026-10-28-auth-and-accounts.md`(역할·권한 표), `2026-11-02-dev-ui.md`(개발 화면 층), `2026-11-07-unit-control.md`(운영자 유닛 조종), `2026-11-08-world-reset.md`(남길 표), 기획 `docs/design/70_BM_LiveOps.md` D-7021(운영자 개입은 원장의 별도 사건, 관리자 화면에서만)·D-7025(관리자 감시 강하게, 자동 경보)

## 배경
- 사용자 요청(2026-11-08, 원문): "운영자 기능 추가 · 목적 : 모든 유저와 유닛을 통제, 감시 하는 모니터링 기능 · 기능 · 유저와 npc를 분리하여 통제 · 모니터링 정보. 방대한 자료는 이동하여 조회(스탯이나 스킬 보유 아이템 등등). 소속이나 위치, 대략적인 자산 등등 유용한 정보들 최대한 추가. · 그 외에 전문적인 운영자용 기능들 제시 추가."
- 범위 질문의 답(2026-11-08, 원문): "감시+계정+월드 통제. 운영진도 권한을 분류하자. 개발자는 전체, 운영자는 2종류로 감시+가벼운통제 정도와 강한 통제까지 가능하게. 가능한 권한을 체크 박스처럼 부여하기도할 수 있게 한다." 추가 기능은 "다양한 기능 알아서, 감사 기록 조회, 서버·월드 현황판, 경제 감시, 세력·도시 목록".
- 그전에는 관리자 화면(`/admin`)에 계정 역할 바꾸기와 운영 스위치(설정 칸)만 있었다. `gm` 역할은 이름만 있었다.

## 결정

### 1. 역할과 운영 권한
- 역할 `gm_lead`를 더한다(`@terra/shared` `ROLES` = player · gm · gm_lead · dev · admin). 계정 역할 문자열에 저장되는 값이라 이름을 다시 쓰지 않는다.
- 운영 권한 13개(`@terra/shared/ops` `OPS_PERMISSIONS`, 계정에 저장되므로 한 번 쓴 ID는 다시 쓰지 않는다):
  - 감시: `view_players`·`view_npcs`·`view_economy`·`view_audit`·`view_server`
  - 가벼운 통제: `account_kick`(세션 모두 지움)·`account_ban`(정지·해제, 사유·기간)·`unit_stop`·`unit_rescue`(가장 가까운 안전 도시로)
  - 강한 통제: `unit_heal`(부상 0)·`unit_teleport`(같은 2차맵 안 칸)·`ledger_grant`(원장 지급·회수)
  - 권한 관리: `manage_grants`(다른 계정에 체크박스 주기)
- 역할 기본: `gm` = 감시 + 가벼운 통제, `gm_lead` = + 강한 통제, `dev`·`admin` = 전체(권한 관리 포함, 사용자 "개발자는 전체").
- 체크박스: 표 `ops_grants`(계정마다 더 준 권한 목록). **더하기만** 한다(역할 기본은 뺄 수 없다). 콘솔 역할(gm·gm_lead·dev·admin)이 없는 계정에는 효과가 없다(기본 거부). 자기 권한은 스스로 못 바꾼다.
- 판정은 Better Auth 권한 표(`src/auth/permissions.ts`)와 따로 둔다(`src/ops/access.ts`): 그 표는 역할 단위라 계정마다 더하기를 못 한다. 계정 관리(역할 바꾸기)는 그대로 admin만 한다.

### 2. 화면 `/ops`(운영자 콘솔)
- 주소 표 새 줄 `ops`(여는 역할 = gm·gm_lead·dev·admin, `RouteAccess` "ops"). 개발 화면 층(네온 다크·라이트). 사이드 메뉴 시스템 묶음에 링크.
- 탭: 현황 · 유저 · NPC 세력 · 도시 · 유닛 · 경제 · 감사 기록 · 권한 부여. 탭은 내 권한(`ops.me`)으로 보인다.
- 유저와 NPC를 탭으로 나눈다. 유닛 탭도 주인 종류(유저·NPC 세력)로 거르고, 유저 유닛은 `view_players`, NPC 유닛은 `view_npcs`가 있어야 본다.
- 방대한 자료는 줄을 눌러 상세 판(넓은 폭은 오른쪽, 좁은 폭은 아래)으로 옮겨 본다: 유저(계정·세션·정지·사이보그 스탯/성장 K/속성/신앙·자산·유닛·보유 물건·스킬·최근 감사 기록), 세력(체제·기술·성향·도시·전쟁·자산·소속 유저·유닛), 유닛(자리·주인·직무·부상·휴먼·생명 수치·스킬·물건·화물).
- 현황 탭의 자동 경보(D-7025): 월드 준비 안 됨, 불변 조건 위반, 24시간 기기 오류 ≥ 50, RSS ≥ 900MB(S3 규모 시험 기준). 기준은 [임시]이고 기획 기준이 생기면 바꾼다.
- 경제 탭: 자산 총량(주체 보유·시스템 계정·보유자 수), 고른 자산 상위 20 주체, 최근 거래 5,000건 안의 큰 항목, 운영자 지급·회수 거래.

### 3. 통제는 tRPC 쓰기로 받는다(AGENTS.md 4장 "게임 상태 명령은 WebSocket" 규칙의 예외)
- 유닛 통제와 원장 지급은 게임 상태를 바꾸지만 `ops.*` tRPC 쓰기로 받는다.
- 이유: 서버는 한 프로세스이고, tRPC 처리기도 같은 메모리 월드 객체와 같은 쓰기 대기열을 쓴다(판정·저장 경로가 같다, Verified: `src/ops/world.ts`가 `SecondMap.halt`·`relocateToSafety`·`setCondition`·`transferOut/In`, 원장 `post` → `writer.durable()`을 부른다). 플레이어 명령이 아니라 감사 기록을 남기는 운영 도구다. WebSocket으로 하면 프로토콜 메시지 추가·`PROTOCOL_VERSION` 올림(PROTECTED)이 필요하다.
- 감수할 점: 상태를 바꾸는 길이 둘이 된다. 운영자 통제는 `src/ops/`에만 둔다.

### 4. 유닛 지우기는 이번에 넣지 않는다
- 종류마다 함께 정리할 자료가 다르다: NPC 휴먼은 NPC 사회 런타임 거울(`npc/persist.ts`가 지운다), 사이보그 유닛은 유전자·화물 상속(`fusion/geneCommands.ts`), 보유 물건·스킬·신앙 줄. 2차맵 `removeUnit`만 부르면 거울과 어긋난다(Assumed: 코드 읽기, 실행 안 함). 종류마다 안전한 지우기를 만들 때 권한 `unit_remove`를 끝에 더한다.
- 더 본 것(2026-11-08): NPC 휴먼의 사망은 세력·사회 규칙 안(`packages/sim/src/simulator/society.ts` 수명 처리 → 안쪽 `removeUnit`: 지갑 상속·예약 취소·도시 인구 고리)에서만 일어나고, 그 함수는 밖으로 열려 있지 않다. 운영자 지우기를 만들려면 판정 코어(PROTECTED)에 길을 새로 내야 한다. 멈추기·구조·치료·순간이동으로 끼임·이상 유닛은 다룰 수 있으므로, 실제 운영에서 지우기가 필요한 사례가 생길 때 판정 코어 ADR과 함께 만든다.

### 5. 원장 지급·회수(D-7021)
- 주체의 위치 없는 계정 ↔ 시스템 계정 `ops:<자산>`. 거래 종류 `ops_grant`(+)·`ops_revoke`(−), 열쇠 `ops:<요청 UUID>`(두 번 들어가지 않는다). 커밋까지 기다린다. 회수는 잔고까지만(원장이 `insufficient`로 거절).
- 운영자 ID·사유(필수)·양·거래 ID는 감사 기록(`audit_log`, `actor_kind` 'admin', `action` `ops.grant`·`ops.revoke`)에 남긴다. 원장 거래 표에는 그 칸이 없다. 원장 코드(PROTECTED)는 고치지 않았다(부르기만 한다).

### 6. 감사 기록
- 통제는 모두 감사 기록을 남긴다: `ops.kick`·`ops.ban`·`ops.unban`·`ops.unit.<stop|rescue|heal|teleport>`·`ops.grant`·`ops.revoke`·`ops.set_grants`. 사유는 `meta.reason`.
- 운영자 동작의 `actor_kind`는 'admin'이다(표 검사 조건 'user'·'admin'·'cli'·'system'을 넓히지 않았다). 누가 했는지는 `actor_id`로 본다.
- admin 계정 정지는 admin만 한다(운영자가 관리자를 잠그지 못하게). 자기 계정은 정지·세션 끊기를 못 한다.

## 이유
- 역할 둘 + 체크박스: 사용자 요구 그대로다. 체크박스를 역할 위 더하기로만 두면 "역할 기본은 늘 있다"가 지켜지고 판정이 단순하다.
- 화면을 `/admin`에 붙이지 않고 `/ops`로 뺀 것: `/admin`은 admin 전용(계정 관리)이라 gm에게 열 수 없다.
- 조회는 DB 기준(유저·세력·도시·물건·스킬·감사 기록)과 메모리 월드 기준(유닛 자리·잔고)을 섞는다. 쓰기 대기열이 커밋하기 전 몇 초는 DB 쪽이 늦을 수 있다.

## 결과
- 좋은 점: 운영진이 배포 없이 유저·NPC·유닛을 보고, 정지·세션 끊기·유닛 구조·치료·이동·자원 보정을 하고, 모든 통제가 감사 기록에 남는다.
- 감수할 점: 유닛 목록은 조회마다 메모리 월드를 한 번 훑는다(10만 유닛이면 조회 한 번에 수십 ms, Assumed: 재지 않음). 열린 WebSocket은 세션을 지워도 세션 조회 캐시(`SOCKET_VIEWER_TTL_MS`)가 끝날 때까지 이어진다.
- 다시 볼 조건: 이상 거래 자동 표시 기준(기획 70 "시장가와 크게 다른 가격, 같은 IP·계정 사이 반복 이동")이 정해지면 경제 탭에 넣는다. 운영자가 많아지면 감사 기록 `action`·`at` 색인을 더한다.
