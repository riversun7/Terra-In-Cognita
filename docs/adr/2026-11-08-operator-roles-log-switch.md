# 운영 역할 다시 나눔(관리자·운영자), 조회 감사 기록 스위치, 권한 부여는 개발자 영역, 읽기 쉬운 감사 기록

- 상태: 확정 (사용자 결정 2026-11-08)
- 날짜: 2026-11-08
- 관련: ADR `2026-11-08-operator-console.md`(일부 대체 — 1·2·6절), `2026-10-29-planet-editor-stage1.md`(정의 조회 감사 기록), `2026-11-02-dev-ui.md`

## 배경
운영자 콘솔을 올린 뒤 사용자 지적(2026-11-08, 원문):
1. "관리자 페이지에 로그를 켜고 끌수 있게 스위치를 추가하자.(기본 꺼짐 상태) 개발단계에서 불필요한 데이터 쌓임 방지. 관리/개발/운영자 중 운영자 2가지를 관리자/운영자(약한통제)로 다시 분리한다 관리자와 운영자가 겹친다."
2. "스크린샷 감시기록이 직관적으로 알아보기 힘들다. 사람 운영자가 보기 쉽게, 필터로 특정 항목을 고를 수 있게 해달라."
3. "권한부여는 개발자가하는 기능이다. 운영자는 불가능. 페이지 이동이나 제거"
- 감사 기록 화면에는 `second_map.observe`(관리자가 2차맵 전체 보기를 켤 때마다 한 줄) 같은 조회 기록이 대부분이었고, 동작 이름·UUID·JSON 원문이 그대로 보였다.

## 결정

### 1. 역할
- `gm_lead`를 없앤다(`ROLES` = player · gm · dev · admin). 이름은 다시 쓰지 않는다. 저장된 `gm_lead`는 모르는 이름이라 권한 없음으로 읽힌다(Verified: `parseRoleString`이 모르는 이름을 버림, 하루 동안만 있었던 역할).
- 운영 권한 기본: **운영자(gm)** = 감시 + 약한 통제, **관리자(admin)** = 감시 + 약한 통제 + 강한 통제 + 로그 스위치, **개발자(dev)** = 전체.
- 권한 부여(`manage_grants`)는 개발자만 한다. 관리자도 못 한다(계정 역할 바꾸기는 그대로 관리자 화면에서 admin이 한다).
- 화면 이름: `gm` = "운영자(약한 통제)", `admin` = "관리자".

### 2. 조회 감사 기록 스위치(기본 꺼짐)
- 표 `ops_switches`(id·enabled, 줄이 없으면 꺼짐). 스위치 `view_audit` 하나: `second_map.observe`, `planet_editor.read_definitions`를 쓸지.
- 운영 권한 `log_switch`(끝에 더함, 관리자·개발자 기본). tRPC `ops.switches.list`·`set`, 관리자 화면(`/admin`)의 "로그 스위치" 판. 바꾸면 감사 기록 `ops.switch`(스위치와 상관없이).
- 계정·운영자 통제·편집 저장·설정 칸 기록은 **늘 남긴다**(책임 기록이라 끄지 않는다). 사용자가 말한 "로그"는 화면에 쌓여 보인 조회 기록으로 읽었다.
- 행성 정의 조회 기록: ADR `2026-10-29-planet-editor-stage1.md`는 시드가 든 자료를 보내기 전에 기록을 남기게 했다. 이 스위치가 켜져 있을 때만 그 규칙이 돈다(개발 단계 기본 꺼짐). 출시 전에 켜 둘지 다시 본다.
- 서버가 켤 때 한 번 읽어 메모리에 둔다(서버는 한 프로세스). 읽지 못하면 꺼짐.

### 3. 권한 부여 화면 위치
- 운영자 콘솔의 탭에서 개발자 영역 `/dev/ops-grants`로 옮긴다. 주소 표 새 접근 종류 `RouteAccess` "dev"(개발자만). 개발자 홈은 열 수 없는 도구 줄을 숨긴다.

### 4. 읽기 쉬운 감사 기록
- 줄마다: 시각(월·일 + 시각), 분류 표지, 한 일(사람 말, 예: "역할 바꿈"), 한 사람(아이디, 시스템·명령줄), 대상(계정 아이디 → 유닛 # → 세력 # → ID 앞 8자), 내용 한 줄(예: "플레이어, 관리자 → 플레이어", "credit 500 (잔고 600) · 사유: 보상"), [원본]을 누르면 JSON.
- 거르기: 분류 칩(전체 + 계정·운영자 통제·2차맵·설정 칸·편집기·행성·항성계·세계, 여러 개), 한 사람 아이디, 대상 아이디, 동작 앞부분(고급). 분류는 `@terra/shared/ops` `AUDIT_CATEGORIES`(동작 이름 앞부분) 한 곳에서 서버·화면이 같이 쓴다.
- 서버 조회는 대상 계정 아이디를 함께 준다(`targetLoginId`).

## 이유
- 관리자와 강한 운영자는 하는 일이 같았다(사용자 지적). 역할 하나를 빼면 권한 표가 단순해진다.
- 조회 기록만 끄면 개발 단계에 쌓이는 줄이 거의 없어지면서, 바꾼 것의 기록(누가 무엇을 바꿨나)은 남는다.

## 결과
- 좋은 점: 감사 기록을 운영자가 읽을 수 있다. 개발 DB에 조회 줄이 쌓이지 않는다.
- 감수할 점: 스위치를 끈 동안 누가 2차맵 전체 보기·행성 정의를 봤는지는 남지 않는다(서버 로그 `second map observe` 한 줄은 남는다).
- 다시 볼 조건: 출시 전에 `view_audit`를 켜 둘지 정한다. 감사 기록 분류는 새 동작 앞부분이 생기면 `AUDIT_CATEGORIES`에 더한다.
