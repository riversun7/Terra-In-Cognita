# 세력 정체성(이름·약어·시그니처 컬러)과 화폐 표시(이름·기호·3글자 약어), 운영자 콘솔 세력 관리·화폐 탭

- 상태: 확정 (사용자 결정 2026-11-09)
- 날짜: 2026-11-09
- 관련: ADR `2026-11-08-operator-console.md`, `2026-11-08-operator-roles-log-switch.md`, `2026-10-31-economy-core.md`(나라 화폐), `2026-11-07-play-flow.md` "WP6 나라 화폐", 콘텐츠 팩 `nation_presets`

## 배경
- 사용자 요청(2026-11-09, 원문): "세력 관리 페이지 추가 · 세력의 명칭/약어, 시그니처 컬러, 화폐(이름과 심볼표시, 3글자 약어. 고유하게) · 민주주의/독재 등의 상태, 도시 수 등등 · 그외에 관리 및 모니터링 편의요소 구현."
- 저장 위치 질문의 답(원문): "세력 생성시 결정하고 npc나 일부는 프리셋이나 기본값 제공, 관리자가 수정도 가능".
- 그전: 세력 표에는 이름 칸이 없었고(화면 이름 = 팩 국가 프리셋 이름, `npc/nations.ts nationName`), 화폐는 프리셋에 코드·이름만 있었다. 반란·새 마을 세력은 따르는 나라의 화폐를 쓴다(`npc/currency.ts`).

## 결정

### 1. 저장(DB, 세계 표)
- `faction_profiles`(세력마다): 이름(1~24자), 약어(글자·숫자 2~5자, 세계 안에서 하나 — 대소문자 무시 고유 색인), 시그니처 컬러(#rrggbb), 출처(preset·default·admin).
- `currency_profiles`(원장 화폐 자산마다 — `cur:<코드>`, 기준 통화): 이름(1~24자), 기호(1~3자), 약어(영어 대문자 3자, 세계 안에서 하나), 출처.
- 둘 다 세계 표다(시험 세계 새로 시작에서 지운다). 세력 행이 지워지면 정체성도 지운다.
- 규칙 한 곳: `@terra/shared/factionProfile`(팩 검사·서버 검사·화면 입력이 같이 쓴다).

### 2. 처음 정하기(한 번)
- 고정 NPC 나라(자기 국가 프리셋이 있는 세력) = 프리셋의 이름·`shortName`·`color`, 화폐 = 프리셋 `currency.name`·`symbol`·`ticker`.
- 그 밖(반란·새 마을·유저 세력) = 기본값: 이름 "<따르는 나라 이름> #ID", 약어 "F<ID 36진수>", 색 = 기본 색 표 16색(세력 ID로 고름). 화폐는 따로 만들지 않고 따르는 나라 화폐를 쓴다(자기 프리셋 → 반란 부모 → 종주 → 태어날 때 부모, 없으면 기준 통화 — 서버 화폐 규칙과 같은 차례).
- 약어·티커가 겹치면(프리셋끼리 겹침 등) 처음 정할 때 겹치지 않는 기본값으로 바꾼다.
- 언제: 운영자 콘솔이 세력·화폐·유저·유닛·도시·경제 자료를 처음 읽을 때 모자란 줄을 정한다(멱등, `on conflict do nothing`). 기본값은 세력 ID·프리셋으로만 정해져 언제 정하든 같다. 서버가 켤 때 정하지는 않는다(`app.ts` 줄 수 상한 — 다음에 세력이 생기는 곳에 붙인다).
- 한 번 정한 값은 다시 정하지 않는다(프리셋을 나중에 바꿔도 세계 값은 그대로 — 관리자가 고친다).

### 3. 관리자 수정
- 운영 권한 `faction_edit`(강한 통제 — 관리자·개발자 기본, 운영자는 체크박스로만). tRPC `ops.npcs.updateProfile`·`ops.currencies.update`. 겹치면 `short_taken`·`ticker_taken`, 규칙에 안 맞으면 `invalid`. 감사 기록 `ops.faction_profile`·`ops.currency_profile`(이전·이후·사유).

### 4. 팩
- `nation_presets`에 선택 칸 `shortName`·`color`, `currency.symbol`·`currency.ticker`. 16개 나라에 임시 값(N01~N16, 색 16개, 기호 ₳…₰, 약어 PCA~PCP). core@58.

### 5. 운영자 콘솔
- "세력" 탭(옛 "NPC 세력"): 표지(색·약어), 이름, 종류, 체제, 기술, 도시, 인구/주거, 평균 만족도, 유닛, 유저, 전쟁·불가침·봉신, 화폐(기호·약어), 국고(그 화폐 잔고). 요약 띠(살아 있는 세력·NPC·유저 세력·체제별 수·전쟁 쌍), 거르기(종류·체제·글자·사라진 세력), 머리 칸 정렬, CSV 내보내기(기기 안에서 만든다).
- 세력 상세: 정체성 띠, 화폐·국고·인구·만족도·외교·정체성 출처, [정체성 고치기](이름·약어·색 고르기·사유).
- "화폐" 탭: 기호·약어·이름·자산 코드·찍는 나라·쓰는 세력 수·보유 합·보유자, 줄에서 고치기.

## 이유
- 사용자 답 그대로: 세력이 생길 때 정하고(프리셋·기본값), 관리자가 고친다. 세계마다 다를 수 있는 값이라 DB에 둔다.
- 화폐 정체성을 세력이 아니라 화폐 자산마다 두면, 같은 화폐를 쓰는 반란 세력과 부모 나라가 같은 기호·약어를 보인다(약어 고유성이 자연스럽다).

## 결과
- 좋은 점: 운영자가 세력을 한 표로 비교하고 정체성을 고칠 수 있다.
- 감수할 점: 게임 화면(세력 화면·지도·랭킹)은 아직 이 표를 읽지 않고 프리셋 이름을 쓴다 — 다음 단계에서 잇는다. 정체성 값이 정해지는 때가 "처음 보일 때"다(세력 생성 코드에 붙이지 않음).
- 다시 볼 조건: 유저가 세력을 만드는 기능이 생기면 그때 이름·약어·색을 유저가 고르게 하고(같은 규칙·고유성), 화폐를 만드는지 정한다.
