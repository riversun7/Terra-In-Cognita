# 크리처 원형 초상화 좌표: 단위와 계산을 한 곳에(`@terra/shared/portraitCrop`)

- 상태: 제안 (구현함. 사용자 확인 뒤 확정)
- 날짜: 2026-11-10
- 관련: 작업 기록 `docs/worklog/2026/11/08-1650-creature-editor.md`(크리처 편집기), `docs/worklog/2026/11/10-2150-creature-portrait.md`, ADR `2026-11-02-dev-ui.md`(개발 화면 층), 팩 스키마 `packages/content/src/schema/creatures.ts` `portraitCrop`

## 배경
- 사용자 보고(2026-11-10, 원문): "크리쳐에디터에 초상화 선택범위가 오차가 심하다".
- 크리처 초상화는 잘라 낸 그림 파일 없이 원본 그림 위의 원 `portraitCrop: { cxPm, cyPm, radiusPm }`(‰, 정수)만 저장한다(팩 `content/core/creatures.json` 91종, 그 세계 덮어쓰기).
- 고치기 전에는 고르는 쪽(선택기의 원)과 그리는 쪽(배지)이 저마다 계산했고 서로 달랐다(Verified, 화면 측정 — 작업 기록의 표):
  - 선택기의 원은 가운데 좌표를 **왼쪽 위 모서리** 자리로 썼다 → 보이는 원이 저장된 원보다 오른쪽 아래로 반지름만큼 어긋났다(512화소 그림·반지름 300‰에서 가로·세로 153.6화소씩).
  - 선택기는 그림을 정사각 상자에 늘려 그렸고(`object-fit: fill`), 배지는 잘라 채웠다(`cover`) → 정사각이 아닌 그림에서는 둘이 다른 곳을 가리킨다(지금 그림 91장은 모두 정사각이라 드러나지 않았다).
  - 반지름 ‰가 "무엇의 ‰인지" 적힌 곳이 없었다.

## 선택지
1. 선택기의 CSS만 고친다(원에 `translate(-50%, -50%)`).
2. 저장 형식은 그대로 두고 단위를 못 박은 뒤, 고르는 쪽과 그리는 쪽이 같이 쓰는 순수 함수 모듈을 둔다.
3. 저장 형식을 그림 화소(정수)로 바꾼다.

## 결정
2번.
- 저장 형식은 그대로다(옮길 자료 없음). 뜻만 못 박는다:
  - `cxPm` = 그림 **너비**의 ‰(0 = 왼쪽 끝), `cyPm` = 그림 **높이**의 ‰(0 = 위 끝), `radiusPm` = 그림 **너비**의 ‰.
  - 원의 기준점은 가운데다. 원이 그림 밖으로 나가도 된다(나간 곳은 빈 바탕).
- 계산은 `packages/shared/src/portraitCrop.ts` 하나에 둔다. 모두 그림 화소 원(`portraitCircle`)을 거친다.
  - 그리는 쪽: `portraitImageRect`(한 변이 정해진 정사각 상자 안 그림 자리), 그것을 CSS로 옮긴 `portraitImageStyle`.
  - 고르는 쪽: `boxPointToImage`·`imagePointToBox`(화면 상자 ↔ 그림 화소), `portraitRingRect`(원 테두리, 왼쪽 위 기준 네모), `portraitCropFromCircle`(그림 화소 → ‰), `nudgePortraitCrop`(그림 화소만큼 옮기기).
- 크리처 초상화를 그리는 곳은 이 모듈만 쓴다. 지금은 `CreatureTokenBadge`(편집기 목록·상세 머리·미리보기) 하나다. 맵 토큰 등 새로 그리는 곳도 `portraitImageRect`(캔버스·텍스처)나 `portraitImageStyle`(DOM)을 쓴다.
- 배지의 CSS는 상자 가운데(`left·top: 50%`)에서 그림 자기 크기의 %만큼 당긴다(`translate(-cx%, -cy%)`, `height: auto`). 그림 비율·상자 크기를 몰라도 `portraitImageRect`와 같은 자리가 된다. `background-position`의 %는 쓰지 않는다(상자와 그림의 같은 % 점을 맞추는 값이라 선형 이동이 아니다).
- 선택기는 포인터 위치를 이벤트마다 그림 요소의 지금 `getBoundingClientRect()`로 바꾼다. 그림 상자는 테두리·안쪽 여백이 없고 그림 비율 그대로다(테두리는 바깥 틀이 든다).

## 이유
- 1번은 지금 그림(정사각)에서는 맞지만 계산이 여전히 두 곳에 있어 다음에 그리는 곳(맵 토큰)이 또 어긋날 수 있다.
- 3번은 그림을 다른 크기로 바꾸면 좌표가 틀어진다. ‰는 그림 크기와 무관하다. 정밀도도 충분하다: 반올림 오차 0.5‰ = 너비 1,024화소 그림에서 0.51화소(Verified, 단위 시험 `portraitCrop.test.ts`).
- 반지름을 너비의 ‰로 한 까닭: 배지 CSS가 그림 비율을 몰라도 된다(너비 % 하나로 크기가 정해진다). 짧은 변 기준이면 그리는 쪽이 그림을 읽은 뒤에야 자리를 정할 수 있다. 지금 91장은 정사각이라 어느 쪽이든 값이 같다(Verified, 파일 머리: 512×512 89장, 1024×1024 2장).
- 고친 뒤 고른 자리와 저장 값의 차이는 그림 화소 1 미만이다(Verified, `e2e/creatures.spec.ts`: 1440 마우스, 확대 150%, 390 터치, 300×200 그림).

## 결과
- 범위 상수가 두 곳에 있다: 팩 스키마(`creaturePortraitCropSchema`)와 `PORTRAIT_CROP_LIMITS`. `@terra/shared`는 `@terra/content`를 가져올 수 없어서다. `portraitCrop.test.ts`가 편집기 한계(`CREATURE_LIMITS`)와 같은지 본다. 팩 스키마 범위를 바꾸면 셋을 함께 바꾼다.
- 너비가 1,000화소를 넘는 그림은 1화소가 1‰보다 작다 → 화살표 키 한 번이 1‰(1,024화소 그림에서 1.02화소)다. 2,000화소를 넘는 그림에서 1화소 정밀도가 필요해지면 저장 형식을 다시 본다.
- 정사각이 아닌 그림에서 `radiusPm`은 너비 기준이다. 세로로 긴 그림은 500‰(너비 전체)까지, 가로로 긴 그림은 높이를 넘는 원도 고를 수 있다(넘친 곳은 빈 바탕).
