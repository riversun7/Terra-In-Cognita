# 편집기 입력 조작(수 조작 칸·분포 막대·표 묶음 바꾸기)

- 상태: 제안
- 날짜: 2026-11-10
- 관련: docs/PLAN.md 14장(편집기 입력 조작 줄), ADR `2026-11-01-dev-settings-panel.md`·`2026-11-01-item-editor.md`·`2026-11-01-skill-editor.md`·`2026-11-02-building-editor.md`·`2026-11-01-balance-screen.md`·`2026-11-02-dev-ui.md`

## 배경

사용자 지적(2026-11-10, 원문): "에디터 편집기들이 전체적으로 ux,ui가 직관적이지 않고 조작이 매우 불친절하다. 확률을 수치를 직접하나하나 써야하는 등 밸런스조절 어려움."

개발 편집기(`/dev/tuning`·`/dev/gather-tiers`·`/dev/items`·`/dev/skills`·`/dev/buildings`·`/dev/creatures`·`/dev/effects`·`/dev/balance`)의 수 칸은 모두 글자 칸이었다. 값을 바꾸려면 칸마다 숫자를 쳐야 했고, 합이 정해진 확률표(1차 생산 티어 확률, 구간마다 합 1000‰)는 한 칸을 고치면 합이 틀려 [적용]이 막혔다. 레벨·등급 표는 줄마다 따로 쳐야 해서 곡선 모양이 보이지 않았다. 옛 프로젝트 편집기는 막대(슬라이더)·프리셋으로 값을 바로 만졌다.

## 선택지

1. 편집기마다 따로 고친다. 화면마다 조작이 달라지고 같은 셈(다시 나누기·채우기)을 여러 번 만든다.
2. 막대·분포 조작 라이브러리를 들인다. 새 런타임 의존성(ADR·라이선스·묶음 크기)이 생기고, 정수만 드는 규칙·담은 변경 흐름·개발 화면 토큰에 맞추는 일이 남는다.
3. 공용 조작부를 직접 만든다(React + CSS 토큰, 의존성 없음). 공용 입력 칸(`NumberField`)이 이미 편집기 대부분의 수 칸을 그리므로 그 안을 바꾸면 한꺼번에 든다.

### 1. 값은 정수만

- 저장하는 값은 모두 정수다(‰·bp·ms·최소 단위). 조작부는 범위 안 정수만 낸다(`clampInt`). 화면에만 보이는 기대값·백분율은 실수여도 된다(저장하지 않는다).
- 이 셈은 기기 화면 전용이다(판정 코드가 아니다): `Math.log`·`exp`를 쓴다. 판정은 서버가 한다(범위·규칙 검사는 그대로).

### 2. 수 조작 칸

- 글자 칸은 그대로 칠 수 있다. 조작은 모두 같은 "한 걸음"을 쓴다: − / + 단추(누르고 있으면 잇달아, 오래 누르면 5배), ↑↓, 이름표 끌기(4화소에 한 걸음), 초점이 있을 때 휠. Shift = 10배, PageUp/PageDown = 10배, Alt = 1(단추·끌기만 — Alt+↑↓는 화면 단축키에 남긴다).
- 한 걸음: 선형 막대는 폭 ≤ 1000이면 1, 넘으면 폭 ÷ 200을 1·2·5 × 10^k로 내린 값. 로그 막대는 지금 값 ÷ 20을 1·2·5 × 10^k로 내린 값.
- 막대 범위(`sliderRange`):
  - 기술 범위 폭 ≤ 10,000: 범위 전체, 선형.
  - 0 이상이고 폭 ≤ 10,000,000: 범위 전체, **로그 눈금**(값은 유효 숫자 두 자리).
  - 그보다 넓거나 음수를 받는 넓은 범위: 값·팩 값의 4배 둘레 창(선형, 끝에 `+`). 끄는 동안 창은 고정이고 놓으면 다시 잡힌다.
  - 화면이 `scale`·`soft`·`step`으로 바꿀 수 있다(사다리는 줄마다 같은 창을 쓴다).
- 막대에 팩 값 눈금이 있다. 누르면 팩 값, 끌 때 가까이 가면 달라붙는다.
- 범위 밖 정수를 치면 그 자리에 까닭을 보이고, 칸을 떠날 때 가까운 끝 값으로 맞춰 넣고 "범위 밖이라 N으로 맞췄습니다"를 적는다. 정수가 아닌 글은 넣지 않는다.
- 막대는 `<input type="range">`가 아니라 `role="slider"` div다(`aria-valuenow`·`-min`·`-max`·`-valuetext`). 칸 안의 `input`은 글자 칸 하나뿐이다. 막대와 − / +는 탭 차례 밖이다(글자 칸의 ↑↓가 같은 일을 한다 — 칸마다 탭이 세 번 걸리지 않게).
- 표 칸(이름표 숨김)은 단추만 붙는다(막대는 `slider`로 켠다). 빽빽한 표(밸런스 가중치 표·전투 실험실·기준 유닛)는 단추도 빼고 ↑↓·휠만 쓴다(`steppers={false}`).

### 3. 합이 정해진 묶음(다시 나누기 규칙)

- 한 칸을 바꾸면 그 칸 = 0 ~ (합 − 잠근 칸 합)으로 자르고, 남은 양을 **잠그지 않은 나머지에 지금 몫대로** 정수로 나눈다(버린 소수가 큰 칸부터 1씩, 나머지가 모두 0이면 고르게). 합은 늘 그대로다.
- 끌거나 치는 동안에는 조작을 시작할 때의 묶음에서 다시 셈한다(반올림이 쌓이지 않고, 처음 값으로 돌아오면 처음 묶음).
- 경계 끌기: 왼 칸이 늘면 오른 칸부터 차례로 준다(0이 되면 다음 칸을 민다). 잠근 칸은 건너뛴다.
- 단추: 균등(잠그지 않은 칸에 고르게), 정규화(합 맞춤), 팩 값으로, 잠금 모두 풀기.
- 조작부는 합이 맞는 정수 배열만 낸다 → [적용]이 산수로 막히지 않는다. 서버의 합 검사는 그대로다.
- 행렬(티어 확률표)에 값을 칠 때도 같은 규칙이다. 한 구간에서 잇달아 친 칸은 잠근 것처럼 그대로 둔다(줄을 처음부터 쳐 넣을 수 있게).

### 4. 표 묶음 바꾸기

- 칸 고르기: 누름 = 한 칸, Shift+누름 = 네모, Ctrl/⌘+누름 = 더 고르기, 머리 단추 = 열 전체.
- 바꾸기: 값으로 · 더하기 · 곱하기(%) · 선형 채우기 · 등비 채우기(열마다 고른 첫 칸과 끝 칸 사이. 두 끝이 양수가 아니면 등비는 선형으로). 칸 모서리를 끌면 아래로 같은 값을 채운다.
- 합이 정해진 행렬은 바꾼 칸을 그대로 두고 그 줄의 나머지를 맞춘다(바꾼 칸의 합이 넘치면 전체를 줄여 맞춘다).
- 열(줄)마다 작은 막대 곡선을 보인다. 늘다가 주는 곡선은 밑줄로 알린다.

### 5. 담은 변경·되돌리기

- 조작은 기존 담은 변경 흐름을 그대로 쓴다(담기 → 검사 → [적용] 한 묶음). 끄는 동안 값은 화면에 바로 보이고 담은 변경에는 80ms 간격으로 넣는다(놓을 때 마지막 값). 서버 검사는 전처럼 입력이 멈춘 뒤 한 번.
- Ctrl/⌘+Z = 마지막 고침 되돌리기(기기 안, 50칸). 같은 칸을 1초 안에 잇달아 고친 것(끌기·치기)은 한 칸으로 묶는다. 글 칸(이름·메모)의 Ctrl+Z는 브라우저에 남긴다. 다시하기는 아이템 편집기에만 있다(전부터 있던 단추).

## 이유

- 공용 `NumberField` 하나를 바꾸면 아이템·스킬·건물·효과·크리쳐 편집기의 수 칸이 모두 따라온다(Verified: `<NumberField` 쓰는 곳을 세어 봄, 작업 기록의 표).
- 로그 눈금 문턱(폭 10,000 초과)은 편집기 칸의 실제 범위에서 골랐다: ‰ 칸(0~1000·0~10,000)은 선형, 배율·시간 칸(0~100,000‰, 0~3,600,000ms)은 로그, 수량·가격 칸(0~2³¹)은 값 둘레 창(Verified: `FACILITY_LIMITS`·`ITEM_LIMITS`·`SKILL_LIMITS`·`EFFECT_LIMITS` 값을 읽음).
- 다시 나누기를 "지금 몫대로"로 한 까닭: 확률표는 모양(어느 티어가 얼마나 큰가)을 지키면서 한 칸만 올리고 싶은 일이 가장 많다(Assumed: 사용자 지적의 "확률을 하나하나 써야" 한다는 말에서).
- 새 의존성이 없다(Verified: `package.json` 바뀜 없음).

## 결과

- 좋은 점: 값을 끌어서 바꾸고 결과(평균 티어·레벨 합계·팩 대비 차이)를 바로 본다. 확률표는 합이 틀릴 수 없다. 새 편집기는 공용 칸을 쓰면 같은 조작이 든다.
- 감수할 점: 설정 칸 패널의 ↑↓가 줄 옮기기에서 값 한 걸음으로 바뀌었다(줄은 Enter·Shift+Enter). 범위 밖 정수는 칸을 떠날 때 끝 값으로 담긴다(전에는 담기지 않았다). 수 칸마다 막대 한 줄이 늘어 편집 판이 길어졌다.
