# 캐릭터 3D 외형 — 로우폴리 부위 조립과 2차맵 모델

- 상태: 제안
- 날짜: 2026-11-11
- 관련: docs/adr/2026-11-01-first-login-cyborg.md(1·2·4절 외형), docs/adr/2026-10-28-unit-display-real-size.md(유닛 표현 단계), docs/adr/2026-11-08-building-art.md(코드로 만든 로우폴리 모델·도형별 인스턴싱), docs/adr/2026-10-28-s1-second-map.md "바뀜 (2026-11-09)"(가시거리 자동 조절), docs/adr/2026-10-29-app-shell.md 11절(첫 화면 JS 상한), 기획 D-529(사용자 요청 2026-11-11)·D-6040·D-064·D-065

## 배경

사용자 요청(2026-11-11): "캐릭터 생성을 더 다양한 프리셋과 폴리곤 3d로 구성할 수있게 해달라. 2차맵에서도 사용가능하게."

지금 사이보그 외형은 2D 그림(SVG)이다. 부위 넷(칸마다 4개)·색 둘(8색)·프리셋 4개뿐이고, 2차맵의 유닛은 모두 캡슐(멀면 점)이라 만든 외형이 지도에 보이지 않는다.

## 선택지

1. 모델 파일(glTF)을 만들어 올린다. 그림 품질은 좋지만 자산 제작·불러오기 의존성·용량이 든다. 지금은 만들 사람이 없다.
2. 코드로 만든 로우폴리 부위를 조립한다(건물 모델과 같은 방식). 자산·새 의존성 없음, 부위 조합이 곧 자료다.
3. 캐릭터마다 지오메트리 하나로 합친다(부위를 병합). 외형이 다르면 그리기 호출이 캐릭터 수만큼 는다.
4. 부위를 단위 도형의 인스턴스로 그린다. 외형이 모두 달라도 그리기 호출은 도형 수(8, 빛나는 조각은 따로 2)다.

## 결정

2 + 4로 한다. 값은 [임시]이고 휴대폰에서 재고 나서 고친다.

### 1. 외형 자료(2판)

`@terra/shared/characterLook`의 `CharacterLook`. 목록 ID(글자)와 정수만 있다.

| 칸 | 값 |
|---|---|
| `v` | 2(판 번호) |
| `build` 체형 | 4 |
| `height` 키 배율 | 90~110(%, 화면은 5씩) |
| `head` 머리 모양 | 8 |
| `face` 얼굴·바이저 | 8 |
| `top` 머리카락·머리 장비 | 13("없음" 포함) |
| `torso` 몸통 | 8 |
| `arms` 팔 · `legs` 다리 | 5 · 5 |
| `back` 등 장식 · `extra` 덧장식 | 8 · 8("없음" 포함) |
| `plating` 겉 장갑(사이보그 판금) | 0~3 |
| `skin`·`primary`·`secondary`·`accent`·`glow` 색 | 색 20개 가운데 하나씩(빛 = 눈·등불) |

- 색 20개는 세계의 칠이다(테마 값이 아니다). 옛 8색은 ID·값 그대로, 12색을 더했다. 아주 어둡거나 흰색에 가까운 색은 두지 않았다(낮·밤 2차맵 빛에서 읽히게).
- 프리셋 24개(앞 넷은 옛 프리셋 ID), 무작위(씨앗 난수 `createRng` — 같은 씨앗이면 같은 외형), 칸마다 잠그기·그 칸만 다시 뽑기.
- 외형이 없는 유닛의 기본 외형은 유닛 ID로 정한다: 휴먼 = 수수한 차림(`commoner`), NPC 국가 지도자 = 망토·온몸 장갑(`leader`).
- 옛 2D 외형과 오간다: 옛 사이보그는 고른 부위·색을 가까운 3D 부위로 넘기고(`characterLookFromLegacy`, 없던 칸은 사용자 ID 씨앗), 2D 얼굴 그림은 3D 외형에서 가까운 옛 부위로 그린다(`legacyAppearanceOf`). 그래서 옛 조회 칸 `appearance`와 2D 그림을 쓰는 화면(위 띠·사이보그 화면)은 그대로 돈다.
- 꾸밈일 뿐이다. 게임 규칙·판정에 쓰지 않는다.

### 2. 모델(엔진 `packages/engine/src/characters/`)

- 모델 = 단위 도형 조각 목록(순수 코드, three 없음). 도형 8가지: 상자 12·사다리꼴 기둥 12·6각 기둥 24·6각 뿔 12·공 36·반구 18·쐐기 8·사각뿔 6(삼각형 수).
- 몸 비율은 3~4등신(D-065): 키 1.8m × 키 배율, 머리 약 0.6m.
- 조각은 묶음 여섯(몸·머리·두 팔·두 다리)에 든다. 움직임은 묶음을 축 둘레로 돌리는 것뿐이다(걷기 = 팔·다리 흔들기, 뼈대 없음).
- 삼각형 상한: 가까운 단계(LOD0) 600 이하, 먼 단계(LOD1) 150 이하. 프리셋 24개와 무작위 외형 모두 시험이 본다.
- 그리기: 도형마다 InstancedMesh 하나(평면 음영 Lambert + 인스턴스 색 + 밤 빛), 빛나는 조각(눈·등불 — 상자·6각 기둥만)은 빛을 받지 않는 재질로 따로 하나씩. 텍스처·모델 파일·새 의존성이 없다. 색은 꼭짓점 색이 아니라 인스턴스 색이다(조각 하나가 한 색이라 결과가 같다).
- 캐릭터마다 지오메트리를 합치지 않은 까닭: 외형이 다 다른 캐릭터 80명을 합친 지오메트리로 그리면 그리기 호출이 80번이다. 도형별 인스턴스는 외형·수와 상관없이 10번 이하다(건물 모델과 같은 방식, ADR `2026-11-08-building-art.md`).

### 3. 만들기 화면

- 외형 단계: 위에 3D 미리 보기(끌어 돌리기·확대·돌림판·낮/밤·걷기), 아래에 프리셋 갤러리(썸네일은 같은 그리기로 만들어 메모리에 둔다)·부위 고르기(칸마다 앞·뒤·다시 뽑기·잠그기)·색 견본·[무작위]·[되돌리기].
- 미리 보기는 따로 진입점 `@terra/engine/characterPreview`를 지연 로딩한다. three는 첫 화면 묶음에 들지 않는다.
- WebGL을 쓸 수 없으면 2D 그림으로 보인다(고르기는 그대로 된다).

### 4. 2차맵

- 외형이 붙은 유닛은 가까우면 모델로, 아니면 지금처럼 캡슐·점으로 그린다. 판정은 프레임마다 엔진이 한다.
  - 점(아이콘): 키 1.8m가 화면 8px보다 작을 때(지금 그대로).
  - 모델: 키 1.8m가 화면 9px 이상이고(돌아갈 때 10px — 깜박임 방지), 화면 가운데 땅에서 가시거리 단계의 거리 안이며, 가까운 차례로 상한 안일 때.
  - 가까운 단계(LOD0): 키가 화면 28px 이상이고 가까운 차례로 LOD0 상한 안일 때. 그 밖의 모델은 LOD1.
  - 나머지는 캡슐.
- 가시거리 단계(`render/viewDistance.ts`, 0~4)에 묶은 값:

  | 단계 | 거리(m) | 모델 상한 | LOD0 상한 |
  |---|---|---|---|
  | 0 | 60 | 32 | 8 |
  | 1 | 80 | 48 | 12 |
  | 2(처음) | 110 | 64 | 16 |
  | 3 | 140 | 96 | 24 |
  | 4 | 180 | 128 | 32 |

  가장 나쁜 경우 삼각형 = 32 × 600 + 96 × 150 = 33,600, 그리기 호출 + 10(도형 8 + 빛 2 — 쓰는 도형만).
- 유닛 1,000개여도 메시는 10개 이하다(인스턴스 버퍼는 그린 조각 수만큼만 자란다).
- 고르기·누르기는 지금 그대로다(화면 자리·몸 크기 셈은 유닛 키·굵기 — `picking.ts`). 고른 표시는 발밑 고리(캡슐 강조 외곽선은 모델에는 그리지 않는다).
- 움직임: 걷는 유닛만 팔·다리를 흔든다(이미 그리는 프레임). 서 있는 유닛은 멈춘 자세다 — 화면 변화가 없으면 그리기를 멈추는 규칙을 지킨다.
- 안개: 유닛은 서버 시야 전송이 보낸 것만 있다(바뀜 없음).
- 유닛은 늘 실제 크기라(ADR 25) 가장 가까이 보아도 휴대폰에서 키가 약 18px이다. 더 가까운 확대 단계는 카메라 줄기와 사용자 결정이 필요해 질문으로 남긴다.

### 5. 자료 길

- 저장: `cyborgs.look`(jsonb, null 가능 — 더하기만 한 열). null = 3D 외형을 고르기 전에 만든 사이보그 → 옛 외형에서 넘긴 값으로 보인다(자료를 옮기지 않는다).
- 만들기: `cyborg_create`에 선택 칸 `look`을 더한다. 서버가 `isCharacterLook`으로 보고, 맞으면 저장하고 옛 칸 `appearance`는 그 외형에서 넘긴 값으로 맞춘다. 틀리면 `appearance_invalid`(새 결과 코드 없음).
- 프로토콜 판은 올리지 않았다(20 그대로): 더하기만 한 선택 칸이고, 메시지 스키마(`z.object`)는 모르는 칸을 버린다. 그래서 이 칸을 모르는 옛 서버도 새 기기의 만들기를 받고(외형은 옛 칸에서 넘긴 값으로 보인다), 옛 기기는 `look` 없이 만든다(지금과 같다). 시험이 본다(`packages/protocol/src/cyborg.test.ts`).
- 2차맵으로: WebSocket 지도 전송은 그대로 두고 tRPC `world.unitLooks`(2차맵 키)로 받는다 — 건물 겉모습 `facilities.mapLooks`와 같은 방식. 스냅샷·시야 전송(유닛마다 자주 가는 메시지)에 외형을 싣지 않으려는 것이다. 서버는 그 사람이 보는 유닛(내 유닛·전체 보기·지금 시야 안) 가운데 사이보그 본체(저장한 외형 또는 넘긴 값)와 NPC 지도자(기본 외형)만 준다. 휴먼 등 나머지 걷는 유닛은 기기가 유닛 ID로 기본 외형을 만든다(서버 일 없음).
- 기기는 받은 외형을 `isCharacterLook`으로 다시 본다. 다른 기기가 보낸 값을 그대로 믿는 길은 없다(서버가 저장 전에 본다).

## 이유

- 자산 없이 바로 만들 수 있고(건물 모델에서 확인한 방식, Verified: `packages/engine/src/buildings/`), 부위 조합이 자료라 프리셋·무작위·편집이 같은 값으로 돈다.
- 그리기 호출이 캐릭터 수·외형 가짓수와 무관하다(Verified: 건물 64채 7번, ADR `2026-11-08-building-art.md`).
- 만들기에 `look`을 싣는 쪽을 골랐다: 사이보그 자료는 월드 쓰기 대기열(WebSocket 명령)로만 바뀐다. tRPC로 따로 저장하면 만들기와 외형 저장이 두 걸음이 되어 사이에서 끊기면 고른 외형을 잃는다. 선택 칸 하나를 더할 뿐이라 프로토콜 판을 올리지 않아도 옛 기기·옛 서버와 맞는다.
- 지도로는 tRPC를 골랐다: 외형은 거의 바뀌지 않는 그림 자료다. 유닛 움직임 메시지를 키우지 않는다.
- 휴대폰 수치는 재지 않았다(Unknown). 헤드리스(SwiftShader) 측정은 작업 기록에 적는다.

## 결과

- 좋은 점: 프리셋 24개·부위 60여 개·색 20개, 만든 외형이 2차맵에 보인다. 휴먼·지도자도 모델로 보인다.
- 감수할 점: 그림이 단순하다(상자·기둥 조립). 서 있는 유닛은 숨쉬기 움직임이 없다. 2D 얼굴 그림은 가까운 옛 부위로만 그린다.
- 만든 뒤 외형 바꾸기는 만들지 않았다: 기획이 환생 때 무료 다시 고르기(D-352)·그 밖에는 계정 서비스(D-7032)로 정했다. 3D 외형을 고르기 전에 만든 사이보그에게 한 번 고르게 할지는 질문으로 남긴다.
- 나중에 다시 볼 조건: 휴대폰 측정에서 프레임이 밀리면 표의 상한을 낮춘다. 모델 파일을 쓰게 되면 같은 `CharacterLook` 칸에 모델을 붙인다. 더 가까운 확대·세력 색 표시·옛 사이보그 다시 고르기는 질문(`docs/questions/2026-11-11-character-3d.md`)으로 남긴다.

## 바뀜 (2026-11-11, 961·963)

기획 답(D-529 포인터, 질문 961~968 모두 추천안 — 사용자에게는 묻지 않음). 코드가 필요한 둘만 넣었다. 962(더 가까운 확대)는 카메라 줄기(`map-seamless-2`)가 합쳐진 뒤 한다. 964~968은 지금 그대로(추천안 = 지금).

### 961 나 — 3D 외형을 고르기 전에 만든 사이보그에게 한 번 무료 고르기

- 조건: 저장한 3D 외형이 없다(`cyborgs.look` 빈 값). 서버만 판정한다. 만들 때 3D 외형을 고른 사이보그·한 번 쓴 사이보그는 고를 수 없다.
- 명령: WebSocket `cyborg_look { id, look }` → `cyborg_result`(프로토콜 판을 올렸다 — 새 메시지라서. 값은 작업 기록). 서버가 `isCharacterLook`으로 보고 `look`을 저장하고 옛 칸 `appearance`는 그 외형에서 넘긴 값으로 맞춘다(만들기와 같은 규칙). 이미 있으면 새 결과 코드 `look_locked`, 틀리면 `appearance_invalid`(기회를 쓰지 않는다), 사이보그가 없으면 `no_cyborg`. 특별한 감사 기록은 두지 않는다(사이보그 행 갱신은 다른 명령과 같은 쓰기 대기열).
- 조회: `cyborg.get`에 `look`(저장한 것 또는 넘긴 값)과 `lookPick`(고를 수 있음)을 더했다. 시안 자료에서는 늘 false.
- 화면: 사이보그 화면 머리 판 그림 아래 [외형 고르기] + "한 번 무료" 안내. 누르면 창(지연 조각 `LookPick`)이 열리고 만들기 화면의 외형 단계(`LooksStep`·`CharacterPreviewPane`)를 그대로 쓴다. 처음 값은 옛 외형에서 넘긴 3D 외형이다. [이 모습으로 정하기] → 한 번 더 묻기(되돌릴 수 없음) → 저장. 저장하면 자료를 다시 받아 단추가 사라지고, 위 띠 얼굴(2D 그림)도 바로 바꾼다.
- 환생 때 다시 고르기(D-352)는 환생이 생길 때 같은 칸(`look`)을 바꾸는 길로 만든다. 지금 그 길은 없다.
- 알려진 모서리: DB의 외형에 목록에서 빠진 ID가 들어 있으면 읽을 때 빈 값으로 보므로 다시 고를 수 있게 된다. 목록 ID는 지우지 않는 규칙이라(1절) 생기지 않아야 한다.

### 963 나 — 2차맵 유닛 발밑 나라 색 고리

- 대상: 내가 보는 모든 유닛(내 것·남의 것, 종류와 상관없이) 가운데 나라가 있는 것. 나라가 없는 유닛은 고리가 없다. 캡슐로 그리든 모델로 그리든 같은 고리이고, 점(아이콘) 표현일 때는 그리지 않는다.
- 색: 건물 깃발·용마루와 같은 국가 색 번호(`buildingLooks.ts` `accentOf` — world.cities 국가 차례, 엔진 `nationAccent`). 건물 색 규칙이 바뀌면 고리도 따라 바뀐다.

  | 크기 3, 사람 아님 | 네 발 짐승(앞다리 = 팔 묶음, 뒷다리 = 다리 묶음 → 걷기가 속보) × 키 × 0.7 ÷ 1.6 |
  | 탈것(표시 종류 `vehicle`) 크기 1·2·3 | 차(키 약 1.5m)·짐차(약 3.4m)·궤도 탈것(약 6m), 배율 1 |

- 사람인지 알려고 `world.unitLooks` 답에 이름표·몸꼴 자료 `labels: [{ unitId, kind, name }]`를 더했다(내가 보는 유닛 가운데 이름이 있거나 크기 2 이상인 것만 — 전체 보기에서 이름 없는 시험 봇 수천 줄을 싣지 않게. DB를 읽지 않는다).
- 옆 2차맵 유닛도 외형·나라 고리·이름표를 받는다(붙은 이웃 2차맵마다 같은 조회, 앞 작업 기록의 "이웃 2차맵 유닛은 외형이 없다"를 고침). 받은 서버 외형은 화면이 바뀌어도 기억한다(걸어서 넘은 직후 새 답이 오기 전에도 내 사이보그가 고른 외형).

### 유닛 이름표

- 지도자 이름표(`leaderTags.ts`)와 같은 덧그림 층(`apps/game/src/map/unitNames.ts`, 스타일 `unitNames.css` — 토큰만). 손가락·마우스를 받지 않고 읽기 프로그램에는 숨긴다(이름은 유닛 목록·한눈 정보에 있다). 새 메시지 키 없음(이름 없는 고른 유닛은 있던 "종류 #번호" 키).
- [임시] 규칙(질문 1108): 내 사이보그(주색 테두리)·고른 유닛(포커스 색 굵은 테두리)은 확대와 상관없이 늘. 다른 유닛은 사람 키 1.8m가 화면 20px 이상일 때(휴대폰 세로 6/6·5/6, 넓은 화면 6/6~4/6) 화면 가운데에서 가까운 10개까지, 화면 안 이름 있는 유닛이 40개를 넘으면 숨김, 겹치면 건너뜀. 지도자는 지도자 이름표가 그린다.
- 이름: 사이보그 본체 = 사이보그 이름, NPC 도시 휴먼 = 휴먼 이름(773 나). 구인한 휴먼·사이보그 유닛·수호신은 이름 칸이 없다(질문 1109).
