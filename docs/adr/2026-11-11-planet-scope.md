# 행성 범위: 편집기·모니터링이 "어느 행성에 반영되는가"를 보이고 고르는 틀

- 상태: 제안 (사용자가 범위 줄·행성 고르기 화면을 본 뒤 확정. 은하 층·행성 사이 규칙은 기획 답(질문 936~945) 뒤 새 ADR)
- 날짜: 2026-11-11
- 관련: docs/PLAN.md 5.1(계층)·6장(편집기·관리자)·9.5(관측), ADR `2026-10-31-space-layer-data-model.md`(우주층 골격, 제안 — 미룸), `2026-10-31-s3-server-stage.md`("행성 ID·영역": 세계 표 `planet_id`), `2026-10-31-star-system-editor.md`, `2026-10-29-planet-editor-stage1.md`(행성 보관함), `2026-11-07-world-layout.md`, `2026-11-08-operator-console.md`, `2026-11-02-dev-ui.md`(개발 화면 층), `2026-11-10-nation-editor.md`, 기획 D-350~D-388(우주)·D-365(행성 고르기는 새 행성이 열릴 때)·D-372(출시는 지구 + 모항, 행성 ID·영역 4종은 처음부터), 질문 `docs/questions/2026-11-11-planet-scope.md`(936~945), 작업 기록 `docs/worklog/2026/11/11-1700-planet-scope.md`

## 배경
- 사용자 요청(2026-11-11, 원문): "문제1. 현재 행성을 선택이 필요한 에디터에 행성 선택하는 기능이 없어 어디에만 반영되는지 확인 불가. 모니터링도 행성별로 가능해야함. 현재는 행성이 하나이지만 최종적으로 하나의 은하를 범위로 할것이고 항성계(태양계)의 미래지구형 행성 하나를 시작으로 할것이고 태양계 행성들을 테라포밍하여 플레이 가능한 행성을 넓히는게 근접한 목표이다."
- 그전 코드(Verified: main `8370909`를 읽음)
  - 세계 표는 처음부터 행성 칸이 있다: `world_cities`·`world_units`·`world_buildings`·`world_exploration`·`second_map_pins`·`planet_pollution`·`gardener_waves`·`world_travels`·`world_ruins`·`territory_beacons`·`world_nation_placements`의 `planet_id`(기본값 `s2_test_planet`, S3 ADR "행성 ID·영역", D-372).
  - "세계 행성"은 상수로 흩어져 있었다: 서버 `DEFAULT_WORLD_PLANET_ID`(열 기본값)·`TEST_PLANET_ID`(2차맵을 띄우는 행성), 화면 `PLANET_ID = "s2_test_planet"`(세계 배치·영토·1차맵·시작 도시 지도), 2차맵 시험 `DEFAULT_PLANET`.
  - 편집기 화면 어디에도 "이 변경이 어느 행성에 드는가"가 없었다. 세계 배치·영토 화면은 요약 줄 끝에 행성 ID를 작은 글씨로만 보였다.
  - 운영자 콘솔(`/ops`)의 도시·유닛 줄에는 행성 ID가 있었지만 거를 수 없었고, 현황은 세계 합만 보였다. 1분 지표 줄에는 행성이 없었다.
- 우주층 데이터 모델(천체·항성계·스타게이트·우주 위치)은 사용자 결정으로 미뤘다(ADR 43 제안 그대로). 이번에는 **은하 자료를 만들지 않고**, 지금 있는 행성 칸 위에 "범위를 보이고 고르는 틀"만 둔다.

## 선택지
1. 범위를 보이는 자리: (a) 편집기마다 자기 머리에 따로 / (b) 화면 틀이 주소 → 화면 표에서 한 번에 / (c) 위 띠(TopBar)에 전역 행성 고르기 하나.
2. 고른 행성을 두는 곳: (a) 주소 검색어 `?planet=` + 계정 기억 / (b) 계정 설정(서버) / (c) 화면 안 상태만.
3. 서버가 플레이 행성을 아는 길: (a) 도우미 함수 하나(지금은 상수 하나를 돌려줌) / (b) 표 `world_planets` / (c) 콘텐츠 팩 행성에 `playable` 칸.
4. 모니터링의 행성 거르기: (a) 조회마다 선택 입력 `planetId`(없으면 전체) / (b) 행성마다 따로 된 화면.

## 결정

### 1. 범위 모델
- 층: **세계(서버 하나) → 항성계 → 행성 → 2차맵**. 은하는 세계에 하나다(ADR 43 1절). 지금 코드에 있는 것은 세계·행성·2차맵 셋이고, 항성계는 편집기 초안(`star_systems`)뿐이다.
- 범위 종류 다섯(`apps/game/src/scope/scopeRoutes.ts` `ScopeKind`):
  - **모든 행성 공통**(`common`): 규칙·수치. 이 세계의 덮어쓰기(설정 칸 `tuning_overrides`, 팩 항목 `content_overrides`)로 저장되고 표에 행성 칸이 없다.
  - **행성 하나**(`planet`): 세계 표의 `planet_id`로 묶인 자료. 행성을 고른다.
  - **행성 보관함**(`library`): 팀이 저장한 행성 초안(`planet_library`). 세계 행성에 반영되지 않는다.
  - **항성계 초안**(`system`): `star_systems`(보관함 행성을 궤도에 놓음). 세계에 반영되지 않는다.
  - **행성과 무관**(`none`): 계정·권한, 이 기기 측정, 시범 전투.
- 행성 상태 셋(`@terra/shared/planetScope` `PlanetScopeStatus`): **공개 행성**(`playable`, 처음 문구 "플레이 중" → D-530 945 다로 바꿈 — 세계의 유닛·도시·2차맵이 놓인 행성) · **편집 전용**(`editor` — 팩에 있지만 세계가 쓰지 않는 행성) · **보관함**(`library`).

### 3. 범위 줄(선택지 1b + 2a)
- 부품 하나: `apps/game/src/scope/ScopeBar.tsx`. 화면 머리에 "범위" 표지와 한 줄 풀이를 그린다.
  - 공통: 고정 표지 **모든 행성 공통** + 풀이("이 세계의 덮어쓰기로 저장되어 모든 행성에 똑같이 적용됩니다") + 지금 플레이 행성 이름.
  - 행성 하나: **행성 고르기**(이름 · 상태) + 상태 표지 + 행성 ID. 플레이 행성이 하나여도 이름으로 보인다.
  - 보관함·항성계: 고정 표지 + "공개 행성(이름)은 바뀌지 않습니다".
- 꽂는 곳: 틀이 보이는 개발·운영 화면은 주소 → 화면 표(`shell/routeViews.tsx`)가 화면 위에 한 번에 그린다(**편집기 파일을 고치지 않는다** — 같은 묶음의 다른 줄기가 고치는 편집기와 겹치지 않게). 틀을 숨긴 화면 넷(행성 편집기·항성계·2차맵 시험·전투 다시보기)은 자기 머리에 `<ScopeBar route="…" inline />` 한 줄을 둔다.
- 화면 → 범위 표는 `scope/scopeRoutes.ts` 하나다. 새 개발 화면은 여기 한 줄을 더한다(줄이 없으면 "모든 행성 공통"으로 보인다 — 새 편집기는 대부분 팩 덮어쓰기다. 화면 시험 `e2e/dev.spec.ts` `TOOL_SCOPES`가 따로 적은 약속으로 본다).
- 고른 행성(`scope/planetScopeStore.ts`): 주소 `?planet=<행성 ID>` → 이 계정이 이 기기에서 마지막에 고른 값(localStorage `terra.planetScope.<계정 ID>.<묶음>`) → 대표 플레이 행성. 주소는 `history.replaceState`로만 고친다(기록 칸을 쌓지 않는다. 주소 표 `routes.ts`는 고치지 않았다 — 라우터는 모르는 검색어를 지우지 않는다). 틀린 값(모르는 행성·그 화면이 고를 수 없는 행성)은 버리고 주소를 고친다.
  - 묶음 셋: 편집(플레이 행성만 — 세계 자료를 바꾸는 화면), 시험(플레이 + 편집 전용 — 보기 전용), 모니터링(**전체** `?planet=*` + 플레이 행성, 처음 값 전체).
  - 선택지 2b(계정 설정에 저장)를 고르지 않은 까닭: 계정 설정 표 형식(`user_settings`)을 넓혀야 하고, 개발 화면 테마도 기기 값이다(ADR 2026-11-02-dev-ui). 기기를 바꾸면 대표 행성부터 다시 고른다.
- 담은 변경 막대의 **적용 대상**(`ScopeTarget`): 공용 막대(`editor/content/contentEditorPending.tsx`)·설정 칸 막대에 "적용 대상: 모든 행성 공통", 세계 배치·영토에 "적용 대상: <행성>".
- 감사 기록: 행성에 묶인 동작은 `meta.planetId`를 남긴다(세계 배치는 전부터, 운영자 유닛 통제 `ops.unit.*`는 이번에). 운영자 콘솔 감사 기록 표에 **범위** 칸(행성 이름 / 모든 행성 공통 = 설정 칸·팩 항목 분류 / 빈칸).

### 4. 서버(선택지 3a + 4a)
- **플레이 행성 목록 도우미** `apps/server/src/world/playablePlanets.ts`: `playablePlanets()`(지금 `[{ id: DEFAULT_WORLD_PLANET_ID, primary: true }]`)·`primaryPlanetId()`·`isPlayablePlanet()`·`resolvePlayablePlanet(입력 없으면 대표)`. `TEST_PLANET_ID`(2차맵을 띄우는 행성)와 `app.ts`의 세계 행성 고르기가 이 도우미를 쓴다. 시험이 "대표 = 열 기본값 = 2차맵 행성"을 본다.
  - 표·팩 칸(3b·3c)을 만들지 않은 까닭: 행성이 하나인 동안 표는 한 줄짜리 설정이고, "플레이 가능"을 누가 어떻게 여는지(테라포밍 규칙)는 기획이 정한다(질문 940).
- tRPC `planetScope.list`(로그인): 플레이 행성(대표가 맨 앞) + 개발·운영 역할이면 팩에만 있는 편집 전용 행성. 이름·면 레벨은 팩 행성 원본에서(이미 공개된 값).
- `planetId` 입력
  - `worldLayout.*`·`territory.*`: 있던 필수 입력을 **선택**으로(없으면 대표 플레이 행성 — 옛 기기 그대로). 플레이 행성이 아니면 `NOT_FOUND`("UNKNOWN_PLANET", 전과 같다).
  - `recruit.board`: 선택 입력을 더함. NPC 사회 런타임은 대표 행성 하나만 돌아서 다른 값은 `NOT_FOUND`.
  - `ops.npcs.factions`·`ops.npcs.cities`·`ops.units.list`·`ops.audit`: 선택 입력(없으면 **전체** — 옛 기기와 같다). 플레이 행성이 아니면 `NOT_FOUND`.
  - 세력 거르기의 뜻: 세력은 세계에 하나다. 행성으로 거르면 **그 행성에 도시나 유닛이 있는 세력**만 남고, 도시·휴먼·주거·만족도·유닛 수는 그 행성 몫이다(전쟁·봉신·소속 유저·국고는 세계 값).
- `ops.overview`: 응답에 `planets`(행성마다 2차맵·유닛·이동 중·도시·휴먼·건물·오염 칸·오는 웨이브)를 더했다. 2차맵·유닛은 메모리 월드, 나머지는 DB(`ops/planetReads.ts`, 한 질의). 플레이 행성이 아닌 ID에 자료가 남아 있으면 그 줄도 보인다("플레이 행성 아님" — 살펴볼 것).
- 지표: 서버 1분 줄(`"metric":"server"`)은 **그대로** 두고, 행성마다 한 줄(`"metric":"planet"`, `planetId`·`maps`·`units`·`moving`·`subscribers`)을 더 남긴다. 서버 줄을 읽는 스크립트(`ops/s3-ramp.sh`·`s3-ramp-summary.mjs`, `nas-metrics`의 grep)는 바뀌지 않는다. `nas-metrics`에 "행성별 1분 지표"와 "행성별 DB 수" 구역을 더했다.
- 마이그레이션 없음. 프로토콜·`SIM_VERSION`·콘텐츠 팩 그대로.

### 5. 테라포밍한 행성이 열릴 때 꽂는 길(구현하지 않음)
1. 행성 정의가 콘텐츠 팩 `planets`에 든다(행성 편집기 보관함 → 팩 반영, ADR 38). 서버가 굽고 행성 값을 메모리에 든다(`keepValuesFor`).
2. `playablePlanets()`에 그 행성 ID를 더한다 → 범위 목록·행성 고르기·운영 조회·지표 줄에 **바로** 나온다(화면·조회는 이미 `planetId`를 받는다).
3. 행성마다 띄워야 하는 서버 몫(지금 대표 행성 하나만): 2차맵 지형 서비스, 세계 배치·NPC 사회 런타임·정원사, 영토 셈의 면 레벨 표. 이것은 그때의 서버 줄기가 한다.
4. 플레이어 화면(1차맵·시작 도시 지도·2차맵 구독)의 행성 고르기는 D-365대로 새 행성이 열릴 때 더한다. 지금 화면 상수(`map/PlanetMapScreen.tsx`·`start/StartCityMap.tsx`의 `PLANET_ID`)는 지도 줄기 몫이라 이번에 건드리지 않았다.

### 6. 일부러 미룬 것
- 은하 층(항성계·스타게이트·천체 ID·우주 위치) 자료와 행성 사이 이동·물류·경제 규칙: 기획이 정한다(D-350~D-388은 우주층 규칙, 행성 사이 경제는 질문 936~939).
- 행성마다 다른 설정 칸·팩 덮어쓰기: 지금은 세계에 하나다(질문 938).
- 표 구조·2차맵 키 바꾸기: 하지 않았다. 나중에 행성 칸이 필요한 표:
  - `world_battles`: 행성·2차맵 칸이 없다(시작 자료 `init` jsonb 안). 행성별 전투 수·전투 목록을 보려면 `planet_id`(+ `map_key`) 칸이 필요하다.
  - `world_humans`: 도시로만 이어진다(`city_id` → `world_cities.planet_id`). 지금은 조인으로 센다. 떠도는 휴먼(도시 없음)이 생기면 칸이 필요하다.
  - `recruit_draws`·`npc_society`·`faction_wars`: NPC 사회 런타임 상태가 세계에 하나라는 전제다. 런타임을 행성마다 띄우면(5절 3) 행성 칸이나 행성별 줄이 필요하다.
  - `ledger_accounts`(창고 = 주체·자산·위치): 위치가 도시·유닛 ID라 행성은 따라 나온다. 천체마다 총량 장부(D-359)는 ADR 43 4절.
  - `market_orders`·시세: 거래소가 도시 단위라 행성은 도시에서 따라 나온다. 행성 사이 시장을 나눌지는 질문 936.
  - `item_holdings`: 주인(주체·유닛·건물)에서 따라 나온다. 칸이 필요 없다(Assumed).
  - `client_perf_samples`: 2차맵·행성 표지가 없다(주소 패턴만). 행성별 기기 성능을 보려면 표지가 필요하다.

## 이유
- 화면 틀에서 한 번에 그리는 것(1b): 편집기 17개에 같은 줄을 넣지 않아도 되고, 새 편집기도 표 한 줄이면 된다. 같은 묶음의 다른 줄기(국가·건물·채집 편집기)와 파일이 겹치지 않는다(Verified: 이번에 고친 편집기 파일은 세계 배치·영토·구인 시험·2차맵 시험과 틀을 숨긴 화면 머리 한 줄, 공용 담은 변경 막대뿐).
- 위 띠 전역 고르기(1c)를 고르지 않은 까닭: 공통 화면에서도 행성 고르기가 보이면 "고른 행성에만 반영된다"로 읽힌다 — 사용자가 지적한 혼동을 거꾸로 만든다. 화면마다 그 화면이 쓰는 범위만 보인다.
- 주소에 두는 것(2a): 링크·새로고침·사진에 같은 행성이 남고, 운영진끼리 "화성 유닛 목록" 주소를 주고받을 수 있다.
- 조회의 `planetId`를 선택으로 둔 것: 직전 판 기기(입력 없음)가 그대로 돈다(AGENTS 4장 "직전 버전 앱이 그대로"와 같은 생각).
- 행성 줄을 서버 줄과 나눈 것: 서버 줄은 평평한 수 표(`Record<string, number>`)이고 스크립트가 sed·JSON으로 읽는다. 행성마다 칸 이름을 늘리면(예: `units_mars`) 읽는 쪽이 행성 수만큼 바뀐다.

## 결과
- 좋은 점: 개발·운영 화면 모두에서 변경이 어디에 드는지 머리에서 보인다. 행성이 늘면 도우미 목록에 한 줄을 더하는 것으로 고르기·거르기·지표가 따라온다. 감사 기록에서 "어느 행성에 한 일인가"를 거른다.
- 감수할 점
  - 플레이 행성이 하나인 동안 행성 고르기는 고를 것이 하나다(이름을 보이는 것이 목적 — 사용자 요청 "어디에만 반영되는지 확인").
  - 고른 행성 기억은 기기 값이다(다른 기기에서는 대표 행성부터).
  - 범위 줄은 작은 조각으로 미리 캐시된다(개발자 홈처럼 플레이어 기기도 서비스 워커 설치 때 받는다 — 범위 줄 2.9kB + 저장소 1.4kB + CSS 0.7kB(gzip 9단계), 첫 화면 JS에는 들지 않는다. Verified: 빌드 뒤 `check-pwa`·`check:bundle`, 값은 작업 기록). 개발 전용 조각 규칙(`DEV_ONLY_CHUNK`)에 넣지 않은 까닭: 운영자 콘솔 조각(미리 캐시됨)이 같이 쓴다.
  - 현황 조회가 DB 질의를 하나 더 한다(행성별 수, 표 다섯의 `group by planet_id`).
  - 전투는 아직 행성별로 세지 못한다(6절 `world_battles`).
- 다시 볼 조건: 두 번째 플레이 행성을 열 때(5절), 기획이 행성 사이 경제·설정 칸·국가 프리셋 범위를 정할 때(질문 936~945), 우주층 업데이트를 설계할 때(ADR 43 확정).

## 바뀜 (2026-11-11, D-530)

- 기획 답(질문 936~945): 테라포밍으로 행성을 여는 것도 운영자 공개만(940, 사용자 답). 경제·국가 프리셋·설정 칸·전쟁·외교는 세계에 하나, 정원사는 행성마다 따로 쌓이고 설정은 공통, 행성 사이 이동은 우주층과 함께 — 이 ADR의 범위 표(`scopeRoutes.ts`)는 그대로 맞다.
- 945 다: 상태 문구 "플레이 중"·"Live" → "공개 행성"·"Public"(메시지 키만, 코드 값 `playable`은 그대로).
- 남은 일: 943 나(플레이어 행성 고르기 = 항성계 화면), 944 나(행성별 접속자·전투 수 — 전투 표에 행성 칸이 필요한 마이그레이션)는 뒤 줄기.
