## 배경
- 사용자(2026-11-11, 원문): "개선2. 생산에디터 : 예전 에디터가 아직 더 낫다. 3가지만 적용하는게 아니라 낚시 채집 등 6가지 전부에 적용하며 각각의 스탯이 주력 보조로 골고루 쓰이게 해야한다. 유닛 정보창에는 스탯에 따라 적합한 1차 생산직군 추천도 보이게 한다. 또한 전투계 스탯조합배열로도 적합한 클래스 추천 및 설명 추가."
- 붙임: 옛 프로젝트 "Production Editor — 1차 생산 파라미터 편집" 화면 두 장. 묶음 탭 줄(필드채집: 벌목장·광산·약초원 / 건물생산: 농장 30·목장 30·낚시터 / 2차가공: 요리 70·무기 공방 15·방어구 공방 11·장신구 공방 6 / 공용: 확률 분포 12·개요), 확률 분포 탭의 "스탯 구간별 티어 채집 확률 (skill_tier_probability)"·"전체 구간 일괄 프리셋", "건물별 메인스탯 매핑 (gather_type_config)".
- 지금(시작 main `8370909`, Verified: 코드·팩 core@61): 채집 시설은 농장·벌목장·광산 셋뿐이다(앞 줄기 `work/gather-tier`·`work/primary-production`이 옛 규칙을 셋에만 옮겼다). 약초·어류·축산물 아이템 사다리는 팩에 이미 있다(30·26·13개, 켜짐). 확률표는 `/dev/gather-tiers`, 스탯 짝은 건물 편집기 채집 구역에서 시설마다 따로 고친다. 유닛 화면에 추천이 없다.
- 기획 답(2026-11-11, D-529 + D-507): 전투 클래스는 [임시] 유형을 만들지 않고 옛 프로젝트의 확정 35 클래스를 그대로 쓴다. 여섯 가지 스탯 짝은 43 §4와 같다. 옛 생산 편집기를 기준으로 삼는 것은 D-513.

## 결정
1. **콘텐츠**(팩 core@62)
   - 시설 셋: `herb_field`(약초원), `ranch`(목장), `fishing_spot`(낚시터). 채집 칸은 위 표. 건설 재료·칸 크기·내구도·창고는 기존 채집 시설 꼴(레벨 1 원자재 → 레벨 2부터 가공품): 약초원 소나무 5·3×3·내구도 100·100kg, 낚시터 소나무 12 + 석재 3·3×3·150·200kg(옛 `building_seed.js` HERB_GARDEN·FISHING_DOCK), 목장 소나무 8·4×4·150·300kg([임시] — 옛 시드에 목장 건물이 없어 농장 값).
   - 겉모습(`look.model`): 전용 모델이 없어 약초원·목장 = `farm`(지붕 이끼색·벽 헛간색), 낚시터 = `lumber`(지붕 청록). 건물 그림 후속에서 바꾼다.
   - 레시피 셋(시뮬·경제 목록용, 한 번에 10번 캠 [임시]): `gather_herbs`, `raise_livestock`, `catch_fish`. 서버 직무 산출은 레시피 없이 사다리를 바로 쓴다(기존과 같다).
   - 약초 덤불(`gather_objects.herb_bush`)을 약초원이 맡는다 → 약초원은 벌목장·광산처럼 오브젝트 채집소다. 목장·낚시터는 농장처럼 시설 안 생산(채집소 종류 `facility`).
   - 세계 씨앗 칸 셋 `npc_seed_herb_fields`·`npc_seed_ranches`·`npc_seed_fishing_spots`(출발값 0 = NPC 시작 도시에 짓지 않는다 — 약초·축산물·어류를 쓰는 사슬이 NPC 경제에 없다, 질문 950). 씨앗 표는 여섯 가지 한 표(`facilities/npcSeed.ts` `SEED_GATHER`).
   - 새 분류 `combat_classes`(36줄: 2스탯 15 + 3스탯 20 + 범용)와 설정 칸 `class_three_stat_pm` 600·`class_generalist_pm` 800.
2. **낚시 성공 확률**: 채집 칸 `catch {basePm, maxPm, statPm, fullStat}` — 한 번 시도의 성공 ‰ = min(maxPm, basePm + ⌊statPm × min(fullStat, 주 + 보조) ÷ fullStat⌋)(옛 `min(0.80, 0.30 + 0.50 × min(1, (주 + 보조) ÷ 200))` → 300·800·500·200). 성공한 시도만 티어를 뽑고 실패한 시도는 빈 번이다(T0 시간은 든다). 시뮬(`rollGatherOutputs` `successPm`)·서버 직무 산출(`gatherLots`)·아이템 편집기 채집 미리 보기가 같은 함수(`gatherCatchPm`)를 쓴다. 옛 "반경 5칸 물" 조건은 넣지 않았다(아래 감수할 점).
3. **셈 자리**: 난수 없는 1차 생산 셈(구간 찾기·진행·수확량·필요 진행·해금 티어·유효 스탯·성공 확률·나올 확률)을 `@terra/shared/gatherMath`로 옮기고 `@terra/sim` `economy/gather.ts`가 다시 내보낸다. 추첨·아이템 고르기(난수)는 시뮬에 남는다.
4. **생산 편집기 `/dev/production`**(`apps/game/src/editor/production/`, dev·admin, 개발 화면 층)
   - 묶음 탭 줄: 필드채집(벌목장·광산·약초원)·건물생산(농장·목장·낚시터) — 수 = 사다리 아이템, 2차가공(가공 단계 시설) — 수 = 레시피, 공용(확률 분포 = 구간 수·스탯 매핑·전투 클래스·개요). `?tab=`으로 탭을 바로 연다.
   - 생산 종류 탭: 주·보조 스탯 고르기, 방식, 수확량 칸, 성공 확률 칸, 자리·창고, 사다리 표(티어마다 아이템·필요 진행·미리 보기 확률), 미리 보기(유닛 주·보조 스탯·시설 레벨 → 유효 스탯 → 구간 또는 해금 티어 → 성공 확률·진행 속도·한 번에 N개·한 번 평균 시간·시간당 기대 산출).
   - 스탯 매핑 탭: 여섯 시설의 주·보조 스탯 한 표 + 스탯마다 쓰임. 스탯마다 주 하나·보조 하나가 아니면 알린다(막지 않는다).
   - 확률 분포 탭: 옛 `/dev/gather-tiers` 화면 그대로(전체 구간 프리셋·구간 조절 판·행렬). 주소 `/dev/gather-tiers`는 이 탭으로 열린다(부모 = 생산 편집기). 개발자 홈 줄은 생산 편집기 하나다.
   - 전투 클래스 탭: 분류 규칙·분류 미리 보기(여섯 스탯 → 클래스), 클래스마다 이름·주요 역할·설명(ko·en). 조합 스탯은 고치지 않는다.
   - 개요 탭: 여섯 가지 한 표 + 표본 스탯(새 유닛 평균의 1·3·6·10배)의 시간당 기대 산출.
   - 저장: 건물 편집기와 같은 `buildings.list·check·save·history`(시설 `put`, 확률표 `put_gather_band`, 전투 클래스 `put_combat_class`·`revert_combat_class`). 담기 → 검사 → 적용, 내보내기는 기존 `terra-tuning-diff`(`entries`에 `combat_classes`).
5. **유닛 추천**(`@terra/shared/unitGuide`, 표시만)
   - 1차 생산: 여섯 가지를 유효 스탯(주 + 보조)으로 줄 세운 위 둘. 같으면 주 스탯이 큰 쪽, 그래도 같으면 표 차례.
   - 전투 클래스(옛 CHR-1 §6): 여섯 스탯을 큰 차례로 세우고 S6 × 1000 ≥ S1 × 800이면 범용, 아니면 S3 × 1000 ≥ S1 × 600이면 위 세 스탯 조합, 그 밖은 위 두 스탯 조합. 정수 곱으로만 견준다. 같은 값은 STR·VIT·INT·WIS·DEX·AGI 차례(옛 문서에 정한 것이 없어 화면 스탯 차례로 고정). 3스탯 조합이 표에 없으면 위 두 스탯 조합으로 내려간다(옛 코드와 같다). 모두 0이면 없음.
   - 서버 `units.guide`(로그인한 누구나): 실효 팩(팩 + 세계 덮어쓰기)의 여섯 시설 스탯 짝·클래스 표·문턱(설정 칸 실효 값). 화면(`roster/UnitAdvice.tsx`)이 5분 동안 붙잡아 쓴다.
   - 보이는 곳: 유닛 상세(스탯 아래), 사이보그 화면(핵심 사양 아래), 구인 카드(한 줄), 2차맵 내 유닛 목록의 고른 유닛(한 줄 — 목록 줄에 1차 스탯 칸 `stats`를 더했다).
   - 풀이 줄을 늘 붙인다: 스탯으로 고른 제안이고, 전투 유형은 이름표일 뿐 규칙 효과가 없다.

## [임시]인 것
- 목장 값(건설 재료·칸·내구도·창고), 목장 사다리 = 축산물만, 새 세 시설의 오염 값 1·자리 10, 레시피 셋의 수량·작업량, 겉모습 모델, 세계 씨앗 칸 셋의 출발값 0과 땅 조건.
- 전투 클래스 영어 이름 열셋(옛 자료에 영어가 없는 것)과 영어 설명·영어 역할 전부(번역), 수행 사제의 영어 이름(옛 "Monk"가 몽크와 겹쳐 "Ascetic Priest"), 범용 설명.
- 같은 값일 때의 스탯 차례(STR·VIT·INT·WIS·DEX·AGI).

## 이유
- 스탯 짝·방식·수확량이 이미 시설 자료라 새 세 가지는 자료와 성공 확률 칸 하나로 끝난다(Verified: 서버 직무 산출 `labor/gatherWork.ts`·채집소 `gather/station.ts`가 팩 채집 칸만 본다 — DB 시험이 목장·낚시터로 돈다).
- 미리 보기를 화면에서 판정과 같은 함수로 세면 스탯 짝·수확량을 고치는 즉시 결과가 보인다(사용자 "밸런스 조절"). 식을 둘로 가르지 않으려고 파일을 옮기고 다시 내보냈다.
- 추천을 화면이 세면 유닛·사이보그 응답 모양이 그대로다. 편집기에서 고친 스탯 짝·클래스 이름은 실효 팩을 읽는 `units.guide`로 바로 든다(Verified: DB 시험·화면 시험).
- 시뮬 출력은 그대로다(Verified: econ16 시드 1·30일, 본문 줄 620개가 앞뒤 같고 머리·요약 줄의 팩 판·해시만 다르다) → `SIM_VERSION` 그대로(22).

## 결과
- 좋은 점: 여섯 가지가 같은 규칙으로 돌고 스탯 여섯이 고르게 쓰인다. 한 화면에서 스탯 짝·확률표·사다리·기대 산출을 본다. 유닛 정보에 생산 직군 둘과 전투 클래스가 보인다.
- 감수할 점
  - 낚시터 물가 조건이 없다: 건물 놓기가 빈 칸만 보고 서버 2차맵이 물 칸을 주지 않는다(옛 규칙 "반경 5칸에 물"). 어디에나 지을 수 있다(질문 947).
  - 목장은 가축 없이 돈다(옛 V4 엔진과 같다). 사다리는 축산물만이다(질문 946).
  - 약초원은 오브젝트 채집소라 반경 안에 약초 덤불(덤불·갈대 소품)이 없으면 일꾼이 내지 않는다(벌목장·광산과 같은 규칙).
  - NPC 도시는 새 세 시설을 짓지 않는다(씨앗 0). 약초·어류·축산물을 쓰는 레시피·생필품이 없다(질문 950·951).
  - 사람이 아닌 유닛(휴먼 구인 카드 뒤 저장 전 기본 스탯 등)은 스탯이 고르면 추천이 표 차례·범용으로 나온다.
  - 미리 보기 기대값은 채집소 버프·피로·창고 상한·오브젝트 번수를 넣지 않는다(화면이 그렇게 적는다).
  - 덮어쓰기 분류 검사를 넓히는 마이그레이션(`20261111110050_nation_power_combat_classes`, 넓히기만 — 직전 판 앱은 모르는 분류 줄을 잠든 줄로 둔다).
- 판: 팩 core@62, 프로토콜 그대로, `SIM_VERSION` 그대로(22), 마이그레이션 하나.
- 다시 볼 조건: 질문 946~960 답, 건물 그림 후속(전용 모델), 놓기 규칙에 땅 조건이 생길 때(물가), 약초·어류·축산물 가공 사슬.
