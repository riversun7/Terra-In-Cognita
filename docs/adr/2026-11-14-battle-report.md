## 배경

사용자 지시(2026-11-14, 원문): "새로만든 /dev/secondary-stats가 메인이고 /dev/balance의 계산식은 필요없다. … /밸런스 페이지는 실제 전투시뮬레이션을
통해. 다중반복, 공성전, 유닛 스탯 및 아이템 등의 비교 테스트를 위한 페이지로 개편해라. 다양한 조건에 따라 N회 반복에 따른 승률이나 상세 데미지,
명중회피, 치명 등의 자세한 수치를 보고서 형식으로 나오게 하고 보고서 및 해당 세팅을 로그처럼 기록되게 하여 나중에 조회할 수도 있게 하면 좋겠다."
같은 날 더한 지시: "전투 흐름에 따라 데미지 계산과정(공격타입/수치, 데미지계산 -> 명중판정 -> 회피판정 -> 방어력(고정,비율,속성값 등), 관통 등 ->
최종 데미지 계산 -> hp/아머/쉴드 반영 이 과정의 흐름도 각각 잘보이게 해달라. 어느 부분에서 밸런스가 안맞는지 판별하기 위함".

옛 [전투 실험실] 몬테카를로는 승률·준/받은 피해·생존만 냈고, 결과를 남기지 않았고, 공성을 돌리지 못했다. 겹침 조사는
`docs/research/2026-11-14-dev-tools-overlap.md`.

## 선택지

1. 기기에서 판정을 돌린다 — AGENTS.md 서버 권위·"apps/game은 packages/sim을 가져오지 않는다"에 어긋난다. 버림.
2. 서버 요청 하나로 끝까지 돌린다(옛 몬테카를로처럼) — 1,000판이면 수십 초라 요청 제한 시간·취소·진행 표시가 없다. 버림.
3. 서버 워커 일(시작·진행·멈춤) + 결과를 DB 기록으로 — 분석 일(`balanceAnalysis.*`)과 같은 꼴. **고름**.

피해 흐름 셈:
- (가) 판정 결과(`AttackResult`)에서 거꾸로 셈 — 방어·배율의 중간 값을 되살릴 수 없다(내림이 단계마다 있다). 버림.
- (나) 판정 코어 `resolveAttack`에 기록 칸(선택)을 넘겨 단계마다 적는다 — 칸이 없으면 적지 않는다(실제 플레이 비용 0). **고름**.

## 결정

### 1. 설정과 판정 (`apps/server/src/battleReport/`)
- 종류 셋: **파티 대 파티**(전투 실험실 사양 만들기 `buildLabUnit`·전투장 `arenaInit`, 홀수 판은 편을 바꿈), **파티 공성**(서버 웨이브·건물 공격과
  같은 공성 전투맵 `siegeArena` + 시작 자리 `siegePlacer`, 도시는 시뮬 도시 평지 배치 `simCitySiegeLayout` 또는 열린 맵, 팀 A 서쪽에서 공격,
  [임시] 공격 편 건물 피해 배율 2,000‰ = 건물 공격 사람형 값), **웨이브 공성**(서버 정원사·시뮬·맞추기 도구와 같은 `waveBattleInit`, 판은 `runWaveToEnd`와
  같은 50틱 멈춤 규칙 — 시험이 같은 끝·같은 시각을 본다).
- 판 시드 = `mix32(seed ^ (판 + 1) × 0x9e3779b1)`(실험실 몬테카를로와 같은 꼴). 같은 입력·시드·규칙이면 같은 보고서(시험: 묶음을 나눠 돌려도 같은 합).
- A/B: B는 같은 종류의 설정(팀·웨이브 값을 따로) 그리고/또는 설정 칸 바꿈(설정 칸 ID 또는 가중치 칸 키, 범위·구조 값 검사, 세계 값은 안 바뀜).
  B는 A와 **같은 판 시드**(공통 난수)라 바꾼 것 하나의 차이만 남는다(시험: 같은 값으로 바꾸면 A와 바이트까지 같은 결과).
  식 덮어쓰기 견주기는 없다(질문 1381).
- 실효 규칙은 요청 때 한 벌(설정 칸·가중치 표·전투 식, 실험실 `rulesNow`와 같은 셈).

### 2. 셈(집계)
- 판정 관찰자(`BattleTrace`) 위에서만 센다: 기본 공격(명중·빗나감·회피·크리, 피해, 크리 피해), 스킬(쓰기·대상 결과), 물리·속성·지속 준/받은 피해,
  회복, 처치·쓰러짐·퇴각, 건물 피해(넥서스·성벽/성문·그 밖), 살아 있던 시간(초당 공격).
- 스태미나로 늦어진 공격([임시], 질문 1378): 틱마다 판정 전에 "행동 시각이 됐고 시전 중이 아닌데 스태미나 < 기본 공격 소모"인 유닛의 기다린 시간,
  그 유닛이 다음 틱 안에 친 기본 공격 수.
- 결과: 승·패·비김, 시간 초과 판정승, 끝난 까닭(전멸·넥서스·시간 초과·공성 크리쳐 다 잃음), 점수(승 1·비김 ½)와 **윌슨 95% 신뢰 구간**,
  전투 시간(평균·p10·p50·p90·막대 12칸), 쓰러뜨리기까지(그 편이 전멸·넥서스로 이긴 판의 시간), 편·유닛(웨이브는 무리) 셈, 공성 결과.

### 3. 피해 흐름(판정 단계)
- `packages/sim/src/combat/attackStages.ts`: `resolveAttack(…, stages?)`가 받은 칸에 단계 값을 적는다. 기본 공격(`battle.ts`)·스킬(`skills.ts`)은
  관찰자에 `attackStages`가 있을 때만 칸을 만들고, 피해 반영 앞뒤 아머·쉴드·HP를 적는다. **판정 값·굴림은 그대로**: 시험이 칸 있음·없음의 결과·끝
  상태가 바이트까지 같음을 본다(`attackStages.test.ts`). SIM_VERSION은 그대로(판정이 바뀌지 않음).
- **엔진 차례**(사용자 목록과 다른 점): 명중 굴림 → 회피 굴림(2차 회피 + AGI 상대 보정, 식 evade_chance로 1~85% 자름) → 크리 굴림(배율은 뒤) →
  공격력(스탯 + 무기 몫, 식 real_attack) → 두 몫 나눔 → 물리: 비율 방어(방어율 − 관통) → 고정 방어 / 속성: 방어 상성 → 속성 방어율 → 속성 저항 →
  크리 배율 → 스킬 배율 → 버프 → 물리 최소 1 → (스킬) 고정 피해 → 아머(물리 몫)·쉴드(속성 몫) → HP.
  사용자 목록은 "데미지 계산 → 명중 → 회피 → 방어"지만 엔진은 **굴림을 먼저**(빗나가면 피해를 셈하지 않는다) 하고, **크리 배율은 방어 뒤**에 곱한다.
  아머·쉴드는 엔진에 있다(물리는 아머부터, 속성은 쉴드부터).
- 저장: 편마다 흐름(단계별 값 합 + 값 막대 — 4분의 1 옥타브 칸, 정수 비교로 칸을 정해 기기와 상관없이 같은 칸)과 공격자→방어자 짝마다 흐름(합만),
  첫 판 표본 8줄. 화면은 단계마다 들어온·나간 수(굴림) 또는 명중 평균(들어옴→나감), p10·p90(막대 근사), 바뀐 몫, **가장 크게 줄인·늘린 단계 표시**.
- 한 대 풀이: 저장된 기록의 판 하나를 지금 규칙으로 다시 돌려 단계 기록(600줄까지)을 낸다(`battleReport.trace`). 저장 때와 설정 판·팩 해시·SIM이
  다르면 "숫자가 다를 수 있음"을 알린다.

### 4. 부하(NAS 1GB·실제 플레이어)
- 워커 스레드(밸런스·실험실과 같은 진입 파일 `balance/duelWorker.ts`, 일 종류 `report`·`reportTrace`, 힙 상한 160MB). 진행은 250ms마다, 멈춤 = 워커 끝냄.
  DB 없는 개발·시험은 같은 스레드에서 4판마다 이벤트 루프에 양보.
- 서버 전체 보고서 한 번에 하나(바쁘면 `busy`), 사용자마다 시작·진행·한 대 풀이 속도 제한. 상한(상수, `REPORT_LIMITS`): 판 수 파티 2,000·공성 200,
  판 수 × 제한 시간(초) 파티 240,000·공성 120,000(A/B는 두 배로 셈), 웨이브 크리쳐 48·수비 32, 파티 6명. 워커 제한 시간은 분석 일과 같은 셈(2~30분).
- 잰 값(Verified, 개발 컨테이너 Node 24.22.1, 실제 팩, 샘플 Lv 30 혼성 5 대 5, 120초 제한, 워커): **1,000판 23.2초**(판 23ms, 판정 CPU 22.9초),
  주 스레드 루프 지연 최대 6ms, 프로세스 RSS 248MB, 보고서 JSON 약 60KB. NAS 값은 재지 않음(Unknown).

### 5. 기록(`battle_reports`, 추가만)
- 설정 전부(`input`), 결과(`report`), 팩 판·해시, SIM_VERSION, 설정 판, 걸린 시간, 만든 사람. 목록 칸(이름·종류·점수)은 따로. 2,000줄을 넘으면
  오래된 것부터 지운다. 세계 새로 시작에도 남긴다(`WORLD_RESET_KEEP`). 마이그레이션 `20261114063847_battle_reports`(표 추가만).
- 감사 기록: `battle_report.start`·`battle_report.cancel`. 권한: `tuning:read`(dev·admin), 기록은 팀이 같이 본다.

### 6. 화면(`/dev/balance`)
- 탭: [전투 보고서](기본, 옛 실험실 팀·유닛 편집·미리 보기 + 보고서 설정 + 한 판·3D 관람), [보고서 기록](날짜·이름·종류로 찾기, 열기, 다시 돌리기,
  둘 견주기), [분포 상성], [스탯 영향도]. 옛 `?tab=lab`은 보고서 탭. 몬테카를로 단추는 없어졌다(보고서가 대신).
- 흐름도: 넓은 화면 가로 사슬, 390px 세로. 개발 화면 층 토큰만.

## 이유
- 판정을 서버 워커에서 돌리고 결과·설정을 기록하는 것이 지시("로그처럼 기록·조회")와 서버 권위를 함께 맞춘다.
- 공성은 새 엔진 없이 서버 웨이브·건물 공격이 쓰는 함수(`waveBattleInit`, `siegeArena`, `siegePlacer`, `simCitySiegeLayout`)를 그대로 쓴다.
- 단계 기록 칸은 판정과 같은 코드 줄에서 적어 "보이는 흐름 = 실제 판정"이 보장된다(다시 셈과 달리 갈라지지 않는다).

## 결과
- 좋은 점: 밸런스 판단(어느 단계가 피해를 가장 많이 깎나·늘리나, 크리 몫, 스태미나 병목)을 수치로 본다. 옛 보고서도 같은 흐름을 다시 보인다.
- 감수: `battleLab.monteCarlo`는 화면에서 쓰지 않는다(지움 권장, 조사 문서 4절). 공성 도시는 시뮬 도시(실제 세계 도시 배치가 아니다).
  웨이브 수비는 [임시] 시뮬 휴먼 사양이다. 흐름 p10·p90은 막대 근사다.
- 다시 볼 조건: NAS에서 1,000판 시간·메모리를 잰 뒤 상한을 맞춘다. 식 덮어쓰기 A/B가 필요하면 질문 1381.

## 바뀜 (2026-11-14, 실제 도시·웨이브 수비·군단)

기획 D-543(1383 나·1384 나)과 D-545(사용자 다시 확인: "실제 세계 도시 고르기", "웨이브 수비에 내 팀", 원문 "전투는 보통 유닛 개별로 움직이는게
아니라 분대,파티가 유닛6개 기본단위이고 파티가 모여 군단 단위로 명령을 한다"). 질문 1461~1470(`docs/questions/2026-11-14-battle-report-2.md`).

### 1. 실제 세계 도시 공성(1383)
- 공성 도시 `city.layout`에 `world`(+ `cityId`)를 더했다. 서버 `battleReport/worldCity.ts`가 살아 있는 세계에서 도시 하나를 **읽기만** 한다:
  배치 = 서버 정원사와 같은 `citySiegeLayout`(넥서스 = 행정 건물 지금 내구도, 다른 건물 = 장애물, 성벽·성문, 지형), 행정 건물이 없으면 열린 맵.
- 수비 고르기 `defense`: 파티 공성 `party`(팀 B, 옛 기록 기본)·`world`, 웨이브 `sim`(옛 기록 기본)·`party`·`world`. 세계 수비 = 그 도시 휴먼
  (정원사 차례 `defenseOrder`, 앞 10명 — 정원사 `WAVE_DEFENDERS`) + 세계 전투 시작 길과 같은 차례(몸 → 비활성·배 위 빼기 → 수호신·방어 버프
  → 남은 HP·아머·쉴드 → 물약·탄). 세계 유닛 ID만 이 길을 지나고, 실험실 유닛 ID는 세계 수비와 싸울 때 2,000,000,001부터·크리쳐는 정원사와 같은
  1,900,000,000부터라 겹치지 않는다. 공격 변은 [임시] 서쪽(질문 1465).
- 세계를 바꾸지 않는다: 쓰기 대기열·DB 쓰기·메모리 표 고침이 없다(DB 시험이 세계 표 지문과 메모리 지문을 앞뒤로 견준다). 스냅숏은 한 요청에
  도시마다 하나(A·B가 같이 쓴다), 판마다 같다.
- 결과 칸 `city`(`ReportCityInfo`): 도시·주인·자리, 스냅숏 시각, 배치 지문(구조 — 내구도 뺌)·넥서스·성벽 내구도, 휴먼·수비·수호신 수, 수비 사양
  지문(자리 뺌). `battleReport.cities`(도시 고르기 목록)·`battleReport.city`(지금 스냅숏 정보, 견주기)를 더했다. 화면은 기록을 열면 지금 도시와
  견줘 바뀐 곳(주인·배치·넥서스·성벽·수비)을 알리고, 한 대 풀이 `same`도 도시 스냅숏을 본다. **다시 돌리기는 지금 도시로 돈다**(질문 1467).

### 2. 웨이브 팀 수비(1384)
- 웨이브 `defense: "party"` + `b`(팀 B 군단): 서버 정원사와 같은 `waveBattleInit`(크리쳐·멈춤 규칙 `runWaveToEnd`와 같은 50틱)에 팀 B 군단을
  같은 시작 자리 차례(`siegePlacer` 수비 자리)로 세운다. 파티 ID 101부터(크리쳐 파티 1~와 겹치지 않음). 무리 줄 대신 파티 유닛 줄.

### 3. 군단(D-179·D-545)
- 팀 = **군단**(`ReportLegion`: 파티 1~4 [임시] 상한, 파티마다 최대 6명) + 군단 명령. 옛 기록의 팀(파티 하나)은 파티 하나뿐인 군단으로 읽는다
  (같은 유닛 ID·파티 ID·자리라 같은 결과 — 시험이 `arenaLegionInit` = `arenaInit`를 본다).
- 판정이 이미 가진 것만 썼다: 파티(`BattlePartySpec`)·지휘관 고르기(지휘 정원 `commandCap`, D-331 "지휘 없음" 표시)·파티 퇴각(D-205).
  파티 명령 = 파티 퇴각 기준선(⑦), 군단 명령 = 정한 시각에 군단 모든 파티 퇴각(판정 입력 `command retreat`). 전진·자리 지키기·목표 같은
  파티·군단 명령은 판정에 없다(질문 1461). 결과 칸 `legion`: 편마다 파티·유닛·지휘 정원·지휘 없음 수(질문 1463).
- 줄 키는 `<팀><파티>.<자리>`(옛 기록 `a2`도 읽는다). 전투장 파티 자리: 0번 가운데, 1·2번 위아래 13칸, 3번 뒤로 7칸 [임시].
- 화면: 팀 판 위 파티 탭(파티 더하기·빼기), 설정 판 "군단 명령"(팀마다 군단 퇴각 시각). 1번 파티는 실험실 팀이라 한 판·3D 관람은 1번 파티끼리
  (질문 1469). A/B에서 B 팀을 따로 고치면 1번 파티만 따로다(질문 1468). 2번부터 파티는 이 기기에 남기지 않는다.

### 4. 부하
- 공성 재료는 여전히 주 스레드에서 만든다. 시작 자리(`siegePlacer`, 공성 재료에서 가장 비쌈 — 개발 컨테이너에서 5~28ms)를 한 번만 만들어
  웨이브 시작 자료와 이어 쓰도록 sim `waveBattleInit`에 선택 칸 `prepared`(미리 만든 전투맵·시작 자리)를 더했다(주지 않으면 같은 결과, SIM_VERSION
  그대로). 스냅숏·재료 덩이 사이에 이벤트 루프에 양보한다.
- 잰 값(Verified, 개발 컨테이너 Node 24.22.1, 부하 평균 5~7의 공유 CPU, 실제 팩, 월드 + NPC 시험 국가 둘, 워커, 20판·제한 600초, 3번):
  주 스레드 루프 지연 p99 = 시뮬 도시 파티 공성 3.5~6.2ms / 실제 도시 파티 공성(세계 수비, 군단 2파티 12명) 4.0~9.1ms / 웨이브 팀 수비(실제
  도시 배치) 4.3~9.7ms. 최대는 셋 모두 7~89ms로 흔들렸다(공유 CPU, 시뮬 도시도 72ms가 한 번). 일 하나 2.3~4.5초. NAS 값은 재지 않음(Unknown).
- 판정을 워커에서만 만들도록(스냅숏 → 워커가 시작 자료) 옮기면 덩이가 더 줄지만 이번에는 하지 않았다(재료 모양이 크게 바뀐다).

## 바뀜 (2026-11-14, 파티·군단 명령·공격 변·수비 군단·군단 한 판 — D-549, 사용자 결정 1464~1469)

질문 1461~1463(기획 D-549)과 2026-11-15 사용자 결정(기획 미러 전 — 조정자 전달, 기획 커밋 b6107b5):
- 1464·1466 원문 "수비도 군단 가능. 군단은 왜 마음대로 4개 분대제한했냐? 3개에서 20개정도로하고 지휘관 능력이나 스킬에 따라 결정되게하자. 수비군도 동일하게 군단가능허다"
- 1465 원문 "실제 웨이브처럼, 위치는 매번설정가능하고 다회반복실험시 랜덤으로 알아서"
- 1467: 다시 돌리기는 지금 도시로, 바뀐 곳을 보인다(지금 그대로). 1468·1469: A/B와 한 판·3D 관람 모두 **군단 전체**. 1470은 묻는 중(지금 그대로).

### 1. 파티·군단 명령(D-549)
- `ReportLegion.orders`(선택, 상한 40): 시각 명령 `{ atSec, party(0부터 · −1 = 군단), kind(advance·hold·attack·retreat·free), target? }`.
  목표 공격의 목표는 상대 군단의 파티·자리(상대가 실험실 군단일 때만 — 파티 대 파티·팀 수비 파티 공성. 웨이브·세계 수비·시뮬 휴먼 상대는 검사가 막는다).
  칸 전진은 보고서에 없다(판마다 편·변이 바뀌어 칸이 같은 뜻이 아니다 — 전진은 적 쪽으로).
- 판정 입력은 `battleReport/orderInputs.ts legionInputs`(보고서·실험실 한 판 같이): 파티 → 판정 파티 ID, 군단 → 편(파티 대 파티의 편 바꾼 판은
  `swappedInputs`로 편 번호만 바뀐다), 목표 → 상대 유닛 ID. 옛 기록의 `retreatAtSec`는 군단 퇴각 명령 하나로 읽는다(옛 판정은 유닛마다 퇴각 명령이라
  지휘 정원 밖 파티도 물러났다 — 이제 1463대로 정원 안만. SIM_VERSION 44라 견주기가 판정 판 차이를 알린다).
- 결과 칸 `orders`: 판 전체 넣은 수·판정이 거절한 수(목표 쓰러짐·정원 밖·다시 넣기 막기). 군단 모양 `legion`의 지휘 정원은 설정 칸 C7 식(실험실 휴먼 1차 10 = 3).
- 화면: 설정 판 "파티·군단 명령"에 팀마다 명령 줄(시각·받는 쪽·명령·목표, 더하기·빼기, `OrdersEditor.tsx`). 파티를 빼면 그 파티 명령을 지우고 뒤 번호를
  당기며, 상대 군단의 그 파티 목표 공격도 지운다. 명령은 이 기기에 남긴다(2번 파티부터를 가리키는 명령은 그 파티가 없으니 열 때 버린다).

### 2. 군단 크기(1464)
- 파티 상한 `legionPartiesMax` 4 → **20**(지휘관 정원 위 끝과 같음). 정원 밖 파티도 편성할 수 있지만 군단 명령을 받지 않는다.
- 전투장 파티 자리: 세 줄(가운데·위·아래 13칸)씩 채우고 다음 셋은 뒤로 7칸(옛 0~3번 자리는 그대로). 뒤로 밀린 파티는 가장 가까운 빈칸.
- 유닛 ID: 팀 A 17~20번 파티는 1001부터(옛 ID 1~·101~과 겹치지 않게 — 팀 B 101~). 줄 키·한 판 이름표는 A2·3 꼴.

### 3. 수비 군단(1464·1466)
- 실제 도시 세계 수비: 정해진 10명 대신 **그 도시 휴먼으로 된 수비 군단** — 스냅숏은 휴먼을 120명(20파티 × 6)까지 담고, 세계 전투 시작 길로 몸을
  만든 뒤 휴먼 수비 파티(6명씩, 정원사 차례) 가운데 지휘관 정원(그 휴먼들 가운데 가장 큰 값, C7)만큼 앞 파티만 남긴다(`setup.ts worldDefenderLegion`).
  수호신 파티는 그대로. 결과 칸 `city.defenders`는 남긴 수. 서버 정원사의 실제 웨이브 수비(10명)는 그대로다(질문 1547).
- 팀 수비(파티 공성 팀 B·웨이브 팀 수비)는 이미 군단이고 명령도 받는다.

### 4. 공격 변(1465)
- 공성·웨이브 `edge`: 0 북·1 동·2 남·3 서 또는 `random`(새 폼 기본). 없으면 서쪽(옛 기록). random이면 네 변 재료(시작 자리·시작 자료)를 만들어
  두고 판마다 그 판 시드로 고른다(`@terra/shared reportRunEdge` — 같은 시드면 같은 변, 다시 돌리기·한 대 풀이가 같다). 결과 칸 `edges`(변마다 판 수).
  네 변 재료는 주 스레드에서 차례로 만들고 사이에 양보한다(재료 시간 약 4배 — NAS 루프 지연은 재지 않음, Unknown).

### 5. A/B·한 판(1468·1469)
- B 팀 따로: 1번 파티뿐 아니라 B 군단 전체(2번 파티부터·명령, 폼 `variantLegion`)를 따로 든다. 팀 판 파티 탭·명령 칸은 고치는 설정(A·B)의 군단을 고친다.
- 한 판·3D 관람(`battleLab.battle`·`replay`): 입력 `legion`(선택 — 군단 둘)이 있으면 모든 파티와 명령으로 돈다(`ArenaJob.legion`, 리플레이 기록기
  입력 포함). 파티 하나·명령 없음이면 옛 입력 그대로. 몬테카를로(옛 도구, D-545 "둠")는 받지 않는다.
