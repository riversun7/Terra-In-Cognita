## 선택지
### 이동 부품을 어디에 둘까
1. **스킬 항목의 선택 칸(자기 이동 `move`, 대상 옮김 `displace`)** — 스킬 편집기·팩 검사·생성기가 같은 항목 하나를 본다. 자원·쿨·시전·조건·AI 고르기(지금은 목록 차례)를 그대로 쓴다.
2. 새 명령 종류(돌진 명령·점멸 명령) — 사용자 답 2와 어긋난다(돌진·회피·은신은 AI가 정함).
3. 효과 사전 항목으로 — 효과는 시간 동안 걸리는 수치라 "한 번에 칸을 옮김"과 결이 다르다.

### 곡선을 언제 걸까
- 가. 계열(속성 스킬이면 늘 마법 거리 곡선 등)로 자동 — 지금 팩 스킬(불꽃 화살 등)의 결과가 바뀐다.
- 나. **스킬마다 고르는 칸(`curves`, `shots`)** — 새 부품이 없는 전투는 결과가 그대로다. 생성기(3단계)가 계열에 맞춰 칸을 채운다.

### 리플레이에 움직임을 어떻게 싣나
- ㄱ. 걸음 사건(`move`)만 — 점멸(사라짐·나타남)·밀치기를 걸음 보간으로 그려 틀린다.
- ㄴ. **새 사건 종류(`motion`·`stealth`·`run`·`multishot`)를 끝에 더하고 키프레임에 은신·달리기 표지** — 실시간 전투와 리플레이가 같은 사건을 읽는다.

## 결정
이동 부품 1, 곡선 나, 리플레이 ㄴ.

### 1. 달리기(running)
- 유닛 상태 칸 `running`(켜졌을 때만 둔다 — 안 쓰는 전투의 상태 JSON이 그대로다). 달리는 동안 한 칸 가는 시간 = 걷기 간격 × `moves.run.intervalPm` ÷ 1000([임시] 600‰ ≈ 1.67배 빠름). 걷기는 그대로 무료(D-418).
- 스태미나: 초당 기본 소모 `moves.run.staminaPerSec`([임시] 15, 공격 한 번 10·분당 회복 720 = 초당 12보다 조금 큼)를 행동 소모와 같은 STA 배율(N13·D-511 `specStaminaCostMilli`)로 셈하고, 틱마다 몫을 나눠 뺀다(분당 회복처럼 버림 손실 없음). 모자라면 달리기가 꺼진다(지친 유닛은 걷는다).
- 켜는 곳: 유닛 대기 명령의 선택 칸 `run`(이동·공격 명령, sim 입력. 프로토콜은 아직 그대로 — 뒤 작업 WP-5)과 AI 고리 `wantsRun`(지금은 명령 칸만 본다). 명령이 끝나거나 바뀌면 꺼진다.

### 2. 이동 부품(모두 칸 단위, 정수)
스킬 항목 선택 칸 `move`(자기 몸) 하나와 `displace`(맞은 대상) 하나. 둘 다 없으면 옛 스킬과 같다.

| 부품 | 칸 | 판정 |
|---|---|---|
| 돌진 `dash` | `cells`, `hitRange`(기본 1) | 목표 쪽 곧은 줄(정수 브레즌햄)로 한 칸씩 간다. 못 지나가는 칸·다른 유닛(아군 포함)이 있으면 그 앞에서 멈춘다. 목표에서 `hitRange` 안에 닿으면 멈춘다. 끝에서 목표가 `hitRange` 안이면 스킬 피해·효과가 붙는다(아니면 헛침) |
| 도약 `leap` | `cells` | 길은 보지 않고(유닛·바위·수풀을 넘는다) 내릴 칸만 본다: 시작에서 `cells` 안, 지나갈 수 있고 빈 칸 가운데 목표에 가장 가까운 칸(같으면 시작에 가까운 칸, 그다음 칸 번호). 건물(성벽·성문)은 넘지 않는다(길 위에 무너지지 않은 건물 칸이 있으면 그 칸은 후보에서 뺀다). 내린 뒤 스킬이 붙는다 |
| 점멸 `blink` | `cells`, `dir`(`toward`·`away`) | 시야 안 순간이동: 시작에서 `cells` 안이고 **자기 시야 반지름 안·시선이 열린** 지나갈 수 있는 빈 칸. toward = 목표에 가장 가까운 칸, away = 목표에서 가장 먼 칸. 사라짐·나타남은 리플레이 사건 하나(`motion` kind blink) |
| 뒷걸음 `backstep` | `cells` | 목표 반대쪽 곧은 줄로 한 칸씩, 막히면 멈춘다(돌진의 반대). 뒤에 스킬 피해가 있으면 새 자리에서 사거리·시선을 다시 본다 |
| 은신 `stealth` | `durationMs` | 자기(대상 self). 은신 중에는 적 편 시야에 들지 않는다(편마다 시야, D-208). 공격(기본 공격·적 대상 스킬)하면 깨지고, 들키면(적 유닛의 감지 반지름 안 + 시선) 깨진다. 맞는 것으로는 깨지지 않는다(범위 스킬은 보이지 않아도 맞는다, D-227) |
| 감지 `detect` | `cells`, `durationMs` | 자기. 그동안 감지 반지름 = max(기본 `moves.detectCells`, `cells`). 기본 감지 반지름은 [임시] 1칸(수풀 C24와 같다) |
| 밀치기 `knockback` (`displace`) | `cells` | 맞은(명중) 대상마다 시전자 반대쪽 곧은 줄로 한 칸씩, 막히면 멈춘다. 부딪힘 피해 없음([임시]) |
| 끌어오기 `pull` (`displace`) | `cells` | 맞은 대상을 시전자 쪽으로, 시전자 옆 칸에서 멈춘다 |
| 묶기 `root` (`displace`) | `durationMs` | 맞은 대상에 상태이상 묶임(효과 사전 `root`와 같은 판정, 저항 없음 [임시]). 효과 ID `move_root` |

- 판정 차례(한 스킬): 자원·쿨 → 자기 이동 → (붙는 피해·효과가 있으면) 새 자리에서 대상에게 → 맞은 대상마다 `displace` → 은신·감지. 옮긴 유닛의 다음 걸음 시각은 지금 + 걷기 간격.
- 점유: 이동 부품은 그 틱의 점유 격자(`occupied`)를 고친다. 공중 유닛은 점유를 보지 않는다(걸음과 같다).
- 돌진·도약은 목표가 시전 사거리 안이어야 고른다(스킬 `range`). AI는 지금 목록 차례로 고른다(`pickSkill`). 같은 고리에서 4단계가 슬라이더로 바꾼다.

### 3. 계수 곡선(설정 칸 `moves.*`, 모두 ‰ 정수)
스킬 칸 `curves`(고른 곡선 이름 목록)와 `shots`(연사 수, 2~8)로 고른다. 곡선은 스킬 배율(`skillMulPm`)에 곱한다(곱할 때마다 버림).

| 곡선 | 칸 이름 | 식([임시] 값) |
|---|---|---|
| 물리 사거리 ↔ 공격 간격 예산 | `range_interval` | 이 스킬 뒤 행동 간격 = 공격 간격 × min(최대, 1000 + max(0, 사거리 − 1) × 칸당) ÷ 1000 (칸당 100‰, 최대 2500‰). 생성기 예산식도 같은 함수를 쓴다 |
| 마법 거리(가까울수록 셈) | `magic_distance` | 대상마다 거리 d(체비쇼프) → max(최소, 가까움 − max(0, d − 1) × 칸당) (가까움 1200‰, 칸당 50‰, 최소 800‰) |
| 마법 대상 수 줄임 | `magic_targets` | 맞을 대상 n: n ≤ 1 → 1000‰, n ≥ 2 → max(최소, 범위 − (n − 2) × 대상당) (범위 550‰, 대상당 25‰, 최소 300‰) |
| 지속 피해 합 줄임 | `dot_total` | 이 스킬이 거는 지속 피해 값 × max(최소, 1000 − max(0, 지속초 − 무료초) × 초당) (무료 3초, 초당 50‰, 최소 500‰). 지속 0(전투 내내)은 최소 |
| 원거리 연사 | `shots` 칸 | 한 발 배율 = max(최소, 1000 − (발 수 − 1) × 발당) (발당 150‰, 최소 300‰). 발마다 명중·회피·크리를 따로 굴린다. 대상 하나 모양(single·projectile)만 |
| 가까이 쏘기 보너스 | `close_shot` | 사거리 2 이상 스킬이 거리 ≤ 칸(2)인 대상에 × (1000 + 보너스) (보너스 200‰) |

- 곡선 함수는 `combat/curves.ts` 하나에 두고 판정·생성기·밸런스 화면이 같이 쓴다.
- 기본 공격(무기)에는 아직 걸지 않는다(질문 1594·1595, 뒤 작업 WP-7).

### 4. NPC·결정성
- NPC·크리쳐·정원사 웨이브 유닛은 같은 스킬 칸을 쓰면 같은 판정을 받는다(P0). 따로 규칙 없음.
- 정수·시드 굴림만 쓴다. 이동 부품은 굴림을 뽑지 않는다(연사는 발마다 공격 굴림 넷). 후보 칸 고르기는 칸 번호까지 차례를 정해 같은 입력 → 같은 칸.
- 새 상태 칸(`running`·`stealthUntilMs`·`detectUntilMs`·`detectCells`)은 켜졌을 때만 둔다 → **새 부품이 없는 전투는 끝 상태 JSON까지 바이트로 같다**(시험이 기준 커밋 지문과 견준다).

### 5. 리플레이·실시간 사건(@terra/protocol 리플레이 형식 2)
- 관찰자(`BattleTrace`)에 선택 칸 넷: `motion(unit, kind, from, to)`, `stealth(unit, on, cause)`, `run(unit, on)`, `multishot(unit, skill, target, shots)`. 상태·굴림에 손대지 않는다.
- 사건 종류를 끝에 더한다(번호를 다시 쓰지 않는다): `motion`(kind = dash·leap·blink·backstep·knockback·pull, 앞 칸·새 칸·방향), `stealth`(on, cause = skill·attack·detected·expired), `run`(on), `multishot`(목표·스킬·발 수). 스킬 모양 끝에 `move`(피해 없이 움직이기만 하는 스킬).
- 키프레임 유닛에 `stealth`·`running` 표지. `applyReplayEvent`가 `motion`으로 자리·방향을, `stealth`·`run`으로 표지를 바꾼다(키프레임과 사건 되짚기가 같은지 시험이 본다). 움직임 부품으로 옮긴 틱에는 걸음 사건을 따로 싣지 않는다.
- 형식 판 `BATTLE_REPLAY_FORMAT_VERSION` 1 → 2. 읽기는 1·2 모두 받는다(1은 표지 없음). 리플레이는 저장하지 않고 요청 때 만든다(Verified: `apps/server/src/battleReplay/compute.ts`) → 옛 자료 걱정 없음. **WebSocket 메시지가 아니라 PROTOCOL_VERSION은 그대로다**(실시간 전투 화면은 아직 없다. 생기면 같은 사건을 보낸다).
- 게임 앱: 보기 화면이 새 사건에서 깨지지 않는다. 자리는 상태 되짚기로 바뀌고, 점멸은 앞·새 칸에 번쩍임, 밀치기·끌어오기·돌진·도약은 그 자리 번쩍임, 은신 중 유닛은 반투명, 연사는 투사체 한 줄로 그린다(자리표시 그림). 절차적 움직임은 WP-2.

### 6. 스킬 체계 고리
- 팩 스킬 항목 선택 칸(`formatVersion` 그대로): `move`·`displace`·`curves`·`shots`. 팩 검사:
  - `move` kind dash·leap·blink·backstep → 대상 enemy. stealth·detect → 대상 self(모양 buff).
  - 모양 `move` ⇔ 피해 없음(damage none) + 자기 이동 부품(dash·leap·blink·backstep) 필수, 대상 enemy.
  - `displace`는 적에게 맞는 모양(single·projectile·area·chain·debuff)만.
  - `shots`는 single·projectile만, 2~8. `curves`는 이름이 겹치지 않게, 피해 스킬만(dot_total은 지속 피해 효과가 있을 때만).
- 판정: `skillFromData`가 칸이 있을 때만 전투 스킬에 싣는다(없으면 칸을 두지 않아 상태 JSON이 그대로). 스킬 편집기는 항목을 통째로 저장하므로(ADR skill-editor 2절) 칸을 잃지 않는다. 편집기 입력 칸은 뒤 작업(WP-6).
- **AI 고리**(`combat/moveAi.ts`, 4단계가 몸통을 바꾼다. 지금 기본값은 아래):
  - `wantsRun(unit, ctx)`: 달릴까 — 지금 = 명령의 `run` 칸. 4단계: ② 추격·⑦ 퇴각·① 교전.
  - `moveSkillAllowed(unit, skill, ctx)`: 이 이동 스킬을 지금 써도 되나 — 지금 = 늘 참(목록 차례). 4단계: 돌진 = ① 교전, 회피(뒷걸음·점멸 away) = HP·위협, 은신 = ③ 엄폐·은신, ⑤ 스킬 아끼기.
  - `stealthBreaksOnDamage`: 맞으면 은신이 깨지나 — 지금 거짓(질문 1583).
  - 유저 스킬 명령("이 스킬을 저 대상에", D-177 1칸·1초)은 같은 `skillUsable`·사거리 검사로 받는다(WP-5).

### 7. 판·버전
- `SIM_VERSION` 46(새 규칙·새 입력 칸. 새 부품이 없는 전투 결과는 그대로), 팩 `core@99`(설정 칸 `moves_*` 더함). 프로토콜(WebSocket) 판은 그대로(32·33 쓰지 않음).

## 이유
- 스킬 칸으로 두면 생성기(3단계)가 "이동 부품 + 곡선 + 예산"을 한 항목으로 만들고, 밸런스 화면·편집기·팩 검사·AI가 새 경로 없이 받는다. 사용자 답 2(AI가 돌진·회피·은신을 정함)와도 맞다.
- 곡선을 고르는 칸으로 두면 지금 콘텐츠의 결과가 그대로다(사용자 지시 "새 부품 없는 전투는 결과가 같게"). 계열 기본값은 생성기가 정한다.
- 켜졌을 때만 상태 칸을 두는 것은 파티·군단 명령(SIM 44)과 같은 방식이고, 스냅숏·재생·지문 시험이 그대로 통한다.
- 리플레이 사건으로 싣기: 점멸·밀치기는 걸음 보간으로 그리면 틀리고(Verified: `replayTimeline.ts`는 걸음을 걷기 간격으로 보간), 실시간 전투가 생겨도 같은 사건을 쓴다.

## 결과
- 좋은 점: 재능 계열의 돌진·도약·연사와 마법의 거리·범위 줄임을 데이터로 만들 수 있다. NPC도 같은 규칙. 리플레이에 보인다.
- 감수할 점: 기본 AI는 이동 스킬을 목록 차례로 쓴다(뒷걸음을 붙어 있지 않아도 쓸 수 있다) — 팩에 이동 스킬을 넣기 전에 4단계가 필요하다. 움직임 부품으로 옮긴 틱의 걸음 몫은 리플레이에서 순간 이동처럼 보인다. 실시간 전투 전송은 아직 없다.
- 다시 볼 조건: 기획 결정 번호가 붙을 때(질문 1581~1600 답), 생성기가 곡선 값을 바꾸자고 할 때, 크기 상성(D-474)으로 밀치기 저항을 넣을 때.

## 뒤 작업(이 줄기 밖)
- **WP-2 절차적 움직임 그림**: 돌진 줄무늬·도약 포물선·점멸 사라짐/나타남·은신 반투명·밀치기 미끄러짐·달리기 보폭(코드로, 자산 없음). 그림 층은 "움직임 사건 → 자세 곡선" 함수 하나로 두어 뼈대 애니메이션이 같은 사건을 받게 한다.
- **WP-3 스킬 생성기**: 힘 예산 식(공격 배율 × 대상 수 곡선 × 거리 곡선 × 연사 × 사거리 예산 ÷ 자원·쿨) → 계열마다 후보를 많이 만들고 밸런스 화면 상성표로 거르고 사람이 골라 이름·효과를 붙인다. 첫 묶음 계열마다 10~15.
- **WP-4 AI 슬라이더 통합**: `moveAi.ts` 고리 몸통(① 교전 ② 추격 ③ 엄폐·은신 ⑤ 스킬 아끼기 ⑦ 퇴각, D-5039·D-5040 기회 굴림).
- **WP-5 유저 스킬 명령**: sim 명령 `skill`(스킬·대상) + WebSocket 명령 + 서버 1초 잠금(D-177), 달리기 칸 `run`의 프로토콜.
- **WP-6 스킬 편집기 칸**: `move`·`displace`·`curves`·`shots` 입력(ko·en 문구).
- **WP-7 무기 곡선**: 기본 공격에 사거리 예산·가까이 쏘기를 걸지(밸런스 화면 확인 뒤).
- **WP-8 실시간 전투 전송**: 같은 사건을 편 시야로 거른 실시간 스트림(D-6036).
- **WP-9 밀치기 저항**: 크기 상성(D-474)·보스.
