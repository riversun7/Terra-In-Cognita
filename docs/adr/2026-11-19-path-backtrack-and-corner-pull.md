# 2차맵 경로 출발 칸 역행 제거와 모서리 당기기

- 상태: 확정
- 날짜: 2026-11-19
- 관련: `2026-11-15-path-smoothing.md`, `2026-11-14-segment-speed.md`, `packages/sim/src/path/waypoints.ts`, `packages/sim/src/path/smooth.ts`

## 배경

사용자 지적(2026-11-19, 모바일 2차맵 사진과 함께): "이동시 이동인디케이터가 끊어져있고 너무 각지며 유닛이 근처 타일로 뒤로 갔다가 이동하는등 부자연 스러운 모습도 개선해라."

원인(Verified: 코드 분석):
1. **출발 칸 중심으로 역행**: `planRoute`는 유닛의 현재 위치 `from`이 출발 기준 칸 중심(`centerOfCell`)과 다를 때 무조건 `from`을 출발 칸 중심 앞에 끼워 넣었다. 이동 중 재명령 등으로 유닛이 칸 중심보다 앞쪽(목표 방향 쪽)에 있을 때도 출발 칸 중심으로 되돌아간 뒤 다시 꺾어 출발하는 부자연스러운 역행이 발생했다.
2. **앞쪽 욕심 탐색의 직각 모서리 과다**: `smoothCellPath`는 출발 칸에서 가능한 가장 먼 칸까지 한 번에 건너뛰므로, 성벽 등 장애물 모서리를 돌 때 모서리 바로 다음 칸에서 비스듬히 꺾지 않고 직선 끝까지 내려간 뒤 직각(L자)으로 꺾는 경로가 남았다.

## 선택지

1. **출발점 직선 검증(`directSegmentPace`) + 2차 모서리 당기기(채택)**: 기존 A* 코어와 비용 규칙은 그대로 두고, `planRoute`와 `smoothCellPath` 후처리만 보강한다.
2. **Theta*로 A* 탐색기 교체**: 최단 임의 각도 경로를 얻지만 A* 코어·노드 예산·기존 골든 시험이 전면 변경된다.

## 결정

1. **출발 칸 중심 건너뛰기 (`sweptAnchorsFromPoint`·`directSegmentPace`)**:
   - `from`이 출발 기준 칸 중심과 다를 때, `from` → 다음 꺾이는 칸 중심으로 크기 등급 `s` 정사각형이 쓸고 가는 기준 칸을 정수 격자선 교차 비교로 정확히 구한다(`sweptAnchorsFromPoint`, 결정적 정수 연산).
   - 쓸고 가는 칸이 모두 통과 가능(`clearance >= s`)하고 원래 출발 칸 → 다음 칸 직선의 최대 칸 비용을 넘지 않으면 출발 칸 중심을 건너뛰고 `from`에서 곧장 진행한다.
   - 단, 출발 칸 중심 쪽으로 앞으로 나아가며 출발 칸이 다음 구간보다 느린 경우(느린 지형을 빠져나가는 경우)는 구간 걸음 배율을 지키기 위해 출발 칸 중심을 유지한다.
2. **2차 모서리 당기기 (`smoothCellPath`)**:
   - 앞쪽 욕심 탐색 결과가 3점 이상일 때 연속 세 점 `A → B → C`에 대해 `A`와 `C` 사이의 A* 칸 `m` 중 `A → m`과 `m → C`가 모두 통과·비용 조건을 만족하며 유클리드 합이 더 짧은 칸으로 `B`를 당긴다.
3. **`SIM_VERSION` 62 → 63**.

## 이유

- 정수 교차 비교(`|dx|·|dy| <= 6.87e10 < 2^53`)와 IEEE-754 명세 함수 `Math.sqrt`만 사용하여 엔진·플랫폼과 무관하게 결정적이다(Verified: `determinism-scan`·단위 시험).
- 장애물 통과 폭·비용 조건을 모두 재검증하므로 벽 모서리를 뚫거나 비싼 지형을 가로지르지 않는다.

## 결과

- 이동 중 방향을 바꾸거나 칸 중심 밖에서 출발할 때 뒤로 갔다가 움직이는 현상이 사라진다.
- 장애물 모서리 주변의 불필요한 L자 직각 꺾임이 줄어든다.
- 같은 입력의 꺾이는 점과 도착 시각이 옛 판(62)과 달라지므로 `SIM_VERSION`을 63으로 올린다.
