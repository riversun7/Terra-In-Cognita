# 누르는 곳 최소 크기 44px 규칙을 24px(WCAG 2.2 AA)로 풀기

- 상태: 확정
- 날짜: 2026-11-21
- 관련: `2026-10-28-design-system.md`(촘촘 변형 "조작부 44px"를 대체), `2026-10-29-app-shell.md` 10절("누르는 곳은 44px 이상"을 대체), 작업 기록 `docs/worklog/2026/11/21-2030-tap-target-relax.md`

## 배경
- 커밋 `65ca9594`(Antigravity, 테마·홈 카드 정돈)가 작은 단추 높이 `--control-h-sm`을 44px에서 38px로 낮췄다. 그 뒤 화면 시험 `smallTapTargets`(기준 `--tap-size` 44px)가 [뒤로]·[닫기]·[멈추기] 등을 잡아 실패했다.
- 처음에는 규칙에 맞춰 38px을 44px로 되돌렸다(커밋 `93860128`).
- 사용자 답(2026-11-21): "일단 마음대로 빠르게만 진행해라. 그런데 디자인 규칙을 바꿔라 왜 그렇게 엄격한 제한을 두는가."

## 결정
- 자동 검사가 막는 누르는 곳 최소 크기는 **24px**이다. 새 토큰은 `--tap-min`이다.
  - 근거: WCAG 2.2 성공 기준 2.5.8 Target Size (Minimum), AA 등급, 24×24 CSS px. 44px은 더 엄격한 AAA 등급(2.5.5 Target Size (Enhanced))이다.
  - 출처(Verified, 2026-11-21 확인): https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html
- `--tap-size`(44px)는 권장 크기로 남는다. 위 띠 높이 같은 배치 값과 큰 조작부에 그대로 쓴다. 다만 이것을 넘지 못했다고 실패하지는 않는다.
- 작은 단추 `--control-h-sm`은 38px로 되돌린다(Antigravity 값).
- 화면 시험 `smallTapTargets`는 기본으로 `--tap-min`을 읽는다. 화면마다 더 크게 보고 싶으면 `min`을 준다.
  - 예: 설정 칸 패널의 휴대폰 화면은 `--dev-touch-tap` 44px를 그대로 본다. 따로 정한 사용자 결정이라 이번에 바꾸지 않았다.

## 선택지
- 24px(WCAG AA): 공인 기준 중 가장 느슨하다. 디자인 자유도가 크다. ← 고름
- 38px(지금 작은 단추 값): 지금 화면에만 맞춘 값이라 근거가 약하다.
- 44px 유지: 사용자가 너무 엄격하다고 함.

## 결과
- 작은 단추는 38px로 보이고 시험도 통과한다.
- 24px보다 작은 누름 요소는 여전히 시험이 잡는다. 지도 핀처럼 꼭 작아야 하는 것은 시험의 `ignore`로 뺀다(WCAG의 Essential 예외와 같다).
- 휴대폰에서 자주 누르는 큰 동작(이동·짓기 등)은 권장 크기 `--tap-size`나 `--control-h`(46px)를 쓰는 편이 좋다. 다만 규칙으로 막지 않는다.
