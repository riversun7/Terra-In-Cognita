# 파일 크기 규칙을 경고만으로 (5,000줄)

- 상태: 확정
- 날짜: 2026-11-22
- 관련: docs/PLAN.md 10장(파일 크기), AGENTS.md 4장, ADR `2026-10-28-dev-workflow.md`(옛 규칙, 일부 대체됨)

## 배경
옛 규칙은 600줄 초과 경고, 1,000줄 초과 검사 실패였다(ADR `2026-10-28-dev-workflow.md`, 기술 쪽 결정 — 옛 프로젝트의 4,765줄 거대 파일과 여러 AI 줄기의 합치기 충돌을 줄이려는 뜻). 2026-11-22에는 1,000줄에 닿은 파일이 10개를 넘었고(`app.ts`·`society.ts`·`facilities/service.ts`·`npc/runtime.ts`·`world.ts` 등, Verified: 묶음 1117e·1117h 작업 기록), 줄기와 합치기마다 줄 수를 맞추려고 기능과 상관없이 파일을 나누거나 고칠 일을 미뤘다(예: no-teleport-b 2697, Verified: 작업 기록 `22-1225-no-teleport-b.md`).

사용자 질문(2026-11-22): "왜 천줄제한을하는가? 파일이 많아지는게 더 지저분한거아닌가?"

## 선택지
1. 가: 지금대로(1,000줄 실패).
2. 나: 2,000줄 실패, 1,000줄 경고(기술 추천).
3. 다: 실패 없이 경고만.

## 결정
**다** — 사용자 결정(2026-11-22, 원문 "다 경고만 5천으로 상향?"). 검사는 5,000줄을 넘는 파일에 경고만 하고 실패시키지 않는다(`scripts/check-file-size.mjs`). 자동 생성 파일 제외는 그대로다.

## 이유
- 줄 수 기준의 억지 쪼개기가 파일을 늘리고 찾기 어렵게 만든다(사용자 지적).
- 경고 기준 5,000줄은 옛 프로젝트의 가장 큰 파일(4,765줄)보다 크다. 그래서 경고가 거의 뜨지 않을 수 있다(Assumed). 거대 파일이 다시 생기는지는 작업 기록·검토에서 사람이 본다.

## 결과
- 줄기·합치기에서 "1,000줄 상한 때문에 나눔"이 더 이상 필요 없다. 나눌 때는 기능 단위로 나눈다.
- 이미 크기 때문에 나눈 파일은 그대로 둔다(다시 합치는 일은 하지 않는다).
- 여러 줄기가 같은 큰 파일을 고칠 때 합치기 충돌이 늘 수 있다. 늘면 다시 본다.
