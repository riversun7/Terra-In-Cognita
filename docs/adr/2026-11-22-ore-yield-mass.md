# 광산 한 사이클 무게를 g 단위 바뀜 전으로 되돌림 (N44 20g)

- 상태: 확정
- 날짜: 2026-11-22
- 관련: `docs/adr/2026-11-21-ore-grams-and-cleanup.md`(결정 3을 일부 대체), `docs/adr/2026-10-31-economy-core.md` "바뀜 (D-506·D-507)", 질문 `docs/questions/2026-11-22-stone-balance.md` 2511, 작업 기록 `docs/worklog/2026/11/22-0122-stone-balance.md`

## 배경
- 커밋 `5cf0d2d89a`(SIM 71, core@137)가 광석 10종을 기본 단위 1g·거래 묶음 10kg으로 바꾸면서 광산 한 사이클 수확을 `50 + VIT × 5`(상한 500) × `n44_ore_grams` 1g = **50~500g**으로 정했다.
- 바뀜 전에는 석재·잡석이 1개 = 1kg(묶음 1)이고 광산 수확은 `1 + VIT × 0.1`(상한 10)개 = **1~10kg**, 금속 광석도 같은 개수 × `n44_ore_grams` 1,000g = 1~10kg이었다(Verified: `git show 5cf0d2d89a -- content/core/items.json content/core/facilities.json content/core/tuning.json`).
- 건물·배·알박기·시작 재료의 석재 수량은 같은 커밋에서 무게 그대로 g로 옮겼다(3개 → 3,000g 등). 그래서 "건물 하나에 드는 석재 ÷ 광산 한 사이클 석재"가 20배 커졌다.
- 사용자 결정 D-587 11 나: 이 느려짐은 의도가 아니다. 어느 쪽을 맞출지는 기술이 시뮬로 정한다(D-515).

## 선택지
1. **`n44_ore_grams`(광석 수확 1단위 g) 1 → 20** — 수확량 식(50 + VIT × 5, 상한 500)은 그대로, 한 단위 = 20g. 사이클 무게가 바뀜 전과 정확히 같다(1,000 + VIT × 100g, 상한 10kg).
2. 광산 수확량 식을 g로 다시 적기(`yieldBase` 1,000·`yieldPerStatPm` 100,000·`yieldCap` 10,000) — `yieldBase`·`yieldCap` 스키마 상한 1,000을 넘어 스키마(코드)를 바꿔야 한다.
3. 건물·배·알박기 석재 수량을 20분의 1로(3,000g → 150g 등) — 광산 하나에 석재 200g 같은 무게가 되어 무게 셈(건설 시간·운반)이 어긋나고, 시작 석재·알박기 값까지 다시 맞춰야 한다.

## 결정
- 선택지 1. 팩 `content/core/tuning.json` `n44_ore_grams` 20, 코드 기본값 `TEST_SOCIETY_COEFFICIENTS.gatherOreGrams` 20, 생산 편집기 옛 서버용 기본값 20.
- 광석 1g 기본 단위·10kg 거래 묶음·g 단위 채집(ADR `2026-11-21-ore-grams-and-cleanup.md` 결정 2·3의 단위)은 그대로다. 바뀌는 것은 한 사이클 무게(50~500g → 1~10kg)뿐이다.
- 같은 칸을 쓰는 직접 채집(서버 `gather/service.ts`)과 사이보그 판 기대 금액(`roster/gatherSheet.ts`)도 같이 20배가 되어 바뀜 전 무게로 돌아간다.

## 이유
- 시뮬 econ16 30일 시드 1~3 NPC 짓기(Verified: `pnpm --filter @terra/sim sim econ16 --seed N --days 30`, 전체 표는 작업 기록):
  바뀜 전(SIM 70) 914·877·925 → 바뀜 뒤(SIM 71) 710·786·742(−22%·−10%·−20%) → 이 결정 뒤(SIM 111) 928·872·913(+2%·−1%·−1%).
  레벨 올리기 508·406·450 → 227·205·271 → 558·458·492, 휴먼 2,148·2,463·2,219 → 1,341·1,896·1,514 → 2,332·2,437·2,220.
  build16u 시드 1 짓기 767 → 565 → 746.
- 원인(Verified: 같은 실행의 `economy.produced`): 석재 생산이 30일 60,166kg → 2,120kg(약 28분의 1)으로 줄었다. 건물 석재 수량(무게)은 그대로라 짓기·레벨
  올리기가 석재를 기다렸다. 시세는 kg당 같다(석재 묶음 1kg·1 → 10kg·10, 철광석 1kg·8 → 10kg·80) — 값 문제가 아니라 양 문제였다.
- 이 결정 뒤 석재 생산은 바뀜 전보다 3~12% 많다: 옛 식은 보조 스탯 10당 1개(1kg) 걸음(내림)이고 새 식은 1당 100g이라, 10으로 나누어떨어지지 않는
  스탯에서 조금 더 캔다(Assumed: 식 비교). 레벨 올리기가 9~13% 많은 것도 이 몫으로 본다.
- 칸 하나만 바꾸는 가장 작은 수정이고, 칸 설명("광석 수확 1단위 무게")이 바로 이 용도다. 스키마·무게 셈 코드를 건드리지 않는다.

## 결과
- 좋은 점: NPC 증축·레벨 올리기·인구가 바뀜 전 수준으로 돌아온다. 직접 채집도 바뀜 전 무게(사이클당 kg 단위)로 돌아온다.
- 감수할 점: 수확은 20g 걸음이다(그 안의 g 단위는 쓰지 않는다). `SIM_VERSION`이 바뀌고 팩 판이 오른다.
- 다시 볼 조건: 광석 무게 밸런스(건설 석재 수량·광산 수확)를 실제 플레이로 다시 맞출 때 이 칸을 같이 본다.
