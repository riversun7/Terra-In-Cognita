## 선택지
- 스탯 범위: (가) 기준값 + 스탯별 오차 ±, (나) 스탯별 최소·최대 12칸, (다) 성향 + 총합 범위만.
- 그룹: (가) 변종마다 따로 항목, 대표를 가리키는 칸, (나) 항목 하나 안에 변종 목록(상속), (다) 그룹 분류(파일)를 새로 둔다.
- 3D: (가) 모델 칸만, (나) GLB 뷰어 + 모델이 없을 때 임시 몸, (다) 임시 몸만.

## 결정
### 1. 화면 탭 둘
- `[도감]`(첫 탭): 전체 크리쳐를 한 줄씩 훑는 표. 이름·ID 검색, 분류·등급·주속성·스탯 성향으로 거르고, 도감 차례·이름·등급·스탯 합으로 차례를 바꾼다. 변종은 대표 아래에 들여 쓰고 그룹마다 접는다.
- `[상세·편집]`: 옛 화면(왼쪽 목록 + 오른쪽 상세) 그대로. 상세 안 탭 맨 앞에 "도감 정보"를 더한다(일러스트 + 3D, 설명·분류·속성, 스탯 성향과 1레벨 조우 범위, 변종 그룹, 전리품 요약).
- 도감에서 줄을 고르면 상세의 "도감 정보"로 넘어간다. `?creature=<ID>`로 열면 옛날처럼 상세의 "기본" 탭(초상화 선택기)이 바로 뜬다. 상세 안 탭은 크리쳐를 바꿔도 그대로 둔다(잇달아 고치기).

### 2. 변종 그룹 = 따로 항목 + `variantOf`
- 팩 크리쳐에 선택 칸 `variantOf`(크리쳐 ID)를 더한다. 변종은 자기 ID·그림·스탯·전리품을 가진 온전한 항목이고, 그룹 대표를 가리킨다. 대표와 단독 크리쳐는 이 칸을 적지 않는다.
- 그룹은 한 단계다: 대표는 변종이 아니어야 한다(팩 검사 `creature_variant_chain`). 자기 자신은 가리킬 수 없다(`creature_variant_self`). 대표가 있는지는 참조 검사가 본다.
- 편집기 동작(도감 정보의 그룹 카드): `[+ 변종 추가]` = 지금 크리쳐를 복제해 새 ID로 담는다(그대로 / 주속성 바꿈 — 주속성 칸과 고른 칸을 맞바꾼다 / 스탯 성향 바꿈 — 같은 합을 다시 나눈다), 기존 단독 크리쳐를 변종으로 넣기, 그룹에서 빼기, 대표로 지정(옛 대표와 다른 변종이 새 대표를 가리킨다).
- 지금 팩 자료는 바꾸지 않았다(91종 모두 단독). 묶기는 편집기에서 한다.

### 3. 3D 미리 보기 = GLB 뷰어 + 임시 몸, 일러스트와 나란히
- 팩 크리쳐에 선택 칸 `model`(GLB 파일 이름 → `/creatures/models/<이름>`, 또는 `/`·`http`로 시작하는 경로)을 더한다. 서버는 `apps/game/public/creatures/models/`의 `.glb`·`.gltf` 이름을 편집기에 알려 준다.
- 엔진 진입점 `@terra/engine/creaturePreview`(`packages/engine/src/creatures/creaturePreview.ts`): 캐릭터 미리 보기와 같은 조작(끌기·휠·두 손가락·돌림판)과 같은 낮 빛. 모델 파일이 있으면 three의 `GLTFLoader`로 읽어 받침 가운데에 세우고(크기는 그대로, 카메라·받침을 모델에 맞춘다) 첫 애니메이션 클립을 돌릴 수 있다. 없거나 읽지 못하면 임시 몸(2차맵 큰 유닛과 같은 네 발 짐승, 크기 등급 배율)을 보인다.
- 새 런타임 의존성은 없다(`GLTFLoader`·`RoomEnvironment`는 이미 쓰는 `three` 0.186.1의 `examples/jsm`).

### 4. 스탯 = 1레벨 기준값 + 스탯별 조우 오차(±)
- `primaries`는 그대로 1레벨 기준값(도감 값)이다. 선택 칸 `primarySpread`(스탯마다 0~10)를 더한다.
- 오차 기본 규칙(칸이 없을 때): 기준 10 이하 ±1, 20 이하 ±2, 그 위 ±3(`@terra/shared/creatureEditor` `creatureDefaultSpread`). 사용자 원문의 "스탯3이하는 3"은 30으로 읽었다(Assumed). 30을 넘는 스탯도 ±3이다(Assumed).
- 조우 범위 = 기준 − 오차 ~ 기준 + 오차(최소 1). 편집기는 여섯 칸이 모두 기본 규칙과 같으면 `primarySpread`를 적지 않는다(기준값을 바꾸면 오차도 따라간다).
- 스탯 성향 표시: 1차 스탯 묶음(STR·VIT 물리, DEX·AGI 기교, INT·WIS 마법) 가운데 몫이 40% 이상인 묶음, 없으면 균형(`creatureStatProfile`). 표시용이고 저장하지 않는다.
- 랜덤 분포 뽑기(편의 기능): 총합(직접 준 값, 없으면 등급 기본)과 고정할 스탯을 정하면 나머지를 성향·크기·주력 비중에 흔들림(±40%)을 얹어 나눈다(`rollCreatureStatDistribution`, 시드 난수, 합 = 총합).
- **여기서 하지 않는 것**: 조우 레벨, 출현 확률, K값. 레벨·출현은 인카운터 페이지(지형·범위별)가 정하고 K값은 기존 규칙(0.8~1.2 랜덤)이다(사용자 답). 조우 때 실제로 스탯을 굴리는 코드도 아직 없다(인카운터 줄기에서 만든다).

### 5. 전리품 = 아이템 + 획득 확률
- 화면은 아이템 고르기(검색·분류)와 획득 확률(‰)만 다룬다. 수량 칸, 기대 가치, 사냥 시뮬레이터는 화면에서 뺐다.
- 자료 모양(`drops`: `item`·`chancePm`·`min`·`max`)은 그대로다. 이미 적힌 수량은 건드리지 않고 새 줄은 `min = max = 1`이다.

## 이유
- 스탯 (가): 사용자 답 그대로다. 기존 91종 값이 그대로 기준값이 되어 옮길 자료가 없다(Verified: `apps/server/src/creatureEdit/views.test.ts` 91종 왕복 통과).
- 그룹 (가): 사용자 선택. 변종이 독립 ID라 전리품·스킬·그림을 따로 줄 수 있고, 이미 따로 있는 항목(슬라임·메탈 슬라임 등)을 자료 옮김 없이 묶을 수 있다. 분류 파일을 새로 두면(다) 덮어쓰기 표의 분류 제약(마이그레이션)까지 늘어난다.
- 3D (나): 사용자 답 "둘 다 보여지게". 모델 자산이 아직 없어 임시 몸이 없으면 3D 칸이 비어 보인다.
- `primarySpread`·`variantOf`·`model`은 모두 선택 칸이라 직전 판 팩·덮어쓰기와 호환된다(Verified: `pnpm check:content`).

## 결과
- 좋은 점: 도감에서 91종을 한 화면에서 훑고, 변종을 대표 아래에서 관리한다. 모델 파일만 넣으면 3D가 뜬다.
- 감수할 점:
  - 조우 범위의 최대 합(기준 합 + 오차 합)은 초기 스탯 합 상한(D-534, 설정 칸 `n9_creature_sum_max`·절대 100)을 넘을 수 있다. 팩 검사는 기준 합만 본다. 조우 때 굴린 값을 상한으로 줄이는 일은 인카운터 줄기 몫이다(`@terra/shared/statGrowth` `capStatSum`).
  - 임시 몸은 모든 크리쳐가 같은 네 발 짐승이다(색·크기만 다르다).
  - 대표를 지우거나 팩 원본으로 되돌리려면 먼저 변종을 그룹에서 빼거나 다른 대표를 세워야 한다(참조 검사가 막는다).
- 다시 볼 조건: 인카운터 페이지를 만들 때(스탯 굴림·레벨·K), 전리품용 아이템이 생길 때(수량·시뮬레이터 되살리기), 크리쳐 3D 자산 규격이 정해질 때(크기 맞춤·애니메이션 이름).
- 기획 미러(`docs/design/`)에는 아직 없는 규칙이다(스탯 오차, 변종 그룹). 기획 세션에 전달이 필요하다.
