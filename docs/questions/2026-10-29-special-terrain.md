- 규모: 1차맵 칸 띠 → 2차맵 안 지점(온천 하나는 실제 10~500m(게임 1~42m)). F9 지점 수(시드별): 온천(실제 40km 간격) 1,284·1,093·1,376곳, 간헐천 지대(80km) 215·181·201곳, 분기공(60km) 308·277·322곳.
- 조건: 땅이고, 열 대용값이 실제 60m(게임 5m) 이상. 열 대용값 = 화산호·섬 호 화산 높이 + 열곡(땅이 갈라져 내려앉은 곳) 깊이 × 2 + 젊은 열점(0~1단계) 화산 높이. 거리장을 쓰지 않아 해상도에 덜 민감하다(F7 2.42% → F9 2.39%).
- 자료 조건: `land && (andeanVolcanicRealM + islandArcRealM + 2 × max(0, −riftRealM) + (hotspotStep <= 1 ? hotspotRealM : 0)) >= 60`
- 지점 종류: 온천 = 강수 250mm 이상(F9 땅 1.73%), 간헐천 지대 = 열 400 실제 m(게임 33m) 이상 + 강수 600mm 이상(0.53%), 분기공·유황 = 강수 250mm 미만(0.66%, 그중 54%가 빙상 위).
- 겹칠 때: 지점 층이라 다른 층과 함께 있다. 화산 칸의 73~84%가 이 띠 안이다(일부러).
- 연결(제안일 뿐): 휴식·치유, 온천 마을(발전도 문화 항목, D-110), 물+불 속성, 유황·규산·붕소, 온실 열원(D-123, 에너지로 칠지는 경제 결정), 간헐천 = 명소.

#### 3. 맹그로브 숲 `mangrove` — Mangrove forest (P1, 생태 층)
- 무엇: 열대의 낮고 잔잔한 해안에서 바닷물에 뿌리를 내린 숲.
- 규모: 1차맵 해안 칸 → 2차맵 안 해안 띠(실제 1~10km = 게임 0.1~0.8km).
- 조건: 해안 땅이고 연평균 21°C 이상, 실제 60m(게임 5m) 이하로 낮고, 습도 100 이상, 바로 옆 바다가 얕은 연안 수심(실제 60m 미만)인 곳.
- 자료 조건: `land && coast && temperatureC >= 21 && realElevationM <= 60 && humidity >= 100 && (8이웃 중 depthClass = 연안인 바다 칸) >= 1`
- 겹칠 때: 생태 층이라 지형 층과 함께 있다. 맹그로브의 4~9%는 삼각주(맹그로브 삼각주), 10~21%는 카르스트(열대 석회암 해안) 위다.
- 연결(제안일 뿐): 은폐(엄폐 1)·느린 이동(D-208), 맹그로브 목재·게·새우(T0~T9), 폭풍 해일 막이, 숲처럼 오염을 줄임(D-115), 물·어둠 속성. (숲의 엄폐는 ADR 35 질문 13 답을 따른다)

#### 4. 산호초·해조 숲 `reef_kelp` — Coral reef & kelp forest (P1, 생태 층)
- 무엇: 따뜻하고 얕은 바다의 산호 정원(환초 포함)과 찬 바다의 해조 숲.
- 규모: 1차맵 바다 칸 → 2차맵 안 초 조각·석호·띠(실제 0.1~1km). 환초 석호는 2차맵 1~3개.
- 조건(산호초): 해수면 기온 23°C 이상(보통 프리셋에서 위도 약 17° 안)이고, 큰 강 하구(유량 50km³/년 이상)에서 실제 150km(게임 12.5km)를 넘게 떨어진 바다(흙탕물을 피함). 그중 (가) 얕은 연안 수심, (나) 땅에 붙은 더 깊은 바다(가장자리 산호초), (다) 가라앉는 옛 열점 화산 위(환초).
- 조건(해조 숲): 해수면 기온 3~17°C의 얕은 연안 수심, 큰 하구에서 실제 100km(게임 8.3km) 밖, 해조 노이즈로 절반쯤만.
- 자료 조건: 산호초 `ocean && seaLevelTempC >= 23 && dist(하구 Q>=50) > 150 && (depthClass = 연안 || (8이웃 땅 >= 1 && depthClass != 연안) || 환초)`, 환초 `continental = 0 && 1 <= hotspotStep <= 5 && hotspotRealM >= 1500 && oceanDepthRealM <= 1500`(실제 1,500m = 게임 125m). 해조 `ocean && depthClass = 연안 && 3 <= seaLevelTempC <= 17 && dist(하구 Q>=50) > 100 && 해조노이즈(주파수 16) > 0`.
- 잰 값 나눔(F9 바다 비율): 산호초 0.95%(얕은 곳 0.80%, 가장자리 0.14%, 환초 0.01% = 행성당 4·0·5곳, 팩·1·42 순), 해조 숲 0.82%(위도 중앙값 37~44°).
- 연결(제안일 뿐): 물·빛 속성, 물고기·진주·산호(사치품), 큰 배에 위험하고 작은 배는 숨기 좋음, 석호 = 안전한 항구, 환초 = 드문 명소. 해조 = 어장·해조 재료.

#### 5. 바다 얼음(해빙) `sea_ice` — Sea ice (P1, 생태 1순위)
- 무엇: 극지 바다를 덮은 두꺼운 얼음, 그리고 빙상 해안에 붙은 얼음·빙붕. 지금은 영하 24°C 바다도 열린 물로 그려진다. 그 구멍을 메운다.
- 규모: 1차맵 극지 바다 칸(큰 덩어리 4~5개).
- 조건: 바다이고 (가) 해수면 기온(위도로 정해짐)에 가장자리 흔들기(노이즈 ±5°C)를 더한 값이 −8°C 이하(대략 위도 70° 넘게), 또는 (나) 빙상 땅에서 실제 100km(게임 8.3km) 안이고 해수면 기온 −2°C 이하.
- 자료 조건: `ocean && (seaLevelTempC + 5 × 해빙노이즈(주파수 8, 3옥타브) <= −8 || (dist(빙상 땅) <= 100 && seaLevelTempC <= −2))`
- 흔들기가 없으면 시드마다 늘 덩어리 2개(완전한 위도 고리)다. 흔들면 넓이는 같고(3.41% → 3.42%) 덩어리가 4~5개로 나뉜다.
- 3%를 넘는 까닭: 극지 바다 전체를 얼려야 기온과 그림이 맞는다.
- 변형 후보(지금 판정에 넣지 않음): 언 호수(호수이고 기온 −11°C 이하 = 호수의 14~28%).
- 연결(제안일 뿐): 얼음 위를 땅으로 볼지 바다로 볼지(습격 영역 규칙 D-202와 이어진다. 제안: 땅 유닛은 걸어서 건너고 배는 막힌다), 얼음 낚시·물개, 얇은 얼음 위험, 빙결 속성.

#### 6. 카르스트 지대 `karst` — Karst (P1, 지형 12순위)
- 무엇: 빗물에 녹은 석회암 땅. 탑 모양 봉우리, 싱크홀, 동굴, 땅속 강.
- 규모: 1차맵 칸 전체(덩어리 중앙값 2차맵 19~40개, 최대 1,564~4,638개) + 2차맵 안 지점(동굴 입구·싱크홀·세노테(물이 찬 석회암 구멍)).
- 조건: 석회암 땅 중 비가 연 700mm 이상, 0°C 이상, 실제 3,000m(게임 250m) 아래. 석회암은 새 "암석 노이즈"로 대륙 지각 땅 면적의 15%에 둔다(행성마다 같은 몫).
- 자료 조건: `land && continental && 암석노이즈(주파수 6, 4옥타브) > 문턱(대륙 땅 면적 위 15%, areaPercentile) && precipitationMm >= 700 && temperatureC >= 0 && realElevationM < 3000`
- 문턱을 고른 이유: 설계안 A의 주파수 3은 시드 차이가 컸다(F7 1.27~5.32%). 주파수 6은 2.39~3.30%이고 덩어리도 더 많다(34~56개).
- 겹칠 때: 지형 층 마지막. 다른 지형과 겹친 6~7%는 그 지형이 이긴다(동굴은 그 아래 지점으로 둘 수 있다).
- 연결(제안일 뿐): 동굴 = 던전 입구, 어둠·땅·크리스탈 속성, 석회암 건축재, 땅속 강·샘 = 물, 탑 바위 = 차폐(엄폐 2). 암석 노이즈는 나중에 광물 배치(D-112)에 다시 쓸 수 있다.

#### 7. 사구 지대 `dune_sea` — Dune sea (erg) (P1, 지형 8순위)
- 무엇: 바람이 쌓은 모래 언덕이 바다처럼 이어지는 사막 한가운데. 나머지 사막은 자갈·바위 사막으로 남는다.
- 규모: 1차맵 칸 전체(큰 덩어리, 최대 2차맵 3,092~8,952개) + 2차맵 안 모래 언덕(제안: 실제 높이 10~300m = 게임 1~25m, 간격 실제 0.5~3km = 게임 40~250m = 지형 칸 약 4~21개). 그보다 잔 물결(게임 약 25m 아래)은 지형이 아니라 지표 그림으로 그린다.
- 조건: 사막 중 가장 마른 곳(강수가 증발 가능량의 12% 이하), 실제 1,500m(게임 125m) 아래, 물이 모이는 마른 분지가 아니고, 평평한(경사 1.2m/km 이하) 땅.
- 자료 조건: `biome = desert && aridityIndex <= 0.12 && realElevationM <= 1500 && basinKind != 마른 분지 && slopeMPerKm <= 1.2` (`aridityIndex` = 강수 ÷ max(80, 45 × (기온 + 6)))
- 3% 근처인 까닭: 사막 면적(F9 땅의 9~19%)에 비례한다. 사막의 19~35%다. 문턱 0.11이면 F7 1.64%로 크게 줄 만큼 민감하다.
- 연결(제안일 뿐): 바퀴 유닛 느림, 모래폭풍, 규사·유리, 바람·땅·폭렬 속성, 묻힌 유적(D-051).

#### 8. 이끼 늪·언 땅 호수 지대 `cold_wetland` — Peat bog & thermokarst lakes (P1, 생태 4순위)
- 무엇: 서늘하고 축축한 평지. 타이가 쪽은 이끼가 쌓인 이탄 습지, 툰드라 쪽은 언 땅이 녹아 생긴 작은 호수가 점점이 박힌 땅.
- 규모: 1차맵 칸 조각(덩어리 중앙값 2차맵 5~12개, 최대 1,522~2,575개) + 2차맵 안 웅덩이·작은 호수·다각형 땅.
- 조건(이탄 습지): 강 칸이 아닌 땅, 연평균 −3~5°C, 습도 170 이상, 실제 400m(게임 33m) 이하, 경사 1.5m/km 이하.
- 조건(동토 호수): 연평균 −11~−3°C, 습도 80 이상, 실제 300m(게임 25m) 이하, 경사 1.2m/km 이하.
- 두 경우 모두 습지 노이즈(주파수 12)가 0보다 큰 곳만 둔다(약 절반). 노이즈 없이는 F9 5.4%로 너무 흔하고 큰 판이 된다.
- 자료 조건: `(이탄 || 동토) && 습지노이즈(주파수 12) > 0`
- 확정 바이옴 습지와 다르다. 지금 습지 규칙은 기온 −3~0°C의 아주 젖은 저지에서만 맞아(땅의 0.1~0.2%) 이 특수 지형과 같은 땅을 노린다. Step 5에서 습지 범위를 정할 때 함께 본다.
- 연결(제안일 뿐): 이탄 연료·물이끼(T0~T9), 느린 이동, 갈대 = 은폐(엄폐 1), 탄소를 붙잡아 오염을 줄임(D-115), 사령·어둠 속성(늪), 언 땅 = 건설 불안정, 매머드 상아·화석, 빙결 속성.

#### 9. 소금 평원·염호 `salt_flat` — Salt flat & saline lake (P2, 지형 7순위)
- 무엇: 물이 증발로만 빠지는 닫힌 분지의 하얀 소금 바닥, 그리고 겨우 넘치는 짠 호수.
- 규모: 1차맵 칸 전체(덩어리 중앙값 2차맵 80~88개). 소금 평원은 행성당 22~30곳, 염호는 6~7곳.
- 조건(소금 평원): 마른 분지(물이 바다로 나가지 않는 웅덩이)의 바닥 쪽 절반(그 칸의 웅덩이 깊이 ≥ 분지 최대 깊이의 50%), 강가 가산을 뺀 습도 110 미만.
- 조건(염호): 호수 중 들어온 물 ÷ 수면 증발이 1.5 미만(겨우 넘침).
- 자료 조건: `land && basinKind = 마른 분지 && depressionDepth >= 0.5 × basinMaxDepth && humidityDry < 110` 또는 `lake && basinInflow ÷ basinEvaporation < 1.5`
- 생성기 구멍(Verified, 설계안 A): 들어온 물이 증발보다 적으면 분지 전체가 마른 분지가 되고 호수가 사라진다. 그런 분지의 물 비율은 0.06~1.0이라 작은 말단 염호가 있어야 맞다. 넣으려면 물 수지 고침과 `GENERATOR_VERSION` 올림이 필요하다(이 제안에 넣지 않음).
- 연결(제안일 뿐): 소금·칼륨·붕사, 리튬 소금물(총량 자원 후보, D-112), 빠른 바퀴 이동·활주로, 엄폐 없음·먼 시야, 신기루, 크리스탈·빛 속성.

#### 10. 오아시스 `oasis` — Oasis (P2, 지점 층)
- 무엇: 사막 한가운데 물이 있는 곳. 강가·호숫가 오아시스와 샘(지하수) 오아시스.
- 규모: 1차맵 칸 띠 → 2차맵 안 지점(야자 숲·샘, 실제 0.1~10km). 실제 50km(게임 4.2km) 간격으로 고르면 행성당 390·447·843곳(F9).
- 조건: 사막 기후(강가 가산을 뺀 습도 55 미만, 0°C 이상, 빙상 아님) 땅 중 물을 얻는 곳: 강 칸, 호수 옆, 메운 작은 웅덩이(얕은 지하수), 마른 골짜기 물길(유량 3km³/년 이상, 강 문턱 12 아래). 소금 평원은 뺀다.
- 자료 조건: `land && humidityDry < 55 && temperatureC >= 0 && biome != ice_sheet && !salt_flat && (riverCell || 8이웃 호수 >= 1 || basinKind = 메운 웅덩이 || dischargeKm3 >= 3)`
- 겹칠 때: 지점 층이다. 14~36%는 사구 지대 안(모래 바다 속 오아시스).
- 연결(제안일 뿐): 물 보급·휴식, 대추야자·약초(D-123), 대상(隊商) 거점·교역, 다툼 지점, 물·빛 속성.

#### 11. 삼각주 `river_delta` — River delta (P2, 지형 5순위)
- 무엇: 큰 강이 바다를 만나 여러 갈래로 갈라지는 낮고 기름진 땅.
- 규모: 큰 하구마다 덩어리 하나(행성당 27~44곳 = 유량 100 이상 하구 수 28~45와 거의 같다). 덩어리 중앙값 2차맵 32~38개, 최대 122~188개.
- 조건: 유량 100km³/년 이상인 강이 바다로 들어가는 하구에서, 강이 클수록 넓은 반경 안의 실제 96m(게임 8m) 이하 땅. 반경 = 60km × √(유량 ÷ 100), 40~150km 실제(게임 3.3~12.5km)로 자른다. 하구마다 크기가 달라 같은 모양이 반복되지 않는다.
- 자료 조건: `land && realElevationM <= 96 && dist(하구) <= clamp(60 × sqrt(Q ÷ 100), 40, 150)` (하구 = 흐름 방향(`receiver`)이 바다인 강 칸, Q = 그 칸 유량)
- 겹칠 때: 갯벌보다 앞선다(갯벌의 10~15%). 생태 층의 맹그로브와 함께 있을 수 있다(삼각주의 9~17%).
- 연결(제안일 뿐): 기름진 흙(땅 비옥도는 D-123 밖의 새 항목), 홍수 사건, 어장, 강·바다 교역 거점, 물·땅 속성, 삼각주 석유·가스(총량 에너지 자원 후보, D-112).

#### 12. 협곡 지대 `canyon` — Canyon lands (P2, 지형 3순위)
- 무엇: 강이 마른 고원을 깊게 깎은 붉은 협곡과 탁자 모양 언덕(메사), 그리고 큰 강이 지나는 산악 협곡.
- 규모: 1차맵 칸 띠. 협곡 자체(실제 폭 0.5~30km, 깊이 0.5~2km = 게임 40~170m)는 2차맵 여러 개에 걸친다. 1차맵 강 흐름 방향(`receiver`, 4.3 4단계에서 `PlanetFields`에 더함)을 따라 이웃 2차맵과 이어 판다. 생성기 침식이 약해(강 칸 침식 p95 실제 약 15m, 설계안 A) 1차맵에는 깎인 협곡이 없다.
- 조건(메사·협곡): 강가 가산을 뺀 습도 30~120의 반건조 땅, 0°C 이상, 실제 500m(게임 42m) 이상, 강까지 실제 80km(게임 6.7km) 안.
- 조건(산악 협곡): 유량 20km³/년 이상 강 칸, 실제 1,000m(게임 83m) 이상, 반경 50km(게임 4.2km) 안 가장 높은 땅보다 실제 400m(게임 33m) 이상 낮다. F9 땅의 0.07%(F7 0.50%)라 해상도에 민감하다.
- 자료 조건: `land && 30 <= humidityDry < 120 && temperatureC >= 0 && realElevationM >= 500 && dist(강 칸) <= 80` 또는 `riverCell && dischargeKm3 >= 20 && realElevationM >= 1000 && (50km 안 최고 바닥 고도 − 이 칸) >= 400`
- 연결(제안일 뿐): 좁은 길·관문(대형 유닛 통과 폭, D-135), 절벽 = 차폐·매복·높은 곳, 드러난 지층·화석·사금(총량), 댐·수력, 땅·바람 속성. (고지대 효과는 ADR 35 질문 14 답을 따른다)

#### 13. 피오르 해안 `fjord` — Fjord coast (P2, 지형 4순위)
- 무엇: 옛 빙하가 깎은 길고 깊은 바닷물 골짜기가 있는 춥고 높은 해안.
- 규모: 1차맵 해안 칸. 좁은 만(실제 폭 1~5km·길이 10~200km = 게임 폭 0.1~0.4km·길이 1~17km = 2차맵 최대 약 11개)은 바다 쪽 이웃과 이어지는 피오르 이웃을 따라 2차맵 여러 개에 이어 판다.
- 조건: 위도 40° 이상, 연평균 5°C 이하, 강수 300mm 이상인 해안 땅 중 반경 50km(게임 4.2km) 안에 실제 1,000m(게임 83m) 이상 땅이 있는 곳. 생성기에 빙하기 기록이 없어 지금의 추위·산·눈으로 대신한다.
- 자료 조건: `land && coast && absLatDeg >= 40 && temperatureC <= 5 && precipitationMm >= 300 && (50km 안 최고 realElevationM) >= 1000`
- 0.2%보다 작은 까닭: 해안 칸 하나 폭이다. 해안 칸으로 보면 2.0%(F9 팩 시드)다.
- 겹칠 때: 화산·빙하보다 뒤다(피오르의 18~31%를 내준다: 화산 피오르 해안, 빙하가 바다에 닿는 해안 변형).
- 연결(제안일 뿐): 깊고 잔잔한 천연 항구·해군 기지, 절벽 길, 폭포, 빙결·물·바람 속성.

#### 14. 빙하 지대 `glacier` — Glacier terrain (P2, 지형 2순위)
- 무엇: 높은 산의 골짜기 빙하와 빙상 가장자리의 크레바스(얼음 틈) 지대.
- 규모: 1차맵 칸 조각. 빙하 혀·얼음 틈(실제 1~50km = 게임 0.1~4.2km)은 2차맵 여러 개에 걸칠 수 있어 내리막(흐름 방향)을 따라 이어 그린다.
- 조건(산악 빙하): 고산 바이옴이고 눈이 많은 곳: 기온 −6°C 미만 + 강수 300mm 이상, 또는 −3°C 미만 + 800mm 이상, 또는 0°C 미만 + 2,000mm 이상.
- 조건(빙하 균열): 빙상 중 빙상 아닌 곳(땅·바다·호수)에서 실제 100km(게임 8.3km) 안, 또는 반경 100km 안 기복 실제 600m(게임 50m) 이상인 험한 곳. 그리고 균열 노이즈(주파수 12)가 0.2보다 큰 곳(약 14%).
- 자료 조건: `biome = alpine && (T < −6 && P >= 300 || T < −3 && P >= 800 || T < 0 && P >= 2000)` 또는 `빙상 땅 && (dist(빙상 아님) <= 100 || 100km 기복 >= 600) && 균열노이즈 > 0.2`
- 나눔(F9 땅 비율): 산악 빙하 0.86%, 빙하 균열 1.34%. 균열 문턱 0.1이면 2.88%라 0.2로 줄였다.
- 연결(제안일 뿐): 크레바스·눈사태 위험, 느린 이동, 얼음 탑 = 차폐, 얼음 동굴 던전, 녹은 물, 빙결 속성, 얼음 속 유물.

#### 15. 갯벌 `tidal_flat` — Tidal flat (P2, 지형 6순위)
- 무엇: 넓은 얕은 바다와 강이 실어 온 흙이 만든 진흙 갯벌. 한국 서해안처럼 익숙한 풍경.
- 규모: 1차맵 해안 칸 → 2차맵 안 갯벌 띠(실제 약 10km 폭까지, 게임 1km 아래).
- 조건: 온대(2~21°C) 해안 땅, 실제 36m(게임 3m) 이하, 큰 강 하구(유량 50 이상)에서 실제 400km(게임 33km) 안, 깊은 바다(실제 200m 이상)에서 실제 100km(게임 8.3km) 넘게 떨어진 곳. 밀물·썰물은 계산하지 않아서 넓은 얕은 바다와 흙 공급으로 대신한다. 맹그로브는 21°C 이상 쪽 짝이다.
- 자료 조건: `land && coast && realElevationM <= 36 && 2 <= temperatureC < 21 && dist(하구 Q>=50) <= 400 && dist(심해) >= 100`
- 연결(제안일 뿐): 조개·낙지·물고기, 염전(소금), 철새, 진흙 = 느린 이동, 물·땅 속성.

#### 16. 바위 언덕 평원 `inselberg_plain` — Inselberg plain (P3, 지형 10순위)
- 무엇: 평평한 초원·사막 위로 거대한 바위 언덕이 섬처럼 솟은 땅(오래된 대륙 지괴).
- 규모: 1차맵 칸 조각(덩어리 93~146개) + 2차맵 안 바위 언덕.
- 조건: 오래되고 안정된 대륙 안쪽(대륙 지각 안쪽 정도 0.6 이상, 판 경계에서 실제 500km = 게임 42km 넘게)의 사바나·초지·사막 평지(반경 100km 기복 실제 500m 미만) 중 바위 언덕 노이즈(주파수 16)가 0.25보다 큰 곳(약 8%).
- 자료 조건: `land && continental && crustRank >= 0.6 && distToPlateBoundaryKm >= 500 && biome ∈ {savanna, grassland, desert} && 100km 기복 < 500 && 바위노이즈 > 0.25`
- 문턱: 설계안 B의 0.15는 F9 3.58%라 0.25로 줄였다.
- 연결(제안일 뿐): 높은 곳 = 시야(시야는 능력치, D-208), 바위 = 차폐, 화강암 건축재, 킴벌라이트·다이아몬드(총량 자원, D-112, 드문 지점), 땅 속성, 포식자 굴. (고지대 효과는 ADR 35 질문 14 답을 따른다)

#### 17. 황토 고원 `loess_plateau` — Loess plateau (P3, 지형 11순위)
- 무엇: 사막에서 날아온 고운 흙이 두껍게 쌓인 고원. 기름지지만 빗물에 깎인 골짜기가 많다.
- 규모: 1차맵 칸 조각(덩어리 28~74개). 골짜기·계단밭은 2차맵에서 그린다.
- 조건: 초지 중 습도 120 미만, 실제 400~2,500m(게임 33~208m), 마른 분지가 아니고, 바람이 오는 쪽(생성기 바람길)으로 실제 1,000km(게임 83km) 안에 사막이나 마른 분지가 있는 곳. "사막 바람 아래에 황토"라는, 플레이어가 배울 수 있는 규칙이다.
- 자료 조건: `biome = grassland && basinKind != 마른 분지 && humidity < 120 && 400 <= realElevationM < 2500 && 바람위1000km(사막 || 마른 분지)`
- 주의: 지금 바람길은 곧은 격자선이다(4.1 원인 1). 기후 고침 뒤 다시 잰다.
- 연결(제안일 뿐): 땅 비옥도·침식 위험(D-123 밖의 새 항목), 골짜기 미로 = 엄폐, 동굴 집, 먼지 폭풍, 땅·바람 속성.

#### 18. 크리스탈 맥 `crystal_veins` — Crystal veins (P3, 지형 9순위, 판타지)
- 무엇: 땅을 가르며 길게 이어지는 거대한 수정 결정 띠. 기후 띠와 상관없이 직선으로 가로지른다.
- 규모: 1차맵 칸 줄(덩어리 94~184개, 중앙값 2차맵 12~27개).
- 조건: 두 판이 옆으로 엇갈려 미끄러지는 경계(변환 단층형: 경계를 따라 미끄러지는 속도가 부딪치는 속도보다 큰 곳)에서 실제 60km(게임 5km) 안의 땅 중 맥 노이즈(주파수 24)가 0보다 큰 곳(약 절반).
- 자료 조건: `land && dist(plateBoundary && |전단| > |수렴|) <= 60 && 맥노이즈 > 0` — 생성기는 경계의 전단(옆 미끄러짐) 성분을 아직 계산하지 않는다(새 계산, 판 속도에서 바로 구함). 변환형이 경계 칸의 40~56%다(값 목록).
- 문턱: 설계안 B의 40km는 F9에서 많이 줄어(1.53% → 0.79%) 60km로 넓혔다.
- 연결(제안일 뿐): 크리스탈 속성 서식지, 희귀 광물 후보(D-124), 수정 기둥 = 원거리 공격을 막는 차폐(D-208). 세계관(정원의 흐름이 드러난 자리)은 기획 판단.

### 1.3 겹칠 때 (우선순위)
- 지형 층: 화산 > 빙하 > 협곡 > 피오르 > 삼각주 > 갯벌 > 소금 평원 > 사구 > 크리스탈 맥 > 바위 언덕 > 황토 > 카르스트. 앞이 이긴다(바이옴 표와 같다). 드물고 뚜렷한 것을 앞에 두었다.
- 생태 층: 해빙 > 산호초·해조 > 맹그로브 > 이탄·동토. 서로 거의 겹치지 않는다(해수면 기온·기온으로 갈린다).
- 지점 층(온천·오아시스)은 어느 층과도 함께 있다.
- 지형 층에서 순위 때문에 내준 몫(F9, 그 후보 칸 중): 피오르 18~31%, 바위 언덕 10~26%(대부분 사구), 황토 8~20%, 빙하 6~15%(화산), 갯벌 10~15%(삼각주), 크리스탈 5~10%, 카르스트 6~7%. 나머지는 3% 이하.
- 서로 다른 층의 겹침은 실제 풍경 조합이다: 맹그로브 삼각주, 열대 석회암 해안(맹그로브 + 카르스트), 모래 바다 속 오아시스.

### 1.5 Step 5 바이옴 범위가 정해지면 다시 맞출 문턱
- 바이옴 이름을 직접 쓰는 것: 사구(사막), 빙하(고산·빙상), 황토(초지), 바위 언덕(사바나·초지·사막), 오아시스(빙상 제외).
- 바이옴 경계와 비슷한 기온·습도 문턱: 맹그로브(21°C, 습도 100), 이탄·동토(−3~5°C·습도 170, −11~−3°C·습도 80), 갯벌(2~21°C), 협곡(습도 30~120), 오아시스(습도 55 = 지금 사막 경계), 황토(습도 120), 카르스트(강수 700mm, 0°C), 피오르(5°C), 빙하(기온·강수 묶음).
- 바이옴 범위와 무관한 것: 화산, 온천, 삼각주, 소금 평원(습도 110만), 크리스탈 맥, 해빙·산호초·해조(해수면 기온 = 기온 프리셋에 묶임).
- 4장의 기후 고침(1·2단계)도 기온·강수를 바꾼다. 그래서 문턱은 기후 고침 뒤에 함께 다시 잰다. 조건은 콘텐츠 데이터라 코드를 고치지 않고 맞출 수 있다(2장).

### 2.1 별도 층 vs 바이옴 항목 추가
| | 칸마다 특수 지형 층 (권고) | 바이옴 항목으로 추가 |
|---|---|---|
| 확정된 바이옴 14개 | 그대로 | 특수 지형이 바이옴을 밀어낸다(카르스트 칸은 사바나가 아니게 됨) |
| 한 칸에 둘 이상 | 지형 1 + 생태 1 + 지점 | 하나뿐(맹그로브 삼각주, 빙하 덮인 화산을 못 그림) |
| 조건 입력 | 생성기 중간값·거리·노이즈 | 기온·습도·고도 범위뿐. 바이옴 규칙 스키마를 크게 늘려야 한다 |
| 작물·서식지·면적표 | 바이옴 규칙(D-123 온습도)과 편집기 바이옴 면적표(D-154)가 그대로 | 바이옴 하나에 섞여 흔들린다 |
| 거친 단계 표시 | 따로 모으기 규칙(아래)으로 남는다 | 최빈값 모으기에 묻혀 사라진다 |
| 일 | 새 분류·필드·타일 형식 2판 | 적다 |
- 권고: 별도 층. 기존 8필드 값은 바뀌지 않는다(특수 지형은 바이옴 뒤에 판정하고 다른 값을 고치지 않는다, Assumed: 설계상). 결정은 새 ADR(특수 지형 층)로 적는다.

### 2.2 자료 모양
- `PlanetFields`에 `Uint8` 4개를 더한다: `feature`(지형 층. 0 = 없음, 그 밖의 값은 행성 `features` 목록 위치 + 1), `featureEco`(생태 층, 같은 번호), `featureVariant`(아래 4비트 지형 변형, 위 4비트 생태 변형), `featureZone`(지점 띠 비트: 1 지열, 2 오아시스, 나머지 예비). F9에서 6MiB 늘어난다. 결과 해시에 넣는다. 윗 단계의 `featureZone`은 비트마다 아래 2×2 중 2칸 이상이면 켠다.
- 지점 목록(2차맵 안 분출구·온천·간헐천·분기공·오아시스·동굴·환초): 행성마다 따로 둔다. 항목 = F9 셀 키 + 종류 + 변형 + 값 하나(크기 등). F9 행성당 약 2,400~3,400개(동굴 제외: 분출구 425~660, 온천 1,093~1,376, 간헐천 181~215, 분기공 277~322, 오아시스 390~843, Verified: 간격 조건으로 고른 수). 2차맵 상세라 탐사·시야 확인 뒤 보낸다(ADR 26). 1차맵 타일에는 띠(특수 지형 번호)만 넣는다.
- 콘텐츠 분류 `terrainFeatures`(팩 `core`, `placeholder: true`): `id`, `name`(ko·en), `description`(ko·en), `color`, `layer`(지형·생태·지점), `variants`(ID·이름 ko·en), `rule`(아래). 행성 정의에 `features: [ID…]`를 더한다. 번호 = 목록 위치 + 1(0 = 없음), 같은 층 안 우선순위 = 목록 순서(바이옴과 같은 방식). 규칙이 바뀌면 정의 해시가 바뀌어 다시 굽는다.
- 규칙은 데이터다(PLAN 6.1 배치 규칙과 같은 생각): `{ "any": [ { "all": [ { "input": "temperatureC", "min": 21 }, { "input": "coast", "is": true } … ] } ] }`. 범위는 바이옴 규칙처럼 [min, max)다. 정수 입력(기온·습도·저장 고도 × 12)에 쓴 "이하"는 max = 문턱 + 한 눈금으로 옮긴다(기온 5°C 이하 → 6 미만, 실제 고도 60m 이하 → 72 미만). 실수 입력(건조 지수·경사·거리·노이즈)은 "이하"를 쓸 수 있게 `maxInclusive`를 둔다. `input`은 생성기가 계산해 주는 이름 목록 안에서만 고른다(아래 2.3). 노이즈 입력은 스트림 번호를 코드에 고정하고 주파수·문턱만 데이터로 둔다.
- 타일 형식 `TCPT` 2판: 칸 값 6가지 뒤에 4가지를 같은 방식(필드마다 size²바이트)으로 붙인다. 형식 버전이 바뀌어 타일 주소도 바뀐다. 옛 앱은 2판을 읽지 못해 "행성 자료를 읽지 못했습니다. 앱을 새로 고친 뒤 다시 열어 주세요."(`planet_invalid`)를 띄운다. 그래서 서버와 앱을 한 배포로 내고, 켤 때 자동 업데이트(ADR 28)로 넘어가게 한다. 한 배포 동안 1판도 함께 낼지는 구현 때 정한다.
  - 윗 단계 모으기(제안): 아래 2×2 중 0이 아닌 같은 특수 지형이 2칸 이상이면 그것, 아니면 0이다. 동점(2칸·2칸)이면 번호가 작은 것(우선순위가 앞)이다. 변형은 고른 특수 지형을 가진 칸들의 변형 중 가장 많은 것이다. F9 팩 시드에서 맵 레벨 9 → 5의 지형 층 칸 몫(전체 칸 기준)은 4.06% → 4.40% → 4.90% → 5.31% → 5.26%, 생태 층은 5.04% → 6.97%였다(Verified). 바이옴처럼 0을 포함한 최빈값으로 모으면 4.06% → 0.93%로 줄고, 하나라도 있으면 켜는 규칙은 18.9%로 부푼다(Verified).
- 목록 정보(`GET /api/planets/<ID>`)에는 `features` 범례(번호·ID·층·색·이름 ko·en·변형)와 결과 해시(`fieldsHash`)만 더한다. 규칙 표는 관리자 전용 조회(행성 정의와 같은 곳)로 낸다. 플레이어용 짧은 창(Q7)을 두면 그때 범례에 설명만 더한다.
- 생성 순서: 바이옴·숲 다음에 특수 지형 단계를 둔다(새 단계 이름 `features`). 지점은 그다음 시드 해시로 고른다. 2차맵은 나중에 특수 지형 번호·변형·지점을 받아 모양을 찍는다(4장 5단계).

### 2.5 결정성
- 조건은 비교와 사칙연산, `Math.sqrt`(삼각주 반경)·`min`·`max`·`round`, 생성기의 `fbm3`·`distanceField`·`areaPercentile`·`streamSeed`·`mix32`·`createRng`만 쓴다. 초월함수가 필요한 곳(크레이터 반지름 등 예비 후보)은 `detExp` 등 `@terra/shared` 함수를 쓴다.
- 지점 고르기: 후보 칸을 정수 해시(셀 키 + 스트림) 순서로 보고, 이미 고른 점과의 현 길이 제곱을 비교한다(삼각함수 없음, 같은 해시는 셀 키 순서). 측정 스크립트는 간격 계산에 `Math.sin`을, 예비 후보 크레이터 측정은 `Math.exp`·`Math.cos`를 썼다. 스크래치 측정일 뿐이고 구현은 `@terra/shared` det 함수나 현 길이로 정한다.
- 새 스트림 번호는 `random.ts` 끝에 붙인다(지금 마지막 8). 기후 고침의 새 스트림과 함께 번호를 정한다.
- 반복 순서는 지금처럼 면 → 행 → 열로 고정한다.
- 출력이 바뀌므로 `GENERATOR_VERSION`을 올리고 골든 해시 3개를 고친다. 시험을 더한다: 특수 지형 골든 개수(F5·F6), "저장 값과 다시 구한 입력으로 다시 판정해도 같다"(바이옴 재판정 시험과 같은 방식), 조항별 판정 = 칸 판정 표.

## 3. 정보창 설계 (D-214 요청: 지형이 되는 조건을 보여 주는 창)

### 3.1 어디에
- 행성 생성기(편집기 1단계, 관리자 화면): 미리보기 지구본에서 칸을 누르면 연다.
- 개발자 정보 메뉴(지금 1차맵 시험 화면, 나중에 관리자 메뉴): 실제 굽기 행성에서 칸을 누르면 연다. 두 곳이 같은 창 부품과 같은 규칙 표를 쓴다.

### 3.2 보여 줄 것
1. 칸 머리: 셀 키, 면·i·j, 맵 레벨, 위도·경도.
2. 칸 값: 게임 단위와 실제 환산을 함께. 고도(게임 m / 실제 m), 연평균 기온, 연강수, 습도(그중 강가 가산), 숲 밀도, 하천 등급, 물 비트 풀이(바다 수심 등급·호수·강·해안). 판정에 쓴 중간값(화산 높이 기여, 유량, 웅덩이 종류, 거리, 노이즈 값)도 실제 단위로.
3. 바이옴 판정: 행성 바이옴 목록 순서대로 규칙마다 조항 통과·실패, "처음 맞은 규칙", 저장 바이옴과 다시 판정한 바이옴이 같은지. 경계까지 남은 양(예: "습도 159, 160부터 열대우림 — 1 차이").
4. 특수 지형: 지형 층에서 이긴 것, 생태 층에서 이긴 것, 지점 띠. 맞은 규칙 전부와 순위 때문에 진 것("카르스트도 맞지만 화산이 앞선다"). 맞은 규칙은 조항마다 값·문턱·통과를 펼친다.
5. 근접 실패: 갈래 하나에서 조항이 하나만 실패하고, 모자란 양이 한 눈금 이하인 규칙(눈금: 기온 2°C, 습도 10, 고도 실제 100m, 강수 15%, 거리 실제 20km, 노이즈 0.05 등). 많아도 3~4개만.
6. 거친 단계 주의: 맵 레벨이 F보다 낮으면 "이 칸은 가장 고운 칸 4^(F−L)개를 모은 값"이라고 쓰고 다시 판정하지 않는다. 아래 칸의 바이옴·특수 지형 분포(받은 타일이 있으면)와 [확대] 버튼을 보여 준다. 모은 값(평균 기온·최빈 바이옴)으로 규칙을 돌리면 실제 칸과 다른 답이 나오기 때문이다.
7. 규칙 출처: 콘텐츠 팩 버전, 생성기 버전, 정의 해시, 규칙 ID. 기획이 "이 문턱은 팩 `terrainFeatures`의 몇 번째 항목"을 바로 찾게 한다.

- 다시 생성 방식: 기기는 행성 정의(콘텐츠 팩 항목, 관리자 전용 조회)와 같은 `@terra/planet` 생성기를 쓴다. 생성기는 결정적이라 기기에서도 같은 값이 나와야 한다. 목록 정보의 `fieldsHash`와 기기 결과 해시를 대조해서 같을 때만 "정확"이라고 표시한다. 다른 엔진에서 같은 해시가 나오는지는 아직 확인하지 않았다(Unknown, ADR 36). 데스크톱에서 약 15초·약 400MB로 본다(Assumed: Node F9 12.4초·297MiB + 특수 지형 단계). 휴대폰은 바로 보기만 쓴다.
- 서버에 중간값을 저장하는 방식(칸마다 판정 비트 + 표시용 값, F9 약 25~40MB, Assumed)도 있다. 그러나 NAS 메모리·디스크를 쓰고 공개 타일과 섞일 위험이 있어 권하지 않는다. 휴대폰 개발자 보기가 꼭 필요해지면 그때 관리자 전용 API로 더한다.
- 화면 문구: 특수 지형·바이옴 이름은 목록 정보 범례(ko·en)에서 온다. 조항 이름("연평균 기온", "큰 하구까지")은 입력 이름마다 메시지 키 하나(ko·en)로 둔다.
- 편집기의 바이옴 면적표(D-154) 옆에 특수 지형 면적표를 둔다. 미리보기(F6~7)는 해안·강 지형을 2~5배 크게 세므로 "굽기(F9) 추정"을 함께 적는다.
