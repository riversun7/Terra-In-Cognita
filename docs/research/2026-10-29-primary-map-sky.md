# 1차맵 하늘 조사: 구름·항성 기준 낮밤·달 (2026-10-29)

사용자 요청(2026-10-29, 원문): "3. 구름 같은 요소도 추가되면 좋을듯 4. 항성의 위치를 기반으로 낮과 밤의 표현. 5. 달도 있으면 좋겠다"

## 요약
- 낮밤: 서버 UTC → 공용 정수 달력(D-091·D-5030: 하루 실제 1시간, 계절 7시간, 한 해 28시간) → 항성 방향을 기기가 계산한다. 보내는 것이 없다. 낮밤은 매끈한 구 법선으로, 기복은 지금 카메라 빛의 경사만 쓴다. 밤은 라벤더, 흰 땅 휘도 약 32%(3판). 수식 확인 15개 통과(V).
- 달: 같은 달력에서 위상(정수 ms 나머지)과 방향을 계산하는 배경 구 하나. 깊이를 끄고 먼저 그려 지도를 가릴 수 없다. 거리 12R·반지름 0.27R이면 사용자 휴대폰 지구본에서 약 35~37 CSS px, 세로 화면에 있는 시간 약 3%(V: 모의).
- 구름: GPU에서 가끔 굽는 큐브 텍스처(R8 512²) + 껍질 구 하나. 덮임은 기후(바다 위도 띠, 땅 습도)를 따른다. 가까이 가면 걷히고 F9 약 637km 안쪽에는 없다. 화소당 큐브 읽기 2번이라 화소마다 노이즈를 계산하는 방식보다 훨씬 싸다(V: 헤드리스 상대 비용, A: 휴대폰).
- 비용: 그리기 호출 +2(달 1·껍질 1), GPU 약 2.7MiB, 1차맵 조각 약 +20~25KB(A). 휴대폰은 재지 않았다(U).
- 사용자 결정(2026-10-29, ADR "사용자 결정"): U1 가까이서 밤 = (나) "가까이선 옅은 밤"(가장 가까이 0.6, 0.5R부터 1), U2 구름 그림자 = "넣지 않는다", U3 달 보기 = "그대로 둔다".

## 2. 저장소에서 확인한 것 (V)
- 좌표: 행성 중심 원점(m), 북극 +z(위도 = asin z), 경도 0 = +x, 동쪽 = +y(`globeCamera.ts`). 생성기 기후도 돌리지 않은 이 좌표(z = 자전축)로 계산한다(ADR 36). 장면 좌표 = 행성 좌표이고, 물체 위치는 카메라 기준으로 64비트에서 뺀다(`planetView.ts`, `cameraRelative.ts`).
- 빛: 보기 공간에 붙은 빛 하나 `(-0.45, 0.62, 0.64)`. 조각: `base × (0.5 + 0.62 × max(dot(n, L), 0))`, 물 반짝임 `0.1 × pow(dot(n, h), 48)`. n은 과장한 지형 법선이라 같은 항이 기복 음영과 가짜 공 모양 어둡기를 만든다(`planetMaterials.ts`). 타일은 uniform 객체 하나를 나눠 쓴다(`uExaggeration`·`uSkirtDepth`·`uLayer`·`uLightDir`·`uPalette`·`uPick`).
- 그리기: 불투명 타일(renderOrder 0..N, 가까운 것 먼저) → 바탕 구(해수면 −1,500m, renderOrder 1e6) → 대기 띠(× 1.018, BackSide, 투명, 0.25R 밖). three는 불투명을 renderOrder 다음 재질·깊이로 정렬한다(`painterSortStable`).
- 그리기 예약: 화면 변화가 없으면 그리지 않는다(`FrameScheduler`). 그리는 함수의 예외를 잡지 않는다(검토 H1).
- 카메라(F9, 412×892): 가장 가까이 12.0km(기울기 40°), 기울기 시작 720km, 가장 멀리 3,150km(행성 중심 6.94R), 가로 892×412는 행성 중심 3.36R. 코드 주석 "하늘이 보이지 않는 범위다"는 가까운 거리의 말이다.

## 3. 시간과 항성
- 정수 달력: 기원에서 잰 ms에 나머지 = `((x % D) + D) % D`, 몫 = `(x − 나머지) / D`. 2300년에도 정확하다(안전 정수 안). 계절 번호 0~3 = 북반구 봄·여름·가을·겨울, 남반구 = (계절 + 2) mod 4.
- 항성(원 궤도, 균시차 없음): L = 2π(yearFrac − φ0), δ = asin(sin ε · sin L), λs = wrap(π − 2π·dayFrac), s = (cos δ cos λs, cos δ sin λs, sin δ). 그곳 고도의 sin = 위쪽 · s.
- 확인 15개(V: 계산 스크립트 "ALL OK", Node 24.22.1): 기원에 λs = 180°, +30분 0°, +15분 +90°. 아무 시각에서 아래 경도의 지역 시각 = 12시. 해 비율 1/8·3/8·5/8·7/8에서 δ = 0·+ε·0·−ε, φ0 = 1/8이면 계절 가운데 날이 그 값. 고도 식 = 내적(2,000개, 최대 오차 5.3e-16). 하지 정오 40°N 73.44° 대 40°S 26.56°. 기원 앞도 이어짐. 2300년 정수 정확. 근사 δ ≈ ε sin L과의 차 ≤ 0.256°.
- 빠르기(V: 계산, R = 531km): 아래 경도 0.1°/s, 적도 경계 927m/s, 1° = 9.27km, ±6° 띠(111km)가 한 곳을 약 2분에 지나간다. 지구본(390px 세로, 원판 약 339px)에서 경계 약 0.3 CSS px/s(A: 기하).
- 계절(V: 계산): 극야·백야는 66.56° 위. 한겨울 계속되는 밤은 70°에서 실제 약 4.8시간, 80°에서 약 10시간, 극에서 14시간. 하지 40°의 낮 길이는 행성 14.8시간 = 실제 37분.
- 행성 항성일 = 태양일 × 28/29 = 실제 57.93분(V: 계산).
- 기원을 정시 UTC로 두면 경도 0의 자정이 매 정시 UTC(= 매 정시 KST)다(A). 기원은 세계 상수가 되어 출시 뒤 바꿀 수 없다(나이 D-021·계절 D-118이 밀린다).
- 같은 하늘: 하늘은 (서버 UTC, 공용 달력 상수, 행성 값)의 순수 함수라 보낼 것이 없다(A). 시계 차이 오차는 비대칭 왕복의 반, 수십 ms라 항성 0.01° 아래다(A). 첫 측정 전에는 기기 시계 오차 Δ만큼 0.1°/s × Δ 틀렸다가 한 번 튄다(A, 검토 M4가 "낮으로 시작" 규칙을 냈다).
- 편집기 미리보기는 하늘 off(지형을 보는 도구), 시험·사진은 `?planet-time=`으로 시각을 멈춘다(A: 설계).

  - 상대 비용(큐브 1번 읽기 = 1): 타일 그림자 0.67, 흐름 맵 1.9, 큐브 + 3D 디테일 1옥타브 1.8, 3D 텍스처 fbm 6옥타브 1.5, 실수 해시 fbm 4옥타브 3.0, 6옥타브 3.1, 심플렉스 5옥타브 3.6, pcg3d 정수 해시 6옥타브 7.2, 휘기 7.7. SwiftShader는 텍스처 필터를 CPU로 흉내 내 텍스처가 비싸게 나온다. 실제 GPU에서는 텍스처 방식 이득이 더 크다고 본다(A).

  - three 0.186.1에서 R8 큐브 렌더 타깃 면별 그리기·마지막 면 뒤 밉맵, `texture(samplerCube, dir, bias)`, `sampler3D`, 데이터 큐브 텍스처 올리기가 콘솔 오류 없이 돌았다. 면 방향(OpenGL ES 3.0 표 3.21을 거꾸로 푼 식)은 선형 함수를 구워 읽은 최대 오차 0.022로 확인했다(면이 뒤집히면 0.1 넘음).
- 노이즈 모양(V: 경위도 그림 3장 비교): 실수 해시 6옥타브, 실수 해시 휘기, 3D 텍스처 휘기 모두 위도 띠를 따르는 뭉게구름이고 3D 텍스처판에 격자 자국은 보이지 않았다.
- 기후 치우침: 바다는 위도 띠(적도 수렴대·중위도 폭풍대 흐림, 아열대 맑음, 생성기 `zonalPrecipitation`과 같은 모양), 땅은 습도. 첫 단계 칸(F9 약 24km)은 각지므로 선형 필터 + 노이즈로 찾는 자리를 흔든다(A). 합친 시제품에서 큰 사막은 맑고 바다 띠는 흐렸다(V: 사진). 가짜 행성은 사막이 아열대 맑음 띠와 겹쳐 땅 습도의 몫을 따로 보기 어려웠다(U). 계절에 적도 수렴대를 ±6~8° 옮기면 남반구 반대 계절이 저절로 나온다(A). 습도는 공개 지형 자료라 숨김 정보가 새지 않는다(V: ADR 26·36).
- 시간: 서버 ms를 32비트 uniform으로 넘기면 1.79e12에서 간격이 131,072ms라 쓸 수 없다(V: 계산). 창 번호를 JS(64비트)에서 셈해 시드로 넘긴다. 무관한 두 노이즈 A·B를 w : 1 − w로 섞으면 분산이 w² + (1 − w)²배라 w = 0.5에서 표준편차가 약 29% 준다(A: 계산). 분산을 지키려면 (wA(A − m) + wB(B − m)) ÷ √(wA² + wB²) + m.
- 껍질: `SphereGeometry(1, 128, 64)`(약 0.37MB), R + 600 게임 m × 고도 과장, 대기 띠 아래로 묶음. S2 시험 행성 가장 높은 땅 830m는 × 6에서 약 5km, × 20에서 약 16.6km(대기 띠 9.6km보다 높다). 512² 텍셀은 면 가운데 약 2.1km·평균 약 1.5km라 640km 근처에서 텍셀 하나가 약 4~6화소로 퍼진다(A).
- 가까이 갈 때: 900km에서 투명해지며 사라지게 하면 지도 전체가 뿌옇고, 문턱을 올려 걷히게 하면 남은 구름이 또렷하고 지도가 더 보였다(V: 사진). 1.2R~2.5R 사이를 쓰면 F9 약 637km 안쪽(맵 레벨 9가 화면을 덮는 일하는 거리)에는 구름이 없다.
- 구름 그림자(설계만, 사용자 결정 U2로 넣지 않음): 타일 조각 셰이더가 같은 큐브를 normalize(땅 방향 + 해 방향 × (구름 높이 − 땅 높이) ÷ (R × max(n·s, 0.15)))로 한 번 더 읽고, 밉맵 한두 단계 위로 부드럽게, 25~35% 어둡게, 밤 쪽 0. 그리기 호출 0, 상대 비용 0.67(V: 헤드리스). 위에서 내려다보면 그림자 대부분이 구름 바로 밑이라 가린다(A). 켜면 구름 아래 땅이 조금 어두워 입체감이 생겼다(V: 사진).
- 메모리(A: 계산): 큐브 512² R8 + 밉맵 2.0MiB(GPU만, JS 사본 없음), 이중 버퍼면 4MiB, 1024²면 8MiB. 기후 큐브 약 12KB, 3D 노이즈 256KiB. JS로 만든 큐브는 three가 컨텍스트 복구용 배열을 들고 있어 JS 1.5MiB가 더 든다(V: 타일에서 같은 동작).
- 묶음(V: 검토가 시제품 모듈을 esbuild 0.28.2로 압축해 잼): 구름 8,078B, 달 2,970B, 재질 차이 +3,935B(그림자 읽기 포함) = 약 15.0KB(gzip 약 6.4KB). GLSL 문자열 안 한국어 주석은 압축 뒤에도 남는다(구름 모듈만 약 200자).
- 쓰지 않을 것: 부피 광선 행진(콘솔 약 2ms, V\*: Nubis. 우주에서 보는 지도에 이득이 작고 휴대폰에 무겁다, A), 낱개 구름 판(유닛 표지와 헷갈리고 날씨 띠를 못 만든다, A), 지구 구름 사진(지구 전용, 미리 캐시 수백 KB, A).

## 7. 사진이 보여 주는 것 (글 묘사, V: 헤드리스 사진)
사진은 저장소 밖 임시 폴더에 있다(저장소에 넣지 않는다). 헤드리스 소프트웨어 그리기라 휴대폰 색과 다를 수 있다.
- 낮밤(2판)
  - 지금 1차맵: 지구본 전체가 밝고 오른쪽 아래만 조금 어둡다(카메라에 붙은 빛).
  - 낮밤 경계: 지구본 한쪽(약 1/3)이 어두운 라벤더이고 경계는 넓고 부드러운 띠다. 낮 쪽은 지금과 거의 같다.
  - 밤 쪽 전체: 어두운 라벤더 빛이지만 사막·숲·얼음·바다 색을 알아볼 수 있다. 가장자리 하늘색 대기 띠가 윤곽을 남긴다.
  - 항성이 행성 뒤: 지구본 전체가 밤이고 가장자리 대기 띠만 밝다.
  - 북반구 여름: 경계가 기울고 북극 쪽이 하루 종일 낮이다.
  - 기후 자료 화면: 밤 효과 35%면 밤 쪽에서도 자료 색이 읽히고, 100%면 범례 색이 탁하다.
  - 300km: 해 질 녘에 좁고 따뜻한 띠가 지나간다. 1판은 탁한 갈색이었다.
  - 18km(가장 가까이): 지금은 밝은 연두·하늘색이다. 밤 세기 100%는 어두운 회청색, 60%는 회색빛 초록, 1판은 회색이었다.
  - 한낮 기복: 항성이 머리 위면 기복 음영이 지금과 같다.
- 밤 2판 대 3판: 3판은 밤 쪽이 조금 밝고 밤 느낌은 남았다. 경계 사진도 3판이 조금 밝다.
- 합친 시제품
  - 지구본 낮: 흰 뭉게구름이 바다의 위도 띠를 따라 있고 큰 사막 위는 맑다.
  - 낮밤 경계: 구름도 밤 쪽에서 라벤더로 어둡고 옅다.
  - 1,500km: 구름이 대륙 가장자리 일부를 덮는다.
  - 900km: 투명 방식은 지도가 뿌옇고, 걷히는 방식은 남은 구름이 또렷하다.
  - 구름 그림자 켬·끔(1,450km): 켜면 구름 아래 땅이 조금 어둡다(사용자가 넣지 않기로 했다).
  - 달 + 구름: 지구본 위 하늘에 작은 볼록달이 보인다.
  - 기후 자료 화면: 구름이 없다.
- 달
  - 지구본 가장 먼 거리: 행성 위 하늘에 작은 볼록달(지름 약 35 CSS px). 행성 가장자리 뒤로 일부 가려지기도 한다(행성이 덮어 그린다).
  - 위상: 같은 항성 방향에서 보름·볼록·반달·초승이 저절로 맞는다. 어두운 쪽에도 라벤더 윤곽이 남는다. 바다 3개·크레이터 15개의 파스텔 장난감 달이다.
  - 300km: 하늘이 화면에 없어 달을 그리지 않는다.
  - 데스크톱 가로 화면: 달이 행성 옆에 보인다.
  - 크기 비교: 지구 비율 약 9px 점, 12R 약 35px, 8R 약 44px.
- 구름 노이즈 세 방식(경위도 그림): 모두 비슷한 띠 모양 뭉게구름이다.

## 8. 남은 것·모르는 것
- 휴대폰 비용(U): 위 표의 휴대폰 값은 모두 추정이다. 특히 중급 안드로이드의 면 하나 굽기 시간, 750~900km(화면 전부 + 타일 최다) 프레임 p95, 쉬는 동안 그린 프레임 수를 재야 한다. 픽셀 비율 상한 2(선명도 작업)에서 기준선부터 다시 잰다.
- R8 큐브 렌더 타깃·밉맵이 일부 기기·드라이버에서 안 될 수 있다(U). ES 3.0 표로는 늘 된다(V\*).
- 3D 노이즈판의 휴대폰 모습, 면 하나씩 굽기·창 바꾸기의 옅어졌다 나타나기는 그려 보지 않았다(U).
- 땅 습도가 구름에 주는 몫은 S2 시험 행성에서 다시 본다(U).
- 지구(ETOPO)를 넣을 때 지리와 격자 사이 회전이 있으면 항성·달에도 같은 회전이 필요하다(U).
- 브라우저 엔진별 `Math` 정밀도는 화면 연출이라 문제 삼지 않는다. 판정이 쓰는 계절은 공용 정수 달력이다.
