# tRPC 11 연결, 서버 타입 공유(타입 전용 예외), Zod 4 연동 확인

- 일시: 2026-10-28 18:51 (KST)
- 작업 도구: Claude Code (클라우드 세션)
- 관련: ADR `2026-10-28-trpc-type-sharing.md`(새, ADR 23), `2026-10-28-m0-toolchain.md`(모듈 경계 검사 일부 대체), `2026-10-28-stack-baseline.md`(Zod 4 확인 항목), PLAN 3장·4.1·10.4·13
- 사용자 결정(2026-10-28): 게임 앱이 서버의 타입 정보만 가져오는 예외를 허용(추천안).

## 한 일
- 의존성: 서버에 `@trpc/server` 11.19.0, `zod` 4.6.7(시험용 개발 의존성 `@trpc/client` 11.19.0). 게임 앱에 `@trpc/client`·`@trpc/server` 11.19.0, 개발 의존성 `@terra/server`(작업공간). 모두 공개 1일이 지나 `minimumReleaseAge`를 통과한다. TanStack Query는 넣지 않았다.
- 서버(`apps/server/src/trpc/`)
  - `context.ts`: 요청 맥락(`contentVersion`, `now`). Node 전용 타입을 넣지 않는다.
  - `init.ts`: tRPC 구성. 오류 응답에 스택을 넣지 않고, 예상하지 못한 오류는 메시지를 `internal_error`로 바꾼다.
  - `system.ts`, `router.ts`: 첫 프로시저 `system.info`(프로토콜·판정·콘텐츠 버전, 서버 시각). `AppRouter` 타입을 내보낸다.
  - `plugin.ts`: 공식 Fastify 어댑터로 `/api/trpc`에 붙인다. 서버 잘못(500)만 원문과 함께 로그에 남긴다.
  - `app.ts`: `routerOptions.maxParamLength: 5000`(묶음 요청 경로가 길어서).
  - `@terra/protocol`에 `TRPC_PATH`("/api/trpc") 추가. WebSocket 메시지가 아니라 `PROTOCOL_VERSION`은 그대로다.
- 타입 공유: TS 프로젝트 참조
  - 서버 `tsconfig.api.json`(composite)이 선언 파일을 `apps/server/dist-types/`에 만든다(저장소에 올리지 않음).
  - 게임 앱 tsconfig가 `references`로 가리키고, `typecheck`는 `tsc -b`다.
  - 서버 `exports`는 `"./trpc": { "types": "./src/trpc/router.ts" }`. 실행 조건이 없어서 값 import는 Vite 빌드에서 실패한다.
- 게임 앱: `src/net/api.ts`(`createTRPCClient<AppRouter>` + `httpBatchLink`, 주소 `/api/trpc`). 아직 화면에서 쓰지 않는다. 새 화면 문구 없음.
- 경계 검사: `scripts/check-boundaries.mjs`에 `TYPE_ONLY` 표. 판정은 `scripts/type-only-imports.mjs`(순수 함수 + 시험). 시험 파일 위치(`scripts/**/*.test.mjs`)를 `vitest.config.ts`에 넣었다.
- 린트: 게임 앱 소스에서 Node 전역(`process`, `Buffer` 등)·Node 내장 모듈 import 금지(`.oxlintrc.json` overrides). 생성 폴더 `dist-types`는 린트·Docker 대상에서 뺐다.

## 확인 (Verified: 이 컨테이너, Node 24.22.1, TS 7.0.2, PostgreSQL 16 임시 클러스터)
| 항목 | 결과 |
|---|---|
| `TEST_DATABASE_URL=… pnpm check` (선언 파일을 지운 상태에서 시작) | 통과. 시험 57개(이번에 15개 추가: 서버 8, 게임 2, 검사 스크립트 5). 서버 typecheck가 게임 앱보다 먼저 돈다 |
| `pnpm build` | 통과. 기기 번들 318.6kB(클라이언트를 아직 부르지 않아 tRPC 코드 없음) |
| 기기 번들에 서버 코드가 없는지 | 클라이언트를 부르게 임시로 바꿔 빌드: 335.2kB(gzip 103.3kB). 서버 로그 문구, Fastify 어댑터, `initTRPC`, `DATABASE_URL` 검색 0건. 임시 변경은 되돌렸다 |
| 빌드한 서버(`dist/main.js`) + curl | `GET /api/trpc/system.info` 200, 묶음 2개 200, 텔레메트리 형식 오류 400·정상 204 |
| 묶음 요청 상한 | `maxParamLength`를 100으로 바꾸면 12개 묶음 시험이 실패, 5000이면 통과 |
| Zod 4 + tRPC 11 | 타입 추론(기본값·변환 포함), 맞는 입력 200, 틀린 입력 400 `BAD_REQUEST`(GET·POST), `error.cause`는 `ZodError`, 500은 원문·스택을 숨김 |
| 타입 단언이 실제로 검사되는지 | 기대 타입을 일부러 틀리게 바꾸면 `tsc`가 TS2344로 실패 |
| 게임 앱 타입 검사가 읽는 서버 파일 | `router.d.ts`, `context.d.ts` 2개(`--listFiles`) |
| 경계 검사 모의 위반 | 게임 앱 소스에 값 import·`import { type X }`·동적 import → 3건 실패(줄 번호 포함). `@terra/server`를 `dependencies`에 두면 실패 |
| 값 import의 Vite 빌드 | `"./trpc" is not exported under the conditions …`로 빌드 실패 |
| Node 전역 린트 | 임시 파일의 `process`·`Buffer`·`node:fs` → 3건 오류 |

비교한 방법과 결과(자세한 이유는 ADR):
- 서버 소스를 바로 가져오기: 지금은 통과한다. 하지만 `@trpc/client` 타입이 `@types/node`를 끌고 와서 우연히 통과하는 것이다. 클라이언트 없이 라우터 타입만 가져오면 `config.ts`에서 `NodeJS`·`process` 오류가 난다.
- 선언 파일을 따로 만들기(참조 없이): 선언 파일이 없을 때 타입 인식 린트가 처리하지 않은 Promise를 놓쳤다.
- 프로젝트 참조(선택): 린트는 선언 파일 없이도 서버 소스로 따라간다.

## 함께 바꿔야 하는 파일
- tRPC 경로를 바꾸면 `packages/protocol/src/api.ts`(`TRPC_PATH`) 하나만 바꾼다. 개발 프록시(`apps/game/vite.config.ts`의 `/api`)와 정적 파일 404 처리(`apps/server/src/app.ts`의 `/api`)도 확인한다.
- 서버 `src` 밖의 파일을 라우터가 가져오게 되면 `apps/server/tsconfig.api.json`의 `include`·`rootDir`을 본다(composite는 모든 파일을 포함해야 한다).
- 타입 전용 예외를 늘리려면 `scripts/check-boundaries.mjs`의 `TYPE_ONLY`와 이 ADR을 함께 바꾼다.

## 건드리지 말 것
- 게임 앱이 `@terra/server`를 값으로 가져오게 하지 않는다(경계 검사·Vite가 막는다).
- 게임 상태를 바꾸는 명령을 tRPC로 만들지 않는다(WebSocket으로만, PLAN 4.3).
- 텔레메트리 경로를 tRPC로 옮기지 않는다(sendBeacon).
- 서버 `exports`에 실행 조건(`import`·`default`)을 넣지 않는다. 넣으면 값 import가 빌드를 통과한다.

- 원래 있던 문제: 게임 tsconfig가 `vite.config.ts`를 포함해 `@types/node`가 게임 코드 타입 검사에 들어와 있었다. 이번에 린트로 Node 전역을 막았다. tsconfig를 앱용·설정 파일용으로 나누는 것은 하지 않았다(`@trpc/client`가 어차피 Node 타입을 불러와 효과가 적다).

- 서버 `tsconfig.api.json`은 서버 `src` 전체의 선언 파일을 만든다. 서버가 커져 느려지면 다시 본다.
