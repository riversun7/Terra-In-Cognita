## 한 일
- 지원 하한을 빌드에 걸었다. 게임 앱 `build.target: "baseline-widely-available"`(Chrome·Edge 111, Firefox 114, Safari·iOS 16.4), tsconfig `lib`는 ES2023.
- 설치형 웹앱(PWA)을 켰다.
  - `vite-plugin-pwa` `generateSW`. 캐시는 앱 껍데기만(JS·CSS·HTML·아이콘·manifest). 실행 중 캐시는 없다.
  - 화면 이동 대체(`index.html`)에서 `/api`·`/ws`·`/health`를 뺐다. 소셜 로그인 콜백이 화면 이동이라서다.
  - manifest 이름은 `messages/ko.json`에서 읽는다(`app_title`, 새 키 `app_short_name`·`app_description`).
  - 임시 아이콘 5개를 `apps/game/public/`에 넣었다. 만드는 스크립트도 넣었다(`apps/game/scripts/placeholder-icons.mjs`, 의존성 없음).
- 새 버전 적용 규칙을 만들었다(`apps/game/src/pwa/`).
  - 켤 때(새로 열기, 또는 30분 넘게 숨겼다가 다시 보기) 15초 안, 첫 터치·키 입력 전에 새 버전이 준비되면 바로 새로고침한다.
  - 그 밖에는 화면 아래 배너로 알린다(지금 바꾸기 / 나중에). "나중에"를 누른 버전은 다시 알리지 않고, 다음에 켤 때 바로 적용한다.
  - 새 버전 확인: 서버 `welcome`마다, 화면이 다시 보일 때(10분에 1번까지).
  - 강제 적용: 서버가 버전을 거절하거나(`protocol_unsupported`) `vite:preloadError`가 나면 새 버전을 찾아(최대 15초) 적용한다. 없으면 그냥 새로고침한다.
  - 새로고침 전에 WebSocket을 정상 종료(1000)한다.
  - 자동 새로고침은 1분에 1번까지다(탭마다, `sessionStorage`). 새로고침이 끝없이 반복되는 것을 막는다. 막히면 배너나 새로고침 버튼으로 사람이 한다.
- 거절 화면의 새로고침 버튼은 이제 강제 적용을 부른다. 그냥 새로고침하면 SW가 옛 화면을 다시 띄워서 다시 거절된다.
- 거절 문구를 바꿨다. 되돌림 배포 뒤에는 기기가 더 새 버전이라 "앱이 오래됐다"가 틀린다.
- CI
  - 빌드 뒤 `node scripts/check-pwa.mjs`: manifest 필드·아이콘 파일과 크기, theme-color 일치, manifest 링크, `sw.js`의 SKIP_WAITING·화면 이동 대체·제외 경로.
  - 이미지 점검: `/manifest.webmanifest` 형식, `/sw.js` 형식, 없는 파일 404.
- `frameStats.ts`의 틀린 `toSorted` 주석을 고쳤다(코드는 그대로).

## 확인 (Verified)
- 패키지 코드(vite-plugin-pwa 2.0.0, workbox-window 7.4.1)
  - `registerSW` 옵션: `immediate`, `onNeedRefresh`, `onNeedReload`, `onOfflineReady`, `onRegisteredSW`, `onRegisterError`. 등록은 기본으로 페이지 `load` 뒤.
  - `onNeedReload`는 SW가 바뀌고(`controlling`) 이 화면이 원래 SW 아래 있었을 때만 불린다.
  - 플러그인의 `updateServiceWorker()`는 플러그인 등록이 끝나야 SKIP_WAITING을 보낸다 → 강제 적용은 기다리는 SW에 직접 보낸다.
  - workbox-window는 밖에서 생긴 첫 새 버전 뒤로 `updatefound`를 더 듣지 않는다 → 등록에서 직접 본다.
  - 개발 서버에서 `virtual:pwa-register`는 아무것도 하지 않는다. `navigateFallback` 기본값은 이미 `index.html`, `cleanupOutdatedCaches` 기본 켜짐.
  - Vite 8.3.5 `baseline-widely-available` = `chrome111, edge111, firefox114, safari16.4, ios16.4`.
- 빌드(Vite 8.3.5): 플러그인이 동작한다. manifest 링크를 넣고 `sw.js`·`workbox-<해시>.js`를 만든다. 미리 캐시 10개.
  - 기기 코드 증가: 첫 화면 묶음 gzip +2.6KB, `workbox-window` 조각 2.25KB → 약 4.9KB.
- 서버(빌드된 `dist/main.js`): `/manifest.webmanifest` `application/manifest+json`, `/sw.js` `application/javascript; charset=utf-8`, 둘 다 `Cache-Control: public, max-age=0`. `/assets/missing-abc.js`·`/api/...` 404.
- Playwright(Chromium 153, 390×844, `ko-KR`, 빌드 A·B를 실제 서버로) 26개 모두 통과
  - SW 등록·활성(`/sw.js`, 범위 `/`), 다시 읽으면 SW가 화면을 맡는다. 첫 방문 화면은 맡지 않는다(`clientsClaim` 안 씀).
  - CDP `Page.getAppManifest` 오류 0개, `Page.getInstallabilityErrors` 0개. 아이콘 5개 모두 Chromium에서 열린다(favicon 48×48 포함).
  - 오프라인 새로고침·화면 경로는 SW가 껍데기를 띄운다. 오프라인 `/api/...` 화면 이동은 SW가 대신하지 않는다(`ERR_INTERNET_DISCONNECTED`). 온라인 `/api/auth/callback/...`은 서버 404.
  - (a) 켠 뒤 입력 전: 서버를 B로 바꾸면 약 1.7초 만에 B로 자동 새로고침. 배너는 안 뜬다. 새로고침 전 WebSocket 종료 코드 1000.
  - (b) 입력 뒤: 배너가 뜨고 A에 머문다. "지금 바꾸기" → 약 1.1초 뒤 B.
  - (c) 입력은 없지만 15초가 지난 뒤: 배너, 자동 새로고침 없음.
  - "나중에": 배너가 닫히고, 다시 접속해도 같은 버전은 다시 알리지 않는다(영어 화면 포함).
  - 거절(`protocol_unsupported`, WebSocket 가로채기): 새 버전을 찾아 B로 적용. 새 버전이 없으면 새로고침 1번, 1분 안에 또 거절되면 멈추고 버튼만 남는다. 버튼은 막지 않는다.
  - `vite:preloadError` → 기다리던 B 적용. SW 차단 환경: 앱은 그대로 뜨고 강제 적용은 그냥 새로고침.
  - 숨김 29분 → 그대로, 31분 → 미뤄 둔 B를 바로 적용(Playwright 가짜 시계, 화면 보임 상태는 흉내).
- 단위 시험: `updatePolicy.test.ts` 12개, `scripts/pwa-build.test.mjs` 9개. `pnpm check`(DB 시험 포함) 통과.
- `toSorted`: iOS·Safari 16.0, Chrome 110부터, Firefox는 115부터(core-js-compat 3.51.0 자료). Vite 대상의 Firefox 114에는 없다.

## 함께 바꿔야 하는 파일
- 색을 바꾸면: `vite.config.ts`의 `THEME_COLOR`, `index.html`의 theme-color, `styles.css`, 아이콘 스크립트의 `BACKGROUND`. 검사가 manifest와 meta 불일치를 잡는다.
- 아이콘을 바꾸면: `apps/game/public/`의 파일 이름을 유지하거나 `vite.config.ts`의 `icons`·`includeAssets`와 `index.html`을 함께 바꾼다.
- 화면 이동 제외 경로를 바꾸면: `vite.config.ts`와 `scripts/pwa-build.mjs`의 `DENIED_NAVIGATIONS`·`ALLOWED_NAVIGATIONS`.
- 게임 명령이 생기면: 새로고침 전에 보내기를 멈추고 응답을 잠깐(최대 2초) 기다리는 단계를 `closeForReload` 앞에 넣는다(ADR).

## 건드리지 말 것
- `registerType: "autoUpdate"`로 바꾸지 않는다(쓰는 중에 모든 탭을 새로고침한다). 바꾸려면 ADR.
- 거절 화면 버튼을 `location.reload()`로 되돌리지 않는다(옛 화면 반복).
- 화면 경로 이름에 점(.)을 쓰지 않는다. 서버가 확장자 있는 경로를 404로 준다.
