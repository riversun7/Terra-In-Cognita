## 한 일

  - 카메라(`camera/cameraMath.ts`, 순수 함수): 쿼터뷰. 기울기 35~55°(기본 45°), 자유 회전, 화면 짧은 변 40m ~ 2차맵 전체, 목표점은 2차맵 안.
  - 조작(`camera/controls.ts`): 포인터 이벤트 하나로 터치·마우스를 받는다. 한 손가락 = 이동, 두 손가락 = 이동·확대·회전, 마우스 끌기 = 이동, 휠 = 확대(커서 아래 땅 기준), 오른쪽·가운데 끌기 = 회전·기울기. 짧게 누르면 고르기.
  - 지형(`terrain/`): 입력 모양 `TerrainInput`(높이 Int16 0.1m 129×129, 지표 코드 128×128: 물·풀·흙·바위). 메시는 Web Worker가 만들고 배열을 넘긴다(transfer). 워커를 못 쓰면 화면 스레드. 꼭짓점 색, 물 판, 가장자리 벽(경계 표시).
  - 유닛(`units/`): 경로(꺾이는 점·출발 시각 서버 ms·속도 칸/초)를 타입 배열(`UnitMotionStore`)에 두고 매 프레임 보간한다. 실제 크기 캡슐 + 화면 1.25px 외곽선(인스턴스 2개가 행렬 버퍼를 함께 쓴다). 시야 안 유닛만 그린다. 멀면 점 아이콘(기준: 키 1.8m가 8px 미만). 고른 유닛은 링 + 강조 외곽선(아이콘이면 큰 점).
  - 건물(`buildings/`): 직사각형 바닥 + 90° 회전(앞면 방향, 홀수면 가로·세로 바꿈), 상자 인스턴스 + 앞면 문.
  - 누른 곳(`picking.ts`): 유닛은 화면에 투영한 점 중 가장 가까운 것(반경 22px, 실제 크기면 몸 크기만큼 더), 땅은 시선이 높이 지도에 닿는 점.

## 건드리지 말 것
- 엔진(`@terra/engine`)을 첫 화면 코드에서 정적으로 import하지 않는다. Three.js가 첫 화면 묶음에 들어온다. `SecondaryMapScreen`만 `React.lazy`로 부른다.
- 워커 만드는 코드 `new Worker(new URL("./terrainWorker.ts", import.meta.url), { type: "module" })`의 모양을 바꾸지 않는다(Vite가 이 모양만 따로 묶는다).
- 렌더러를 화면마다 새로 만들지 않는다(`acquireRenderer`). iOS는 컨텍스트를 거듭 만들면 메모리가 는다.
- 엔진 색 값은 색 관리를 끈 상태(`ColorManagement.enabled = false`)에 맞췄다. 켜면 색이 바뀐다.
- 외곽선 인스턴스는 몸 인스턴스와 행렬 버퍼를 함께 쓴다. 개수(`count`)를 함께 바꾼다.
- 화면 CSS에 색·px 값을 직접 쓰지 않는다(`pnpm check:contrast`).

- `pnpm dev:game`(Vite 개발 서버)과 개발 모드 두 번 마운트(StrictMode)는 미실행. WebGL을 못 쓰는 기기 안내(unsupported)도 화면으로는 미실행.
- 지도는 읽기 프로그램으로 쓸 수 없다(캔버스는 `role="img"` + 설명).
- 지형 색 경계가 흐리다(꼭짓점 색 평균). 가짜 자료라 그대로 둔다.
- Vite가 2차맵 조각 500kB 초과 경고를 낸다. 지연 조각이라 그대로 둔다.

## 사용자 결정 대기
- ADR 33 확정(휴대폰 측정 뒤): 아이콘 전환 기준, 기울기·확대 범위, 픽셀 비율·MSAA.
- 2차맵 조각을 서비스 워커가 미리 캐시할지(지금: 한다).
- 터치로 기울이는 동작이 필요한지.
