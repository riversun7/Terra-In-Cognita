## 한 일
- 기능 통로(`apps/game/src/net/serverLink.ts`): 2차맵 같은 기능이 앱의 WebSocket 연결 하나를 함께 쓴다. 준비(welcome)·끊김 알림, 기능 메시지 보내기·받기, 마지막으로 잰 시계 차이(새로 잴 때까지 유지).
- 연결(`connection.ts`): 인사·시계 맞추기·백오프·새로고침 전 정상 종료는 그대로 두고 통로에 알린다. 2차맵 서버 메시지를 통로로 넘기고, `reconnect()`(지금 소켓을 1000으로 닫고 바로 새로 맺음, 옛 소켓의 늦은 사건 무시)를 더했다.
- 로그인한 사용자가 바뀌면 연결을 다시 맺는다(`App.tsx`). 서버는 WebSocket 연결 요청의 쿠키로만 사용자를 알고, 앱은 로그인보다 먼저 연결한다. 그대로 두면 로그인 → [2차맵]에서 구독이 늘 `sign_in_required`가 된다(Verified: 서버 코드 `app.ts` "머리글은 연결할 때 한 번 읽어 둔다").
- 자료 받기(`apps/game/src/map/mapFeed.ts`, 타입 `feedTypes.ts`, 조각 `snapshotParts.ts`, 측정 `feedMeter.ts`)
  - 열면 subscribe, 닫으면 unsubscribe. ready(처음 연결·다시 연결)마다 다시 구독한다.
  - 스냅샷 조각을 part 0부터 모아 다 받으면 엔진의 유닛·건물을 통째로 바꾼다(고른 유닛이 남아 있으면 다시 고른다).
  - `unit_paths`·건물 이벤트는 `secondMap.ts` 머리 주석의 rev 규칙대로. 빠지면 다시 구독(앞 구독과 1초 띄움)하고, 새 스냅샷 전까지 오는 변화는 버린다. 조각 사이에 다른 2차맵 메시지가 끼거나 차례·머리가 어긋나도 빠짐으로 본다.
  - 결과 코드: busy·rate_limited·internal_error는 1초부터 두 배씩(15초까지) 다시, `sign_in_required`는 연결을 한 번 다시 맺어 다시, 그 밖은 실패 + [다시 시도]. 스냅샷이 10초 안에 다 오지 않으면 다시.
  - 우리 구독의 ok 전에 온 스냅샷은 앞 구독의 것이다 → 그려 두되 우리 답을 기다린다(개발 모드 두 번 마운트에서 실제로 생긴다).
  - 스냅샷 뒤 처음 보는 유닛이 오면 목록을 다시 넣는다. 엔진 상한(2,048)을 넘는 유닛은 그리지 않고 센다.
- 지형(`terrainLoader.ts`): 스냅샷의 주소(같은 출처 경로만)를 쿠키와 함께 받아 `decodeTerrain` → 엔진 입력(`mapWire.ts`: cm ÷ 10 반올림 → Int16, 넘치면 기준 높이로 옮김, 지표 그대로, 칸 11.72m, 물 0m). 첫 조각이 오면 바로 받기 시작하고, 주소가 같으면 다시 받지 않는다. 실패는 이유 코드(network·sign_in·not_found·server·invalid, 엔진 메시 실패는 render) + [다시 시도]. 404면 한 번은 다시 구독해 새 주소를 받는다.
- 유닛·건물 바꾸기(`mapWire.ts`): 위치·속도 ÷ 1024, 출발 시각은 서버 ms 그대로(엔진 `serverNow` = 기기 시각 + 통로의 시계 차이). 건물 rotation ÷ 90, height → depth. [임시] 크기 등급별 겉모습과 탈것 모양(아래 "정한 것").
- 명령: 고른 유닛 + 땅 누르기 → 관리자만 `move_unit`(목표 = 칸 × 1024 + 512). 보기 전용은 "보기 전용입니다…" 안내만 하고 보내지 않는다. 결과는 코드 문구(ko·en)로 아래 판에 6초 보인다.
- 화면(`SecondaryMapScreen.tsx`): 기본은 서버 자료. `@terra/engine/mock`은 화면에서 쓰지 않는다(꾸러미·시험은 그대로 둠, 빌드 조각에서도 빠짐 — Verified). [모두 멈춤]을 뺐다. 여는 곳(계정 줄 [2차맵] + `OpenView` "map")은 그대로이고 화면 속성은 `onClose`·`monitor`만 남았다(시계는 통로에서 읽는다).
  - HUD: fps·p95·메모리·유닛·그리기·표현 단계·엔진 몫(그대로) + "스냅샷 KB · 준비 ms · 다시 구독 N", "갱신 N/초 · KB/초 · 지연 ms"(최근 1초, 지연 = 받은 서버 시각 − 출발 시각의 중앙값).
  - 가운데 안내: 연결하는 중·2차맵 자료를 받는 중·지형을 받는 중·지형을 만드는 중·연결이 끊어졌습니다·실패(이유 + [다시 시도]).
  - 시험용 `data-*`: feed·terrain 상태, rev, 구독 수, 빠짐, 스냅샷 크기·시간, 준비 시간, 갱신 양, 지연, 명령 결과·시간 등.

Playwright 묶음에서 확인한 것
- 관리자·파스텔: 로그인 뒤(연결을 다시 맺음: 소켓 2개, 1개 닫힘) [2차맵] → 준비 약 0.9초. 캔버스 1개. 스냅샷 유닛 1,000개·2조각, 구독은 한 번, ok 다음 조각. 지형 200·gzip·`private, max-age=31536000, immutable`. 3초 동안 rev가 오르고 가는 유닛이 있음, 빠짐 0. 버튼 44px·가로 넘침 없음.
- 관리자 명령: 멀리서 유닛 고르기 → 가까이 → 땅 누르기 → `move_unit`(목표 x·y가 1024로 나눈 나머지 512) → 같은 번호의 결과 ok(약 47~82ms) → "유닛 906: 길을 찾아 출발합니다." → 그 유닛 위치가 바뀜. [선택 해제]. 닫으면 unsubscribe 1번, 캔버스 0개. 콘솔·페이지 오류 없음.
- 일반 사용자·다크: 유닛 고르기("유닛 835 선택됨.") → 땅 누르기 → "보기 전용입니다. 유닛은 관리자만 옮길 수 있습니다." → `move_unit` 프레임 0개. 오류 없음.

## 함께 바꿔야 하는 파일
- 프로토콜 2차맵 메시지·결과 코드를 바꾸면: `mapFeed.ts`(rev 규칙·결과 처리), `mapMessages.ts`(코드 표 — `satisfies`가 빠진 코드를 알려 준다), 문구 ko·en.
- 지형 형식(TCTR)·엔진 지형 입력을 바꾸면: `mapWire.ts` `toTerrainInput`과 시험(엔진 상수와 같은지 본다).
- 엔진 유닛 상한을 바꾸면: 화면 `UNIT_CAPACITY`(엔진과 자료 받기에 같이 넘긴다).
- 2차맵 화면을 앱 화면 흐름(아래 탭)으로 옮기면: `App.tsx`의 `OpenView` "map"·lazy, `AccountBar.tsx`의 [2차맵]. 화면은 `onClose`·`monitor`만 받는다.
- 서버의 구독 속도 제한을 바꾸면: `mapFeed.ts`의 `MIN_RESUBSCRIBE_GAP_MS`·다시 구독 기다림.

## 건드리지 말 것
- 통로가 시계 차이를 다시 연결 동안 유지하는 것: 0으로 돌리면 유닛이 시계 차이만큼 튄다.
- 로그인이 바뀔 때 다시 연결(`followIdentity`): 빼면 앱을 켠 뒤 로그인한 사용자의 구독이 모두 `sign_in_required`가 된다.
- 요청 번호를 1부터 세지 않는다(서버 중복 방지 10분).
- 지형은 같은 출처 경로만 받는다(`isSameOriginPath`): 쿠키를 다른 곳에 보내지 않게.
- 엔진(`@terra/engine`)을 첫 화면 코드에서 정적으로 import하지 않는다(엔진 작업 기록과 같다). 자료 받기 모듈은 엔진 타입만 가져온다.

## 미검증·TODO·알려진 문제
- 실제 휴대폰·NAS에서 재지 않았다(Unknown): 프레임 p95·메모리 20분, 첫 진입 3초·다시 열기 1초(4G), 시계 차이가 큰 기기에서 유닛 위치, iOS 백그라운드 복귀 뒤 다시 연결·다시 구독, 휴대폰에서 스냅샷 조각 해석(Zod 검사) 시간.
- 움직임 지연 약 100ms 때문에 차(약 4.7칸/초)는 받을 때 약 0.5칸 앞으로 건너뛴다(서버 작업 기록과 같다). 휴대폰에서 거슬리면 서버 묶기를 줄이거나 기기가 부드럽게 따라가게 한다.
- 지형 해석기(`decodeTerrain`)가 첫 화면 조각에 들어간다(약 1~2kB). 프로토콜 진입점이 하나라서다. 줄이려면 프로토콜에 지형 전용 진입점이 필요하다(PROTECTED: 의미는 그대로라 버전은 그대로).
- 유닛이 사라지는 메시지는 프로토콜에 없다. 새 스냅샷에서만 사라진다.
- 건물 놓기·치우기 명령 화면은 없다(서버 명령은 있다). 건물 이벤트 적용은 단위 시험으로만 확인했다(시험 2차맵에 건물이 없다).
- 관리자 명령 화면은 시험용이다. 진짜 명령(내 유닛)·권한(소유)은 기획·S3 뒤.
- 시험 2차맵 키(`S1_TEST_MAP_KEY`) 하나만 연다. 1차맵에서 고르는 2차맵·이웃 2차맵 미리 받기는 없다.
- 끊긴 동안 받은 유닛은 마지막 경로대로 계속 간다(다시 연결 뒤 새 스냅샷으로 맞춘다). 길게 끊기면 서 있는 자리가 틀릴 수 있다.
