  - 3절 하단 탭: 순서 하나의 앞에서부터 폭만큼 칸을 채운다. C는 가운데 지도를 건너뛰고, A는 순서 + ☰다. 기본 순서 홈·지도·유닛·경제·세력·사이보그가 두 기본 탭(D-6010)을 그대로 만든다(`navigation.ts`의 `NAV_ITEM_IDS`·`DEFAULT_NAV_TABS`로 확인). 좁음 단계 안에서 폭 → 칸 수 규칙(D-265 "좁은 휴대폰은 4칸, 넓으면 더 많이")을 정하고, 12절 "390px의 5칸"을 더 넓은 칸 수에서 다시 본다.
  - 4절 `nav`: `tabs`(배치마다 4칸)·`menu`를 순서 하나(`order`) + `layout`으로 바꾼다. 설정 칸은 배치 고르기 + ↑·↓ 목록 하나 + 탭 미리보기. 홈도 순서를 따른다(D-265 "홈 칸을 앞에 고정할지는 해석으로 두지 않았다").
  - 코드(0단계, main): `NavigationSettings`·`parseNavigation`·`visibleTabs`(칸 수 인자)·`mergeNavigation`·`NAV_TAB_SLOTS`. 계정의 `nav` 저장 칸(`user_settings`)은 아직 없어 옮길 저장값이 없다(Verified: main `apps/server/src/db/schema.ts`). 모르는 칸을 남기는 규칙(5절)은 그대로.
  - 5절 길이 상한: "탭 4, 메뉴 32, 카드 24" → "순서 32, 카드 24". 13절 시험에 순서 규칙(칸 수별 채우기, C의 지도 건너뛰기, 모르는 ID).
  - 8절: D-266이 추천 "가"를 확정했다. "해석·Q2" 말을 D-266으로 바꾼다. 30분 숨김 뒤 다시 볼 때도 보던 화면에 남는다(D-266 결정 문장).
  - 1절 예약: `/start` 앞 성인 인증 단계 자리를 지운다(D-6044, 계정 화면 = ADR 29 범위). `/start` 흐름은 이름 → 외형 → 초기 스탯 → 세력 → 시작 도시(1차맵) → 강하 → 핵심 10분 튜토리얼 → 대시보드(D-6039~D-6043). 튜토리얼 단계 상태로 보내기 규칙("사이보그가 없는 계정은 `/start`")을 넓힌다. 단계마다 기록 칸을 쌓을지는 2절 뒤로 규칙으로 정한다.
  - 1절 예약: `/economy/auction/:kind`에 운송 수단(D-271). 몸값 매물은 원래 주인에게만 보인다(D-269). `/report/:token`은 로그인한 계정만(ADR 35 질문 35 기본안, D-267). 관리자 경제 감시(D-6047)는 `/admin/<구역>` 고정 줄, 개발자 도구(D-6048 틀, 건물 에디터 D-5044 포함)는 `/dev/<도구>` 고정 줄. `/shop` 예약(여는 곳은 질문 92 기술 기본안: 사이드 메뉴 시스템 묶음).
  - 3절 위 띠: D-6049로 잔액·상점 단추를 넣지 않는다(지금 문장과 같다. 근거만 더함).
  - 7절 처리할 일: 새 종류 후보 `settlement_goal`(정착 안내 목표 카드, D-6042. 분류는 제안·결정, 기술 제안), 반란 위험·반란 시작(위협, D-253·D-256, 아직 없음), `captive_ransom`은 D-269 매물에 맞는다(7절 "포로" 줄의 "몸값 형식을 기획이 확인하는 중" 문장을 고친다). 8절 복귀 요약 칸에 복귀 패키지(D-7034).
