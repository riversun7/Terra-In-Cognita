## 고침 안과 다르게 한 것
- 지적 1
  - 설정 파일에서 살아 있는지 보기만 하지 않고 잠금 파일을 만든다(`wx`: 이미 있으면 실패). 실행 기록은 전역 준비가 빌드 뒤에 쓴다. 그래서 보기만 하면 앞 실행이 빌드하는 동안(첫 실행이면 1분까지) 두 번째 실행이 들어와 같은 `dist`에 함께 빌드할 수 있었다.
  - 시험 작업자는 `E2E_HARNESS`가 아니라 Playwright가 넣는 `TEST_WORKER_INDEX`로 가린다. 작업자가 설정 파일을 읽기 전에 들어 있다(`playwright/lib/worker/workerProcessEntry.js`). `--list`는 결과 폴더를 지우지 않아서 뺐다.
  - 주인이 죽은 잠금을 두 실행이 같은 순간에 가져가면 둘 다 잡을 수 있다. 전역 준비가 실행 기록으로 한 번 더 막는다(미실행: 같은 순간을 만들지 못했다).
- 지적 2는 고침 안대로다. 시험 파일마다 계정을 따로 만드는 다른 길은 하지 않았다. 세션을 만들 때 들어가기를 쓰는데, 주소마다 분당 10번 제한이라 시험 파일이 늘면 막힌다.
- 지적 4: 신호를 받아도 잠금은 놓지 않는다. 놓으면 바로 뜬 다음 실행이 아직 살아 있는 이 실행기의 실행 기록을 보고 멈출 수 있다. 주인이 죽은 잠금은 다음 실행이 가져간다.
- 지적 5: `cwd` 대신 시작 시각으로 가린다. 실행기의 `cwd`는 저장소 뿌리가 아닐 수 있다(`e2e/`에서 돌리기 등).
- 지적 6
  - 모달이 여럿 열려 있으면 모두의 안을 본다. 어느 것이 맨 위인지 알 길이 없다. 아래 모달의 칸도 따로 열렸을 때 검사를 통과해야 하므로 새 거짓 보고는 없다고 본다(Assumed).
  - `--tap-size`가 px 값이 아니면(rem 등) 계산하지 않고 44로 본다.

계정 메뉴·홈(W2 + 이 가지 트리, 계정 player, 시험 4개 모두 통과)
1. 앞 시험: 기본 맥락으로 연 뒤 계정이 `{ theme: "pastel", followSystem: false, locale: "ko", nav: {}, home: {} }`였다. 그 뒤 tRPC `settings.set`으로 메뉴 배치 `a`, 홈 카드 1개, 다크, 영어를 넣었다.
2. `nav: null`·`home: null`(고치기 전 틀처럼 메뉴·홈을 넣지 않음): 기기에 앞 시험의 메뉴·홈이 왔다(새는 길). 테마·언어는 넣은 값(파스텔·한국어)이 계정에 올라갔다.
3. 기본값: 로그인하며 계정이 다시 1의 기본값이 됐다. 기기의 "올릴 것" 표시도 비었다(올리기 성공).
4. 두 번째 기기: `home: null`이면 첫 기기가 바꾼 홈이 왔다. 기본값 기기는 계정 홈을 `{}`로 되돌렸다.
- PostgreSQL jsonb는 칸 순서를 바꿔 돌려준다(`layout`·`menu` → `menu`·`layout`). 메뉴·홈 값을 글자로 비교하는 시험은 칸 이름을 정렬해 비교한다.
- 이 가지(W2 전 바탕)의 앱은 `nav`·`home` 칸과 그 표시를 읽지 않는다. smoke·사진이 그대로 통과했다(Verified).

- ADR 37 11절·ADR 36의 115,427 B는 Python `gzip.compress(…, 9)`로 잰 옛 빌드 값이다. 0단계 기록의 113,744 B는 GNU `gzip -9`(파일 이름을 머리에 넣음) 값이다. S2 다듬기 기록의 115,550·114,171 B는 검사와 같은 Node zlib 값이다.

- Node 24.22.1의 zlib는 `1.3.2.1-motley-285e94b`, Python 3.13.17의 zlib는 `1.3`이다.
- 첫 화면 JS(검사): 이 가지 114,171 B, main `dbe87c2` + 이 가지 114,168 B. 상한은 136,000 B다.
