## 한 일
- W3 검토 고침의 저장소 밖 확인 스크립트(`fix.cjs` 35개, `break.cjs` 8개, `focus-probe.cjs`)를 시험 틀 안의 시험 20개로 옮겼다: `e2e/inbox.spec.ts` 17개, `e2e/summary.spec.ts` 3개.
- 시험 틀을 넓혔다.
  - 가짜 계정 `dev`(역할 `player,dev`). 시안 자료는 admin 대신 가장 좁은 역할인 dev로 본다. 전역 준비의 들어가기는 2번 → 3번.
  - 들어가기 응답의 계정 ID(`userId`)를 적는다. 선택 `preview`(계정 이름)로 기기 저장소 `terra.preview`(`{ v: 1, user }`)를 미리 넣는다.
  - `helpers/messages.ts`: 메시지 원본(`apps/game/messages/{ko,en}.json`)에서 문구를 읽는다. 시험에 문장을 따로 적지 않는다.
  - `helpers/trpc.ts`: 묶은 tRPC 요청 보기(프로시저·입력), 요청이 멈출 때까지 기다리기(모두 끝나고 1초 동안 새 요청 없음), 응답 data 고치기(한 묶음의 여러 프로시저를 한 처리기가 고친다).
- main을 합친 뒤 처리할 일 자리 선택자를 처리함 화면(`section.inbox`) 안으로 좁혔다. 홈 대시보드(W4)도 처리할 일을 그리지만 이 시험은 `/inbox`만 본다(홈 묶음은 `home-inbox-group*`).
- 앱 코드는 바꾸지 않았다. 시험이 찾은 앱 버그는 없다.

## 건드리지 말 것
- `rewriteTrpc`는 화면마다 한 번 부른다(한 묶음의 여러 프로시저를 처리기 하나가 고친다). 두 번 부르면 앞 처리기가 묶음을 먼저 받는다.
- `filter({ has })` 안의 선택자는 줄 기준이다. 화면 범위(`section.inbox`)를 붙이지 않는다(전체 1차 실패의 원인).
