# S3 계단 시험: 시험 DB를 전용 컨테이너로 바꿈

- 일시: 2026-10-31 16:00 (KST)
- 작업 도구: Claude Code
- 관련: ADR `2026-10-31-s3-server-stage.md`(제안) 6절·WP-E, 작업 기록 `31-2100-s3-wpe.md`(WP-E), PLAN 9.4

## 한 일
- `s3-ramp` 첫 실행(run 41177812396)이 준비 단계에서 "시험 DB 컨테이너(terra_testDB)가 돌고 있지 않다"로 멈췄다(Verified: 작업 로그). 그 컨테이너는 이 스택을 만들 때 지웠다(PLAN 9.4, 사용자 결정 2026-10-28).
- `ops/s3-ramp.sh`가 시험 전용 PostgreSQL 컨테이너 `tic-s3-ramp-db`를 잠깐 띄우게 바꿨다.
  - 이미지는 운영 DB와 같은 `postgres:18.6-trixie`다. 메모리 상한 512MiB, `cpu_shares` 512, 전용 네트워크 `tic-s3-ramp-net`이고 공개 포트는 없다.
  - 앱은 컨테이너 이름으로 접속한다.
  - 비밀번호는 실행할 때 만들고, GitHub에서 가리고, `-e 이름`으로만 넘긴다.
  - 끝나면 컨테이너·익명 볼륨·네트워크를 지운다.
  - 운영 DB(`tic-db`)와 다른 프로젝트 DB는 쓰지 않는다.
- ADR·AGENTS·워크플로 머리 주석의 `terra_testDB` 문구를 고쳤다.

## 건드리지 말 것
- 계단 시험은 운영 컨테이너(`tic-app`·`tic-db`)와 다른 프로젝트 컨테이너를 건드리지 않는다.
