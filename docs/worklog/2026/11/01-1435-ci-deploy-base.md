# CI 배포 판단 기준을 "마지막으로 성공한 main 실행"으로

- 일시: 2026-11-01 14:35 (KST)
- 작업 도구: Claude Code
- 관련: `.github/workflows/ci.yml` changes 단계, ADR `2026-10-28-deploy-and-ops.md`(문서만 바뀌면 배포 생략)

## 한 일
- 발견: GitHub 동시 실행 묶음(`ci-refs/heads/main`)은 실행 하나 + 대기 하나만 둔다. 코드 푸시의 실행이 대기 중일 때 다음 푸시가 오면 대기 실행이 취소된다(실제로 run 169·174가 cancelled). 다음 푸시가 문서만 바꿨다면 changes 단계가 그 푸시 범위(`github.event.before`..)만 보고 배포를 건너뛰어, 취소된 코드가 다음 코드 푸시 때까지 배포되지 않을 수 있었다. 지금까지는 취소된 것이 문서 실행뿐이라 빠진 배포는 없었다(Verified: run 173 3120b4f 성공·배포).
- 고침: changes 단계가 `gh api`로 마지막으로 성공한 main 푸시 실행의 커밋을 찾아 그것을 기준으로 바뀐 파일을 본다(그 커밋이 지금 커밋의 조상일 때만, 못 찾으면 푸시 범위 그대로). 워크플로 권한에 `actions: read`를 더했다. 기준 커밋을 Summary에 적는다.
