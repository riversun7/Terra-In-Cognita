- 테마 단추: 틀 위 띠 [라이트 모드](`aria-pressed`). `localStorage terra.devTheme`(try/catch, 없으면 기본 네온).
- 기본 부품의 개발용 모양 `styles/dev.css`(`:where(:root[data-surface="dev"])` — 기본 부품 뒤에 불러와 같은 우선순위에서 이기고 화면 CSS에 진다): 납작한 작은 버튼, 네모 고르기, 늘이지 않는 버튼, 공용 표 `.dev-table`(고정 머리·줄무늬·올림·고정폭 숫자).
- **설정 칸 패널**을 촘촘한 표로 다시 짰다: 코드 · 이름·ID(덮어쓰기 정보) · 표지 · 지금(차이·담은 값) · 팩 · 범위(작은 막대 + 글·단위) · 새 값 칸 + [담기] · 되돌리기/담기 취소. 무리마다 표 머리 줄. [바꾸기]로 펼치던 단계는 없앴다(새 값 칸이 늘 보인다). 담기·적용(한 묶음)·확인 창·내보내기·모두 되돌리기는 같다. 찾기 줄은 한 줄.
- 관리자: 사용자 한 명 = 한 줄(아이디 · 가입 · 역할 · 저장 · 알림, 줄무늬). 스킬 목록 = 한 줄(이름 + ID·종류·소모), 행동별 소모 표·가중치 표 = 줄무늬·이름과 표지 한 줄. 개발자 홈 = 넓은 폭 두 줄. 공용 콘텐츠 편집기 칸(`contentEditor.css`) 촘촘하게. 나머지 화면(전투 실험실·계산식·전투 다시보기·2차맵 시험·행성·항성계 편집기·셰이더 측정)은 토큰만으로 촘촘해졌다.
- 대비 검사: 개발 테마 둘을 테마 4개와 같은 쌍 + 개발 전용 쌍(표 머리·줄무늬·올림·고른 줄 위 글자, 코드 글자)으로 재고, 개발 블록이 게임 테마 색 토큰을 빠짐없이 다시 정했는지 본다(`devThemeGaps`).

## 함께 바꿔야 하는 파일
- 개발 화면 층 색 토큰을 더하면 네온·라이트 블록 둘 다에 넣는다(빠지면 `pnpm check:contrast` 실패). 게임 테마에 색 토큰을 새로 더해도 두 블록에 넣는다.
- `DEV_THEME_STORAGE_KEY`(`shell/devSurface.ts`) = `e2e/helpers/test.ts` `DEV_THEME_KEY`.
- 새 개발 도구 주소는 `/dev/…`(`dev_*`)면 자동으로 층에 든다. 다른 이름이면 `isDevSurfaceRoute`를 고친다.

## 건드리지 말 것
- `styles/dev.css`의 `:where(…)` 낮춘 우선순위와 `main.tsx`의 불러오는 차례(styles.css 뒤). 바꾸면 화면 CSS가 지거나 기본 부품이 이긴다.
- 표 상자(`.tp-table-wrap`·`.dev-table-wrap`)의 `position: relative`: 줄 안 `.visually-hidden`(absolute)이 문서를 가로로 넓히지 않게 한다(390px에서 534px 넘침을 잡았다).

## /dev/items(아이템 편집기)에 남은 일
- `work/item-editor-2` 가지가 고치는 중이라 아이템 전용 파일(`editor/items/*`, `itemEditor.css`·`itemList.css`, `e2e/items.spec.ts`)은 건드리지 않았다. 공용 층(토큰·`dev.css`)과 `editor/content/contentEditor.css`만 들어간다(토큰만으로 글자·간격·조작부는 촘촘해졌다).
- 남은 것: 아이템 목록 카드(`itemList.css` `.il-*`, 한 항목 4줄 약 75px)를 한 줄 표(`.dev-table` 또는 스킬 목록처럼 줄)로, 칩의 알약 모서리(`--radius-pill`) → `--radius-sm`, `e2e/items.spec.ts` 사진 반복을 `devTheme` 둘(neon·light)로.
