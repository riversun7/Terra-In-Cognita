## 한 일

- 원인: 광산 한 사이클 수확이 1~10kg(옛 1 + VIT × 0.1개 × 1kg, 금속 광석은 같은 개수 × N44 1,000g) → 50~500g(50 + VIT × 5 × N44 1g)으로 20분의 1이 됐는데, 건물·배·알박기·시작 석재 수량은 무게 그대로 g로 옮겼다. 석재 생산 30일 60,166kg → 2,120kg. kg당 시세는 그대로라(석재 1kg·1 → 10kg·10) 값이 아니라 양 문제(Verified: 요약 `economy.produced`, `git show 5cf0d2d89a`).
- 고침: 설정 칸 `n44_ore_grams`(광석 수확 1단위 무게) 1 → 20g. 수확량 식(50 + VIT × 5, 상한 500)은 그대로라 사이클당 1~10kg = 바뀜 전 무게. 코드 기본값(`TEST_SOCIETY_COEFFICIENTS.gatherOreGrams`)과 생산 편집기 옛 서버용 기본값도 20. 건물 석재 수량·광석 1g 단위·10kg 묶음은 그대로.
- 다른 선택지를 뺀 까닭: 광산 수확량 식을 g로(1,000·100,000·10,000)는 `yieldBase`·`yieldCap` 스키마 상한 1,000을 넘어 스키마를 바꿔야 한다. 건물 석재를 20분의 1로는 광산 하나에 석재 200g처럼 무게(건설 시간·운반 셈)가 비현실이 되고 시작 석재·알박기 값도 다시 맞춰야 한다.
- `SIM_VERSION` 71 → 111(줄기 번호 = main 71 + 40, 코디네이터가 다시 매김), 팩 `core@138 → core@181`(줄기 번호). 출력 형식 23 그대로.
